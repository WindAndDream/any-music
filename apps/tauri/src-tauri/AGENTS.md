# Tauri Rust native boundary

Follow the [application guide](../AGENTS.md), [Desktop Development](../../../docs/en/desktop/development.md) and [Backend Engineering](../../../docs/en/desktop/backend-engineering.md). GM and TypeScript/Vue conventions do not apply to Rust.

- Use Rust 2024 and stable syntax satisfying Cargo.toml's minimum version. Respect ownership and short lock scopes; standard MutexGuard must not cross await. Deny `unsafe_op_in_unsafe_fn` and `await_holding_lock`. Application typecheck includes zero-warning all-target Clippy; explain necessary local lint exceptions at their owning function.
- Inherit root workspace edition/MSRV 1.90/lints; release toolchain is pinned to 1.91.1. Root owns lockfile/target. Pure protocol/policy boundaries live under `crates/`; workspace changes do not move account/CDP/media/IPC ownership.
- Register all app commands only in `src/ipc.rs`; build.rs derives AppManifest from that list. Product capability matches only the main WebView, never parent/window wildcards granting executor access. `s03-isolation-probe` is a separate fixed diagnostic example excluded from release. `pnpm check:plugin:isolation` builds/tests only; it establishes neither actual WebView acceptance nor launch authorization.
- Group named modules under `accounts`, `browser`, `network`, `storage`, `plugins` and `system`; `lib.rs` composes IPC/lifecycle. Moves update embedded-resource paths, fixtures and bilingual docs while preserving IPC, serialization, storage and public example APIs.
- Search IPC fully validates arguments in `browser/douyin_browser/commands` before account/browser dispatch. `browser/douyin_browser/search/cache` owns bounded raw responses and fixed cursor identity. Do not reread duplicates/stale responses. Drop must remove pending records when cancellation discards a future.
- `browser/douyin_browser/import` owns import pages/allowlisted request identity and reuses listing lifecycle/body budgets. Keep watch history, personal likes, collected videos/mixes and mix works on their own endpoints. Read collected-video cursors from POST forms; history/like timestamp cursors may decrease. Retain bounded consumed-cursor markers without duplicating music DTO parsing. CDP reader discards unrelated resources/byte-progress events before queueing while retaining business completion/failure and Fetch interception events.
- Validate numeric work IDs and video/note kinds at the same IPC boundary. `browser/douyin_browser/detail` captures only matching APIs/main-frame documents in an account's temporary target. Shared code parses protocols. Intercept Media/Image; close targets on success/failure/cancellation/timeout. Media bytes still use native HTTP/loopback grants.
- `network/http` and `network/request_registry` own requests, size/time budgets and request-ID cancellation. Built-ins bind account CookieStore/proxies; anonymous external paths never borrow account credentials. Declarative source gateways in plugins/source_auth own verified QR/credential/SMS challenges and encrypted installation/configuration-bound tokens, under explicit source/network consent. Guest networking stays anonymous; see [Music Source Authentication](../../../docs/en/desktop/source-authentication.md).
- `accounts`, root `state` and `storage/vault` own accounts/native state/encrypted credentials. `storage/product` owns separate product snapshots; IPC exposes public projections only. `accounts/login` and browser douyin_browser/cdp/process own production Douyin browsers, QR/SMS and session/search capture. `accounts/douyin_login` and `accounts/douyin_passport` retain protocol tests, not production login. Copying test-profile credentials does not prove native HTTP availability.
- Current schema-2 product saves check format/revision and atomically replace under one lock. Unsupported formats and stale revisions fail without overwriting data. Shared host code validates namespaces/business ownership; product mirroring is not plugin grant authority. PluginStore initializes schema 3 directly and rejects previous database schemas.
- Bilibili `browser/verification` reads credentials only after user completion. Douyin uses headed system browsers on separate inactive Windows desktops by default; continuous CDP returns public projections/allowlisted responses only. Storage.getCookies keeps credentials in Rust. `browser/login_experiment` requires explicit enablement, separate cleanup and clear experiment status. Remote pages receive no product IPC permissions.
- `media` owns bounded revocable loopback grants with source-account cookies/proxies; `system/download` owns native saving. Never persist media URLs, credentials or disk paths in product snapshots.
- Shared DTOs/mapping/lazy pagination/workbench behavior stay in TypeScript packages. Rust owns runtime transport, authentication, credentials and system capabilities, without copied source protocols.
- Native unit tests stay with Rust modules. From root, run application test/typecheck (workspace fmt/all-target Clippy) and check:native (workspace all targets plus explicit release target/features), then check:rust:msrv/check:rust:deny and root checks. Launching apps/verification browsers/login experiments still requires an explicit current-task request.
- plugins.rs composes am-plugin-runtime; storage/plugins owns separate SQLite. Synchronous transactions recheck identity/epoch/version/idempotency at commit and atomically persist provenance/receipts. Persist revocation first. The DB blocking pool is single-concurrency; executing jobs retain permits after canceled waits. Unknown schemas/damaged grants fail closed and preserve files. Fixture installs never enter product commands.
- plugins/network injects am-plugin-net Gate. Persist revocation, cancel install tokens, then acknowledge; final sink/dispatch polling share the authority barrier. Network ledgers use schema-3 plugins.sqlite3. Generic omit only reads current loopback grants; anonymous media registration fails. Unsupported external proxies/capabilities never fall back to account clients. admission/consent gates installation/execution.
- plugins/package_files publishes only native-generated content addresses: sync code/data before schema-3 committed DB pointers. Process locks cover install/recovery/GC. packages owns immutable previews without trusting renderer identity/grants; control consumes native tokens and explicit install/rollback consent. Return owned verified bytes without reopening paths after validation. Migrate owned copies only; rollback preserves epochs/revocation. revocations accepts only application-provisioned roots and persists their union; missing authority rows fail. Distribution roots remain unprovisioned; package keys are not trust roots.
- delivery unifies local/anonymous HTTPS/deep-link previews. control accepts only native tokens/explicit consent. executor checks actual window/WebView/document/context/deadline/sequence and cross-realm budgets. Install WebView2 all-source filtering before guest delivery; allow only fixed resources/exact relay, with independent Worker CSP. Windows DEV uses single-use SID ACL pairing, separate directories and explicit reapproval per update. ACK waits for transaction outcome; end blocks late installs before revocation. Keep commands in the unique registry with exact main permissions. Unknown targets fail; S16 is in progress. Android main-android grants bounded content-URI/native previews, diagnostics and opaque-token document saves; iOS main-mobile remains local-only. The Rust-only Kotlin bridge exposes no JS credential/URI/path command. Keystore wraps the native data key; missing/corrupt material fails closed. Both policies remain none, with no install/command/DEV grants. Mobile excludes desktop executor/DEV resources and acceptance features, and invalidates transient work/acquisition/previews on suspension. Android provides Bilibili-only QR app handoff/account HTTP, account proxy routing, Keystore credentials and foreground account-bound loopback media/Range. Bind the listener before capability discovery; Android WebView cleartext exceptions are loopback-only. iOS media/authentication stay unavailable. Real Android playback/seek/proxy acceptance remains separate from offline tests. Only explicitly opened unexpired QR handoffs survive suspension; no requests or tasks replay. New handoff device/clone acceptance remains separate. Android Clippy is a candidate build check, not release/device/channel admission; iOS requires macOS/Xcode. See [S16](../../../docs/en/cross-platform/architecture/plugin-system-s16-mobile-delivery.md).

- The product is unreleased: implement the current architecture directly. Do not add compatibility packages, previous product-schema readers, source JSON importers, archive UI or duplicate IPC aliases. Current plugin upgrade/rollback and crash recovery remain supported.

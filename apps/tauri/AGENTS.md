# Tauri desktop runtime

Applies to `apps/tauri`. Read [Desktop Development](../../docs/en/desktop/development.md) and [Runtime Status](../../docs/en/desktop/runtime-architecture.md); use `$any-music-tauri-runtime` for platform integration. Native code, permissions and configuration also follow [src-tauri/AGENTS.md](src-tauri/AGENTS.md). Mobile capabilities require explicit declarations.

The native crate belongs to the root Cargo workspace. Application test/typecheck/check:native cover all members; release outputs live in root `target/release/` and root start:tauri consumes that path. Builds/checks do not authorize product launch.

- music-workbench owns shared music behavior. src/platform adapts IPC, HTTP, login, media and storage. Frontend consumes QR/public state/allowlisted business responses, never cookies, CDP connections or proxy passwords.
- Current product schema-2 mirrors recover committed generations and revisions before mounting. Failed writes stop later saves; unsupported schemas are rejected. Product storage does not convert earlier formats.
- Ordinary built-in requests follow `native-http.ts -> http_request IPC -> Rust HTTP` with included credentials. Generic guest transport remains anonymous and follows the native Gate restrictions below. Declarative source authentication belongs to plugins/source_auth, with separate source-owned vault tokens and no built-in CookieStore/proxy/browser authority; see [Music Source Authentication](../../docs/en/desktop/source-authentication.md). Douyin login/session/search, watch history/personal likes/collected videos/mixes, mix works and work detail use `douyin-browser-catalog.ts -> douyin_catalog_request -> Rust douyin_browser` in the account system browser; shared code receives portable ports only. Imports match page/endpoint and GET-query/POST-form cursors; stopping closes targets. Details read matching official APIs or React Flight documents and close temporary targets. Media bytes stay in Rust HTTP/loopback grants. Both paths cancel through cancel_request, without WebView fetch/cookies or GM doubles.
- Preserve account identity across APIs, lazy pages and media. Rust registers loopback grants; account environment changes revoke old work. GM Range, page BDMS and protected-page capture are not desktop capability evidence.
- src-tauri owns account catalogs, separate CookieStore/HTTP clients, system vault and Chrome/Edge verification processes. Remote pages have no app IPC permissions.
- Production browsers use per-account UUIDs, separate user-data-dir, file locks, proxies and process trees, never WebView/headless/test Chromium. Official Douyin pages generate login/search; Rust observes allowlisted CDP responses, operates uniquely matched SMS controls and reads credentials. Windows uses a headed browser on a separate inactive desktop by default; visible verification requires user action. Bilibili reads credentials/browser version only after the user selects completion.
- Windows-debug-only `login_experiment` uses separate temporary profiles/system Chrome or Edge and official requests. Credentials remain in memory without production accounts/vault access. Only user action opens a visible browser; release IPC rejects experiment operations.
- Bilibili uses native QR; Douyin returns official-page QR/status/SMS results through CDP. Unverified platforms use the same account's system browser, without invented SMS/CAPTCHA protocols. Model mobile login/QR capabilities explicitly; never fall back to WebView authentication.
- Tests live in test; native unit tests stay with Rust modules. Run pnpm from root. App/browser launch requires an explicit runtime-inspection request in this task.

Run application test/typecheck (including Rust fmt/all-target Clippy), check:native for native changes, then root checks. TypeScript/Vue naming does not apply to Rust; read [Backend Engineering](../../docs/en/desktop/backend-engineering.md) and the native guide.

- tags/creation inject metadata and separate `/vue` loaders from features/plugins. Bind existing generation storage, without exposing GM/IPC, accounts or private repositories.
- built-ins use independent source metadata and lazy /runtime assembly. Keep provider IDs separate from module/contribution IDs. Disablement/invalidation cancels old lists/resolution/media; restore never replays tasks. Zero usable sources must not block core views.
- plugins.sqlite3 (schema 3) is native authority. native-plugin-authority injects snapshot/revoke, previews and named delivery ports; the center never creates grants. Native verification/consent drives install/rollback, without fixture seeds, arbitrary grants/sessions or general data-relay commands.
- Generic omit only reads current loopback media grants. plugins/network injects am-plugin-net Gate for external networking, without account cookies/proxies. Reject unknown required capabilities according to S15.

- The product is unreleased: implement the current architecture directly. Do not add compatibility packages, previous product-schema readers, source JSON importers, archive UI or duplicate IPC aliases. Current plugin upgrade/rollback and crash recovery remain supported.

- features/plugins/built-in-theme-directory owns metadata only; built-in-themes preloads the classic fallback and dynamically imports Studio Vue/styles. The sole MusicSourceWorkbench owns one controller/audio above the complete ThemeHost. Shared/SFC/theme CSS resources are activated transactionally inside its stable Shadow surface; protected slots receive host-only CSS. Build audits record actual static execution graphs.

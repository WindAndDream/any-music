# Any Music Development Guide

## Start work

- Start at the [documentation index](docs/en/README.md). Identify `userscript`, `tauri` or `shared`, then read the target module's relevant section, nearest `AGENTS.md`, current implementation and tests. From the repository root, explicitly read the target package guide. For cross-runtime changes, trace and verify each runtime separately.
- Before adding, modifying or removing code/configuration, create and index a step document under [In progress](docs/en/changes/in-progress/README.md). Record the user's goal, steps and targeted verification. **Keep small fixes small. A few lines and one focused check are enough. Avoid defensive overengineering.**
- Update the step's next action when switching tasks. Move the record to [Acceptance](docs/en/changes/acceptance/README.md) when implementation is ready, or to [Temporary acceptance](docs/en/changes/temporary-acceptance/README.md) after explicit user approval to proceed with a gap. Follow the [documentation workflow](docs/en/guides/documentation-workflow.md) for statuses, closeout and evidence. User-approved scope and actual verification belong in the same record.
- Use `$any-music-userscript-runtime` for GM, `$any-music-tauri-runtime` for IPC/native data/accounts, `$any-music-ui-delivery` for product UI and `$music-source-adapter` for source or playback startup. Source capture skills establish website contracts, with GM and Rust acceptance separate.

## Place implementations

- [System architecture](docs/en/architecture/README.md) maps layers. [Package boundaries](docs/en/architecture/package-boundaries.md) owns dependency directions and public entries. Applications inject runtime ports, `music-workbench` owns shared orchestration, `core` owns domain contracts, and `ui` and theme packages own controlled presentation. Shared packages cannot import apps or runtime-specific APIs. Keep public lightweight metadata entries free of Vue/styles/codecs and retry failed dynamic imports.
- Keep `account-pool -> network-routing` pure with injected clocks/transport. Production multi-account/proxy composition lives in Tauri. Source packages use portable ports and public `core`/`plugin-center` contracts. Applications inject built-in source, tag, creation and theme implementations.
- Use `workspace:*` for internal dependencies and public exports. Put tests under each owner's `test/` mirroring `src/`, with application composition tests in the app. Follow [Development Workflow](docs/en/guides/development-workflow.md) for TypeScript/Vue naming, ownership, extraction and builds. Use Composition API and typed `<script setup lang="ts">`, keep components controlled, and put cross-view state, async races and cleanup into composables. Rust follows [native engineering](docs/en/modules/tauri/backend-engineering.md).
- Implement the current unreleased architecture directly. Avoid compatibility packages, old product-schema readers, source JSON importing, archive UI and duplicate IPC aliases. Preserve current plugin upgrade/rollback and crash recovery.

## Preserve product contracts

- Follow [Privacy and Secret Handling](docs/en/guides/privacy-and-secrets.md). Keep credentials, personal contact data, account/browser state and local machine paths out of tracked content, commits, evidence and screenshots. Use synthetic fixtures and portable placeholders. Git author/committer metadata may use personal email, although GitHub noreply is recommended. Review images and binaries manually. Run pinned gates without bypassing hooks or broadening exceptions.
- Userscript transport uses `GM_xmlhttpRequest`, including its manager fetch option. Tauri renderer uses IPC to native HTTP, with Rust binding account Cookies/proxies. Built-in requests use explicit `credentials: 'include'`. Keep secrets in the runtime owner. See [Userscript development](docs/en/modules/userscript/development.md) and [Tauri development](docs/en/modules/tauri/development.md).
- Persist stable product identities, recipes and necessary operation metadata. Keep ephemeral media URLs, Blob URLs, bytes and final disk paths out of product snapshots. [Resource caches](docs/en/modules/resource-cache.md) are disposable, bounded and separate from backups and credentials. Use `AppErrorState` across layers and storage. Keep tag/creation namespaces separate from host library writes and withdraw projections on disablement.
- Preserve descriptor → native streaming → bounded Range/MSE → complete-read fallback. Custom tracks prefetch bounded leaf segments. Seek, track switch and disposal abort prior work. Follow [Media loading](docs/en/modules/sources/media.md) and [Custom track recipes](docs/en/modules/library/custom-tracks.md).
- Card movement preserves paint coordinates, rendering and elevation through FLIP interruption, preview and landing. Follow [Motion and Gestures](docs/en/modules/ui/motion-and-gestures.md#7-motion-and-gestures) and cover bidirectional moves, rapid reversal and stale completion cleanup.
- Userscript fixes `externalPlugins: none`. Tauri composes from `runtime_capabilities`; native verification, exact target admission and explicit consent govern installation. Mobile external install/execution/DEV remain unavailable. Generic guest networking is anonymous; declarative native source gateways use scoped source-owned credentials and explicit source/network consent. External catalogs provide no media resolution. See [Plugin runtime policy](docs/en/modules/plugins/runtime-policy.md), [Desktop delivery](docs/en/modules/plugins/desktop-delivery.md), [Music source authentication](docs/en/modules/tauri/source-authentication.md) and [Mobile capabilities](docs/en/modules/tauri/mobile.md).
- For plugin work read the relevant [plugin module](docs/en/modules/plugins/README.md) and nearest package/crate guide. VM uses SDK/fixed engine and pure injected tools. Keep `/profile`, `/control` and adapter roots engine-free, refresh hashes for Profile/bridge changes, and treat `pnpm check:plugin:vm` as same-engine/offline evidence. CLI/testkit never enter production.
- Native authority commits values/provenance/receipts and revocation through injected `Store`/`Clock`/`Ids`/`InstallFiles` and separate schema-3 `plugins.sqlite3` transactions. Keep install/grant authority native. Request hops, Range and delivered bytes share native Gate checks, budgets and revocation. Use controlled dialogs with an epoch recheck for exports. Close contexts before acknowledging cancellation; install native resource filters before guest delivery. Reject unknown required contracts, capabilities and targets.

## Verify and deliver

- Keep both locales, counterparts and links current. System and module pages describe current contracts. Change records own work/acceptance status; delivery matrices and scoped evidence own admitted capabilities. Move future and discarded ideas to their indexes and prune redundant completed material. Maintain `documentType`, `runtimeScope` and source contract `platform`. Advance `captureDate` only after live recapture.
- Write repository `AGENTS.md`, skills and public SDK/CLI/testkit READMEs in English. Keep `README.md` and `docs/zh-cn` in Chinese; `README.en.md` and `docs/en` in English. Preserve literal strings and identifiers.
- Run targeted checks during work, from the repository root with pnpm. Before committing, install the pinned scanner via `pnpm privacy:setup` and run `pnpm check:privacy`, `pnpm check:privacy:history`, `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check` and `pnpm build`.
- Native work uses the root Cargo workspace, one lockfile and root `target/`. Read [crates/AGENTS.md](crates/AGENTS.md) and [Tauri Rust guide](apps/tauri/src-tauri/AGENTS.md). Also run `pnpm check:native`, `pnpm check:rust:msrv` and `pnpm check:rust:deny`. Use the explicit release feature sets. Source/playback tests check request counts, order, concurrency, cancellation and retry.
- **Launch development servers, product previews, browser sessions, emulators or other live UI inspection only when explicitly requested in the current task.** Automated logic/component checks, builds and local test backends without product UI can run directly. Report live acceptance separately from test/build results.
- Follow [Git Flow](docs/en/guides/git-flow.md). Integrate topic branches by reviewed PR/merge commits. Never push directly to, force-push or delete long-lived branches. Publish only explicitly accepted annotated version tags from `main`; confirm back-merges before deleting completed topics. Commit/push only on request, split by responsibility, and use English Conventional Commits.
- Report actual commands, results and remaining verification in the task handoff. Avoid local logs and per-commit notes unless requested. Preserve referenced evidence and follow [result reporting](docs/en/guides/development-workflow.md#verification-results).

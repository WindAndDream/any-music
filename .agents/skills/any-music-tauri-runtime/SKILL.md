# Any Music Tauri Runtime

Read apps/tauri/AGENTS.md, the [desktop rules](../../../docs/en/desktop/development.md) and affected [native guide](../../../apps/tauri/src-tauri/AGENTS.md). Rust conventions are maintained in the [backend guide](../../../docs/en/desktop/backend-engineering.md).

## Follow the native boundary

Trace built-in HttpClient through src/platform/native-http.ts, http_request IPC and Rust network/http and network/request_registry. Preserve request-ID cancellation, response-size limits and error projection. Built-in include binds the selected account's CookieStore/proxy. Generic omit only reads current loopback media grants. Generic external package networking goes through plugins/network and am-plugin-net with native grants, independently of account clients. Declarative API source authentication uses plugins/source_auth and host-owned token injection, with configuration fingerprints and explicit source/network consent; see [Music Source Authentication](../../../docs/en/desktop/source-authentication.md). It never borrows built-in cookies/proxies or opens an external login browser. Do not use WebView fetch/cookies, GM shims or host login state for business data.

Keep portable DTOs/signing/mapping/pagination in the independent plugin-source packages. Formal Douyin authentication belongs to Rust accounts/login and browser/douyin_browser, browser/cdp and browser/process; accounts/douyin_login and accounts/douyin_passport retain protocol tests. Session/search, selected personal imports and work details use the injected native-owned CDP catalog port; media bytes retain Rust HTTP/grants. Userscript BDMS, GM_cookie and background-page capture are optional userscript capabilities, not assumed native fallbacks.

Keep public account routing in desktop composition, secrets in Rust, and identity stable across listing pages and media. Preserve bounded loopback grants and revoke old work on account changes. Product snapshots stay separate from credential storage and any-music:userscript:*; native commands own file saving and permissions.

The formal system-browser verification path and dedicated test-browser contract capture have different rules. Preserve explicit enablement/lifecycle of existing login experiments and identify their evidence separately. Do not treat browser login success as Rust success or desktop capability as mobile support.

## Verify the desktop layer

Run pnpm --filter @any-music/tauri test and typecheck; native changes also run check:native, followed by root gates. Tests should prove the affected IPC/transport/account/media behavior without launching UI. Use `$music-source-adapter` or `$any-music-ui-delivery` when shared contracts change.

Only explicit runtime inspection authorizes launching the app/browser. Report website observations, Rust tests, real native account/HTTP checks and desktop playback acceptance separately. Transport fixtures cannot prove live CookieStore, proxy or IPC correctness.

For plugin delivery, follow [S15](../../../docs/en/cross-platform/architecture/plugin-system-s15-tools-and-desktop-delivery.md): plugins/delivery and plugins/control use verified opaque previews, explicit consent and exact target/resource admission. Native runtime_capabilities drives composition: admitted desktop targets supply sandboxed, other desktop targets declarative, and unaccepted mobile targets none; the native install policy still denies unadmitted activation. DEV uses owner-SID pairing and independent DB/code/data/profiles. Executors require a native all-source resource filter before guest delivery, isolated CSP and native context/sequence checks; cancellation closes contexts before acknowledgement. Never restore unsupported media execution through generic HTTP.

For S16 mobile work, read the [mobile engineering record](../../../docs/en/cross-platform/architecture/plugin-system-s16-mobile-delivery.md). Use main-android for bounded package previews/document saving and main-mobile for iOS local data; never infer execution admission from adapter or desktop evidence. Android Keystore/URI/opaque save tokens remain private to Rust, without a JS bridge command. Keep none policy and preview-only controls until separate execution admission. Mobile does not assemble desktop executor/DEV resources. Android built-in Bilibili playback/downloads use native account-bound loopback media with Range streaming; initialize the listener before capability discovery and keep Android cleartext exceptions restricted to loopback. Android account proxies use native HTTP routing and explicit accountProxy capability; iOS media remains unavailable. The trusted host MP3 encoder needs local Blob workers and wasm-unsafe-eval in the main CSP; keep isolated external executor policies independent. Reference debug playback/seek/MP3 saving and proxy requests have device evidence; optimized-release/audio-focus/interruption acceptance remains separate. Suspension cancels transient work without task replay. Android's minimum API is 26; product startup requires WebView 111+ with a native fallback message. Keep Tauri/Gradle/NDK minimums aligned. Run check:mobile:boundaries and check:mobile:android. build:mobile:android accepts --release/--signed; signing is explicit and verified, never a debug-key fallback. accept:mobile:android requires a dedicated running emulator's explicit serial and live-inspection authorization; it records skipped cases and does not reset product data. accept:mobile:android:device requires an explicitly selected physical arm64 device and an installed byte-matched verified release; native tests use an independent temporary debug identity/UID and remove only their own packages. Report those adapter tests separately from optimized-release launch/IPC and minimum-device acceptance. Local signatures and 16 KiB build alignment do not establish publisher/channel/device or plugin execution acceptance. iOS requires macOS/Xcode.

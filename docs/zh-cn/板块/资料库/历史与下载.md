# 播放历史、待听与下载

[English](../../../en/modules/library/history-and-downloads.md)

共享控制器和仓储管理播放历史、队列顺序及下载任务，应用注入持久化和保存能力。

## 播放历史与队列

所有播放入口按稳定曲目 ID 共用播放历史，每首曲目保留一条记录。重播会将该曲目移到最前，并记录本次播放的进度。曲目仍在历史中时，歌单的播放次数统计会计入重播次数。读取快照时先为每首曲目保留最新记录，再应用数量上限。合并备份时也为每首曲目保留最近一次播放记录。共享存储写入按一秒节流，避免 `timeupdate` 高频触发存储，切换曲目、播放完成或组件卸载时保留最新状态。用户可在全局设置中将保留上限设为 1～500 首，调小后立即裁剪最旧记录，读取快照时也按同一硬上限校验。

待听列表使用独立的 `playback-queue:v1` 业务后缀（Userscript 添加正式 GM 前缀；桌面写独立快照），只保存资料库曲目 ID 的顺序和播放模式。加入待听前先立即保存规范曲目，刷新后再通过资料库解析 ID；“我的喜欢”可把当前筛选与排列结果作为临时播放上下文，并复用顺序、单曲循环、随机和随机不重复模式，但不会用整个喜欢列表覆盖待听。当前选中项、播放进度、临时媒体 URL、临时播放上下文和随机洗牌袋不跨刷新恢复。

## 批量下载与下载历史

音乐列表、待听、我的喜欢和单个用户歌单都提供曲目多选与“下载已选”。应用只运行一个全局下载调度器；设置中的最高并发值限制为 1～5，并在每个批次开始时形成快照。单首歌曲首次失败后最多重试 3 次，某一首耗尽重试不会取消同批其他歌曲。“下载”板块统一管理当前任务和已下载记录，提供状态选择、歌曲操作、暂停、继续与重试。批量下载统一即时解析媒体并生成 MP3；多曲批次只触发一次浏览器保存，ZIP 内包含所有成功文件及完整批次报告，单曲批次仍直接保存 MP3。自定义歌曲仍从已编译的叶子时间线生成，短时媒体 URL 不会作为下载身份或历史字段保存。

下载历史使用独立的 `download-history:v1` 业务后缀（Userscript 添加正式 GM 前缀；桌面写独立快照），与有数量上限的播放历史完全分开。每次用户点击形成独立批次，永久保存发起板块与名称快照、批次起止时间、实际并发、完整 `Track` 快照、每次尝试的起止时间与错误、取消/最终状态、成功文件与最终 ZIP 的名称、MIME 和字节数；不自动裁剪。已下载任务保留在下载页，确认移除记录时保留已保存文件。浏览器不能读取用户最终选择的磁盘路径。若页面在下载中关闭或刷新，下次启动会把仍在运行的批次和尝试标记为“中断”，保留中断前已经写入的全部信息。暂停任务继续时重新解析媒体，不保留字节；字节范围续传、调整单曲优先级和刷新后自动继续下载仍未实现。

## 下载界面与运行端准入

经典主题下载页的歌曲操作弹窗复用[发现的歌曲摘要和完整歌名预览](../界面/歌曲结果页.md)。弹窗顶部显示「歌曲操作」。

- 下载页提供全部、下载中、已暂停、已下载、下载失败状态选择。待听、我的喜欢与下载按板块及区域独立持久化展示偏好：全部歌曲、各平台详情、各下载状态互不影响；未设置的区域桌面默认第二项标准密度，手机默认第一项一行一个。当集合实际宽度不超过 760px、排列选项需要占满一行时，或宿主已进入手机布局时，仅保留一个展示图标按钮并移到筛选器左侧，与筛选器保持 36px 等高；宽列表保留顶部入口。侧栏引起的桌面内容区变窄也遵循相同规则。下载封面长按 500ms 后复用待听、喜欢的拖拽排序，短按仅在操作器模式下选择，方向键在两种模式下均可逐项移动。拖拽生效后使用十字移动光标，松手、取消或卸载时恢复。下载顺序仅独立保存稳定任务 ID，不改变批次归属和调度准入；筛选后排序保留隐藏项位置，进度更新不重置顺序。发现与下载顶部均复用操作器的无滚动条横向按钮栏：溢出时右侧出现箭头，点击前进，到末尾后可返回开头；尺寸或按钮数量变化时重新判断。状态和展示按钮在悬停、键盘聚焦时有背景反馈。灰色集合背景、白色空状态、歌曲行及筛选器/操作器入口与其他集合一致。蓝色数字区显示“2 并发”，数字在前，字号和字重与待听、我的喜欢保持一致。筛选包含文本、用户标签、时长、平台和任务日期，历史独立保存。下载按稳定歌曲 ID 保持跨批次唯一，再次提交复用任务 ID 和尝试记录，并替换原列表项。操作器支持继续暂停任务、重新下载已下载或失败歌曲、暂停活跃任务、取消所选排队/下载/暂停任务，以及确认移除记录而保留已保存文件。混合选择显示“下载”，处理可操作任务；只选已下载歌曲时显示“重新下载”。取消会清除待自动继续的任务并中止媒体和重试流程，保留可重试记录；已取消记录归入“已暂停”筛选并明确显示已取消。行内按钮随任务状态变化，末尾为“操作”。歌曲信息显示状态，歌曲操作弹窗提供当前任务状态对应的操作。文件生成后仍须等待保存确认，部分批次重试不会改变已保存歌曲的成功状态。原生重新下载先在当前保存目录核对精确文件名、字节数与完整 SHA-256，同一 ZIP 文件每轮只流式校验一次；复用凭据前还需确认导出标题、配方与创作者一致。文件缺失、改名、内容变化或没有可信指纹时重新下载，仅内容相同但名称不同不能跳过。单曲仍保存 MP3，多曲仍保存 ZIP；ZIP 校验针对保存的压缩包，不检查另行解压的文件。Userscript 无法读取磁盘目录，允许重新保存而不声称已校验本地文件。

- 暂停会中止读取/编码，资源清理完毕后释放并发名额，并保留任务身份、尝试记录和明确提交的试听配方。继续时重新解析媒体，不保留媒体字节，也不表示 HTTP 字节断点续传。桌面和 Android 注入 Rust FIFO 信号量控制整首任务准入，篡改猴使用前端 FIFO；重试策略和受信浏览器编码器仍由共享层持有。刷新/挂起取消临时任务，不自动重放；中断任务由用户明确重启。优先级调整和字节断点续传尚未实现。

# 桌面账号、代理设置和验证

[English](../../../en/modules/tauri/accounts.md)

原生账号状态负责身份、代理路由和验证，渲染器界面使用公开投影和具名操作。

## 账号与验证

桌面端内置网易云音乐，使用账号绑定的 HTTP／媒体和原生二维码轮询，也可在账号的应用内官方页面完成登录与验证。Rust 在提交凭证前核对官方账号和资料身份。协议观察与尚待进行的真实 GM／桌面验收见[网易云接口接入记录](../音乐源/网易云/接口接入.md)。移动端不注册此来源。

官方账号页面是产品窗口的子 WebView（`browser/embedded`）。每个账号拥有一份持久页面上下文：WebView2/WebKitGTK 使用 `profiles/<uuid>/webview` 数据目录，macOS 使用由账号 UUID 派生的 WebKit 数据存储；同时持有独占存储锁和绑定代理。隐藏页面保持 1280×800 视口并位于可见窗口区域之外，关闭后台节流，使官方布局、懒加载列表和滚动观察与可见标签页一致。文档开始前注入的桥接脚本只上报白名单内的 fetch/XHR 交换（抖音 `/aweme/v1/web/` 与 `/passport/web/`）、作品页序列化主文档和固定原生脚本结果；它禁用媒体播放，从不删除或改写网站 DOM。上报只经过 `account_page_report`，它是独立 `account-pages` 能力中唯一的命令：仅限抖音／B 站／网易云远程来源和 `account-page-*` 标签，不接受本地调用方；每个页面另有随机令牌，并只路由到自己的 actor。驱动层以有界 CDP 子集（页面、导航、脚本执行、页面内输入、经原生 WebView Cookie 接口读取 Cookie）对接现有账号 actor，登录、搜索、详情和导入状态机保持既有请求身份、预算与清理。已保存的原生凭证只在新建页面上下文时导入一次，已登录账号不会因迁移而掉线。产品命令接收调用方 `tauri::Webview`，只接受 `main` 标签。该传输目前只有自动化测试，尚未进行实站验收。

首次安装账号列表为空，不自动生成默认账号；用户先建立登录草稿，内置平台验证成功后才进入账号列表；外置声明式网关仅在明确声明允许时提供免登录，见[音乐源认证](音乐源认证.md)。读取已有配置时保留已保存的账号，删除所有账号后重启也不会补建。账号可添加、删除、命名、启停，选择直连或一个无认证 HTTP(S)/SOCKS5 主代理及最多八个有序备用代理。账号连接设置与原生路由持有这一有界回退链，详见后文。代理认证和代理组界面仍未提供；独立 account-pool/network-routing 算法不代表原生连通性或实站验收。

正式入口在设置中：“音乐源 → 账号管理”维护账号、登录验证、连接分配和自动选择请求策略；“网络与下载 → 代理管理”保存多个独立代理，显示关联账号，解除分配后才允许删除。表单沿用共享设置的卡片、开关、控件圆角和容器内单列适配，不再使用窗口顶部的临时工具栏。

代理设置分为“添加代理”和“代理管理”两个区域。添加表单在字段旁显示校验错误，保存失败保留输入；原生保存成功且快照确认后清空草稿。管理列表集中展示名称、协议、地址、分配数量和关联账号，窄容器下改为分行展示。前端和 Rust 均校验无认证的 HTTP、HTTPS、SOCKS5/SOCKS5h 端点，要求合法 IPv4、方括号 IPv6 或域名，以及显式的 1–65535 端口；拒绝路径、查询、片段、凭据和不完整的 IPv4 写法。名称去除首尾空白后必须唯一；地址规范化协议/主机大小写、域名末尾点、IPv6、端口数字和末尾斜杠后查重，默认端口仍显式保存。Rust 在同一次原生配置事务中校验与查重，阻止并发重复添加。上述校验只验证格式，不代表代理连通性。

发现页的账号按钮可打开平台账号切换弹窗。所有平台的按钮都只显示当前默认账号的自定义名称。每个平台在启动刷新前恢复上次选择的公开账号 ID；没有有效选择时，按账号列表顺序选取首个已启用、非待保存、状态就绪且已配置凭证的账号（外置来源也允许匿名账号），否则选取首个已启用、非待保存的账号，并保存为默认选择。已保存的账号即使需要登录或验证，也保持选中并显示待处理状态。平台尚无账号时显示“无账号”和“添加”，直接打开独立的账号创建弹窗并预选当前平台，不打开全局设置；受保护的弹窗保留标准进出场动画，关闭后回到发现页。允许免登录的来源也需要填写账号名称。手动选择只持久化公开账号 ID，作用于新的搜索、导入、会话检查和播放/下载解析；已有歌曲列表和媒体不因搜索偏好变化而中断。进入歌曲列表后，平台和实际请求账号只读，重试时优先沿用原账号。所选账号删除或停用后，按相同固定顺序选择并保存替代账号；没有已启用、非待保存的账号时清空选择。空闲列表在下一次加载时选择可用账号并从第一页重建，不能混用旧游标。正在加载的列表中止并弹出错误，重试重新选择可用账号；平台没有可用账号时提示到账号设置中添加或启用。切换弹窗与设置共享产品主题和模态宿主。本次验证覆盖组件、状态组合与 Rust 自动化测试，未进行应用视觉或实站账号复测。

账号 UUID 同时绑定 CookieStore、HTTP 客户端、加密凭证文件和 `profiles/<uuid>`。该目录由应用生成，不接受前端路径。系统保险库存放 32 字节加密密钥，凭证文件使用 ChaCha20-Poly1305；保险库失败不会退回明文。内嵌页面引擎按其原生机制保存页面数据；应用只通过原生 WebView Cookie 接口读取 Cookie，不在 URL 或日志传递凭证。

B 站继续使用原生二维码生成、轮询、确认和取消。抖音正式登录由 Rust `douyin_browser` 驱动账号内嵌页面中的官方页面；软件显示页面返回的 PNG 二维码，持续通过页面桥接获取扫码、二次验证、短信发送/提交和最终账号状态。用户选择短信并输入六位验证码后，Rust 操作唯一匹配的官方控件；刷脸、发送短信及未知安全挑战在应用内页面弹窗中显示同一账号的官方页面。登录 UUID 隔离替换、取消和短信操作；挑战留在页面及 Rust 内存，过期响应不能写入新会话。

2026-10-20 直接检查 B 站原生生成接口，返回地址为 `https://account.bilibili.com/h5/account-h5/auth/scan-web`，携带一致的 32 位挑战标识。Rust 挑战构造和 Android Intent 校验均接受该精确域名/路径及此前观察到的 Passport 扫码路径，同时校验 HTTPS 和唯一的 32 位挑战标识，继续拒绝普通账号页面。Android 分别报告无效授权地址与应用唤起失败，不再把所有拒绝都归因于未安装客户端。抖音二维码与轮询响应白名单覆盖 `www.douyin.com`、`login.douyin.com` 上的精确 Passport 路径。浏览器内容流程的辅助资料读取为主账号流程保留最多 32 个进行中的登录请求和 96 个有序事件，不保留响应头或签名查询，避免静默吞掉二维码或确认状态。

后台工作不会打开任何窗口：隐藏页面位于可见窗口区域之外，不出现在任务栏或 Alt+Tab。只有显式登录或验证的展示页面会按渲染端上报的占位区域（`account_page_layout`）覆盖在应用内弹窗中。验证页面在官方页面出现登录或安全挑战前保持隐藏；出现后通过 `visibility` 规则只显示挑战对话框，不删除 DOM，弹窗按挑战尺寸预留空间。页面加载 12 秒后仍识别不到挑战时显示整页。没有 headless 参数或指纹伪装；macOS 页面 User-Agent 使用系统 Safari 版本。不能承诺平台风控判断与可见浏览相同。显式可见交接先关闭该账号的页面，再打开同一持久上下文，不承诺旧二维码或挑战延续。

后台搜索、可见验证和应用重启沿用账号唯一的内嵌页面上下文。退出交接关闭全部页面，并等待页面驱动结束后才释放存储锁。网页登录或验证后的首次目录操作按需打开隐藏的账号页面。账号启动、验证、登录和删除共用账号交接锁，防止退出期间重新占用页面上下文。

每账号独立 UUID、内嵌页面上下文、独占存储锁与绑定代理。退出/取消关闭全部页面并保留上下文。每页正文缓冲有界（16 份、24 MiB），在所属 actor 读取前暂存上报的响应；个别登录响应因跳转失效时等待新的官方账号确认，不凭空推断登录成功。认证用户对象与有效登录 Cookie 同时成立后，通过原生 WebView Cookie 接口获取含 HttpOnly 的平台 Cookie，加密存入原生保险库，并保存页面实际 User-Agent；渲染端不接收凭证原文。独立账号检测按需通过 Rust HTTP 查询官方身份接口。可见验证完成时重新读取最新 Cookie 并关闭展示页面。过期的短时 Cookie 不会阻止有效登录凭证的导入。

B 站／网易云应用内登录页面在用户点击“我已完成登录”后一次读取 Cookie 和页面 User-Agent，再关闭该页面。专用测试浏览器的契约记录不等于正式桌面账号或 Rust HTTP 验收。

进入浏览器验证会暂停该账号队列并取消旧会话；其他账号继续工作。明确的登录拒绝和已知验证信号分别进入未登录或需要验证；HTTP 403、429 本身不证明账号失效，验证信号优先于 HTTP 401。匿名登录检查不会把匿名账号标为过期。每账号 API 单并发，加入抖动与有界指数退避；连续三次网络/超时失败暂停账号，等待用户检查。未知失败不冒充代理故障；没有自动直连泄漏代理偏好的回退，也没有后台周期登录探活。

抖音账号检测与搜索使用以下状态边界。Chrome 抓包确认了身份接口和访客响应的区别，Rust 与渲染端自动化覆盖了身份投影及过期结果处理。正式原生 HTTP 实站验收仍独立进行。

原生账号公开 `state.login`、`state.verification` 与 `state.connection` 三个独立维度；`status` 是账号池路由投影，`authentication` 只表示凭证保存模式。已登录且需要验证可以同时成立。登录操作暂停请求时不记录虚假的人机验证需求，取消和重启解除操作暂停，保留实际的内容验证要求。没有保存抖音登录凭证的账号直接返回未登录。

账号路由预检失败也携带具体账号 ID。首屏及后续页验证错误都把账号绑定到列表；只有绑定仍存在且已启用时才暴露验证动作。浏览器启动失败、关闭、取消、超时或确认失败保留原请求原因，并在同一详情中显示验证操作的原因与重试入口。验证完成时先确认官方搜索响应、身份与凭证，再刷新快照并从第一页重新加载；快照刷新失败或取消加载使用“重试”入口，不要求再次打开浏览器验证。当前列表只允许自己的成功凭证更新穿过恢复阶段，账号删除、停用和代理变更仍中止旧操作。回归测试覆盖正式来源适配器、账号选择、列表状态与模拟原生 IPC；这不是本次真实账号浏览器验收。

| 观察与操作                                                                 | 账号状态及恢复                                                                           |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 登录时用户资料有效，或检测返回的 UID 与已绑定 UID 一致，且登录 Cookie 可用 | 登录有效；单独的内容验证要求继续保留                                                     |
| 独立检测发现登录 Cookie 缺失，或有效响应中的 UID 与已绑定 UID 不同         | 未登录（登录失效），可重新登录                                                           |
| 登录拒绝或登录面板，但浏览器仍保留登录 Cookie                              | 需要验证；Cookie 的存在不保证平台会接受，不能据此宣告失效或成功                          |
| `2483`、验证链接或搜索 `verify_check`                                      | 需要验证，优先于 HTTP/业务登录拒绝；不清除凭证                                           |
| 缺少身份字段、未知业务码、格式改变、连接错误、超时                         | 检测未完成，保留原账号状态；按需重新请求身份接口                                         |
| 二维码过期、验证窗口关闭或取消                                             | 二维码过期只属于本次扫码；取消不证明退出登录，也不证明验证完成，已保存账号保留待验证状态 |
| 官方搜索响应确认验证完成，并重新确认身份与凭证                             | 保存最新凭证并恢复可用，同一列表从第一页重新加载                                         |

共享适配器解析搜索业务状态，通过可选 `reportFailure` 回报当前账号/列表。Rust 核对列表仍属于当前浏览器、同账号 Cookie 和会话代次后持久化公开状态；请求 ID 支持取消，旧列表、旧账号环境与晚到结果不能覆盖新状态。无可用候选时保留“需要验证”或“连接不可用”的实际原因。账号检测分别统计未登录、需要验证与检测失败；短信请求、提交、等待官方确认和失败重试各自显示进度。

## Windows 开发版后台登录试验

独立的“抖音后台登录试验”通过 Windows Rust debug 构建中的独立 example 运行。试验不读取或更新正式账号、保险库或用户 Profile，实验与正式账号 CDP 会话相互独立，不作为正式验收证据。

依次比较系统 Chrome（未安装时使用 Edge）的有头 `--no-startup-window` 加 CDP `Target.createTarget(hidden: true)` 与现代 `--headless`。官方页面生成二维码、签名、轮询和短信请求；Rust 只观察限定接口并操作唯一匹配的页面控件。未识别的页面或安全挑战停止自动操作。用户点击可见浏览器入口后才关闭后台进程，以同一临时 Profile 开始新的官方登录，不承诺延续旧二维码或挑战。

每次使用独立 UUID、临时 Profile 和本机调试端口；Windows Job 持有专属进程树，启动前安装窗口显示事件监测。“未观察到窗口”只表示事件观察，仍需人工确认闪现、任务栏与 Alt+Tab 表现。短信操作要求用户输入，重复提交、重发、响应读取与十分钟总时长有界。取消、替换、退出和超时结束监听、关闭进程并检查目录归属后清理 Profile；清理失败独立报告。

官方最终 `confirmed` 与有效登录 Cookie 同时成立才确认浏览器登录；随后以内存 CookieStore、相同 User-Agent 和浏览器新签名的自身资料 URL，经 Rust HTTP 重放 `/aweme/v1/web/user/profile/self/`，按已有会话检查的用户对象标准判断。该结果验证凭证交接与原生传输，不证明共享适配器的独立本地 `a_bogus` 或全部音乐业务可用。Cookie、挑战 token、请求 URL、手机号原文与验证码不进入公开结果或日志。

同一后端的显式实站驱动器：`cargo run --manifest-path apps/tauri/src-tauri/Cargo.toml --example douyin-login-experiment -- headed-hidden`（对照模式为 `headless`）。仅在用户请求实站运行时使用；临时扫码 PNG 在退出后删除，支持人工 `sms`、`code <六位数字>`、`visible`、`cancel` 操作。

临时 Profile 实验未通过 2026-10-03 的采用条件：headed 模式止于二次验证控件，headless 未找到登录入口。完整 QR／SMS 确认、原生凭据交接和严格不可见仍未验收。生产使用持久账号内嵌页面，实验结果不接受生产路径。

## 账号设置与请求连接

原生账号身份采用 `(platformId, platformUserId)`，与浏览器/Profile UUID 和可编辑的本地名称分离。登录提交与官方身份检测拒绝同一平台身份的其他已配置账号，停用账号也参与去重；尚未登录的条目需要登录后才能确定真实身份。B 站使用原生官方登录的 `DedeUserID` 与 nav `mid`，抖音使用已验证自身资料中的 `uid`。已绑定的登录环境不能改绑为其他平台用户。删除后重新添加同一平台账号会创建新的运行时 UUID 与凭证，公开名称投影关联此前各阶段的账号。

`accounts.json` 原子保存公开账号历史，记录有序名称区间（`fromMs`/`untilMs`）与删除时间；删除仍会清理凭证、连接设置和浏览器数据。IPC 只通过 `accountLabels` 投影每个阶段账号对应的最新名称，不传输完整名称历史；状态更新不重复追加相同名称。歌曲可保存有界、仅用于展示的 `acquisition` 元数据（账号 UUID、添加时名称与时间），详情通过投影显示最新名称。持久化来源记录不参与请求账号选择，也不会恢复旧操作；资料库与下载历史保留添加时快照。此前未记录来源账号的歌曲仍然有效，不推测其账号关联。

删除确认将简短问题与“将清理 / 将中止 / 会保留”三项影响分开，明确保留歌曲、音乐列表与账号名称历史。

账号管理进入后直接展示平台列表与账号数量、已登录、待登录/验证和停用摘要，底部右侧统一提供添加账号和一键检测；各布局移除重复的顶部说明，保留账号隔离提示。添加表单在管理弹窗内打开，保留名称草稿并支持平台选择；平台账号列表的添加按钮预选当前平台。账号项采用连续紧凑列表，名称、状态、请求连接与检测操作并排展示，详情入口的悬停背景与检测按钮之间保留间距。检测结果直接进入账号项的状态行，“登录有效”替换重复的已登录标签，不额外增加结果行；检测失败保留已知账号状态，停用后显示停用状态，较长错误允许换行。账号详情分别编辑名称、请求连接和登录状态，删除入口与返回按钮并排放在底部，保留独立删除确认；路径仅显示在弹窗内，以当前平台或添加弹窗为根，不包含外层账号设置。点击路径可返回弹窗内任意上级，根层关闭后回到平台概览，长路径支持隐藏滚动条的横向滚动。窄屏沿用底部面板；操作按钮按内容宽度排列，空间不足时换行，保留至少 44px 点击高度。同平台名称去除首尾空白后必须唯一，原生层在持久化前再次检查。

管理区提供一键检测，列表与详情提供单个账号检测。检测按账号顺序串行执行，停用账号跳过；B 站与抖音对没有保存登录凭证的账号直接提示未登录。每个待检测账号仅执行一次所属平台的会话检查，不竞争或切换身份，不自动登录。关闭设置或取消检测会中止原生读取，并忽略晚到结果。内容暂停时仍可调用限定的身份接口。抖音使用 GET `/aweme/v1/web/query/user/`，仅在返回 UID 与已绑定的 UID 一致时确认登录。身份确认后，通过该账号的隐藏 WebView 在固定时限内读取官方资料接口 `/aweme/v1/web/user/profile/self/`。Rust 校验绑定的 UID，只向界面返回昵称。昵称读取保留原生登录和验证状态。最后一次验证的昵称保存在原生账号元数据中，重启后可直接显示，读取失败时继续保留。原生层依据明确的认证结果更新状态，网络故障、超时和无效响应不冒充过期，也不清除既有凭证。身份有效不会解除单独的内容安全验证要求，检测会提示仍需完成验证。已登录账号禁用重复扫码与浏览器登录，确认失效或需要验证后恢复入口。

登录提供二维码与“应用内网页登录”两个入口。后者在应用内弹窗打开该账号独立的官方页面，点击“我已完成登录”保存登录，关闭弹窗即取消。二维码生成、编码或显示失败后禁用该账号的二维码入口，提示改用应用内网页；过期二维码允许重新生成。二次验证展示平台实际允许的方式，应用无法原生完成的方式在应用内页面中完成。关闭面板、切换方式和晚到结果按登录 UUID 隔离，避免结束新会话。

请求连接从已添加的代理中选择一个主代理和最多八个有序备用代理，也可选择直连。Rust HTTP 的可重放读取仅在代理连接、连接超时或代理认证失败时顺序尝试，保持同一 CookieStore 与账号；成功代理在当前账号环境中复用。连接尝试共享总预算，成功媒体流不继承短连接超时；写入不自动重放，来源认证或安全挑战不作为代理失效，也不隐式回退到直连。抖音只在代理或隧道错误时用下一个代理重开该账号的内嵌页面；经代理的导航 15 秒内没有文档时按隧道失败处理。已有后续分页提示刷新，避免跨页面上下文复用旧游标。

删除确认说明会中止此账号的请求、播放、下载与登录验证，使用中的账号也可删除。原生操作启动与删除共享原子门：删除开始后阻止新工作，取消旧会话与排队请求、撤销媒体 grant、结束浏览器验证并释放渲染端占用，随后在阻塞线程中清理凭证，并通过同卷重命名将已校验的 Profile 脱离账号目录。后台单线程回收缓存文件并在重启后重试。目录脱离失败保留已停用状态及错误，允许重试。渲染端通过运行端失效通知同步列表、会话缓存、播放器和下载；涉及该账号的播放恢复空闲，不自动续播，其他账号和已保存的歌曲、列表、待听不受影响。失效的列表重建第一页后才能继续分页。

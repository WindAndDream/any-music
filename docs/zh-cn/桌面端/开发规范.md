# 桌面端开发规范

英文对应页：[Desktop Development](../../en/desktop/development.md)。适用于 `apps/tauri`，先读应用指南；改 Rust、原生配置或权限时继续读 `src-tauri/AGENTS.md` 与[后端工程规范](后端工程规范.md)。本页明确运行边界，后端页统一版本、异步、缓存与质量检查。

## 数据获取与调用链

`music-workbench / plugin-source-* → apps/tauri/src/platform/native-http.ts → invoke('http_request') → src-tauri/src/network/http.rs → Rust HTTP 客户端`。

- 渲染端负责端口转换、公开账号选择与业务组合；实际平台请求、账号 CookieStore、代理和凭证在 Rust。取消从请求 ID 对应到 `cancel_request`；不能只忽略前端结果而让旧原生请求继续读取。
- 普通 `http_request` 返回原始二进制 IPC 帧：四字节大端元数据长度、最多 1 MiB 的 UTF-8 JSON 元数据（`status`、`statusText`、`headers`、`responseType`），随后是未改写的正文。字节响应使用渲染端 buffer view；文本响应保留 UTF-8 容错解码和开头的 BOM。原有正文预算独立于元数据预算。取消优先于迟到的原生成功或失败，所有已结束请求都会解除渲染端取消订阅。
- 共享内置源使用 `credentials: 'include'`；Rust 根据账号绑定凭证。声明式源 `omit`，不能借账号注入 Cookie。不得改用 WebView fetch、WebView Cookie、GM 替身或宿主页登录态获取业务数据。
- 桌面抖音登录、会话检查、搜索、观看历史/个人喜欢/收藏视频/收藏合集、合集作品和作品详情使用原生持有的账号 CDP 会话，经 `douyin-browser-catalog.ts -> douyin_catalog_request -> douyin_browser` 注入共享来源端口。官方页面生成请求与签名；Rust 限定来源、类型、列表、关键词、游标或作品标识，并保持取消和大小预算。导入列表按迭代器惰性打开页面，只读取对应 GET 查询或 POST 表单游标的响应；提前结束、失败和取消均关闭目标。作品详情每次新建临时页面，等待匹配作品的 API 后关闭；页面 load 事件不代表媒体详情已返回，React Flight 文档仅在读取预算耗尽且没有 API 响应时回退，解析仍归共享包。验证、登录或权限失败不重放到本地签名通道。其他列表导入、收藏音乐详情与媒体字节继续使用原生 HTTP，不能用浏览器详情成功冒充媒体流验收。
- 正式抖音账号浏览器在 Rust 的 accounts/login、browser/douyin_browser、browser/cdp 与 browser/process；B 站继续使用原生登录协议。accounts 中的旧 douyin_login/douyin_passport 保留协议测试。共享来源协议仍在 music-sources，不为“全部放 Rust”复制已有 DTO、分页或映射。
- IPC command、capabilities、账号生命周期和本机媒体权限留在 `apps/tauri`。远程验证页不授予应用 IPC 权限。

## 账号、媒体与存储

- 账号和独立代理由桌面组合管理，纯调度算法复用 account-pool/network-routing；渲染端只处理公开身份和状态，不保存登录 Cookie、CDP 凭证或代理秘密。
- API、后续分页、播放和下载保持所属账号。远程媒体注册为 Rust 内存中的随机本机回环 grant，原生播放/Range/完整读取使用相同账号环境；取消、停用和账号环境变化清理旧任务与 grant。
- 稳定产品数据使用独立桌面快照与原生 `product.json` 镜像；凭证进入原生专属加密存储。不得读写 `any-music:userscript:*`，不得把 Cookie、短时媒体 URL、字节或最终磁盘路径写入产品快照。
- 当前渲染端 `any-music:tauri:product:v2` 与原生 schema 2 镜像按已提交代次和修订号恢复，挂载前等待一致。同步保护覆盖代次读取与提交，拒绝重入并比较持久镜像是否符合写入者预期；启动在原生保存前后重新检查镜像，再发布本地快照。原生保存串行校验再原子替换，拒绝不支持的格式和修订冲突，不转换早期快照；写失败停止后续保存。渲染端保留的当前格式快照用于恢复，不是可移植导出。参见[数据归属](../跨平台/架构/插件数据归属.md)。
- UI 挂载唯一 embedded 完整主题工作台，文件保存经原生命令。T11 在稳定的内部主题 Shadow 曲面激活共享／SFC／所选主题 CSS 字符串；受保护插槽使用独立宿主资源，原生宿主 CSS 仍正常导入。宿主页外层 Shadow 注入、悬浮启动器、@grant/@connect 和 GM proxy 仍仅属用户脚本。
- 正式系统浏览器验证与专用测试浏览器捕获是不同流程；已有实验登录模块保持其显式启用边界，不把实验观察写成正式原生验收。账号登录和移动限制见[运行端架构](运行端架构.md)。

## 原生命令权限与执行器

src/ipc.rs 是唯一注册表，build.rs 从同表派生 AppManifest。注册表包含原生下载准入及 S03/S15 两个独立 relay，测试校验完整命令和精确权限覆盖。产品 capability 精确匹配主 WebView；执行器只获得自身 relay，并由原生绑定真实窗口、文档、会话、上下文、期限与序号。S03 原型证据不代替 S15 生产资源/目标验收；未知目标关闭，完整矩阵见[S15](../跨平台/架构/插件系统重构S15工具与桌面交付.md)。

## 技能与验证

- IPC、HTTP、账号、媒体和原生接入使用 `$any-music-tauri-runtime`；涉及共享来源或 UI 时叠加对应共享 skill。
- 先跑应用 test（前端与 Rust）与 typecheck（Vue/TS、Rust fmt/全目标 Clippy 零警告）；Rust/原生依赖改动另跑 check:native（全目标编译）。构建使用根 `pnpm build:tauri`，全量交付遵守根检查。
- 用户明确要求运行态查看后才启动应用或浏览器。区分网页契约观察、Rust 自动化测试、真实原生 HTTP/账号验证和桌面播放验收；缺少任何层的证据就如实列出。

S09：来源实现从独立 plugin-source-* 的 /runtime 进入。操作与账号租约都能取消同一 Rust HTTP 请求；CDP/账号路由不移入来源包。内置来源适配器拥有绑定账号的媒体授权及幂等释放；宿主准备只接受对应回环地址并拒绝未授权地址。自动化 IPC 替身不代表 Rust 公网或桌面播放验收。

## S16 手机工程

原生 runtime_capabilities 选择 mobile 形态和分平台 ACL。Android 提供有界 content URI/包预览、系统文档保存和 Keystore，仅预览端口不展示执行/DEV 控制。移动两端外置策略保持 none，缺失能力明确 unavailable；不装配桌面执行器/DEV，后台取消临时工作。Android 要求 API 26 和产品 WebView 111+，旧引擎显示原生更新提示。pnpm build:mobile:android aarch64 或 x86_64 构建调试 APK；--release 增加 APK/AAB，--signed 要求显式签名环境变量，签名产物自动运行 check:mobile:release。check:mobile:android 离线执行 Clippy；accept:mobile:android --serial emulator-N 在明确授权后对指定运行中的专用模拟器执行仪器测试。accept:mobile:android:device --serial DEVICE_SERIAL 以独立临时 debug 宿主/UID 验证同一份原生适配器，保留已安装且校验一致的 Release。参考 arm64 手机已有 Release 启动证据，最低设备、插件执行及渠道退出仍未完成；iOS 需要 macOS/Xcode，见 [S16 证据与剩余退出项](../跨平台/架构/插件系统重构S16手机交付.md)。

### Windows Android 工具链与迁移

可直接执行的安装、环境变量、构建与设备安装步骤见 [README 的 Android 开发流程](../../../README.md#android-开发)。

构建前安装完整 JDK 和 Android SDK。维护中的工程使用 Gradle 9.6.1、Android Gradle Plugin 9.3.1、平台 37 和 Build-Tools 36.0.0。使用 `scripts/native-targets.json` 声明的发布工具链 JDK 21 和 NDK 30.0.16248370。NDK 提供 API 26 交叉编译器。在固定 Rust 工具链下，为手机安装 `aarch64-linux-android` 目标，为模拟器构建安装 `x86_64-linux-android`。

当前 Android Command-line Tools 使用 `android sdk install platforms/android-37.0 platforms/android-36 build-tools/36.0.0 ndk/30.0.16248370 platform-tools` 安装 SDK 包。锁定的 Tauri Android 库还使用平台 36；接受 SDK 许可后，Gradle 可自动安装它。当前 Windows `sdkmanager.bat` 会转交给 Android CLI，该 CLI 使用斜杠分隔包标识；旧版 SDK Manager 使用分号分隔。通过 `--sdk=PATH` 指定目标 SDK。

用户环境变量指向实际安装目录：`JAVA_HOME` 是 JDK 根目录，`ANDROID_HOME` 是 SDK 根目录，`NDK_HOME` 是其中的 `ndk/30.0.16248370`。将 JDK 的 `bin`、SDK 的 `platform-tools` 和 `cmdline-tools/latest/bin` 加入用户 `Path`，再重新打开终端或 IDE。这些路径属于本机环境，不写入受版本控制的项目配置，见 [Tauri 前置依赖](https://v2.tauri.app/start/prerequisites/#android)。

迁移项目后，若依赖链接仍指向旧位置，运行 `pnpm install --frozen-lockfile`。Android 构建脚本支持 pnpm 的 Node 和独立可执行入口，根据锁定的 Cargo 依赖图重建被忽略的 Gradle 路径，并使用锁定依赖生成 Tauri/Wry Kotlin 桥接及 Tauri ProGuard 规则。保留维护中的 Android 工程，无需通过 `tauri android init` 重新生成。被忽略的旧 `local.properties` 仍可能覆盖 SDK 位置，Gradle 报 SDK 路径错误时检查其 `sdk.dir`。Android 编译使用 CPU，更换 AMD/NVIDIA 显卡不要求修改构建配置。模拟器图形与硬件加速需要另行检查运行环境，生成 APK 不验证这些能力。

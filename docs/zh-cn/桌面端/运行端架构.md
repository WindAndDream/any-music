# Tauri 桌面运行端架构

适用范围：当前桌面原生组合与实现状态，开发入口见[桌面规范](开发规范.md)。本页移动章节只声明能力边界，不代表移动验收；Userscript GM 规则见[篡改猴规范](../用户脚本/开发规范.md)。

英文对应页：[Tauri Runtime](../../en/desktop/runtime-architecture.md)。

当前正式应用为 `apps/userscript` 与 `apps/tauri`。后者使用 Tauri 2、Vue 3、Vite 与 Rust，不使用 Electron。桌面与移动通过显式能力装配同一应用；Android 原生适配、签名产物和部分参考设备证据已存在，iOS 及最低设备、外置执行、渠道等剩余出口尚未完成。各项独立边界见[S16 矩阵](../跨平台/架构/插件系统重构S16手机交付.md)。

## 运行命令

从根目录执行：

```bash
pnpm install
pnpm dev:tauri          # 开发服务器 + Tauri 应用，日常开发入口
pnpm build:tauri        # prod 前端 + 本机 release 可执行文件
pnpm start:tauri        # 启动已构建的 release 文件
pnpm build:tauri:dev    # dev 前端 + debug 原生文件
pnpm build:tauri:staging
pnpm bundle:tauri       # 为当前操作系统生成安装包
```

Windows release 文件为 `target/release/any-music-tauri.exe`。编译需要 Rust（当前锁文件验证使用 1.91.1）、MSVC C++ 工具链与 WebView2 Runtime；产品界面使用 Tauri WebView，登录/风控验证使用系统 Chrome/Edge。macOS、Linux 需要对应 Tauri 系统依赖与系统浏览器。[GitHub Actions](../跨平台/架构/GitHubActions构建与发布.md) 已声明 Windows x64、macOS arm64/x64、Linux x64 安装包构建，其中 Windows/Linux 未签名，macOS 使用临时签名。托管 Runner 构建、安装包关联与运行验收分别验证，工作流不会更新外置插件准入。证书签名／公证、应用自动更新和商店发布仍不在当前交付范围。

`pnpm build`、三模式根构建会覆盖 Tauri；`pnpm test` 包含 Rust 单元测试，`pnpm typecheck` 包含 Rust 格式检查。构建和单元测试不启动产品窗口。

开发前端固定使用 `http://127.0.0.1:21420`，Vite 的 `server.port`、Tauri 的 `build.devUrl` 与 Rust 的开发来源检查保持一致。按 [Tauri Vite 配置](https://v2.tauri.app/start/frontend/vite/)保留 `strictPort: true`，开发服务器由 `tauri dev` 的 `beforeDevCommand` 调用 `pnpm dev:frontend`。本机原来的 `1420` 位于 Windows 的 `1365–1464` TCP 排除范围，因此改用已通过绑定检查的 `21420`；可用 `netsh interface ipv4 show excludedportrange protocol=tcp` 检查系统排除范围。

## 共用产品功能与边界

`music-workbench` 拥有共享工作台、资料库、收藏、歌单、播放器、播放队列、下载、历史、宿主持有的已发布配方及快照编排，测试随实现所有者维护。应用注入 HTTP、稳定值存储、来源实例、登录入口、媒体适配和保存文件等能力。`plugin-tag-management` 持有标签规则/关联及专属界面，`plugin-music-creation` 持有草稿/材料/编辑状态及专属界面，工作台消费其具名端口和投影。`ui` 保持受控展示，`plugin-source-bilibili` 与 `plugin-source-douyin` 持有来源协议，`core` 持有领域与 ports。见[包边界](../跨平台/架构/可复用包边界.md)。

Userscript 保留 `any-music:userscript:*` 存储键、Shadow DOM、轻量启动器、GM HTTP、宿主单账号和单代理配置；桌面不会读写该命名空间。桌面取消隐藏悬浮产品入口，使用 embedded 布局和原生文件保存。

Tauri 渲染端快照与原生 `product.json` 镜像保存当前完整代次映射和提交指针。启动先选择最高的完整代次，再比较 revision；两份镜像一致后才暴露资料仓库或工作台。不受支持的镜像版本或无法恢复的快照损坏会停止初始化并保留恢复数据，可读取的另一份镜像可用于恢复损坏副本。写入先同步更新本机镜像，再排队持久化到原生；原生镜像失败有可见反馈，并阻止后续写入直到重启。稳定快照不保存 Cookie、媒体 URL、字节、Blob URL 或最终磁盘路径。账号策略只含公开 ID 与操作元数据。桌面不自动导入篡改猴资料库。见[数据归属](../跨平台/架构/插件数据归属.md)。

桌面与 Android 通过注入的 `DownloadScheduler` 申请原生下载准入。Rust 持有有界 FIFO 信号量（1–5 首整曲任务）并处理等待任务取消；渲染层拿到原生许可后才开始任务。许可覆盖解析、读取、编码和重试，任务资源清理后才释放；共享层保留重试策略和浏览器编码。主 WebView 关闭/重载、应用退出及移动挂起清理临时准入。篡改猴保留前端调度；iOS 媒体与保存仍不可用。自动化测试不代表设备验收。

下载目录选择位于“设置 → 网络与下载 → 歌曲下载”。桌面通过原生文件夹选择器选目录，仅在原生 `download-directory.json` 中保存目录偏好，不写入产品快照或下载历史；原生保存回执仅包含文件名、字节数与完整 SHA-256，不包含最终磁盘路径。重新下载只打开当前目录内的精确同名文件，以 64 KiB 缓冲区流式校验全部内容；仅文件名、大小或内容相同均不足以跳过。保存时请求名称和内容均一致则跳过重复写入，其余冲突通过独占新建自动编号，保留已有内容。Android 使用 `ACTION_OPEN_DOCUMENT_TREE` 和原生偏好中的持久读写授权，渲染层仅接收文件夹显示名称；下载在授权目录中新建文档，继续经过原有受限保存令牌适配器（32 MiB、前台/生命周期/时限检查）。恢复“每次询问”后使用逐文件系统保存窗口，取消目录选择保留原设置。目录消失、授权撤销或写入失败会明确报错，允许重试或重新选择。Android 11+ 限制存储根目录及 Download 目录本身，可选择允许的子文件夹，见 [Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)。iOS 继续声明原生保存不可用。Rust、渲染层测试和 Android 编译检查不代表真实选择器或设备验收。

## 账号与验证

桌面端内置网易云音乐，使用账号绑定的 HTTP／媒体和原生二维码轮询，登录界面仅提供二维码；提交凭证前核对官方账号／资料身份。协议观察与尚待进行的真实 GM／桌面验收见[网易云接口接入记录](../跨平台/平台接口/网易云/接口接入.md)。移动端不注册此来源。

抖音可见验证复用账号浏览器启动时的空白标签页：Rust 先连接该页面并启用响应观察，再导航官方页面，不额外创建第二个可见窗口。调试端口先于初始页面就绪时有界等待；无启动窗口的后台路径仍创建隐藏目标。该行为通过 CDP 替身验证目标复用与命令顺序，尚未进行本次系统浏览器实站复测。

首次安装账号列表为空，不自动生成默认账号；用户先建立登录草稿，内置平台验证成功后才进入账号列表；外置声明式网关仅在明确声明允许时提供免登录，见[音乐源认证](音乐源认证.md)。读取已有配置时保留已保存的账号，删除所有账号后重启也不会补建。账号可添加、删除、命名、启停，选择直连或一个无认证 HTTP(S)/SOCKS5 主代理及最多八个有序备用代理。账号连接设置与原生路由持有这一有界回退链，详见后文。代理认证和代理组界面仍未提供；独立 account-pool/network-routing 算法不代表原生连通性或实站验收。

正式入口在设置中：“音乐源 → 账号管理”维护账号、登录验证、连接分配和自动选择请求策略；“网络与下载 → 代理管理”保存多个独立代理，显示关联账号，解除分配后才允许删除。表单沿用共享设置的卡片、开关、控件圆角和容器内单列适配，不再使用窗口顶部的临时工具栏。

代理设置分为“添加代理”和“代理管理”两个区域。添加表单在字段旁显示校验错误，保存失败保留输入；原生保存成功且快照确认后清空草稿。管理列表集中展示名称、协议、地址、分配数量和关联账号，窄容器下改为分行展示。前端和 Rust 均校验无认证的 HTTP、HTTPS、SOCKS5/SOCKS5h 端点，要求合法 IPv4、方括号 IPv6 或域名，以及显式的 1–65535 端口；拒绝路径、查询、片段、凭据和不完整的 IPv4 写法。名称去除首尾空白后必须唯一；地址规范化协议/主机大小写、域名末尾点、IPv6、端口数字和末尾斜杠后查重，默认端口仍显式保存。Rust 在同一次原生配置事务中校验与查重，阻止并发重复添加。上述校验只验证格式，不代表代理连通性。

发现页的账号名称可打开平台账号切换弹窗，自动模式显示“随机”，仍按各操作的请求策略选择可用账号。平台尚无账号时显示“无账号”和“添加”，直接打开独立的账号创建弹窗并预选当前平台，不打开全局设置；受保护的弹窗保留标准进出场动画，关闭后回到发现页。允许免登录的来源也需要填写账号名称。手动选择只持久化公开账号 ID，作用于新的搜索、导入、会话检查和播放/下载解析；已有歌曲列表和媒体不因搜索偏好变化而中断。进入歌曲列表后，平台和实际请求账号只读，重试时优先沿用原账号。账号删除或停用后清除失效偏好；空闲列表在下一次加载时选择可用账号并从第一页重建，不能混用旧游标。正在加载的列表中止并弹出错误，重试重新选择可用账号；平台没有可用账号时提示到账号设置中添加或启用。切换弹窗与设置共享产品主题和模态宿主。本次验证覆盖组件、状态组合与 Rust 自动化测试，未进行应用视觉或实站账号复测。

账号 UUID 同时绑定 CookieStore、HTTP 客户端、加密凭证文件和 `profiles/<uuid>`。该目录由应用生成，不接受前端路径。系统保险库存放 32 字节加密密钥，凭证文件使用 ChaCha20-Poly1305；保险库失败不会退回明文。浏览器自己的 Profile 按其原生机制保存，不读取 Cookie 数据库，不在 URL 或日志传递凭证。

B 站继续使用原生二维码生成、轮询、确认和取消。抖音正式登录改由 Rust `douyin_browser` 驱动系统 Chrome/Edge 官方页面；软件显示页面返回的 PNG 二维码，持续通过 CDP 获取扫码、二次验证、短信发送/提交和最终账号状态。用户选择短信并输入六位验证码后，Rust 通过 CDP 操作唯一匹配的官方控件；刷脸、发送短信及未知安全挑战使用主动打开的可见浏览器。登录 UUID 隔离替换、取消和短信操作；挑战留在页面及 Rust 内存，过期响应不能写入新会话。

2026-10-20 直接检查 B 站原生生成接口，返回地址为 `https://account.bilibili.com/h5/account-h5/auth/scan-web`，携带一致的 32 位挑战标识。Rust 挑战构造和 Android Intent 校验均接受该精确域名/路径及此前观察到的 Passport 扫码路径，同时校验 HTTPS 和唯一的 32 位挑战标识，继续拒绝普通账号页面。Android 分别报告无效授权地址与应用唤起失败，不再把所有拒绝都归因于未安装客户端。抖音二维码与轮询响应白名单覆盖 `www.douyin.com`、`login.douyin.com` 上的精确 Passport 路径。辅助账号状态检查为主账号流程保留最多 32 个进行中的登录请求和 96 个有序事件，不保留响应头或签名查询，避免静默吞掉二维码或确认状态。

Windows 默认创建独立非活动桌面，以 `STARTUPINFO.lpDesktop` 启动正常有头浏览器，不切换用户桌面。正式后台会话在该桌面使用普通有头页面，保留页面的可见性与焦点行为；其窗口不显示在当前桌面、任务栏或 Alt+Tab。显式可见会话的辅助搜索页才使用 CDP `hidden` 页面。没有 headless 参数或指纹伪装，不能承诺平台风控判断与可见页面相同。显式可见验证先结束同账号后台进程，再使用同一持久 Profile 打开系统浏览器，不承诺旧二维码或挑战延续。非 Windows 隐藏模式兼容性尚未验收。

同一 Profile 记录所选系统浏览器类型，后台搜索、可见验证和应用重启沿用同一 Chrome 或 Edge；旧 Edge 账号根据已保存的真实 User-Agent 迁移。已绑定的浏览器缺失时报告错误，不自动换另一浏览器。退出交接先正常关闭，再等待 Windows Job 的全部进程退出；超时才终止所属进程树并再次等待，不能仅凭主进程结束释放 Profile 锁。账号启动、验证、登录和删除共用账号交接锁，防止退出期间重新占用 Profile。

每账号独立 UUID、user-data-dir、文件锁、随机本机回环 CDP 端口与绑定代理。Windows 进程挂起启动，加入 kill-on-close Job 后才恢复，退出/取消清理所属进程树并保留 Profile。响应读取使用有界缓冲并保留跨进程导航响应；个别登录响应因跳转失效时等待新的官方账号确认，不凭空推断登录成功。认证用户对象与有效登录 Cookie 同时成立后，通过 `Storage.getCookies` 获取含 HttpOnly 的平台 Cookie，加密存入原生保险库，并保存实际浏览器 User-Agent；渲染端不接收凭证原文。后续显式会话检查使用临时辅助页面获取新状态，没有周期探活。可见验证完成时重新读取最新 Cookie，再正常关闭浏览器刷新 Profile 后返回隐藏会话；过期的短时 Cookie 不会阻止有效登录凭证的导入。

旧 Rust Passport 登录曾在干净 CookieStore 中生成二维码，但检查进入 `4031`/CAPTCHA；保留模块与测试，不作为当前抖音正式路径。B 站人工系统验证仍在用户点击完成后一次读取版本和 Cookie，再关闭该验证浏览器。专用测试浏览器的契约记录不等于正式桌面账号或 Rust HTTP 验收。

进入浏览器验证会暂停该账号队列并取消旧会话；其他账号继续工作。明确的登录拒绝和已知验证信号分别进入未登录或需要验证；HTTP 403、429 本身不证明账号失效，验证信号优先于 HTTP 401。匿名登录检查不会把匿名账号标为过期。每账号 API 单并发，加入抖动与有界指数退避；连续三次网络/超时失败暂停账号，等待用户检查。未知失败不冒充代理故障；没有自动直连泄漏代理偏好的回退，也没有后台周期登录探活。

抖音账号检测与搜索使用以下状态边界；状态边界有自动化测试覆盖，原生实站观察见下文。

原生账号公开 `state.login`、`state.verification` 与 `state.connection` 三个独立维度；`status` 是账号池路由投影，`authentication` 只表示凭证保存模式。已登录且需要验证可以同时成立。登录操作暂停请求时不记录虚假的人机验证需求，取消和重启解除操作暂停，保留实际的内容验证要求。抖音原生快照仍是访客时，显式身份检查会核对同账号浏览器的资料与 Cookie；确认已有登录后导入原生凭证，不直接把访客配置判定为未登录。

账号路由预检失败也携带具体账号 ID。首屏及后续页验证错误都把账号绑定到列表；只有绑定仍存在且已启用时才暴露验证动作。浏览器启动失败、关闭、取消、超时或确认失败保留原请求原因，并在同一详情中显示验证操作的原因与重试入口。验证完成时先确认官方搜索响应、身份与凭证，再刷新快照并从第一页重新加载；快照刷新失败或取消加载使用“重试”入口，不要求再次打开浏览器验证。当前列表只允许自己的成功凭证更新穿过恢复阶段，账号删除、停用和代理变更仍中止旧操作。回归测试覆盖正式来源适配器、账号选择、列表状态与模拟原生 IPC；这不是本次真实账号浏览器验收。

| 观察与操作                                                | 账号状态及恢复                                                                           |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 官方用户资料和登录 Cookie 均确认                          | 登录有效；单独的内容验证要求继续保留                                                     |
| 官方登录拒绝或可见登录面板，且同账号浏览器已无登录 Cookie | 未登录（登录失效），可重新登录                                                           |
| 登录拒绝或登录面板，但浏览器仍保留登录 Cookie             | 需要验证；Cookie 的存在不保证平台会接受，不能据此宣告失效或成功                          |
| `2483`、验证链接或搜索 `verify_check`                     | 需要验证，优先于 HTTP/业务登录拒绝；不清除凭证                                           |
| 资料缺字段、格式改变、连接错误、超时                      | 检测未完成，保留原账号状态；显式重试读取新资料                                           |
| 二维码过期、验证窗口关闭或取消                            | 二维码过期只属于本次扫码；取消不证明退出登录，也不证明验证完成，已保存账号保留待验证状态 |
| 官方搜索响应确认验证完成，并重新确认身份与凭证            | 保存最新凭证并恢复可用，同一列表从第一页重新加载                                         |

列表的错误弹窗在首次打开已恢复的验证错误时即可提供“验证”按钮。仅在打开错误详情时构造轻量验证闭包，不创建迭代器、租约或请求；运行中的失败仍绑定实际失败账号，恢复的闭包使用当前操作账号策略范围内需要验证的账号。用户点击后打开该账号的系统 Chrome/Edge，沿用独立 Profile 和代理。软件观察该关键词的官方搜索响应；共享适配器确认业务成功、包含结果数组且无 `verify_check` 后，Rust 重新读取凭证、关闭可见浏览器并恢复隐藏会话。列表自动从第一页重新加载，固定使用刚刚验证的账号，后续滚动仍沿同账号翻页。仅隐藏验证码、仅存在登录 Cookie、空响应或验证失败响应均不视为搜索验证通过。

## 账号设置与请求连接

原生账号身份采用 `(platformId, platformUserId)`，与浏览器/Profile UUID 和可编辑的本地名称分离。登录提交与官方身份检测拒绝同一平台身份的其他已配置账号，停用账号也参与去重；尚未登录的条目需要登录后才能确定真实身份。B 站使用原生官方登录的 `DedeUserID` 与 nav `mid`，抖音使用已验证自身资料中的 `uid`。已绑定的登录环境不能改绑为其他平台用户。删除后重新添加同一平台账号会创建新的运行时 UUID 与凭证，公开名称投影关联此前各阶段的账号。

`accounts.json` 原子保存公开账号历史，记录有序名称区间（`fromMs`/`untilMs`）与删除时间；删除仍会清理凭证、连接设置和浏览器数据。IPC 只通过 `accountLabels` 投影每个阶段账号对应的最新名称，不传输完整名称历史；状态更新不重复追加相同名称。歌曲可保存有界、仅用于展示的 `acquisition` 元数据（账号 UUID、添加时名称与时间），详情通过投影显示最新名称。持久化来源记录不参与请求账号选择，也不会恢复旧操作；资料库与下载历史保留添加时快照。此前未记录来源账号的歌曲仍然有效，不推测其账号关联。

删除确认将简短问题与“将清理 / 将中止 / 会保留”三项影响分开，明确保留歌曲、音乐列表与账号名称历史。

账号管理进入后直接展示平台列表与账号数量、已登录、待登录/验证和停用摘要，底部右侧统一提供添加账号和一键检测；各布局移除重复的顶部说明，保留账号隔离提示。添加表单在管理弹窗内打开，保留名称草稿并支持平台选择；平台账号列表的添加按钮预选当前平台。账号项采用连续紧凑列表，名称、状态、请求连接与检测操作并排展示，详情入口的悬停背景与检测按钮之间保留间距。检测结果直接进入账号项的状态行，“登录有效”替换重复的已登录标签，不额外增加结果行；检测失败保留已知账号状态，停用后显示停用状态，较长错误允许换行。账号详情分别编辑名称、请求连接和登录状态，删除入口与返回按钮并排放在底部，保留独立删除确认；路径仅显示在弹窗内，以当前平台或添加弹窗为根，不包含外层账号设置。点击路径可返回弹窗内任意上级，根层关闭后回到平台概览，长路径支持隐藏滚动条的横向滚动。窄屏沿用底部面板；操作按钮按内容宽度排列，空间不足时换行，保留至少 44px 点击高度。同平台名称去除首尾空白后必须唯一，原生层在持久化前再次检查。

管理区提供一键检测，列表与详情提供单个账号检测。检测按账号顺序串行执行，停用账号跳过；B 站匿名账号直接提示未登录，抖音同时检查同账号浏览器中可能已有的登录。每个待检测账号仅执行一次所属平台的会话检查，不竞争或切换身份，不自动登录。关闭设置或取消检测会中止原生读取，并忽略晚到结果。B 站仅允许官方 GET nav 身份探测穿过暂停状态，抖音仅允许自身资料操作；内容请求继续暂停。原生层依据明确的认证结果更新状态，网络故障、超时和无效响应不冒充过期，也不清除既有凭证。身份有效不会解除单独的内容安全验证要求，检测会提示仍需完成验证。已登录账号禁用重复扫码与浏览器登录，确认失效或需要验证后恢复入口。

登录仅提供二维码与系统浏览器两个入口，由原生层选择已安装的兼容浏览器，继续使用独立 Profile。二维码生成、编码或显示失败后禁用该账号的二维码入口，提示改用系统浏览器；过期二维码允许重新生成。二次验证展示平台实际允许的方式，站外验证直接进入系统浏览器。关闭面板、切换方式和晚到结果按登录 UUID 隔离，避免结束新会话。

请求连接从已添加的代理中选择一个主代理和最多八个有序备用代理，也可选择直连。Rust HTTP 的可重放读取仅在代理连接、连接超时或代理认证失败时顺序尝试，保持同一 CookieStore 与账号；成功代理在当前账号环境中复用。连接尝试共享总预算，成功媒体流不继承短连接超时；写入不自动重放，来源认证或安全挑战不作为代理失效，也不隐式回退到直连。抖音 CDP 只在明确代理或隧道错误时重建同账号浏览器；已有后续分页提示刷新，避免跨浏览器复用旧游标。

删除确认说明会中止此账号的请求、播放、下载与登录验证，使用中的账号也可删除。原生操作启动与删除共享原子门：删除开始后阻止新工作，取消旧会话与排队请求、撤销媒体 grant、结束浏览器验证并释放渲染端占用，随后在阻塞线程中清理凭证，并通过同卷重命名将已校验的 Profile 脱离账号目录。后台单线程回收缓存文件并在重启后重试。目录脱离失败保留已停用状态及错误，允许重试。渲染端通过运行端失效通知同步列表、会话缓存、播放器和下载；涉及该账号的播放恢复空闲，不自动续播，其他账号和已保存的歌曲、列表、待听不受影响。失效的列表重建第一页后才能继续分页。

## 操作、分页与媒体

设置中已移除“自动选择账号的请求方式”。自动选择继续使用既有默认策略，兼容已存的参与账号、random/shuffle、串行或最多两个并行尝试策略。只对可重放的读取竞争，二维码与验证提交不进入竞争。账号尝试预算 25 秒、总预算 60 秒；首个有效结果取消其他尝试。

抖音搜索按上述稳定性规则固定为串行，遇到风控等待用户验证；其他操作保留配置的竞争方式。

搜索/导入首屏选择获胜账号，后续惰性分页保持该身份和游标；停止消费、账号停用、删除或环境更改会释放请求。播放和下载的媒体 URL 转换为 Rust 提供的随机本机媒体 grant，原生 audio、Range 与完整读取均使用该 grant 的账号 Cookie 和代理；只有随机 grant ID 进入本机 URL。服务绑定 127.0.0.1、流式传递 Range，不缓存完整文件。grant 仅在内存、有数量/有效期预算；账号环境变更立即撤销。媒体策略继续保持描述解析、原生流式、有界 Range/MSE、完整读取兜底的顺序。

抖音搜索由官方搜索页面生成请求，Rust 捕获限定的 general/search/stream 与 general/search/single 响应，保留原始字节交给共享 DTO/映射。每个列表独立 target、关键词和游标；首屏按消费创建，后续页按需滚动，停止消费关闭页面。官方页面可能提前加载下一游标，因此在等待消费或检查账号状态期间保留匹配的响应；每列表至多三个待消费响应、全账号缓存上限 24 MiB，最多八个列表且响应/时长有界。会话检查同样来自官方页面。

作品播放、下载和单作品导入的详情解析也使用所属账号浏览器：原生端校验数字作品标识和 video/note 类型后创建独立临时页面，仅读取精确匹配的 aweme/detail 响应或主框架作品文档，正文最多 12 MiB、页面读取最多 18 秒。页面 load 事件可以先于客户端详情请求，因此优先等待匹配 API，只有读取预算耗尽且没有 API 响应时才使用文档回退；网络、验证或登录失败保持原错误。共享包解析 API/React Flight，并校验作品身份与媒体结构；搜索结果的短时媒体地址不复用、不持久化。临时页面拦截 Media/Image 读取，成功、失败或取消后关闭；实际媒体仍经相同账号的 Rust HTTP 与本机回环 grant 流式读取。官方详情失败不再退回缺少网页安全签名的本地详情请求。观看历史、个人喜欢、收藏视频/合集及合集作品已走所属账号的 CDP 导入端口；未接入该端口的列表与收藏音乐详情仍走 Rust HTTP/共享签名，具体实站覆盖见契约记录。

本次原生账号复测确认两条真实作品的 API 详情可以通过共享解析器解析，其中一条使用所属账号的 Rust HTTP 返回 HTTP 206 和 1024 字节 video/mp4；响应和媒体地址仅在内存流转。自动化回归覆盖文档/load 先于详情 API、无 API 时的有界回退、网络失败不被文档掩盖、超时、取消、响应大小和目标清理。该证据不包含产品 audio 的 playing 事件或完整本机回环 grant 播放验收，也不更新网页契约 captureDate。

## 移动端设计

`core/ports/account-login` 区分二维码内容与显示方式：`display` 给另一台设备扫描，`handoff` 解析内容后交给同机平台客户端/原生认证入口，`unavailable` 禁止不支持的流程。移动实现不能把桌面二维码图片当作手机扫码完成。

系统验证通过能力声明选择 `system-browser`、`platform-auth-session` 或 `unavailable`，不回退到 Tauri WebView。Android 提供仅限 B 站的原生账号 HTTP、独立 CookieStore 和 Keystore 凭证保存。二维码呈现为 `handoff`：生成后自动通过 `bilibili://browser/` 打开 B 站官方扫码授权页，由 Android 应用选择框选择客户端；不绑定包名，因此系统可提供已安装的应用分身。授权页保留“登录 / 打开哔哩哔哩”按钮，复用当前二维码会话；过期或失败后可重新生成。`open_qr_login` 仅接收账号和登录 ID，由原生会话派生跳转地址，渲染层不能提交任意应用链接。[官方扫码页](https://passport.bilibili.com/h5-app/passport/login/scan)采用该应用浏览器机制；源码核对不代表设备验收。

Android 通过 `FLAG_ACTIVITY_NEW_DOCUMENT`、`FLAG_ACTIVITY_MULTIPLE_TASK` 和 `FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS` 请求独立的临时授权任务。官方扫码页在确认成功后关闭应用浏览器；独立任务使关闭后可以回到 Any Music，避免露出 B 站已有的页面栈。应用选择框保留这些标志和客户端 / 分身选择，原生二维码轮询仍负责校验和保存凭证。参见 [Android 文档任务行为](https://developer.android.com/reference/android/content/Intent#FLAG_ACTIVITY_NEW_DOCUMENT)。实际客户端版本、B 站已有任务及应用分身的自动返回行为仍需现场回归，尤其需要验证覆盖文档启动行为的客户端。

登录方式列表仅在第一步显示；点击“选择方式”会取消旧二维码或浏览器会话并滑动返回，不能跳过验证或直接完成。触控按钮至少 44 px，减少动态效果设置会关闭过渡。桌面端保留二维码显示及独立系统浏览器验证；Android 仅提供二维码同机授权，iOS 仍需 Keychain 和认证适配。

原生能力决定移动形态及明确的 unavailable 错误。移动使用分平台 ACL 和 `externalPlugins: none`，不装配桌面执行器/DEV，后台取消临时工作；只有已明确打开的二维码授权会话可在原始 180 秒有效期内保留，普通二维码、请求、媒体和插件操作均取消。返回应用不会自动再次跳转，取消、替换或过期均不能恢复旧会话。2026-10-20，参考 API 35 arm64 手机的调试 APK 完成了用户亲自确认的 B 站客户端授权、返回、凭证复用及重启后的自动已登录检查；原生搜索成功加载 5 页、150 条结果，另有 3 项独立 Android 授权跳转测试通过。文档/Keystore 和 Release 证据独立记录在 [S16](../跨平台/架构/插件系统重构S16手机交付.md)。Android 已接通前台 B 站播放和下载，使用原生账号绑定的回环媒体授权、Range/seek 读取及原生代理路由。监听在能力发现前完成绑定；network_security_config.xml 仅对回环地址开放 WebView 明文例外，依据 [Android 网络安全配置](https://developer.android.com/privacy-and-security/security-config)。代理管理由 accountProxy 能力决定，不再按桌面形态限制。原生夹具测试覆盖 Cookie、Referer、代理选择、Range 顺序、取消与授权清理；渲染层测试覆盖描述符登记、释放及文档保存。2026-10-20，参考 API 35 arm64 调试手机完成 B 站播放、从约 106 秒跳到 65 秒并继续播放，以及通过系统文档选择器保存 5,610,491 字节 MP3。独立临时匿名账号经本机观测的代理隧道收到 B 站原生 HTTP 200 响应；临时账号、代理与 USB 转发均已清理。下载实测发现主宿主 CSP 拦截 Blob Worker/WASM，现已显式允许可信编码器所需的 worker-src self/blob 与 wasm-unsafe-eval，外部执行器策略不变。见[调试验收记录](../../baselines/android-builtin-media/2026-10-20.json)；优化 Release、音频打断和其他设备仍需单独验收。应用分身、优化 Release 认证、iOS 适配和最低设备/执行/渠道验收仍未完成。

官方参考：[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)、[开发前置依赖](https://v2.tauri.app/start/prerequisites/)、[Chrome 独立调试目录要求](https://developer.chrome.com/blog/remote-debugging-port)。

## 插件宿主与移动目标

原生 crate 负责协议、策略、权威、匿名联网和包校验，应用注入具体存储、调用方、审批与传输。账号 HTTP／CDP／媒体 grant 和 `product.json` 保持宿主基础设施；客体投影不能包含凭据或获得主视图 IPC 权限。执行器绑定真实隔离原生主体、epoch、范围、期限及预算，原生全来源过滤器安装后才交付资源。宿主／Profile／资源变化必须重新做匹配验收。

[桌面交付](../跨平台/架构/插件系统重构S15工具与桌面交付.md#退出证据与限制)维护精确准入边界。当前 Profile 与保留的已验收记录不同，外部安装／执行继续关闭；原型、离线测试及 CLI／testkit 不续期准入。

当前契约见[原生权威](../跨平台/架构/插件原生权威.md)、[匿名联网](../跨平台/架构/插件联网.md)、[插件包与恢复](../跨平台/架构/插件包与恢复.md)。目录不提供媒体解析，生产分发信任根尚未配置。

移动外部策略保持 `none`，没有安装／命令／DEV 权威。Android 包获取只提供惰性预览／文档保存；iOS、最低设备、执行及渠道退出见[移动交付](../跨平台/架构/插件系统重构S16手机交付.md)。桌面进程／Profile／CDP 验收不接受移动目标。

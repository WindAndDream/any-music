# 桌面后端工程规范

英文对应页：[Backend Engineering](../../en/desktop/backend-engineering.md)。官方文档核对日期：**2026-10-08**。适用于根 Cargo workspace 的原生 crate 与 `apps/tauri/src-tauri`，运行边界仍遵守[桌面开发规范](开发规范.md)。下面的模块分工和预算是本仓库的工程选择，不是框架强制架构。

## 版本与语法

Tauri 使用当前锁定的 2.12.1 和 v2 文档。Rust crate 使用 **2024 Edition**，workspace 最低版本统一为 **1.90**，发布工具链在 `rust-toolchain.toml` 固定为 **1.91.1**。Edition 与编译器版本分别管理，优先使用已经稳定且满足最低版本的 `let` chains、`let else`、`?`、迭代器和拥有所有权的数据转换。不启用 nightly，也不为简写引入额外分配或改变锁的生命周期。

依据：[Tauri v2 command](https://v2.tauri.app/develop/calling-rust/)、[Rust 发布记录](https://doc.rust-lang.org/releases.html)、[Rust 2024](https://doc.rust-lang.org/edition-guide/rust-2024/index.html)。

## 模块与目录

根虚拟 workspace 使用 resolver 3、显式 members 与应用 default-member；根 `Cargo.lock` 和 `target/` 由全部 member 共享。各 crate 保留自己的 `Cargo.toml` 与 `src/lib.rs`、`src/main.rs` 入口，不要求业务文件平铺。Rust 模块树可以按职责嵌套；本项目使用 `模块.rs + 模块/子模块.rs`，入口文件声明子模块，避免用 `#[path]` 维持旧目录映射。此次模块目录核对日期为 **2026-10-11**，不代表平台实站复测。

```text
src/
├── lib.rs                 # Tauri 组合、IPC 注册与退出清理
├── main.rs                # 可执行入口
├── accounts.rs + accounts/ # 账号命令、登录、状态与操作租约
├── browser.rs + browser/   # 人工验证、CDP、进程树、抖音账号浏览器与实验
├── network.rs + network/   # 原生 HTTP、代理与请求取消登记
├── storage.rs + storage/   # 加密凭证、原子文件与独立产品快照
├── system.rs + system/     # 文件保存与外部应用能力
├── media.rs               # 有界、可撤销的 loopback 媒体 grant
├── model.rs               # 原生公开投影与请求校验
└── state.rs               # 跨模块原生状态组合
```

子模块默认保持 crate 内可见，不把目录整理变为新的外部 API。`login_experiment` 保留 crate 根的公开重导出，供原有独立 example 使用。IPC 命令名称、参数、二进制响应、存储文件名和权限不随 Rust 模块路径变化。原生单元测试仍共置；嵌入 JS 资源及前端契约测试随所属浏览器目录移动，进程树测试根据 `module_path!()` 派生子进程测试名。

产品资料的 `product.json` 命令归 `storage/product.rs`，与账号命令、加密凭证分开；共享业务和协议仍留在 TypeScript 包。S02 已建立 `am-plugin-protocol`（SDK Schema 生成 serde DTO、有界解码与字段校验）和 `am-plugin-policy`（纯兼容/权限/预算判定）。应用业务模块保持原位，原生插件权威/网络/包事务与执行器现已由 plugins 组合。详见 [包边界](../跨平台/架构/可复用包边界.md)。

依据：[Cargo 包布局](https://doc.rust-lang.org/cargo/guide/project-layout.html)、[Rust 模块文件拆分](https://doc.rust-lang.org/book/ch07-05-separating-modules-into-different-files.html)。

## 工作区与插件 crate 边界

保持单 Git monorepo 与根 Cargo workspace。`workspace.package`、`workspace.dependencies`、`workspace.lints` 集中管理版本、依赖约束与原生检查规则，各 member 显式继承。内部 crate 使用 path 依赖及 `publish = false`；pnpm 管理 `apps/*`、`packages/*`。整理模块时保留应用 package/lib 名、手机入口及公开 example 导入；只有具备稳定端口、独立测试和具体复用或隔离需求时才提取应用模块。

| Crate                | 职责与依赖边界                                                                                                                |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `am-plugin-protocol` | SDK Schema 生成的 DTO、版本与有界校验；无 Tauri、Tokio、IO、凭证或音乐业务规则                                                |
| `am-plugin-policy`   | 依赖 protocol；注入时间与策略快照，纯函数判定主体、操作、范围、风险与预算                                                     |
| `am-plugin-package`  | 依赖 protocol；有界 ZIP/资源、完整性与签名；无联网、安装/授权权威或执行能力                                                   |
| `am-plugin-runtime`  | 依赖 protocol/policy；通过 Store/Clock/Ids/InstallFiles 编排安装、授权、上下文、来源标记与事务日志；无具体 DB、HTTP 或文件 IO |
| `am-plugin-net`      | 应用注入 Gate，提供匿名传输与公开目标校验；不依赖 protocol/policy/runtime、Tauri、账号 CookieStore、代理或安装权威            |
| 应用                 | 组合 runtime/package/net、SQLite/文件、原生审批、命令、执行器及平台适配                                                       |

runtime 与 net 不互相依赖。原生派发在向 net 交付上下文前绑定安装实例、会话、epoch、目标策略、累计预算与取消；重定向、重试和 Range 读取继承同一上下文。不得通过 net 命令绕过 runtime，也不复用带账号认证的客户端。公共端口使用有界 DTO、具名操作与不透明标识，策略结果不构成渲染端持有即生效的授权。通过 Cargo metadata 与独立 crate 测试检查传递依赖边界。

Cargo feature 负责编译裁剪，实际运行能力、渠道策略和用户同意仍决定权威。测试默认与精确发布目标/feature 组合，防止桌面能力泄漏到手机。可移植 crate 不依赖 AppHandle、WebView 标签或桌面进程 API；缺失平台适配时明确返回不可用。QuickJS-WASM 在受限 WebView/Worker 中执行，更换执行器必须重新通过隔离验收。

依据：[Cargo workspace](https://doc.rust-lang.org/cargo/reference/workspaces.html)、[feature resolver](https://doc.rust-lang.org/cargo/reference/resolver.html#resolver-versions)。实际支持范围以 [S15 矩阵](../跨平台/架构/插件系统重构S15工具与桌面交付.md)和 [S16 记录](../跨平台/架构/插件系统重构S16手机交付.md)为准。

## 应用命令与隔离

`src/ipc.rs` 是唯一注册表，build.rs 从中生成显式 AppManifest；`permissions/product.toml` 只授权精确主 WebView。诊断中继绑定真实原生调用方，只有独立 `s03-isolation-probe` example 创建固定会话。产品、执行器与 Worker CSP 分开。`pnpm check:plugin:isolation` 仅作离线构建／测试；生产执行要求[精确目标／资源准入](../跨平台/架构/插件系统重构S15工具与桌面交付.md#退出证据与限制)，原型验收不接受变化的产品构建。

## 搜索职责

| 层              | 职责与当前实现                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| 渲染端 / 共享包 | 输入、展示、公开账号选择；共享协议、签名、JSON/帧解析、DTO 映射与惰性分页仍由 music-sources 拥有，两个运行端复用 |
| Rust command    | `browser/douyin_browser/commands.rs` 校验完整搜索身份；无效关键词、列表、游标在账号排队及浏览器启动前拒绝        |
| Rust 账号 actor | 持有浏览器/Profile、CookieStore 与代理；串行操作、代次检查、取消、截止时间、凭证提交与空闲回收                   |
| Rust CDP 搜索   | `search.rs` 只驱动官方页面并匹配响应；`search/cache.rs` 管理有界传输正文、去重和旧游标释放，不复制音乐 DTO 协议  |

B 站搜索已经通过 `native-http -> IPC -> Rust HTTP` 获取，共享分页与字段映射无需再建立 Rust 副本。抖音登录、会话检查和搜索统一使用 CDP；验证与普通网络/页面超时失败仍停止；明确的代理或隧道错误可以按用户设置的顺序切换备用代理，保持同账号身份。已有后续分页必须刷新，不能跨浏览器复用旧游标。接口调用、策略和进程控制集中于原生层，共享层继续负责 DTO 映射。

## 异步、状态与所有权

- 执行网络、等待或较重工作的 Tauri command 使用异步入口。纯内存状态用短作用域的标准 Mutex；跨 await 的资源用异步锁或唯一 actor，禁止持有标准 MutexGuard 跨 await。阻塞工作若需要迁出，使用有并发预算的 blocking task；取消 blocking future 不等于底层操作已经停止。
- 同一账号按队列推进，继续保持固定账号代次与取消 token。截止时间必须覆盖排队、启动和读取；超时后回收旧任务，不能只丢弃渲染端结果。浏览器目标创建确认与进程树退出遵守既有有界清理契约。
- `browser/cdp.rs` 的等待记录由 Drop guard 拥有；外层 timeout/select 丢弃 future 时立即移除记录，晚到回复不会完成下一条命令。reader 通过移动 JSON Value 交付回复，不克隆整页正文。普通正文从 String 直接转为 bytes；Base64 先检查编码大小再解码。
- 渲染端关闭列表先发送 `cancel_request`，再排队关闭目标，并拒绝晚到成功。原生账号 actor 负责关闭 CDP 目标并回收取消的读取。保留第一项失败原因，晚到事件不能恢复已关闭列表。
- 用户可见错误保持现有 AppErrorState/native 错误投影；上游诊断与私密上下文只留在适配器内部。command 不新增任意 URL、远程页面 IPC 权限。

依据：[Tauri 状态管理](https://v2.tauri.app/develop/state-management/)、[Tokio 有界 channel](https://docs.rs/tokio/latest/tokio/sync/mpsc/index.html)。

## 数据结构与预算

- 账号签名投影只借用所需 Cookie 字段，不复制整份 Cookie 表；保留同名 Cookie 最后值覆盖、`UIFID` 优先于 `UIFID_TEMP`、空值与缺失字段的原有行为。原生请求头黑名单使用 ASCII 大小写比较；响应头直接写入一个 String，保留重复头、顺序和非文本值的空串投影，并继续过滤 Set-Cookie。
- 切换平台身份时维持账号取消顺序，再建立一次借用的 HashSet，用于撤销属于这些账号的媒体 grant，将账号与 grant 的交叉扫描改为期望 O(账号数 + grant 数)。匿名媒体和其他平台账号继续保留，配置和凭证不变。
- Rust 会话索引和缓存键查询使用 HashMap，期望 O(1)；全账号正文预算维护增减计数，避免每次正文完成时扫描全部缓存。只有最多 8 个待捕获请求的游标去重与最多 3 个页面包的释放做有界扫描，不为小集合额外维护多套索引。
- CDP 正文每包 **12 MiB**、每列表最多 **3 包**、每账号总正文缓存 **24 MiB**；每列表最多 8 项待捕获请求、账号最多 8 个列表。拒绝重复请求/游标；消费一个游标后释放较旧包和待捕获记录，缓存满或响应已过期时不调用 getResponseBody。
- 独立定时检查在两分钟空闲后关闭搜索列表；已认证且不可见的账号浏览器同样在两分钟无操作后回收整个进程树，后续请求可使用原有 Profile 重开。
- CDP 响应匹配要求固定 HTTPS 来源/端口、XHR/Fetch 类型、唯一关键词/offset、ASCII 数字游标及范围；空值重复参数和片段也拒绝。
- 继续使用原始二进制 IPC Response；渲染端使用 buffer view，不将正文展开为 JSON 数字数组或 Base64。上述数字约束的是缓存正文，浏览器、WebSocket、解码中间对象及整个进程树内存需要另行实测。

## 质量与验收

`pnpm --filter @any-music/tauri typecheck` 纳入 Vue/TS、Rust 格式和 `cargo clippy --workspace --all-targets --locked -- -D warnings`。原生检查涵盖所有目标；禁止以全局 allow 掩盖警告，固定 IPC 参数和进程树测试的必要例外应在局部说明原因。

原生测试使用 `cargo test --workspace --locked`；fmt 使用 `cargo fmt --all --check`。`pnpm check:rust:boundaries` 检查 metadata 中的完整纯依赖闭包；`pnpm check:protocol` 执行同测试样本集差分；`pnpm check:rust:msrv`、`pnpm check:rust:release` 和 `pnpm check:rust:deny` 分别检查最低工具链、明确 target/features 与依赖审计。`scripts/native-targets.json` 已声明 Windows x64、macOS arm64/x64、Linux x64 构建组合，禁止 `--all-features`。构建检查不代表运行或外置插件准入，见[发布流程](../跨平台/架构/GitHubActions构建与发布.md)。

从根执行目标测试、应用 typecheck/check:native，再完成 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`。回归应证明请求次数、重复响应去重、缓存预算/释放、固定身份和取消后的清理，不能仅比较公开网络耗时。

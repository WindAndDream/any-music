# 无界面宿主与 Web 入口

[English](../../../en/plans/future/web-host.md)

**提案。** 基于[本地用户隔离](本地多用户.md)和现有具名工作台操作。Tauri、WebView、系统保险库、原生媒体和内置来源传输留在适配器。先提取可验证的异步宿主用例，再公开独立浏览器入口。

| 范围                             | 下一步设计与结束条件                                                                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F01–F03、J04 · 宿主 API 和浏览器 | 提取不依赖 Tauri 的用例。服务端验证外部主体，每次请求映射到可信操作身份和权限范围。调用方传的本地 ID 不能作为权威。实现有明确限制的 Web 入口和可独立部署的宿主服务。 |
| H01–H06 · 任务、缓存与资产       | 有真实恢复需求时再引入有界租约、重试和 Outbox。先测本地缓存，再考虑伴随服务。容量、失效、降级行为决定是否需要共享缓存或远程资产。                                    |
| I01–I03 · 扩容与隔离             | 验证迁移、恢复、租户归属与过期 worker 屏障。按选定存储／服务的实际需要引入分区、连接池、RLS 或多 worker。                                                            |
| J01–J03 · 运行端验收             | 桌面产物、Android／iOS 发布门禁分别验收。来源凭证和原生执行按运行端隔离。                                                                                            |

通过配置支持离线独立、私有自托管和公共服务。独立应用无须启动 HTTP 监听或缓存伴随服务。可选服务业务留在[自己的板块](可选云服务.md)。

# 本地多用户与验证账号绑定

[English](../../../en/plans/future/local-users.md)

**提案。** 资料库目前只有一个本地配置，Tauri 音乐源账号各自持有原生凭证。第一批是 A01，梳理宿主／插件／服务归属以及切换和删除时的生命周期。

- 宿主持有稳定 LocalUser ID、显示名、创建／选择／删除、私有资料库、设置和租约。切换先停止旧来源、播放、下载及插件会话，等待写入完成或取消，再切换当前身份。数据、缓存、原生授权、队列和导入按所有者隔离。
- 区分本地 ID、提供方／服务实例、外部主体和音乐源账号。每个用户可有多份验证绑定，按操作明确选账号。原生验证实例／受众、一次性挑战和回执来源后提交绑定。自报名称及可移植数据的作者 ID 仅作归属展示。
- 凭证存储／撤销归可信运行端端口。提供方注册、登录、MFA 和找回由[可选服务](可选云服务.md)负责，本地资料离线可用。
- 逐步提取权威数据端口，先做当前 schema 预检、版本迁移、备份／失败恢复和归属校验。引入异步用例时保持单写入权威。有测量支持再替换当前存储。

| 工作                                     | 对应批次       |
| ---------------------------------------- | -------------- |
| 归属、身份、契约和持久化选择             | A01–A04        |
| 分用户启动、迁移执行和可验证恢复         | B01–B03        |
| 本地创建、选择、切换、删除及受控界面     | C01、C05b、C07 |
| 提供方／实例验证、账号选择及撤销         | C02–C05a、C06  |
| 正式资料库写入、顺序、喜欢、元数据与迁移 | D01–D07        |

先做本地切换和隔离。真实数据迁移前确认需求，并验证跨用户拒绝、过期写入、恢复和取消。Web 身份映射可以复用这些边界。[Web 宿主](Web宿主.md)。

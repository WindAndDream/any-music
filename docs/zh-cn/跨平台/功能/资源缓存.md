# 资源缓存

英文对应页：[Resource Cache](../../../en/cross-platform/features/resource-cache.md)。

在“设置 → 资源缓存”管理图片、封面和媒体字节。缓存独立于歌曲库、产品分代、凭证和已下载文件。默认上限 **1 GiB**，最低 **128 MiB**，最高 **100 GiB**。上限不是预留空间；条目数量和脚本管理器实际配额也会限制占用。表单与运行端均校验整数容量。缩小到当前用量以下需要确认，并立即淘汰较旧内容。进入页面和点击“刷新用量”时更新统计。

用户上传的歌单封面使用独立且有上限的本地存储：Userscript 使用异步 GM 值 `any-music:userscript:playlist-covers:v1`，Tauri 使用独立的 WebView IndexedDB 数据库 `any-music:tauri:playlist-covers:v1`；共享工作台只接收注入的封面端口。上传后保留原图比例，生成最长边不超过 1024px 的 JPEG，小图不放大；最多尝试三档编码质量（0.9、0.8、0.7），单张 ASCII 数据上限为 512 KiB，编码数据总预算为 8 MiB。空间满时拒绝新上传，保留已有封面；更换或删除后释放不再引用的图片，启动时清理遗留草稿。产品代次和可移植备份只保存稳定的 `coverId`，图片字节仅保存在本地，与网络资源缓存及其清除操作相互独立；图片缺失时显示默认歌单图标。

| 运行端  | 存储与位置                                                                                                                 | 缓存范围                                                                              |
| ------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 桌面    | 系统应用缓存目录内独立的 `resources-v1.sqlite3`；原生目录选择器可改为所选目录下的专属 `AnyMusicCache` 子目录，也可恢复默认 | 已授权账号的原生流、Range/MSE、导出读取，以及支持的内置来源公共 CDN 图片              |
| Android | 相同原生存储，位于应用私有系统缓存目录；系统可能回收                                                                       | 已有的 Bilibili 原生媒体与内置 CDN 图片，不增加账号、来源或插件权限                   |
| 油猴    | `any-music:userscript:resource-cache:v1:*` 下的异步 GM 存储，跨宿主页面共享，与产品分代隔离                                | 惰性 GM 图片和单次不超过 4 MiB 的合规 GM 二进制响应；浏览器直接播放仍由浏览器管理缓存 |
| iOS     | 仅本地缓存设置与清理                                                                                                       | 保持原生媒体不可用状态，不新增媒体传输                                                |

手机无法将任意 SAF 文档文件夹作为随机访问的 SQLite 目录；油猴没有任意磁盘目录权限。两端设置展示运行端管理的位置。桌面切换目录先确认清理旧缓存，再验证并打开带进程锁的新目录，最后持久化原生设置。取消选择保留原目录。清理与重置只处理专属缓存数据库，不删除所选父目录或下载的歌曲。

## 原生数据结构与算法

- 原生存储使用带索引的 `(key, offset)` 查询和近似 LRU；同一缓存块的访问时间最多每分钟更新一次。歌曲键散列账号、歌曲和实际音质身份，图片键散列完整公共 URL。URL、凭证请求头、Cookie、授权地址和渲染端 Blob URL 不会持久化。缓存不授予离线播放权；播放前仍先进行当前来源解析与账号、媒体授权检查。
- 歌曲仅在既有按需媒体流中旁路记录，单块最多 **1 MiB**；最多四个尽力执行的后台写入避免磁盘操作阻塞播放，预算用尽时可以跳过缓存块。不增加整首请求、解码、网络预取或完整文件累积。切歌会停止网络读取，并尽力异步保存已经收到的未完成块。只接收成功、未压缩编码且具有有限 MIME 元数据的有效媒体响应，排除 `no-store`。
- 缓存片段按需读取，即使只覆盖请求范围的一部分也可复用。遇到第一个缺口时通过原生账号客户端发起一条连续 Range 续传，该流也可进入缓存；短探测不会让每个缺失块各产生一次网络请求。账号取消仍会停止字节交付。续传版本改变或服务端忽略 Range 时，通过既有播放恢复流程处理错误。
- SQLite 连接只由一个原生阻塞任务操作。播放路径遇到缓存忙碌或不可用会绕过，磁盘工作最多等待 100 ms；设置操作串行执行。即使调用方取消等待或等待超时，阻塞任务仍持有并发许可。普通互斥锁不跨越 `await`，数据库锁内不执行网络请求。
- 条目写入七天后不再命中。容量与 32,768 条目上限限制存储和索引增长；统计包含每条元数据预留量，SQLite、系统开销与有限事务回滚临时空间另计。FULL 自动收缩在淘汰后归还文件页，批量淘汰每个事务最多处理 32 块。清理保留进程锁，关闭、删除唯一专属数据库并重建，避免再复制一份旧缓存。通过数据库应用标识拒绝外部文件。
- 图片使用会话签名的本机地址，仅允许构建时已知的 HTTPS CDN。原生请求不携带 Cookie、账号凭证，也不跟随跳转。最多四个活动读取、32 个已接收请求、单图 8 MiB 和统一超时限制资源占用。最多两个尽力执行的后台写入避免磁盘操作延迟图片响应。相同图片的并发请求共享原生任务锁。不支持的图片地址回退到既有无 Referer 展示路径。图片成功加载前保持隐藏；来源切换或卸载时共享组件清理请求和 Blob 使用权。

## 内存缓存与设置

设置分别提供硬盘容量、内存容量和缓存位置三个独立卡片。“缓存介绍”位于页面标题右侧并垂直居中，点击后查看详细机制和运行端限制。硬盘卡片右上角提供刷新用量图标按钮，保留无障碍名称和悬停提示；底部的“清除缓存”和“保存上限”并排显示。两类容量按钮均简写为“保存上限”，无障碍名称分别指明硬盘和内存。主题通过缓存插槽的 `placement` 安排标题区和内容区，介绍弹窗与缓存操作仍由宿主负责。内存上限默认 **64 MiB**，允许 **0–1024 MiB**，与硬盘草稿独立保存；0 表示关闭。上限不会预留等量内存，缩小后立即按近期最少使用顺序释放多余条目，“清除缓存”同时清空两层。仅持久化容量偏好，不保存内存字节或会话地址。

原生缓存沿用既有的资源、账号与音质散列身份、范围校验和到期时间，通过独立的有界树索引以 O(log n) 查询片段及调整、淘汰 LRU，最多保留 4,096 块；内存命中绕过磁盘任务，重叠片段未命中时仍回到原有带索引的磁盘查询。GM 使用保持插入顺序的 Map，实现期望 O(1) 查询与调整，最多保留 1,024 个响应，并沿用单响应 4 MiB 上限。仅在合规磁盘写入或读取成功后填充内存，磁盘写入失败仍可重试。两端统计数据字节和逐条元数据预留量，向调用方交付独立缓冲区，清理或修改内存容量后拒绝旧请求重新填充。不新增网络预取或整首歌曲累积。

这些上限仅约束应用自有的可复用字节缓存，不代表进程总内存。浏览器、系统播放缓冲、解码图片、活动使用者和有界 IO 缓冲独立管理；油猴直接播放仍使用浏览器自身缓存。

## 油猴限制与清理

油猴另设 **32 MiB** 实际占用上限，包含 Base64 与逐条元数据预留量，即使配置容量更大也不突破。Tampermonkey 会把 GM 值放入启动消息；缓存必须为脚本、产品分代及管理器元数据留出空间，避免超过 Chrome 的 64 MiB 消息限制。每次缓存写入前和打开已有缓存时按 LRU 淘汰，设置会说明这一运行端限制。该限制独立于可配置的产品偏好，不改变原生缓存容量。

GM-R2 复现了 69,030,799 字节的管理器记录，导致应用尚未注入就失败。专用测试配置的恢复只移除 `any-music:userscript:resource-cache:v1:*`，验证产品分代指纹不变后重载管理器。已经超限的测试存储需在管理器侧清理缓存，注入失败的应用无法自行修复；不要为清理可丢弃的缓存而重置歌曲库或凭证。

GM 适配器散列完整二进制请求身份，仅保留安全响应头，限制单次响应与最多四个待写任务，通过保持插入顺序的 Map 实现常数时间 LRU 调整。最多保留 1,024 条，元数据合并检查点写入。启动时一次性回收中断写入产生的孤立值与过期条目。Base64 和元数据开销计入用量，实际管理器配额可能更低。文本接口、失败或不完整 Range 响应、`no-store` 数据不缓存。缓存写入失败不影响成功网络响应，损坏或失败的缓存读取回退 GM 传输，不引入宿主页 `fetch`、IndexedDB 或 WebView 凭证存储。

图片保持惰性交集触发、四个活动 GM 读取、有上限且可取消的等待队列，以及可释放的 Blob URL。油猴无法在保持既有传输、启动契约的同时截获浏览器原生播放字节，因此直接播放继续使用浏览器缓存，设置中明确说明。产品存储在释放管理器拥有的写入标签注册之前，先冻结并等待缓存写入，包括页面退出。

所有破坏性缓存操作复用现有确认弹窗。共享控制器阻止重复操作，以及已关闭或卸载设置会话的过期确认。原生和 GM 代次会拒绝清理、配置变更前发起的请求写回。后续新访问可以重新生成缓存。歌曲库、收藏、历史、插件命名空间、凭证和导出下载均保持独立。

## 验证边界

原生内容／持久化与缓存续传测试的夹具注入仅测试可用的 30 秒磁盘等待预算，使命中和字节断言不依赖宿主文件系统速度；正式运行仍保持 100 ms 上限。独立测试使用该默认预算和显式阻塞的工作线程，验证读取／覆盖检查降级、写入有界等待、超时后保留并发许可、忙碌请求跳过，以及仅已获准写入可以在后台完成。

确定性测试覆盖容量下限、重启持久化、索引淘汰、短探测替换、过期、忙碌与错误重试、清理后晚到写入、路径隔离、缓存 Range 覆盖和清理后的连续续传。共享测试覆盖确认取消、重复操作、设置会话失效、草稿保留与错误恢复；GM 测试覆盖命名空间、隐私、重启命中、取消、无效响应及存储失败。测试和 Android 交叉编译不代表已安装油猴、真实 WebView 布局、原生目录选择器交互或物理设备播放验收。缓存改动不更新网站捕获日期。

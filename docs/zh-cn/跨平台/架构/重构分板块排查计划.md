# 重构分板块排查计划

英文对应页：[Refactoring Audit Plan](../../../en/cross-platform/architecture/refactoring-audit-plan.md)。规划日期：2026-10-21（Asia/Shanghai）。

本页是可复用的排查流程，批次的初始未审查状态不代表当前进度。既有排查的已审查与待处理范围以[台账](../../../baselines/refactoring-audit/2026-10-21-b00-e0884a5/summary.json)为准。

本计划用于回答三个问题：实现是否位于正确的板块、是否满足当前重构标准、还有哪些验收证据缺失。采用“板块 → 子批次 → 单条调用链”的方式推进，每个会话只完成一个子批次。本文是排查入口，不是已完成的审计报告；所有批次初始均为“未排查”。

## 1. 使用方式与基线

1. 首次执行 B00，只建立基线、板块清单和执行队列。
2. 从第 4 节选择一个板块，再选择其中一个子批次；例如 `B10-bilibili-listing-shared`，不要一次检查整个 B10。
3. 只读取第 2、3、5 节、所选板块条目及其必要规范；无需把整份计划、英文对应页和所有阶段记录放入会话。
4. 按第 5 节完成定位、调用链、测试和状态判定，保存第 7 节的交接记录，然后开新会话继续。
5. 完成相关局部批次后执行 B21 汇总与全量门禁。全量命令可以执行，但不因此加载整个仓库源码。

规范来源按职责使用：根目录及目标目录的 `AGENTS.md` 定义约束；[项目架构](项目架构.md)、[可复用包边界](可复用包边界.md)、[开发工作流](开发工作流.md)定义归属；[实施步骤](插件系统重构实施步骤.md)记录当前进度；[S15](插件系统重构S15工具与桌面交付.md)/[S16](插件系统重构S16手机交付.md)矩阵限定实际能力。历史阶段的通过数量和关闭状态不能替代当前证据。出现冲突时记录具体条目，按当前指南和实际交付矩阵核对，不靠文档日期猜测。

当前文档声明：共享插件架构、S11–S15 已实施，S16 进行中；Userscript 仅内置插件，移动外置策略为 `none`，桌面外置执行依赖精确目标准入和原生同意。外置 catalog 尚无媒体解析，包注册表发布、系统安装关联、移动设备/渠道验收仍有独立出口。这些声明用于确定预期范围，不算本次排查结论。

## 2. 控制上下文与 token

| 项目     | 每个子批次的默认限制                                               | 到限后的处理                                       |
| -------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 业务范围 | 一个不变量或一个用户操作；一个来源、一个运行端                     | 建立下一个子批次                                   |
| 代码范围 | 一个主模块及直接调用方/适配器一跳；首次读 6–10 个相关实现/测试文件 | 超过约 15 个新文件则拆分，不继续追完整依赖树       |
| 规范     | 根指南、目标局部指南、1–2 篇文档的相关章节、必要技能               | 新增规范前说明它解决哪个具体疑点                   |
| 工具输出 | 先文件名/符号，再带行号片段；单次输出约 150 行以内                 | 输出截断时缩小路径或行段，不能按不完整输出判通过   |
| 会话预算 | 可把新增阅读量约 6k–10k token 作为拆分提醒                         | 这是估计值，不是计费保证；原生事务等复杂链继续拆分 |
| 交接摘要 | 约 300–600 字，保留证据位置和下一步                                | 原始日志留在本地，不粘贴全部日志                   |

先用 `rg --files <明确目录>` 定位，再用 `rg -n <符号> <明确文件或目录>` 搜索。`Get-Content -LiteralPath <文件> | Select-Object -Skip <起点> -First <行数>` 用于局部读取。先看匹配文件数量再读正文；本机没有 `rg` 时使用等价的定向查找。

默认不执行无路径的全文搜索，不一次读取全部 `AGENTS.md`，不读取锁文件、构建输出、生成代码或大型夹具全文。B00 可列举工作区清单，B21 可运行仓库边界检查；两者都不等于全仓库源码审查。Schema/生成产物问题先用生成一致性检查，再定位最小差异。

跨边界疑点只记录“调用方 → 公共接口 → 被调用方、待确认事项、对应批次”。只在不继续就无法判断当前不变量时读取直接邻居，且记录扩展原因。修复、额外功能和无关命名整理另列任务，默认排查不修改产品实现。

## 3. 统一判定标准

每个子批次从下面选择 3–5 条具体检查项，逐项记录“通过/失败/未知/不适用”及证据。不适用必须说明能力边界；发现故障后也应完成当前可独立检查的项目。

| 标准              | 应检查的事实                                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1 归属与依赖     | 一个职责一个实现所有者；只消费公共导出；内部依赖用 `workspace:*`；没有共享包反向依赖应用、私有路径越界、循环或无职责的转发包                                                          |
| C2 入口与注入     | 轻入口不提前加载 Vue/编解码器/来源实现/引擎；运行能力显式注入；动态导入失败后可重试                                                                                                   |
| C3 行为与生命周期 | 可见文案、事件、数据结果保持契约；请求数、顺序、并发有界；取消、重试、失效结果、订阅和资源释放有明确所有者                                                                            |
| C4 数据与错误     | 产品快照只保存稳定身份、配方和必要元数据，排除临时媒体 URL、Blob URL、字节、最终路径和凭证；凭证仅留所属运行端专用存储；跨层使用 `AppErrorState` 并保留上游原因；命名空间和恢复不越权 |
| C5 权限与端边界   | GM、Rust 内置账号请求和外置匿名 Gate 分开；原生确认身份/epoch/预算；未知能力或目标拒绝；渲染端缓存不成为授权依据                                                                      |
| C6 验证与维护     | 测试跟随所有者，覆盖行为与失败路径；声明范围有匹配证据；中英文、索引、进度和支持矩阵一致；不凭整理文档更新 `captureDate`                                                              |

状态分三个字段记录，避免用一个“已完成”混淆架构和交付：

| 字段     | 值与含义                                                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 重构状态 | `unreviewed` 未排查；`partial` 新旧职责并存或迁移不完整；`conformant` 当前范围符合标准；`violating` 存在具体越界或契约回归                                                                        |
| 验证证据 | 分别列出 `static` 静态调用链、`tests` 定向自动化、`artifact` 生产构建/资源图、`live` 精确运行环境实测；每项标记通过/失败/未执行/不适用，不假定后一项包含前一项                                    |
| 批次结论 | `pending` 待查；`pass-scoped` 所选范围通过；`needs-fix` 有已确认问题；`blocked` 环境/外部条件阻塞并说明原因；`deferred-live` 尚缺必要实测；`unsupported-by-design` 当前明确不支持且拒绝路径已核对 |

`conformant + tests通过 + live未执行` 只能表达局部代码符合，不能宣称对应运行端验收完成。纯算法不强求 live；GM/Rust/设备能力需要各自证据。网页抓取、Vite 替身、IPC mock、构建成功、参考设备 Debug 成功分别只证明自己的范围。汇总保留失败和未知项，不以通过率平均掩盖权限、数据损坏或取消泄漏。

## 4. 板块路线与检查清单

建议顺序：B00 → 基础 B01–B04 → 共享产品 B05–B10 → 两端 B11–B12 → 外置插件 B13–B18 → 移动 B19 → 文档 B20 → 汇总 B21。可以按风险优先处理 B06 数据、B07 取消、B14 原生权威、B15 网络撤权、B16 恢复；遇到依赖证据缺失时只加待办，不顺势全局扫描。

以下路径均相对仓库根目录。每个编号是一个板块，其列出的子批次要分别执行；不要求一个会话完成整个编号。目标指南和技能在实际执行对应子批次时加载，本次制定计划不等于审查这些实现。

### B00 基线与范围（repository）

- 只读根指南、相关索引/进度、根清单和工作区名称；记录 `git rev-parse HEAD`、`git status --short`、目标范围差异、工具版本和本次待回答的问题。保留现有未提交修改。
- 建立所有板块 `unreviewed` 的台账，区分文档声明、待复核实现、当前不支持能力。先选一个子批次；不要从完整历史 diff 或全部包源码开始。
- 输出：基线标识、子批次队列、允许路径、对应规范和验证命令。后续会话复用该记录，只补读变化。

### B01 纯工具、音频算法与核心领域（shared）

- 子批次分别选择 `audio-composition` 的配方/预取或 `/browser`、`core` 的 errors/library/download/player/ports；每次只选一个目录中的一条链。
- 检查纯音频根入口无内部依赖和运行时污染；编解码器限于 `/browser`；core 保持领域和端口，无 Vue/DOM/GM/Tauri；没有重复时间线、错误目录、下载调度算法。检查整数毫秒、非法边界、溢出和取消。
- 证据：本包公共 exports/依赖、调用方一跳和对应 `test/`。小工具留在所属模块，使用该模块的测试与类型检查验证。

### B02 账号选择与网络路由算法（shared）

- 子批次：先 `packages/network-routing`，再 `packages/account-pool`，最后将桌面接线移交 B12。
- 检查 `account-pool → network-routing` 单向依赖；无音乐模型、DOM、Vue、Node、GM、原始凭证；时钟/传输可注入。覆盖租约竞争、请求竞速、超时、失败健康状态和取消后的释放。
- 证据：目标策略及失败测试；Userscript 仍为单宿主账号/代理，不将桌面组合能力误写为共享或 GM 已接入。

### B03 SDK、Schema 与原生协议（shared / tauri）

- 子批次：`packages/plugin-sdk` 的 root/music/schema/guest/host/node 分开；`crates/am-plugin-protocol` 的生成契约另查。
- 检查 DTO、wire 版本和命名执行端口；SDK 不反依赖 core/UI/运行端；`/schema` 使用生成验证器；`/node` 不进入生产浏览器图；Rust DTO 同源生成，按版本/Schema 验证字段并拒绝未知必需能力。
- 证据：公共入口、版本/预算测试、生成一致性、跨语言同一语料。不要手改生成 Rust 或建立第二套 Schema 权威。

### B04 插件生命周期与贡献注册（shared）

- 子批次：`packages/plugin-center` 的通用 root、`/music-sources`、依赖/启停/可用性分别查。
- 检查通用身份/生命周期与音乐模型分离；目录存描述符，不持有具体组件/业务实例；应用注入实现。覆盖依赖缺失、内置保护、移除重装、过期可用性结果和解除订阅。
- 证据：公开契约、一个贡献的注册→停用链及竞态测试；中心的授权展示缓存没有原生授予权。

### B05 共享工作台编排（shared）

- 子批次：`packages/music-workbench/src/features` 中 library/music-sources/plugins/settings 各选一个；`runtime`、`stores`、`plugin-adapters` 的接线分别查。
- 检查只通过显式运行端口工作，无 GM/Tauri/Electron/Node/app 导入；根组件组合依赖，跨视图状态和竞态由 composable 管理；UI 受控，工作台不导入标签/创作具体实现。
- 证据：一个用户动作→端口→状态投影、对应 feature 测试和直接调用方。存储移交 B06，媒体移交 B07，不重复展开。

### B06 数据归属、持久化与恢复（shared / userscript / tauri 分批）

- 子批次：workbench `src/storage` 与[数据归属](插件数据归属.md)；Userscript GM generation；Tauri renderer/native product mirror；插件命名空间 portable-data；每次只查一个存储边界。
- 检查宿主数据/标签/创作命名空间独立；禁用保留数据并撤回投影；启动直接创建当前格式，无旧业务 key 扫描或兼容读器。核对 stage/journal/commit pointer、版本/revision、失败后停止保存、未知命名空间保留且不获得执行权。
- 证据：写入、导入预检、损坏/中断/并发写的失败注入和两端独立恢复测试；不保存临时 URL/字节/路径/凭证。插件安装 SQLite 权威与配对 code/data 恢复归 B14/B16。

### B07 播放、Range、下载与导出（shared，接线按端拆分）

- 子批次：workbench `src/media`、features/player、downloads、audio-export 分开，必要时各交接一条 GM/Rust 适配链。
- 检查“轻量媒体描述 → 原生流式 → 有界 Range/MSE → 完整读取兜底”的顺序；自定义歌曲仅预取有界叶片段；seek/切歌/停用/dispose 中止旧读；完整编码不成为普通起播前置；每个生产运行端只有一个下载管理器。
- 证据：记录请求次数、顺序、并发上限、取消和重试；覆盖迟到结果、重复资产只读一次、失败队列不再领取任务、Object URL/grant 释放。GM/Rust 实测各列待办，不以网络耗时代替验收。

### B08 受控 UI、主题与视图装配（shared）

- 子批次：`packages/ui` 一组受控组件；`packages/plugin-ui-vue` 的 root/directory/trusted 分别查，真实布局另列。
- 检查 Composition API、typed props/emits、可见契约、焦点/键盘语义和清理；ui 不依赖插件框架；主题目录无 Vue/样式，可信主题只走构建已知加载器，切换失败可恢复且卸载清理完整。
- 证据：组件黑盒交互、主题事务/重试测试及公共依赖；组件测试不证明实际布局/焦点/移动设备效果。使用 `$any-music-ui-delivery` 和 Vue 相关技能；当前任务未授权 UI 实测。

### B09 标签与创作内置插件（shared）

- 子批次：`packages/plugin-tag-management`、`packages/plugin-music-creation` 分开，再分别检查应用注入点。
- 检查轻 root、lazy `/vue`，只消费公开 core/plugin-center/ui；插件持有标签规则/关联或草稿/材料，宿主持有已发布配方；宿主资料库写入不重写插件命名空间。
- 证据：关闭→数据保留/投影撤回→重启恢复，以及创作关闭后标准配方仍执行、叶来源停用后受影响媒体明确失败的测试。

### B10 来源协议与懒加载（shared，按来源/功能拆分）

- 子批次：Bilibili 或 Douyin 二选一，再选 descriptor、session、search、某类 import/listing、media 中一个；路径为对应 `packages/plugin-source-*`。GM/Rust 接线分别交 B11/B12。
- 检查 metadata 不提前加载 `/runtime`；签名/DTO/映射/分页在来源包，HTTP/账号/页面能力注入；分页按需消费、游标和去重有界、取消和失败重试可靠；内置 HTTP 明确 `credentials: 'include'`。
- 证据：一种来源操作的请求数/顺序/并发/取消/重试测试；Douyin contracts/browser 可选入口与协议分离。使用 `$music-source-adapter`；网页契约复采不证明 GM/Rust 接受，不因本次排查更新 `captureDate`。

### B11 Userscript 运行端（userscript）

- 子批次：`apps/userscript` 的 document-start/launcher、Shadow DOM、platform/http、page bridges、storage、单代理、生产构建图分别查。先读该应用指南、[开发规范](../../用户脚本/开发规范.md)及 `$any-music-userscript-runtime`。
- 检查 GM_xmlhttpRequest 传输、超时/尺寸/abort、目标域 Cookie 和 GM 代理边界；不替换为宿主 fetch。桥只交换最小允许 DTO；nonce 不构成同页授权。首次展开才加载工作台，失败可重试；隐藏保留会话，卸载清理。
- 证据：GM doubles/桥测试、元数据 `@grant/@connect/@noframes`、生产依赖图；所有入口固定 `externalPlugins: none`，无 JSON 来源安装器、外置 Worker/WASM/Gate。真实 Tampermonkey 回归单独记录。

### B12 Tauri 内置运行端、账号与媒体（tauri）

- 子批次：`apps/tauri/src/platform` 接线；原生 network/request_registry；accounts/vault/proxy；browser/CDP 的一个操作；media grants；system/download；IPC/ACL；逐项拆开。
- 检查 renderer→IPC→Rust HTTP，Rust 独占 CookieStore/凭证/代理；请求 ID 能取消原生读取；公开账号身份不含秘密。Douyin 原生浏览器只返回匹配身份/游标的有界响应且退出关闭 target；媒体仍为 Rust 账号绑定 loopback grant。
- 证据：身份一致、过期请求/切账号撤销、Range/保存、精确主 WebView 权限和远程页无 IPC 的测试。先读应用/原生指南、[桌面规范](../../桌面端/开发规范.md)、[后端规范](../../桌面端/后端工程规范.md)及 `$any-music-tauri-runtime`；CDP 页面成功不证明 Rust 媒体可播。

### B13 无权限 VM、Worker 与同引擎测试（shared）

- 子批次：`packages/plugin-vm` Profile/control、引擎/桥、`plugin-sandbox-browser`、`plugin-testkit` 分开。
- 检查 VM 只依赖 SDK/固定引擎；profile/control/adapter root 不加载引擎；guest 不获得宿主对象、原生函数或业务权限；预算、序列化、Promise bridge、单次会话和强制终止保持边界；测试不在宿主导入 guest entry。
- 证据：恶意语料、超时/内存/取消、同引擎和资源哈希。`pnpm check:plugin:vm` 是离线证据，不能证明 WebView 隔离或生产目标准入；CLI/testkit 不进入生产依赖。

### B14 原生策略、授权与事务（tauri）

- 子批次：`crates/am-plugin-policy` 纯决策、`am-plugin-runtime` 注入端口、应用 `storage/plugins`、plugins 命名操作的 commit/revoke 分开。
- 检查纯 crate 无具体 IO/数据库/全局时钟；Store/Clock/Ids/InstallFiles 注入。独立 `plugins.sqlite3` schema 3，串行事务重检身份/epoch/version/幂等并原子保存 values/provenance/receipts；撤权持久化先于确认。
- 证据：提交与撤权竞争、取消等待不提前释放阻塞池许可、未知 schema/坏授权拒绝、生产无 fixture seed/任意 grants/sessions/通用数据中继；读取 `crates/AGENTS.md` 和目标 crate 指南。

### B15 外置匿名网络与撤权屏障（tauri）

- 子批次：`crates/am-plugin-net` 的公开目标/有界传输；应用 `plugins/network` 的原生 Gate、账本与最终字节交付分别查。
- 检查每跳重定向、Range、最终 sink 共用身份/epoch/预算/撤权屏障；外置无账号 Cookie/密钥/任意链接/宿主写入；不支持的代理拒绝，不回退到账号客户端。
- 证据：本地传输测试覆盖私网目标、重定向、超预算、取消、撤权期间在途/最终交付。匿名媒体注册拒绝；generic omit 只读现有 loopback grant；本地 TLS 成功不启用生产插件。

### B16 包校验、安装、升级与崩溃恢复（tauri）

- 子批次：`crates/am-plugin-package`；runtime InstallFiles；应用 `plugins/package_files`、packages、revocations；分开检查。
- 检查有界 ZIP/资源、完整性/签名/路径；校验返回拥有的不可变 bytes，加载不重开路径；code/data 落盘先于 DB 指针；进程锁覆盖安装/恢复/GC；回滚保持 epoch 单调，迁移只触及自有副本。
- 证据：写入步骤故障注入、成对 generation 恢复、升级/回滚/撤权；预览不授权、自签不等于可信发布者、未知分发根不自动信任。未发布产品不新增旧架构兼容层，但保留当前插件升级/回滚和恢复。

### B17 作者工具、公开包与 DEV（Node / tauri 分开）

- 子批次：`packages/plugin-cli` 的构建/pack/sign；SDK `/node` 与 testkit 独立产物；Windows DEV 配对/更新/结束分别查。
- 检查目录内源码封存、固定 JSON/Vite、无项目 hook/config/.env/宿主测试执行；公开包可独立使用、许可证随产物；production 不依赖 CLI/testkit；本地可打包不等于已发布注册表。
- 证据：独立包测试、固定构建和诊断脱敏；DEV 当前 SID 单次配对、独立 DB/code/data/Profile、每次 reload 重新同意/提高 epoch、取消先关闭 context 再 ACK，结束阻断迟到安装。

### B18 桌面外置执行与交付准入（tauri）

- 子批次：原生 delivery/control；executor 窗口/relay；生产资源过滤；一个命令/catalog/诊断保存动作；每次只选一个入口。
- 检查安装/回滚只接受原生 preview token 和明确同意；实际 OS/WebView/Profile/资源哈希匹配准入矩阵；all-source filter 先于 guest bytes，独立 Worker CSP；context/deadline/sequence/跨 realm 预算强绑定；受控保存时重检 epoch。
- 证据：自动化拒绝路径、生产资源图和精确目标实测分别列出；未知能力/贡献/目标拒绝，catalog 不解析媒体。S03 原型和离线 S11 不替代 S15；不要按旧命令数量推断当前 ACL 正确。

### B19 移动工程与交付出口（tauri，Android/iOS 分开）

- 子批次：Android runtime_capabilities/ACL；document URI/保存/Keystore；生命周期；Bilibili 账号/代理/媒体；构建签名；最低设备/渠道；iOS 适配另列。只按 [S16](插件系统重构S16手机交付.md) 当前矩阵选择路径。
- 检查 API 26/WebView 111+ 启动门槛、旧引擎原生提示；main-android 与 iOS main-mobile 权限不同但 externals 均 `none`，无 install/command/DEV；挂起撤销临时工作；凭证/URI/路径不通过 JS 通用桥暴露。
- 证据：离线边界/编译、签名 APK/AAB、模拟器、实体 Debug、优化 Release、渠道分栏。已有参考 Android 实机播放/seek/保存/代理证据，不推出更广设备/Release/音频中断已通过；iOS、最低设备、移动外置执行/渠道出口仍独立待验。

### B20 文档、指南、技能与遗留清理（repository）

- 子批次：仅检查已排查板块的维护文档/指南/技能引用；阶段历史和当前进度区分；最后核对双语对应页与索引。
- 检查直接修正过时归属/状态/范围，避免末尾追加相反说明；AGENTS/仓库技能为英文；文档声明 runtimeScope，平台契约保留 documentType/platform/真实 captureDate，归档提案声明 archived。
- 证据：定向检查产品入口无旧来源 JSON 安装器、兼容包、重复 IPC 别名；不要删除当前升级/回滚/恢复或只因名称包含 legacy 就删除文件。测试、夹具、生成产物和公开入口随所有者迁移。

### B21 总结、回归与最终状态（repository）

- 输入是各子批次报告和必要的最终差异；不重新读取全部源码。检查每个子批次覆盖、依赖待办、失败/未知、证据时效和精确运行端；发现遗漏只补最小批次。
- 按第 6 节执行适用门禁；新增故障转给明确所有者，修复后复跑受影响测试与已失效门禁，不因预算紧张记为通过。
- 输出：“已复核符合”“已确认需修复”“尚未核查”“实现存在但缺运行验收”“按设计不支持”五类清单。只有预定范围内必要项与证据闭合才结束该范围；S16/渠道等剩余项保持未完成，不宣称整个项目全部重构验收完成。

## 5. 每个子批次的固定步骤

1. **框定问题**：写清 ID、runtime、一个待验证不变量、允许路径、排除项、3–5 条检查项和预期证据。跨运行端必须拆报告。
2. **读取约束**：根 `AGENTS.md`、目标最近指南、必要技能及相关规范章节。原生补读 `crates/AGENTS.md`、目标 crate/应用原生指南和后端规范；不加载无关模块指南。
3. **最小定位**：检查目标 manifest/exports、入口、直接调用方、对应测试；优先 6–10 个文件，记录实际查过的文件和行号。
4. **追一条链**：入口→业务所有者→注入端口→适配器→返回/提交→取消/释放。分别核对正常、失败、取消、恢复；没有涉及的路径标未知，不默认覆盖。
5. **运行定向验证**：先最小有效测试，再在接口或依赖变化时扩到直接消费者；检查退出码，保存失败原因。只为未被现有行为测试覆盖的实质风险补测试，不写镜像实现的测试。
6. **判定并交接**：逐条标准给证据，记录缺口/风险/归属批次，更新三个状态字段；保存短摘要后停止扩展。已发现明确问题应给出触发条件和影响，不写无证据的“疑似全局问题”。

## 6. 分层验证命令

全部从仓库根目录执行。先核对当前 `package.json`；下面带 `<...>` 的是模板，替换为实际包/测试路径，不能原样执行。优先使用拥有者的 test 脚本；确需单个 Vitest 文件时确认其 build/generate 前置条件已经满足。

```powershell
# 纯 TS / 共享 Vue 包：一个包的一组测试及类型检查
pnpm --filter @any-music/core test
pnpm --filter @any-music/core typecheck
# 单文件/目录：保留该包必要的构建、生成校验前置步骤
pnpm --filter @any-music/<package> exec vitest run <test-path>
# Tauri 局部前端测试，避免其 test 脚本自动扩成 Cargo workspace
pnpm --filter @any-music/tauri exec vitest run <test-path>
# Rust 单 crate / 原生命名模块
cargo test -p am-plugin-policy --locked
cargo test -p any-music-tauri --lib <module-filter> --locked
```

按板块选择门禁，不在每个子批次重复全跑：

| 板块               | 对应离线检查/构建                                                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| B01–B12 依赖与接线 | 定向测试/typecheck；公共入口变化后，两端 `pnpm build:userscript`、`pnpm build:tauri`；仓库依赖与生产图检查见最终 lint             |
| B03 协议           | `pnpm check:protocol:generated`、`pnpm check:protocol`                                                                            |
| B13 VM             | `pnpm check:plugin:vm`                                                                                                            |
| B14–B16 原生       | 目标 crate/module tests；`pnpm check:plugin:package` 适用于包与安装恢复；检查所需工具链                                           |
| B17 工具           | `pnpm check:plugin:tools` 加目标 CLI/testkit tests                                                                                |
| B19 移动           | `pnpm check:mobile:boundaries`；具备 Android 工具链时 `pnpm check:mobile:android`；有对应构建产物再做 `pnpm check:mobile:release` |
| B20 文档           | 仅改动文件的格式、元数据、对应页与本地链接检查                                                                                    |

最终收口及任何提交前，完成 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`；原生修改还需 `pnpm check:native`、`pnpm check:rust:msrv`、`pnpm check:rust:deny`。保留显式 release target/features 组合，禁止用 all-features 替代。工具链/系统缺失记为阻塞，不能当通过。没有新改动或失效原因时可复用同一基线的有效结果。

本计划和普通静态排查不授权启动开发服务器、产品预览、应用、浏览器、模拟器、截图/点击或 live 回归。只有用户在对应任务明确要求浏览器/应用检查时，才执行那一范围的实测。`accept:*` 不能当普通离线门禁；不自动复采平台接口、提交、推送或发布。

## 7. 报告、续接与完成条件

建议开始实际排查时才创建 `docs/baselines/refactoring-audit/<run-id>/summary.json` 和每个子批次的 `<batch-id>.json`，采用稳定字段/枚举；原始日志存本地并脱敏。本次只生成计划，不创建虚假的通过记录。台账最少包含以下字段：

```text
batchId / runtime / scope / criteria
baseline: HEAD + relevant working-tree changes or file hashes + environment
declaredStatus: document claim and reference
refactorStatus / verdict
checks: criterion, pass|fail|unknown|not-applicable, file:line, test evidence
verification: static/tests/artifact/live, result, exact command, exit code, time, log path
findings: trigger, effect, severity, owner, evidence, suggested next action
unreadPaths / missingEvidence / dependencies / nextBatch
```

短交接模板：

```text
批次 / 运行端 / 基线：
本批问题与允许范围：
已读文件及关键证据位置：
逐项检查结果与已确认问题：
执行命令、退出码、证据级别及未执行原因：
重构状态 / 批次结论：
未读路径、跨板块待办、下一批唯一入口：
```

证据复用前检查相关文件、公共接口、依赖、Schema、Profile/资源哈希、工具链或目标环境是否变化。HEAD 未变不代表未提交源码未变；无关文件变化也不必废弃全部结论。仅失效的检查转回待核验，保留旧记录作历史依据。

新会话提示词（替换占位内容）：

```text
按《重构分板块排查计划》只执行 <batchId>，runtime=<shared/userscript/tauri>。
目标问题：<一个不变量>；允许路径：<一个主目录及直接邻居>。
先读根/目标 AGENTS.md、计划第 2/3/5 节和本批条目，再按需加载对应技能。
复用 <上一批摘要或报告路径>，先核对基线变化；不要扫描其他板块或读取全部历史。
本批只排查并记录结果，不修改产品代码。运行最小有效定向测试，超出范围的疑点列待办。
分别报告重构状态、static/tests/artifact/live 证据和批次结论，标明未知项。
到阅读预算或需要展开第二条独立调用链时保存交接并停止扩展。
不启动产品/浏览器/模拟器，不提交/推送；下一步只给一个明确子批次。
```

一个子批次完成需要：选定标准逐项有结论；必要测试已执行或缺失原因已记；明确问题有归属；未读范围可见；下一步无需重读本批。板块完成需要其所有计划子批次和依赖闭合。整个计划的完成以约定范围、有效证据和剩余缺口清单为准，不以“文件都看过”或一次全量测试通过为准。

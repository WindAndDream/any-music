# 虚拟列表与布局性能实施方案

英文对应页：[Virtual Lists and Layout Performance Implementation Plan](../../../en/cross-platform/architecture/virtual-list-implementation-plan.md)。

**状态，2026-11-07：C03 Studio“我的喜欢”（原生表格与皮肤网格）候选已实现并具备消费回归；C00–C03 分别保持默认关闭。** O01 等价行高重建优化已实现，C00 与 O00–O02 的运行端收尾仍开放；完整代次非阻塞持久化单列 S00。P00–P15／R00–R08 保留已有实现证据。C01／C02 复用现有测量网格、完整宿主筛选集合与手势适配器，补入口范围的语义恢复。GM 小列表侧栏回退、原生高速真实行高变化／完整行几何成本仍待实测解决。恒速滚动、快速滚动与全范围压力分别评价；现有压力失败和持久化长任务不因拆分而通过。C03 复用公共表格／网格基础，接入有界交互与语义恢复。下一独立消费批次为 C04／C05；受影响入口的生产启用仍须通过自己的运行端门禁。完整生产产物、持续媒体／账号与设备组合由 G01–G03 收尾。现有筛选器继续搜索完整归属集合并有界渲染；Ctrl+F／Cmd+F 保持原生且仅搜索已挂载内容，不新增查找入口或全量 DOM 模式。第 3 节定义当前执行顺序，第 10 节保留分构建证据与限制。

## 1. 目标、决策与归属

对所有渲染内容可能大量增长的滚动集合实施虚拟化，保持当前外观、顺序、控件、手势、动画、焦点、滚动行为与业务结果。以“我的喜欢”验证首个网格族，再按复用关系成批迁移生产入口；每个入口保留独立状态和恢复边界。固定导航、协议限制的短预览和少量静态选项需要在清单中明确分类，不直接套虚拟化。仅有协议上限不构成排除理由；有上限但仍跨越许多屏幕或渲染成本较高的集合也在范围内。

拟统一采用 `@tanstack/vue-virtual`。2026-11-03 已核对版本 `3.13.51`，P04 在安装前重新确认实际版本、许可、适配器行为及真实消费构建的体积成本。[Vue 适配器](https://tanstack.com/virtual/latest/docs/framework/vue/vue-virtual)与[虚拟器 API](https://tanstack.com/virtual/latest/docs/api/virtualizer)提供动态测量、稳定键和可扩展渲染范围，但这些能力本身不证明应用性能。本次不引入第二套虚拟器，也不新建工作区包。

| 归属                                              | 职责                                                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `packages/ui`                                     | 受控虚拟列表／网格基础、纯几何计算、测量、滚动／焦点辅助和通用拖拽适配，仅通过公共入口提供。                                  |
| `packages/theme-default`／`packages/theme-studio` | 分别适配自己的行、表格、网格、标题、对话框及作用域样式，两个主题不互相引用。                                                  |
| `packages/music-workbench`                        | 保持既有业务生命周期和语义化展示连续性；仅在虚拟目标确有需要时扩展公共连续性契约，不引用具体主题。                            |
| 标签／创作插件                                    | 使用公共 UI 基础适配既有中性专属控件和编辑状态，命名空间与会话仍由插件负责。                                                  |

## 2. 必须保持的行为契约

| 契约       | 必须对比的结果                                                                                                                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外观       | 卡片皮肤、封面比例、字体、卡宽、行高、间距、密度、手机列数、空态／加载／错误、吸顶标题和滚动条保持一致。测量真实几何，不给可变高卡片强行指定统一固定高度。                                                                                      |
| 稳定身份   | 密度与列数变化后，仍在渲染范围内的项保留带稳定键的组件和资源作用域。离屏卸载／重建是预期机制，但不能丢失草稿、动作或结果；不能削弱已有 `TrackCardGrid` 节点身份测试。                                                                           |
| 滚动       | 保留现有滚动容器、嵌套滚轮／触摸行为、页面转场、回到顶部与返回导航。重排或前方项目变高时，以稳定项锚点和项内偏移保持视图；不覆盖原本有意执行的滚动重置。                                                                                        |
| 选择与播放 | 数量、筛选、全选、批处理、播放顺序及排序提交使用完整筛选集合，而非已挂载窗口。除非已有行为，否则不新增播放跟随滚动。                                                                                                                            |
| 拖拽       | 保留长按与短点区别、拖动柄、命中计算、筛选子集规则、跨组限制、邻项让位、边缘自动滚动和键盘替代。向前／向后均可拖入新挂载的行。                                                                                                                  |
| 松手落地   | 遵守[落地交接契约](../功能设计/跨端界面与交互规范.md#7-动画与手势)：提交顺序、禁用过渡进行坐标重基、从当前可见帧继续、落地完成前保留可见性和层级。覆盖新的受控快照与跨行移动。                                                                  |
| 弹层与编辑 | 行滚出后仍保留原始项／会话、菜单位置、Escape、焦点返回、输入法组合输入和未完成内容，迟到的确认不能作用于替换后的其他项。                                                                                                                        |
| 分页       | 保留逐页准入、空页／过滤页、显式滚动需求、短列表补齐、重试与 `hasMore`。虚拟挂载、尺寸变化、主题替换均不能额外请求页面。                                                                                                                        |
| 筛选与查找 | 现有筛选器匹配归属方提供的完整集合，包含当前未挂载项，再把有序匹配结果交给同一个虚拟渲染器。数量及动作覆盖完整结果，挂载仅限视口、预渲染及有界交互保留项。不新增查找／查看按钮、不拦截快捷键，不增加隐藏搜索副本、远程分页遍历或全量 DOM 模式。 |
| 生命周期   | 主题替换、插件停用、用户脚本隐藏／恢复、零尺寸容器和销毁不重启播放、不取消下载、不写命名空间、不重放动作。正确清理观察器、动画帧、动画和监听器。                                                                                                |
| 可访问性   | 保留原生列表／表格语义、名称、逻辑位置、键盘顺序和焦点，未挂载的逻辑目标先挂载再聚焦。浏览器 Ctrl+F／Cmd+F 与原生文本选择仅覆盖已挂载内容；通过现有筛选器与滚动访问离屏项目，不要求与全量 DOM 等价。                                            |
| 侧栏       | 保持当前时长、缓动、左右位置、内容区／播放器移动边界、快速反向开合、断点与减少动态效果行为。不把桌面动效改成覆盖抽屉、瞬间跳变或文字缩放。                                                                                                      |

已有 `content-visibility` 优化不等于虚拟列表；它的占位几何不能被当成真实内容高度。只在被测量的虚拟展示表面调整包含规则，并保留拖动／落地期间的可见性保护。

## 3. 最小步骤执行与故障恢复

**状态阅读与维护**：第 5–9 节每个步骤的“状态”列是当前进度，第 10 节保留对应证据。“待执行”表示尚未开始，“进行中”表示正在实施，“已实现”表示已具备记录的静态／自动验证证据，“待评估”表示需要实测证据才能决定是否修改，“已评估”表示当前决策已记录并保留后续条件门禁，“待验收”表示所需验收尚未完成，“已验收”仅在全部适用出口有证据后使用。P03 的结构／构建部分已记录，真实布局／视觉／帧耗时仍待验收；P12 已有原生表格证据，P15 已有反复资源／生命周期证据。P14 的 C00–C02 Classic 与 C03 Studio“我的喜欢”接入已有自动语义证据，Studio 待听／歌单对应入口及原生恢复验收仍开放。R00–R08 已有自动几何／保留／窗口／落地／中断／离屏焦点／键控位移验证证据，C00–C03 候选检查不关闭生产准入。后续每轮同步更新步骤状态、顶部进度、双语页面及第 10 节证据，不能仅更新台账。

下文 ID 用于追踪覆盖、验收和最小反向范围，不代表必须分别开启一个开发／全量验收周期。以第 7 节复用族组织可审查批次；同批共享一次基础验证，各入口补自己的业务差异。续接默认读取顶部状态、第 3 节、目标消费／优化行和第 10 节最近相关批次；只有契约变化或回归失败才展开旧 P／R 实施记录，不重建未受影响的历史基线。每批执行以下流程：

1. 重新读取当前实现、最近的指南和测试，保留所有已有已修改／未跟踪内容；修改前记录本步准确文件范围与预期行为。
2. 针对本步风险补充最小且有意义的回归，再实现单一职责，不夹带无关格式化、改名或状态归属迁移。
3. 开发小步运行改动对应的目标回归；批次结束完成受影响包测试与类型检查。公共入口／依赖变化检查边界，共享样式／入口变化构建真实消费前端。稳定实现批次结束、提交前及 G00 执行五项根检查；纯方案／证据文字维护检查链接、双语一致性与格式。新增修改或失败只重跑受影响检查，未变路径的证据须可追溯，不以旧通过结果接受新差异。
4. 更新第 5–9 节对应步骤的状态列和顶部进度，再更新第 10 节简洁执行台账：修改文件、检查结果、证据、剩余真实界面门禁及最小修复／反向修改范围。两种语言保持同步；缺少必要视觉／运行端证据时，“已实现”不等于“已验收”。
5. 失败后停止推进依赖本步的入口，使用最小数据复现，只修复或反向修改本步负责的差异，再跑对应回归。不能重置或暂存移走用户已有修改；某个入口失败不应迫使回退其他独立页面。

实施检查直接在任务交接中说明。历史方案日志记录于 `logs/2026-11-03-virtual-list-plan/` 和 `logs/2026-11-07-virtual-list-plan-optimization/`。实施产生需要长期保留的构建身份和简洁验收证据时，存入 `docs/baselines/virtual-lists/`。未经要求不提交、不推送；划分成便于审查的差异不代表获得了提交授权。

依赖按实际公共契约确定：P00–P15／R00–R08 已有实现证据 → C00 与必要的 O00–O02 收尾 → 同族消费入口；S00 单独推进，G00–G04 汇总最终交付。P14 的语义恢复、分页／表格／拖拽能力只阻塞实际依赖它们的入口。共享正确性缺陷会阻塞相关入口启用；某个极限压力、设备或发布产物门禁未关闭，不阻止独立入口的代码接入。不得启用一半完成的拖拽路径，等待界面检查授权也不等于通过验收。

### 3.2 证据复用与验收分层

- 共享几何／保留／运动／生命周期回归由其归属包验证；消费入口主要补完整集合业务、自己的滚动根、会话与恢复映射。公共契约变化才扩大到全部受影响调用方。
- 每个拟启用入口分别完成适用运行端的布局、焦点、输入／拖拽、请求或写入副作用检查；共用宿主的持续播放／下载／账号组合在 G 阶段统一覆盖，相关生命周期有变化时提前定向回归。调试检查不代替生产产物／权限准入。
- 复用证据记录构建／源码身份、运行端和场景。测量变化重测几何／滚动，运动变化重测中间帧与落地，存储变化重测提交／恢复；未受影响的主题／配色／皮肤无需在每个小步重跑全组合。最终产物仍须有自己的证据。

## 4. 拟采用的技术结构

- 数据与选择仍在现有归属中。渲染器接收只读项目、稳定键、真实滚动元素和受控显示选项，提供可见逻辑项、布局位置、总高度／长度、按键定位和临时交互保留能力，不读仓库、不解析媒体。
- 适配器和缓存生命周期放在 `packages/ui/src/composables/virtual-scroll/`，纯布局辅助就近放置，受控组件放在 `packages/ui/src/components/virtual-scroll/`。路径为拟定命名，只新增具有独立可测职责的模块，并走公共导出。
- 卡片网格按**逻辑行**虚拟化，每行取最高单元格高度，保留逐行顺序与当前 CSS Grid 等宽结果，不能仅设置 `lanes` 就视为等价。已挂载卡片保留扁平且稳定键相同的父容器；列数改变时，不能移入新键的行包装层而丢失资源身份。
- 区分虚拟定位层、稳定落点层和内部拖动／FLIP 动画层，避免覆盖彼此的 `transform`；保留当前单元格查询容器、语义 token 和逻辑坐标／RTL。
- 挂载测量目标与容器共用观察器池，缓存有界，几何读取批量执行；不为整个数据集创建观察器或副作用。自然高度按稳定身份和布局／内容代次缓存，宽度、密度、内容变化均失效，既能增高也能缩短。
- `useVirtualItemMeasurements` 通过 `observeItem(key, element)` 及其释放句柄注册自然、未缩放的边框盒单元。调用方提供语义内容代次和密度／字体布局代次；实际列表宽度也会使高度失效。展示内缓存默认最多 512 项（包括挂载单元），仅保留当前代次，按测量新近度淘汰；离屏淘汰后恢复估计值，重建时再测。仅挂载单元持有效果／监听，不能以尺寸包含、占位高度或指定高度约束测量目标。`refresh()` 重读挂载单元；本地捕获 load 事件也支持无 ResizeObserver 时的延迟图片。
- `useMeasuredVirtualList` 以此有界缓存作为唯一高度权威，每批变化后重置现有引擎几何，不再累积第二份已访问高度表。引擎／身份索引几何仍随完整集合增长，不宣称帧耗时有界；可选 `useVirtualScrollAnchor` 消费不可变几何快照；默认列表不主动补偿滚动。
- `useMeasuredVirtualGrid` 按带类型、与顺序无关的同行项集合管理拉伸测量：排序只使变化的行组失效，保留行内换位及无关行的有效缓存，避免原生滚动范围坍缩。它先从高度缓存派生有界的非估值行高；等价换窗／淘汰或未改变行最大值的测量复用原不可变几何，不再先构造全行再比较。只有所有单元格均已测量且低于估值时，该行才能缩短；完整行循环读取已捕获的标量。真实空间变化仍构造 O(N) 行并重置引擎，不宣称高速滚动或总内存已准入。
- 同列宽度变化丢弃旧高度权威，在虚拟行更新前批量读取当前挂载项的自然高度，避免渲染估算／测量往返。运动快照贯穿该同步批次；连续宽度及其引起的位置／高度变化由 CSS 推进，不重启 FLIP。独立内容／加载重排和列数／分组／间距变化仍触发运动，拖拽空间代次仍包含宽度。空窗口也结束批次。旧运动快照不回填缓存、不约束自然高度，也不作为拖拽／锚定几何；完整空间比较仍可能为 O(N)。
- 测量同时发布高度代次与真实重排原因。首次／重挂载和有界缓存淘汰更新渲染、锚点与实时拖拽几何，不触发 FLIP；每个已挂载单元保留上次自然高度，在缓存淘汰后仍能识别真实 resize／load 变化，混合换窗／真实重排批次也保留该信号。内部运动比较基线随换窗前进，不推进运动代次。行几何及保留的运动快照仍随 N 增长。
- 与分页和连续性恢复共享实际滚动容器，纳入列表起点、标题和嵌套／Shadow 表面的偏移；不默认监听 `window`，不添加内层滚动条，不为每行挂全局测量监听。
- 仅挂载可见行、调优后的缓冲行和有界交互保留项，随视口高度、解析列数、当前风格／自然高度动态决定；30／50／32 是观测值，不是上限，遵循[挂载预算](../功能设计/跨端界面与交互规范.md#72-随视口变化的挂载预算)。拖动／落地项、活动编辑器及必要焦点／菜单锚点只在真实生命周期内保留；离屏播放项依靠宿主状态，不为每行常驻一个播放器。消费方适配器注册跟随挂载表面身份，在不可变受控排序提交时保持稳定，见[拖拽交接准则](../功能设计/跨端界面与交互规范.md#71-拖拽松手与消费方生命周期)。
- 测量稳定后，按语义键及项内偏移恢复视图；用户滚动或展示替换时取消过时任务。缓存和临时锚点不进入产品快照／备份。宿主契约若需扩展，保持中性并覆盖跨主题测试。
- `useMeasuredVirtualTable` 复用测量列表缓存并推导完整物理行位置。`VirtualTable` 使用合法表格分区及远端保留组前后的占位区间；一首歌及其详情／操作行共用自然测量的稳定键 `tbody`。默认插槽为组件生成的物理行提供单元格，`rows` 插槽保留既有 `tr` 组件。调用方声明准确的表头／表尾／项目行数和原生行 ARIA 位置，提供列宽，并将跨行合并限定在一个逻辑单元内。内联零间距／占位几何抵御普通主题单元格规则。原生列宽／吸顶／辅助技术树等价性仍开放，不向 `tbody` 塞任意 `div`。
- 已迁移的可增长集合始终使用虚拟渲染，包括空集合、单项、小结果和筛选结果；不增加按数量切换、原生查找／文本选择补偿或错误时退回全量 DOM 的路径。固定短控件仍按清单单独分类。临时准入开关仅隔离未验收候选与原有生产基线，属于内部实现，不是用户偏好或搜索模式，G04 移除。

### 结构与性能要求

- 视口／布局／交互保留项相同时，1,000 或 10,000 项不能挂载全部行／卡片。挂载单元格上限为 `(可见行 + 2 × 缓冲行 + 保留行) × 列数`，表格／详情区分逻辑项和真实 DOM 行数。
- 稳态滚动、指针移动和侧栏动画帧不能枚举完整数据集 DOM 或重建无关业务投影。真实数据变化时可以进行完整筛选／索引构建，单独测量其成本。
- 多次从首项滚到末项再返回时，每个采样窗口的已连接 DOM、存活组件作用域及测量／资源订阅都保持有界。追踪离开窗口的旧节点并确认断开连接，累计挂载调用量与当前存活量分别记录；不能为每个访问过的项保留完整 Vue 组件，明确的编辑会话仍在现有归属中保留。
- 同时比较 80 项响应和 1,000／10,000 项规模，记录同环境下冷挂载、滚动、侧栏开合帧分布、长任务、布局／绘制与真实包体差值；报告 p95／p99 及退化，不能凭模拟或一次均值承诺 FPS。
- 以记录的参考环境中常见 60 Hz 下约 16.7 ms 帧预算为目标，同时保留真实刷新率。具体设备阈值根据 P03／O00 证据在评价结果前确定；即使耗时改善，功能／视觉等价性仍是硬条件。

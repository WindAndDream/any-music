# 音乐源插件架构

英文对应页：[Music Source Plugin Architecture](../../../en/cross-platform/architecture/music-source-plugin-architecture.md)。

适用范围：共享音乐源与媒体契约。数据传输由[篡改猴 GM](../../用户脚本/开发规范.md)或[桌面 IPC/Rust](../../桌面端/开发规范.md)实现，不在共享协议中判断运行环境。

## 1. 目标

音乐源插件把“某个平台如何发现和播放内容”转换为 Any Music 的统一音乐领域。内置来源的协议与测试归各自 plugin-source-* 包，不拥有产品界面；正式 Userscript 与 Tauri 通过各自传输/存储及可选页面端口消费共享实现。S15 外置目录的当前能力见第 9 节。

## 2. 分层

### 内置来源分配

| 运行端       | 内置音乐源                 |
| ------------ | -------------------------- |
| 篡改猴       | 哔哩哔哩、抖音、网易云音乐 |
| Tauri 桌面端 | 哔哩哔哩、抖音、网易云音乐 |
| Tauri 移动端 | 哔哩哔哩                   |

各音乐源包通过轻量 `*_BUILT_IN_TARGETS` 明确声明分配端。应用目录将目标列表、描述符、URL 预检、模块创建与运行端工厂组合；`selectBuiltInSources` 拒绝重复来源 ID，并在构造实例前筛选。未列出的运行端不会自动获得新来源；新增来源必须明确声明目标端。原生端依据 `runtime_capabilities.form` 装配，不用视口宽度或用户代理判断。来源列表、插件模块、账号平台与账号切换共用筛选后的目录；传输不可用时只保留当前端来源的元数据。已存歌曲和配方保持原有来源身份，不因此启用未支持来源；Rust 独立检查原生账号准入。

来源分配不代表原生能力相同：Android 提供 B 站二维码同机授权及账号 HTTP；iOS 认证和移动媒体仍不可用。移动端不注册抖音和网易云来源、模块和账号入口，待原生适配实现并验证后再明确加入。

```text
Vue 组件
  ↓ 仅使用 Track / TrackListing / Session / ResolvedMediaSource
应用 feature 与 composables
  ↓ MusicSourcePlugin
平台插件（URL、签名、原始类型、接口、映射）
  ↓ HttpClient / Storage 等端口
运行端适配器（Userscript GM HTTP / Tauri IPC → Rust HTTP）
```

- `packages/core`：`Track`、插件公共契约、错误状态、分页/媒体策略和音乐配方适配。
- `packages/audio-composition`：独立音频配方编译、时间线和浏览器编解码。
- `packages/plugin-center`：无界面的注册、状态检测和惰性加载。
- `packages/plugin-source-*/src`：正式版可移植协议、签名、DTO 与映射。
- `apps/userscript/src/platform/music-plugins/<platform>`：宿主 Cookie、签名和页面桥；`apps/tauri/src/platform`：IPC 端口，`src-tauri`：原生 HTTP、账号与登录。

详见 [可复用包边界](可复用包边界.md)。

- `apps/*/src/features/music-sources`：运行端内置来源构造；注册表、会话和列表等公共组合在 `packages/music-workbench/src/features`。
- `packages/music-workbench/src/features/player`：不区分来源的播放队列与媒体调度；应用注入传输、媒体准备与保存能力。
- 组件只发出搜索、导入、播放、入队等意图，禁止拼第三方 URL。

目录按职责而不是最初来源命名。`useTrackCatalog`、`usePluginSession`、`usePlaybackQueue` 等只消费 core 契约，不得放进 `features/bilibili` 或 `features/douyin`；只有 API 路径、签名、原始类型、平台 URL 识别和字段映射保留平台名。

### 2.1 描述符、有效性与按需模块

`MusicSourceDescriptor` 是不执行平台实现即可读取的稳定元数据，包含 ID、名称、内置/外部来源、能力和精确 URL 范围。URL 导入先用描述符做纯本地预检；不支持的地址不能先创建抽屉或发出网络请求。内置源通过 `LazyMusicSourcePlugin` 延后签名、DTO、API 和媒体实现，第一次会话、列表迭代或播放才动态导入，成功结果复用，失败 Promise 不缓存。

已注册来源使用 `unchecked/checking/available/invalid/unavailable` 可用性状态。只有来源明确返回无效才进入 `invalid`；网络或协议失败进入可重试的 `unavailable`。已启用但尚未通过检测的来源不能发起搜索/导入，已有抽屉保持配方并暂停，而不是删除数据。

## 3. 稳定身份与临时媒体

`Track.id` 建议为 `<plugin>:<kind>:<resource>:<part>`。`Track.source` 只保存：

- 插件 ID；
- 视频、音频或自定义类型；
- 平台稳定资源 ID；
- 可选分 P/章节 ID；
- 可选原始页面 URL。

`ResolvedMediaSource` 每次播放时生成。远程媒体包含短时 URL、备用节点、MIME、编码、时长、加载策略、当前音质和按高到低排列的可用音质；明确声明为 `complete-binary` 的小媒体携带当前会话字节、MIME 和单一成品音质。音质 ID、排序值和媒体结果都只属于当前解析会话，禁止落库。运行端可注入幂等的临时 `release()` 以持有账号占用和本机媒体 grant：播放器在切歌/卸载后释放，导出在读取完成或失败/取消后释放，自定义歌曲预取在加载器回收时释放；取消或竞争落败的媒体描述也必须释放。该回调不进入配方或存储。

运行端独立的[资源缓存](../功能/资源缓存.md)可保留有限图片、媒体字节，与产品存储隔离。缓存不保存媒体描述或 URL，也不替代当前账号、媒体授权检查和原生流优先的启动流程。

## 4. 惰性列表

`TrackListing.account` 可携带实际请求账号的公开标识、平台用户名与自定义命名。多账号运行端在首个惰性分页选出账号后补齐该投影；共享工作台重新读取，不能用当前选中账号替代。工作台将首次成功分页的公开账号 ID 和名称随缓存结果保留，账号状态和请求路由仍来自运行时；换账号续载不改变原身份，手动刷新则重新确定。凭证和实时账号状态不持久化，也不为详情展示增加会话请求。单宿主账号运行端可在请求开始时保留已知身份。

搜索、合集、投稿和收藏统一返回 `TrackListing`。`pages()` 是异步迭代器，每次 `next()` 只读取一页：

工作台以响应式方式跟踪列表运行实例的增删。同步视图可能在新配方发布后、运行实例插入前读取列表；实例插入和后续分页结果必须触发视图刷新。仅缺少运行实例不能判定音乐源已卸载，只有来源注册表不存在该提供方 ID 时才显示此状态。首次登录状态检查等待来源模块启用完成，避免启动流程取消自身检查；启动完成前卸载工作台不会再发起检查。

运行端可为当前列表注入可取消的 `verify()`，绑定实际失败账号；该能力不进入稳定配方，也不由共享包选择浏览器或传输。错误面板仅在 `verification-required` 时提供用户主动验证入口。验证成功后工作台复用同一列表从第一页重新加载；没有注入能力的来源保留来源页面链接与手动重试。

```ts
for await (const page of listing.pages()) {
  render(page.items)
  if (userStopped) break
}
```

停止迭代代表停止消费，不应在后台继续抓完整合集。分页结果同时携带页号、页大小、可选总数和 `hasMore`。B 站页码分页遇到空页或 `hasMore=false` 必须终止；抖音游标分页还要在游标不变时终止，避免异常接口造成无限循环。

发现板块在工作区快照中保留稳定歌曲元数据、已加载页数、总数、错误和可选的 `TrackPage.continuation` 续载位置。重新打开、重启、切换筛选或重复提交相同来源/类型/输入时，直接复用结果；显示未筛选的短列表时可能请求后续页。空闲列表因音乐源模块初始化、停用或整个音乐源失效而暂停时，会关闭旧读取器，但保留缓存结果；下次加载通过当前音乐源绑定新的列表，从已保存的位置续载。已完成的列表保持完成；缺少续载位置或位置被拒绝时保留歌曲，等待用户手动刷新。发现页对未筛选的短列表逐页补齐，直到滚动区域填满或来源结束；后续向下滚动逐页加载，不提供“加载更多”按钮，手动刷新才从原始请求的第一页重建。歌曲按稳定 ID 去重，避免平台排序变化造成重复。

续载位置只包含下一页页码或数字游标。B 站列表提供页码；抖音搜索保留平台实际返回的游标，不根据已显示歌曲数量推算；抖音公开游标列表也提供续载位置。私有/个人列表、嵌套目录和未显式提供续载位置的外部目录，在重启后保留结果并要求手动刷新。游标过期或被拒绝时保留旧结果、停止自动请求，不回放已加载页。这些能力由离线适配器测试覆盖，不构成新增网站、GM 或 Rust 实机验收证据。每个列表最多缓存 10,000 首歌曲；快照损坏或被截断时不得复用会跳过缺失歌曲的续载位置。

播放确认的 `not-found` / `source-not-found` 错误按稳定歌曲 ID 保存失效标记，在其他列表和重启后保持显示。网络、超时、登录、验证、限流、响应格式和普通媒体失败不会永久标记歌曲失效；成功播放后清除标记。媒体地址、字节、账号租约、Cookie 和验证能力不进入快照，每次播放仍实时解析媒体。

## 5. 会话状态机

插件返回五种稳定状态：

- `not-required`：插件不需要账号会话；
- `signed-out`：明确未登录；
- `signed-in`：已登录并携带最小用户摘要；
- `expired`：UI 曾显示登录，但业务请求报告鉴权失效；
- `unavailable`：网络、平台或响应异常，不能推断登录与否。

UI 的 `loading` 是请求过程状态，不写入领域会话。任意业务请求收到未登录错误时，应把已缓存的 `signed-in` 转成 `expired`，再由用户决定是否打开登录页。

所有失败语义与持久化规则见 [错误与状态模型](错误与状态模型.md)。音乐源只把平台异常映射为共享 code；HTTP 状态、原始业务码和响应片段留在适配器诊断上下文中。

## 6. 媒体加载

- `eager`：短内容允许浏览器积极预加载；仍使用远程媒体，不等于持久化二进制。
- `range`：长内容只读取 metadata，并依靠媒体元素的 HTTP Range 按需 seek。

插件只表达策略；播放器决定 `preload`、备用 URL 切换和失败提示。B 站视频优先请求 DASH 并选择音频 representation，不下载视频轨。抖音普通视频优先完整作品音轨，避免把背景配乐误当完整声音；图文使用作品配乐。无请求头和只有 Referer 的媒体先尝试浏览器原生流式播放；跨站 Referer 使用 `no-referrer`，同站则保留浏览器默认来源。原生失败或来源要求其他自定义头时，播放器通过注入的 HTTP Range 与 Mediabunny 抽取已编码音轨，重封装为碎片媒体并交给 MediaSource，使原生 `<audio>` 继续负责暂停、seek 和倍速。

Range 传输在响应头发现入口重定向成过大的完整响应时立即中止，并只在当前 reader 内复用最终短时 CDN 地址重试分段请求。备用节点以 250 ms 间隔错峰竞争到“首个编码音频包可读”，而不是只竞争封装识别；胜出后取消其他探测。抖音 MP4 的 AAC 预卷可能产生负时间戳，兼容通道以首包为零点平移包时间线，不解码或重编码。MSE 只保留播放点前约 30 秒、后约 15 秒的窗口，后台读取通过背压等待并清理旧片段，避免长音频快速灌满 SourceBuffer。seek 目标仍在窗口内时直接移动原生时钟；目标位于已清理区间或尚未生成的远端区间时，播放器中止旧会话，从目标音频包重新建立 Range/MSE 流，并恢复 seek 前的播放或暂停状态。原生控件连续拖动会短暂防抖，后一次 seek 会使前一次异步读取失效。首个可播放碎片的总预算为五秒；超时或所有节点无法建立 Range 输入时跳过必然重复的整段抽取，进入完整媒体兜底。浏览器明确拒绝 MSE 编码时仍可生成会话级音频专用 Object URL。播放器在原生控件上方提供加长时间轴，悬停显示 0.1 秒精度的目标时间；拖动按上述窗口规则选择直接跳转或重建流。

播放器省略 `qualityId` 发起首次解析，插件必须按自己的平台规则选择当前最高可用音质。用户切换时播放器携带候选 ID 重新解析短时地址，成功后保持当时的播放位置与播放/暂停状态；失败则继续使用旧媒体。音质高低和文案不得由通用组件猜测：平台插件优先使用码率、quality/quality_type、gear_name、编码等原始字段并校验请求 ID，只有缺少结构化字段时才从 URL 的扩展名或码率参数推导，最终回退为“音质 1”“音质 2”。

共享 Range reader 对并发读取和大小探测统一限制最多三个 HTTP 请求，每个分片不超过 2 MiB。一次读取失败时，会在排队任务启动前取消同组分片，其他独立读取仍可继续。每个 206 响应必须与请求区间、字节长度及一致的资源总大小匹配。大小探测失败后允许重试；取消会拒绝迟到响应和缓存读取，dispose 会清理会话缓存。完整文件加载也在 HTTP 返回后检查取消状态，再交付字节。

GM 的 fetch/XHR 超时与单代理细节仅属于[篡改猴规范](../../用户脚本/开发规范.md#gm-传输与代理细节)。桌面使用[IPC/Rust HTTP 与账号媒体 grant](../../桌面端/开发规范.md)，不继承 GM proxy 或浏览器宿主状态。

## 7. 跨站图片

曲目封面属于展示资源，不进入平台 API 请求链路，但普通 `<img>` 会默认携带当前宿主页的 Referer。在抖音页面显示 B 站 `i*.hdslb.com` 封面时，这会触发 B 站 CDN 防盗链并返回 403。

所有第三方封面统一通过共享 UI 的 `RemoteImage` 组件显示：

- 使用 `referrerpolicy="no-referrer"`，不把当前宿主站泄漏给图片源；
- 保留浏览器原生图片缓存与惰性加载，不把封面转成持久化二进制；
- 加载失败显示稳定占位，不能让平台错误扩散为破损布局；
- 不在 `Track` 中保存 B 站、抖音等域名策略，也不在通用组件按 `pluginId` 分支。

若未来平台即使无 Referer 也拒绝加载，再在运行端增加受大小限制、可撤销 Object URL 的资源加载端口（Userscript GM / Tauri 原生）；不要直接把 `GM_*` 放进共享 UI。

## 8. 自定义歌曲配方

已实现的配方结构以毫秒为单位：

```ts
interface SegmentRecipe {
  sourceTrackId: string
  startMs: number
  endMs: number
}
```

自定义歌曲再次截取时，保存前执行递归扁平化：沿自定义曲目引用把区间映射到叶子媒体，使用访问栈检测环，合并相邻且同源连续片段。虚拟时长是所有片段长度之和；播放头通过前缀和或二分索引映射到具体片段。普通规模用前缀和数组即可，只有大量片段与频繁编辑同时出现时才考虑 Fenwick Tree 等动态结构。

片段创作还使用 `MaterialCollection` 约束一次配方的直接素材必须来自同一合集。自定义歌曲可以作为合集成员再次被引用；编辑层保留该节点，编译层使用缓存递归展开并通过二分区间裁剪得到普通平台叶子。下载时由 `audio-composition/browser` 的 Mediabunny 转换器逐样本统一编码，应用注入媒体读取，core 只保存合集 ID、来源曲目 ID 和片段配方，不依赖浏览器媒体 API 或第三方编码库。

### 8.1 自定义歌曲的有界流式播放

自定义歌曲首播不得先下载每条叶子原曲并完整渲染成品，否则十秒配方也会受数十分钟来源媒体的下载时间支配。默认播放路径把编译后的叶子时间线切成不跨来源边界、最长四秒的范围解码块：开始播放前准备至少三秒且最多三个连续块，同时以三路并发把前向二十秒窗口继续解码为会话级 PCM。多个一秒片段因此会同时占用预取槽，而不是在每个拼接点才开始解析。AudioContext 把已经连续就绪的块排到同一时钟上，片段边界不再依赖低频 `timeupdate` 临时换 URL。

范围预取只读取目标片段需要的媒体区间，短时描述符和解码结果仅存在于当前播放会话；失败 Promise 立即移除，seek、切歌和卸载会中止旧读取并重建播放点附近的窗口。声明为 `complete-binary` 的解析器会在调用前退出后台预取，避免完整媒体与首播抢占带宽。来源拒绝 Range、浏览器不能解码或预取失败时，播放器保留虚拟位置并退回单个原生 `<audio>` 的逐叶子流式通道；该通道也会按十秒前向窗口、最多十二块和三路并发预解析轻量描述符。同一叶子内 seek 直接移动原生时钟；跨叶子 seek 则锁住用户选择的位置和播放意图，直到目标媒体时钟接管。主 URL、备用节点和运行端 HTTP Range/MSE 兼容顺序继续与普通曲目一致。

只有叶子片段的全部流式通道都失败时，应用才使用 Mediabunny 顺序渲染会话级 MP3，并通过临时 Object URL 交给原生 `<audio>` 兼容播放。切歌会中止尚未完成的兜底渲染。生成的 MP3 字节、Object URL、原始媒体字节和短时 URL 都不得进入资料库；下载操作仍走完整导出管线。

## 9. 自定义插件边界

外部来源使用经过原生验证、审批及精确目标准入的 `.amplugin` 包，按需返回目录项，目前不解析媒体，也不加载客体 artwork/page URL。

机器可读 Schema 与数据归属见[本地资料库与插件](../功能设计/本地资料库与自定义插件.md)。当前外置矩阵见[S15](插件系统重构S15工具与桌面交付.md)。

### 9.1 统一来源契约与未开放媒体能力

内置 music.sources 实现与原生验证后的外部目录使用同一选择器。以下媒体与扩展契约中尚未提供的部分仍是目标要求，不得作为已开放功能：

- 内部 MusicSourcePlugin/TrackListing 保留；外置只传 DTO、listingRef、分页/关闭/取消与短时资源引用，可信适配器恢复宿主行为。
- 每次消费只请求一页，停止、撤权或替换代次终止旧任务；启用/安装/可用性/登录分别表达。保留来源和曲目 ID，不因包名变化重写数据。
- 内置能力由运行端可信端口注入；外置网络仅走原生匿名 Gate，选中私密字段按其敏感等级验权。
- 将来接入媒体时，图片/Range/下载同样绑定身份、epoch、预算与撤权，不把外部 URL 直接交给 WebView。保持轻量描述、原生流式、有界 Range/MSE、完整读取兜底及叶子预取预算；当前无媒体能力时明确 unavailable。

协议、Profile、贡献与数据版本独立协商。自动化验证分页、请求数量/顺序、取消、旧结果拒绝与明确的媒体不可用；真实 GM、Rust 和设备播放分别记录证据。

## 10. 扩展检查表

新增或调整平台适配器时使用 `$music-source-adapter`。需要复抓 B 站时使用 `$bilibili-contract-capture`，复抓抖音时使用 `$douyin-contract-capture`。完成后验证稳定 ID、缺失字段、空页、游标不变、私密资源、登录过期、多分 P/图文、短/长媒体、备用节点，以及从非来源宿主页显示封面。B 站与抖音当前契约分别见 [哔哩哔哩 Web 接口契约](../平台接口/哔哩哔哩/网页接口契约.md) 和 [抖音 Web 接口契约](../平台接口/抖音/网页接口契约.md)。

## 来源归属与取消屏障

B 站与抖音的元数据、协议、签名、DTO、映射、分页及测试分别归 plugin-source-bilibili / plugin-source-douyin。根入口仅提供描述符、URL 预检和 music.sources 贡献，/runtime 惰性加载实现；抖音 /browser 与 /contracts 明确区分可选浏览器能力和可信类型。模块 source.bilibili / source.douyin 与 provider bilibili / douyin、贡献 source.*/provider 分离，不重写曲目或配方 ID。

运行端直接装配 plugin-source-*，GM 与账号 Rust HTTP/CDP/grant 保持独立注入。来源包只依赖 core 和 plugin-center 公共出口，工作台不直接依赖来源实现，不装配转发包或来源 JSON 解释器。

宿主注册表持有来源代次、操作取消和媒体释放；停用、失败或策略/身份失效撤销旧列表、解析、预取与媒体，工作台停止受影响播放和导出，保留资料与队列。重新启用不重放旧任务；下次用户分页/重试重建列表。故障或策略造成零可用来源时不自动改写启停偏好，核心页面继续可访问。用户停用最后一个已启用来源仍被拒绝。

## 运行端策略

Userscript 固定 externalPlugins: none，在构造前及启用/命令/媒体/预取时拒绝外置来源。内置身份仅来自构建目录。Tauri 通过 runtime_capabilities 获取策略，原生安装拒绝未准入激活。见[当前运行端策略](插件运行策略.md)与[S15 交付矩阵](插件系统重构S15工具与桌面交付.md)。

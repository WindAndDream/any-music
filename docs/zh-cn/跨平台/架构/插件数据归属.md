# 产品与插件数据归属

英文对应：[Product and Plugin Data Ownership](../../../en/cross-platform/architecture/plugin-data-ownership.md)。

软件尚未正式发布，直接读写当前架构，不导入早期产品布局、来源 JSON 清单或旧仓库版本。

| 数据                             | 归属                        | 可选插件停用后的行为         |
| -------------------------------- | --------------------------- | ---------------------------- |
| 曲目、喜欢、歌单、队列及历史     | 宿主核心                    | 保持可用                     |
| 已发布配方与创作者署名           | 宿主核心                    | 独立于创作编辑器编译和播放   |
| 用户标签与关联                   | `feature.tags` 命名空间     | 保留数据，撤下编辑和筛选投影 |
| 素材、待归档曲目、草稿及编辑关联 | `feature.composer` 命名空间 | 保留数据，结束编辑会话       |
| 工作区、导航、主题及恢复设置     | 宿主                        | 与业务资产分别保存           |
| 安装、授权、来源追踪及撤销       | 原生插件权威层              | 不通过普通产品备份恢复       |

## 当前产品存储

可选插件 `feature.composer` 统一拥有“自定义音乐”（`custom-tracks`）与“片段创作”（`composer`）的导航、页面和打开命令。停用时同时撤下两个板块；若正在其中一个板块，则返回发现。重新启用后，两个板块沿用已保存的导航偏好、作品、素材和草稿。已发布资产仍由宿主核心保存，已加入我的喜欢、歌单或待听的作品继续支持常规播放与下载，无需创作编辑器。

两个运行端均在配置工作台前创建代次存储。分区只有 `core`、`host` 和 `namespaces`。`local-library:v1` 等仓库键是访问分区的命名端口，不是另一份持久化副本。启动不扫描早期业务键，也不执行自动格式转换。

资料库仅接受当前 schema 6，下载历史仅接受 schema 2。资料库运行时视图重新编译已发布配方，宿主标签和合集关联为空；插件通过命名端口访问自己的命名空间。普通资料库写入不能修改插件数据。资料库和下载曲目元数据只保留 HTTP(S) 或协议相对形式的封面、页面地址，排除 Blob/data/file URL 及内嵌凭证。筛选历史中的标签条件通过对应命名空间写入；未知命名空间版本作为有界不透明数据保留，不理解该版本的写入者不能覆盖它。

不可变代次分块使用规范化校验和、schema 2 清单及一个提交指针。运行端提供 `ProductGenerationBackend.withExclusiveWrite`，在独占持久存储期间完成初次读取及每次完整的同步提交。保护范围包括过期修订号检查、回收、暂存、校验和指针发布，独立的读取与写入不能替代原子比较。完整暂存和校验候选数据后才发布。写入失败后冻结当前写入者及后续代理设置写入，直到重启；过期页面不能覆盖新代次。回收保留当前有效代次。此恢复机制保护当前写入，不承担旧布局迁移。

油猴端仅使用 `any-music:userscript:*` GM 存储，代理配置使用独立运行时键。读取产品数据前，先通过 `GM.saveTab` 登记唯一所有者，再以 `GM.getTabs` 核对会话；第二个展开的工作台会被拒绝。隐藏后的播放、下载仍持有会话，实际卸载或退出页面才释放。启动通过异步 GM 读取载入当前代次，串行且等待确认的 GM 写入在首次失败后停止。释放时立即冻结写入，等待保存队列结束，再仅移除自身登记。关闭的标签页由管理器清除，挂起所有者不按时间过期。Tauri 渲染端提交防止重入并核对持久镜像是否变化；原生保存继续串行校验修订号并原子替换文件。两者之间镜像当前 schema 2 信封，以已提交代次和修订号选择完整快照，拒绝不支持的格式。账号凭证、CookieStore 和代理秘密均在产品数据之外。

Tauri 启动时先验证完整镜像，再回收写入中断遗留的不可达代次分块，然后保存镜像。当前已提交代次、紧邻的上一代及无关键均保留，损坏或不支持的候选不会因回收而被改写，避免遗留分块撑满 WebView 存储后阻塞下载历史和上次平台选择的保存。原生 JSON 解码在 IPC 与磁盘往返中保持 JavaScript 浮点数的精确值，防止播放历史的小数时长破坏规范化校验和。平台选择从已提交工作区恢复，各平台的账号选择独立恢复，并显示当前原生账号状态。

## 可移植业务数据

后续本地用户与绑定遵循[本地／云端规划](多用户与本地云端部署规划.md)，当前仍是单 profile 存储。宿主拥有本地身份／资料库作用域和经过验证的绑定；账号提供方与同步／分享／报告插件拥有各自业务状态及服务。命名空间访问还须按本地用户／资料库，以及必要的绑定／实例隔离。普通导出即使包含插件命名空间，也不能携带绑定证明或会话秘密；导入作者 ID 不建立所有权。这些是待实施约束，不代表已支持多用户／同步。

`exportPortableProductData` 与 `previewPortableProductImport` 只携带稳定核心记录及插件 ID/schema 命名空间。预检拒绝重复 ID、悬空配方、未知核心版本、字节/深度超限以及冲突的备份身份；命名空间内容保持不透明。导入仅提交一次，后续写入前必须完整重载工作台。

导出不含凭证、授权、安装元数据、代理秘密、媒体地址/字节、句柄或磁盘路径。恢复数据不会注册或启用插件。原生插件升级和回滚仍须配对经过验证的代码/数据代次，并保持单调递增的权限纪元和撤销记录；这些当前事务独立于产品存储。

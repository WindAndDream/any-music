# 独立主题开发指南

英文对应：[Independent Theme Development](../../../en/cross-platform/architecture/independent-theme-development.md)。正式契约为 `@any-music/ui/theme`；[主题验收](独立主题UI迁移计划.md)维护 T13 剩余实测用例。

## 新增第三个构建内置主题

1. 创建 `packages/theme-paper`，提供英文 `AGENTS.md`、包级 `test/`、Vue 类型检查和 Vitest 脚本。包名为 `@any-music/theme-paper`，UI/core 内部依赖使用 `workspace:*`。包只提供三个入口：`.` → `./src/index.ts`、`/vue` → `./src/vue.ts`、`/styles` → `./src/styles/index.scss`。仅依赖 UI 公共契约／基础组件及 core 公共类型。
2. 在 `src/index.ts` 导出轻量 `descriptor`，使用稳定 ID `paper`、标题、`contractVersion: 1`、`settingsSchemaVersion: 1` 及支持的 `desktop`／`mobile` 形态。ID 以小写字母开头，仅含小写字母、数字和单个连字符分隔段，最长 64 字符；`host` 留给受保护构建资源。元数据不能执行 Vue、样式、业务工厂或插件实现。
3. 使用 Composition API 实现根组件，在 `/vue` 导出 `definition satisfies UiThemeDefinition`。实现全部 13 个 `UI_THEME_REQUIRED_VIEWS`；宿主启用对应能力时提供 `tags`／`composer`。视图只接收只读功能状态、状态／可用性及具名操作，根组件负责组合。独立实现页面结构，不导入其他主题或依赖其类名，不增加按主题分叉的业务逻辑。
4. 将样式限定于 `:where(.am-theme-paper)`，使用共享 `--am-*` 变量；按需复用 `ui`、`ui/catalog`、`ui/library` 的中性组件与无界面编辑能力，以及 `card-styles/vue` 的可复用卡牌。卡牌发出操作意图，弹窗与业务操作继续独立。专业编辑器只提供宿主绑定的中性控件，草稿、配方和命名空间仍归插件。账号身份／登录、原生安装／同意、存储恢复及媒体保留宿主插槽／同级归属。
5. 在各接入应用的 `features/plugins/built-in-theme-directory.ts` 导入新元数据；在 `built-in-themes.ts` 增加明确惰性注册，导入 `/vue`、`/styles?inline` 和 `virtual:any-music-theme-styles/paper`，将 CSS 值与 `protectedStyles` 组合，保留明确经典回退。将同一元数据目录作为 `createWorkbenchModuleDirectory` 的第三个参数；运行端 `uiThemes` 与 `themes` 必须对应同一构建注册，不从存储数据读取加载器。
6. 共享样式收集器和包／插件／手机边界检查会自动识别 `theme-*` 包。模块适配器只在 `theme.root` 注册 `theme.paper/root`，不再逐行／列表／导航替换。增加包行为／覆盖／样式测试、应用加载器测试，以及通过仅测试主题依赖运行的工作台跨主题夹具，覆盖第三主题加载、失败／重试、模块停用及受保护宿主连续性。
7. 执行定向测试／类型检查、边界反例和根五项门槛：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`。检查两端真实构建审计与字节量；可选主题不得进入启动执行图，油猴单文件仍可能物理包含其代码。浏览器／应用／模拟器检查需要当前任务中的明确请求。

## 归属与切换

构建内主题描述可配置 `unavailableReason`，在模块分配和延迟加载前阻止启动与选择。工作室主题当前使用该开发限制：已保存的工作室偏好会改为启动经典主题；手动选择工作室时，共用顶部提示显示其配置文案，不切换或保存该选择，选择弹窗保持打开。主题就绪后才移除元数据限制；展示标签本身不允许启动。

`MusicSourceWorkbench` 持有唯一业务控制器和音频节点；`createWorkbenchThemeFeatures` 将其投影为公共契约；`plugin-ui-vue/trusted` 校验覆盖、分配一个根组件、激活有范围的资源并按语义恢复焦点／滚动。替换主题不会创建仓库、来源、下载、媒体或专业编辑会话；宿主持有的稳定编辑单元保留未完成输入，只有明确操作拥有重置语义。

各主题主内容区统一使用 `data-am-scroll-key="workspace"`。若容器查询使滚动在嵌套元素之间转移，两者使用同一语义键。宿主按轴采集最大偏移，并按各目标的实际滚动范围限幅恢复，避免不滚动的外壳遮蔽实际容器的位置；彼此独立的滚动区域使用不同键。

当前实现已无 `UiPresentation`、歌曲行分派、包装经典的旧工作室实现、局部加载器入口或提取期 `chrome`／`catalog`／`library` 映射。导航、功能视图、歌曲次级操作／详情、批量操作和筛选等合法语义插件贡献仍保留；它们不选择其他主题的页面，也不授予原生权威。

偏好继续使用运行端隔离的 `ui-theme:v1` 业务键，UI 主题与浅色／深色／系统外观独立。只有成功且仍为当前的渲染选择才持久化；回退／恢复、导入失败和存储失败沿用已有事务，无需数据转换或兼容读取器。

设置投影通过 `themeError` 传递同一宿主会话的错误；两个主题的设置都须显示，包括选择失败但已回退，以及偏好读取／保存失败。Tauri 构建只为打包内的可选主题模块入口生成重试 URL：成功导入保留同一个缓存 Promise，失败后释放，并在下次明确尝试时使用新 URL，避开 WebView 的失败模块缓存。预加载的经典根、来源加载器及静态启动图不参与此转换。

二级弹窗须离开已暂停／inert 的面板祖先，仅离开滚动内容仍不足。经典主题在根组件持有模态层、操作器及工具条目标，页面和普通设置弹层使用这些目标。受保护账号弹窗使用可替换主题之外的独立宿主 Shadow 浮层，只接收宿主样式与同一已解析外观；am-root 上使用 data-am-theme 选择深浅色变量。

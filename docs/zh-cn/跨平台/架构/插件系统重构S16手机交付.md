# S16 手机工程与交付门禁

英文对应：[S16 Mobile Engineering and Delivery Gates](../../../en/cross-platform/architecture/plugin-system-s16-mobile-delivery.md)。当前进度由[实施步骤](插件系统重构实施步骤.md)维护。**2026-10-20** 经授权开展 Android 模拟器和实体设备检查后更新。用户暂无 macOS/Xcode，本轮先完成当前可验证内容。

S16 仍为**进行中**。Android 新增 arm64/x86_64 签名 Release APK/AAB、可重复原生测试、WebView 启动兼容提示，以及实体 arm64 设备通过的 11 项原生用例和 Release 生命周期冒烟检查。iOS 工程、最低实体设备测量、Android 媒体/代理优化 Release 验收与 iOS 账号/媒体适配、声明式/代码分别准入和正式渠道验收仍未完成。移动端两类执行均未准入；S00–S15 保持既有范围。

## 已实施工程

- 真实应用的 Android 工程在 `apps/tauri/src-tauri/gen/android`，由锁定 Tauri CLI 2.12.1 生成并维护。当前最低系统为 **API 26**，compile/target SDK 37。经授权启动早期 API 24 APK 时，Tauri 的 Jackson 依赖因缺少 `java.lang.BootstrapMethodError` 崩溃，已修正 Tauri 配置、Gradle 与 NDK 工具的最低值，不把旧配置当作已支持系统。最低实体设备验收仍待完成。Android/iOS 使用 `com.anymusic.app`，桌面身份/存储保留；iOS 仅有配置。
- `pnpm build:mobile:android aarch64` 或 `x86_64` 构建前端、锁定 Cargo 库和调试 APK；加 `--release` 产出优化原生库/R8 的 APK 与 AAB，加 `--signed` 显式签名。debug/release JNI 目录分离，忽略旧 main/JNI 暂存，避免连续构建串入旧文件。从锁定 Cargo 图生成机器 Gradle 路径并保留 Kotlin/XML。需要 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME`、Rust target 和 SDK 组件；构建不启动产品或上传产物。`pnpm check:mobile:android` 离线执行 arm64 零警告 Clippy；`pnpm check:mobile:boundaries` 检查 ACL 和最低 SDK。
- 产品启动要求 Chromium WebView **111 或以上**；导出的原生入口在构造 Tauri/WebView 前检查，缺失或过旧 provider 显示中英文更新提示，主 Activity 保持私有。有效 OS Intent 及授权在同一应用 UID 内转发。该值不授予外置插件准入，也不表示所有更新引擎均已验收；API 34/WebView 113 有 debug 工作台/IPC 检查，参考手机有 API 35/WebView 153 的 Release 启动证据，API 26 的旧 provider 仅验证原生更新提示。参见 [Jackson 的 Android 下限记录](https://github.com/FasterXML/jackson-databind/issues/4653)。
- 桌面 `main`、Android `main-android`、iOS `main-mobile` 分离，仅匹配主 WebView。iOS 保留本地数据/能力查询/取消；Android 授予有界包预览、快照/撤权、系统文档保存及脱敏诊断，并提供仅限 B 站的原生账号 HTTP、二维码同机授权、账号代理与账号绑定媒体授权。不授予系统浏览器/CDP、DEV、安装/回退、插件命令或执行器中继。Kotlin `mobile-platform` 仅供 Rust 调用，没有 JS handler；此前设备测试确认渲染层无法直接读取其凭证命令。
- 原生能力在挂载前确定移动形态。Android 提供文档/Keystore/账号 HTTP/代理/前台媒体适配，插件端口仍仅支持预览，不展示 DEV/安装/执行控制。缺失能力明确 unavailable，移动外置策略仍为 `none`。移动来源、模块和账号目录仅保留 B 站；iOS 只保留不可用元数据，不构造账号工厂。此前真实注册表测试及挂载修复了空注册表启动失败。2026-10-20 的参考 arm64 调试验收完成用户亲自确认的 B 站客户端跳转/返回、凭证复用、重启后的自动已登录检查、5 页共 150 条原生搜索结果，以及 3 项独立 Android 跳转测试。Rust 与 Kotlin 现统一接受两种官方扫码路径，无效地址不再误报为未安装应用；列表运行实例增删改为响应式，修复新搜索误报音乐源已卸载，首次会话检查等待来源启用完成。分身和优化 Release 认证仍需单独验收，Android 前台媒体已有参考调试设备验收，优化 Release 与其他设备另行验收。见[当前登录与来源分配](../../桌面端/运行端架构.md#移动端设计)。
- Android 通过 `ACTION_OPEN_DOCUMENT` 和单个带授权 `content://` VIEW/SEND 流获取包，五秒内最多复制 16 MiB 到私有、fsync 后发布的不可变快照。名称/大小声明不授权内容。读取轮询支持取消；两个打开槽容纳不响应取消的 provider，并关闭迟到描述符。Rust 仅接收生成的暂存 ID，清理后走既有校验/预览。会话哈希去重 OS 输入，手动选择可重试；重启只回收自有暂存。URI/路径不进入 JS，预览不授予安装权。
- Android 注册包关联/分享及 `anymusic://plugins/install`。固定通知不携带 URI/字节/权威，宿主消费原生入口。深链复用公共 HTTPS 匿名获取，拒绝凭证/私网/畸形链接。后台清空待处理 OS 输入、取消获取并使预览失效，旧下载不能发布可用的迟到预览。不新增解释器、Renderer fetch 或凭证回退。
- AndroidKeyStore 保存 AES-256-GCM 包装密钥，`noBackupFilesDir` 仅保存认证的版本化信封，数据密钥通过私有桥接进入 Rust。材料损坏/缺失时关闭读取，不替换已有凭证；关闭 Android 自动备份。模拟器不证明硬件保护或实体锁定/失效行为；iOS Keychain 不可用。
- Android `ACTION_CREATE_DOCUMENT` 保存使用原生单次令牌（30 秒过期）、私有 outbox、读取前/提交时 32 MiB 限制和五秒打开/写入预算。后台/取消使目的地/写入及此前排队任务失效，重启回收自有 outbox。诊断使用同一适配；插件结果保存保留对话框后的 epoch 复查，但此目标不开放该命令。最终 URI/路径不持久化到产品数据。失败 provider 可能留下空/部分目标，宿主不删除任意 provider 所有的文档。
- 原生后台取消登记请求、账号及普通二维码会话、临时媒体 grant/渲染层租约、获取/预览和内存密钥，恢复不重放。仅已明确打开的 B 站同机授权在原始 180 秒有效期内保留，替换、取消或过期后不能恢复。移动编译排除桌面执行器/DEV 资源及桌面验收 feature；Android 前台 B 站媒体使用原生账号绑定的本机回环流服务，在能力发现前完成监听；Range 请求保留账号 Cookie、Referer、代理和取消。WebView 明文例外仅限回环地址。播放和下载复用共享流式/回退链路与原生文档保存。后台执行及 iOS 媒体仍不可用；参考调试设备已验证前台播放/跳转/MP3 保存及原生代理请求；优化 Release 和音频打断仍需另行验收。
- 重启实测发现代次校验和依赖字段顺序，Rust map 重排可能使较新的原生镜像失效。代次 manifest 升为版本 2，使用递归排序对象键的 `c1:` 校验和；继续读取版本 1 的顺序校验和，旧读者对新 manifest 只读拒绝，避免选中陈旧镜像。原生单镜像恢复回归覆盖重排和 WebView 存储丢失。既有可移植数据规则保留未知 namespace，不携带安装/grant/session 权威；这是恢复修复，不是同步机制。

## 可重复 Android 发布与模拟器检查

从根目录运行；构建命令不授权实际应用检查：

```sh
pnpm build:mobile:android aarch64 --release
pnpm build:mobile:android aarch64 --release --signed
pnpm check:mobile:release aarch64
pnpm build:mobile:android x86_64
pnpm accept:mobile:android --serial emulator-5580
pnpm accept:mobile:android:device --serial DEVICE_SERIAL
```

签名要求同时提供 `AM_ANDROID_KEYSTORE`（绝对路径）、`AM_ANDROID_STORE_PASSWORD`、`AM_ANDROID_KEY_ALIAS`、`AM_ANDROID_KEY_PASSWORD`。密码不进入命令参数或被跟踪的 Gradle 文件；输入不全在构建前失败，不回退到 debug 签名。即使环境中有签名变量，未请求签名仍保持无签名模式。升级需保留所选私钥；本地验证签名不代表正式发布者或 Play 身份。

签名构建自动校验 APK 签名和单个非 debug 签名者、AAB 每项有效载荷的完整签名且与 APK 一致、真实 manifest 包名/最低与目标 SDK、非调试/非测试/禁备份/禁明文设置、无测试 provider、APK ZIP 16 KiB 对齐以及每个 ELF 的 ABI/LOAD 对齐。读取归档不解压，公开哈希/证书元数据写入 APK 旁的 `release-verification.json`。构建对齐不能证明在 16 KiB 设备运行正常。

实际验收脚本要求明确指定已经运行的专用 x86_64 模拟器和已有 debug 构建，拒绝默认/实体设备及已安装的测试包。脚本重建配对的应用/测试 APK，不删除产品数据，以 JUnit 完成结果判定通过，单列跳过项，记录设备/WebView/页大小/产物证据，并只清理自建测试 APK/调试转发；不清空 AVD，不注入 grant。纯原生测试覆盖适配与引擎边界；独立进程的 debug WebView 检查覆盖真实挂载/能力、桌面及私有桥接 IPC 拒绝、私网拒绝、前后台和强杀进程重启后全部活动 core/host/namespaces/archives 数据保留。比对规范化业务数据，排除镜像修订号与过期代次。旧引擎改验原生更新提示并明确报告 `bootstrapOnly`，不宣称工作台通过。报告位于忽略的 `.codex-tmp/s16-accept/`。

独立真机脚本要求明确指定 arm64 设备、已安装且字节完全匹配的已校验本地 Release。它在独立 UID 的临时 `com.anymusic.adaptertest`/`.test` 内运行同一份原生适配器源码，不含启动入口/网络权限/原生 JNI 库，安装前核对真实包身份，先初始化自有测试 provider，结束只移除这两个包。不替换或仪器化用户的 Release，不开启 Release 调试或放松 R8 规则；测试宿主的 Keystore 元数据说明被测适配器在该设备的保护能力，不代表产品已有密钥。仅测试宿主按 [Android 包可见性](https://developer.android.com/training/package-visibility/declaring) 声明查询自己的夹具 provider。手机必须允许 USB 安装；弹窗超时后可用 --prepared 重用已构建 APK，仍重复身份/Release 校验且不跳过仪器测试。直接对优化 Release 运行仪器测试曾因缺少 runner 专用 `androidx.tracing.Trace` 在测试前退出，不计为 Release 仪器测试通过。

同一仪器进程反复强制销毁/重建 Activity 时，暴露原生 `pthread_mutex_lock` 访问已销毁互斥锁的问题。该路径仍未验收，与通过的正常前后台/进程重启检查分别记录。脚本从产品进程外驱动检查，避免仪器框架清理反复拆除 Tauri 事件循环；这不修复或代表强制 Activity 重建已通过。

API 35 软件渲染 Release 模拟器在较慢的首次冷启动中还触发 Wry 0.57.0 `main_pipe.rs:421`：`GetUrl` 回复已取消后发送导致 panic。再次启动进程可显示工作台，实体手机的 Release 首次 Activity 启动报告 503 ms，之后截图确认工作台显示；失败环境的冷启动仍未验收。保留来源校验及 Release 安全设置，暖启动成功不能关闭该失败。

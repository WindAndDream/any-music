# 错误与状态模型

英文对应页：[Error and State Model](../../../en/cross-platform/architecture/error-and-state-model.md)。

## 1. 唯一错误目录

`packages/core/src/errors/app-error.ts` 是全应用可预期错误的唯一事实源。每个错误同时包含：

- `code`：供 TypeScript 分支使用的语义码，例如 `not-authenticated`；
- `statusCode`：供日志、截图和用户支持检索的稳定编号，例如 `AM-2001`；
- `message`：当前上下文的可展示文案，未覆盖时使用目录默认文案；
- `category`、`severity`、`isRetryable`：由目录统一派生，不由调用方重复填写。

应用捕获 `unknown` 时使用 `normalizeAppError` 或 `toAppErrorState`。Vue、下载历史和其他可序列化状态只保存 `AppErrorState`，显示时统一调用 `formatAppErrorMessage`。平台原始错误码、HTTP 状态和异常对象留在适配器的 `cause` 中，不直接扩散到通用层。

## 2. 状态码编号规划

| 编号段    | 职责                                         | 现有代表码                                                    |
| --------- | -------------------------------------------- | ------------------------------------------------------------- |
| `AM-1xxx` | 通用输入、冲突、缺失、取消、上限与内部不变量 | `AM-1001 invalid-input`、`AM-1004 not-found`                  |
| `AM-2xxx` | 登录与权限                                   | `AM-2001 not-authenticated`、`AM-2002 access-denied`          |
| `AM-3xxx` | 音乐源、上游响应、验证与分页限制             | `AM-3002 upstream-error`、`AM-3005 verification-required`     |
| `AM-4xxx` | 运行端网络传输                               | `AM-4001 network-error`、`AM-4003 request-timeout`            |
| `AM-5xxx` | 本地持久化                                   | `AM-5001 storage-read-failed`、`AM-5002 storage-write-failed` |
| `AM-6xxx` | 声明式插件清单                               | `AM-6001 invalid-shape`、`AM-6006 unsupported-version`        |
| `AM-7xxx` | 媒体、导出与下载                             | `AM-7003 media-decode-failed`、`AM-7201 download-failed`      |
| `AM-8xxx` | 本地资料库、素材合集与片段配方               | `AM-8001 collection-not-found`、`AM-8105 circular-reference`  |

状态码一经发布不得改义或复用。删除业务时保留已使用编号；新增错误优先占用所属编号段的下一个空位。`packages/core/test/errors/app-error.test.ts` 会检查编号格式和全局唯一性。

## 3. 哪些异常进入统一目录

进入目录的是用户或外部系统可能触发、调用方需要展示或分支处理的操作型错误，例如登录失效、资源不存在、存储失败、媒体不可解码和输入冲突。

以下内容继续使用原生 `Error`、`TypeError` 或 `RangeError`：构建配置错误、开发期不变量、调用契约被代码自身违反。它们代表缺陷，不应伪装成可恢复的业务状态。边界若需要向用户展示，必须先映射为合适的 `AppError`，同时通过 `cause` 保留原异常。

## 4. 正确状态与其他状态

成功不分配“成功错误码”。成功由返回值或领域状态表达；额外的 `AM-0000` 会制造无意义分支，也容易把流程状态与错误分类混为一谈。

状态按三个层次规划：

| 层次       | 规则                                                                                              | 当前状态机                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 请求过程   | 只描述一次异步工作的生命周期；状态名使用 `idle/checking/loading/ready/error/cancelled` 等一致词汇 | 播放器 `idle/resolving/ready/error`，目录抽屉 `idle/restoring/ready/error`                                                             |
| 领域状态   | 保留业务含义，不压平成全局枚举；失败分支携带 `AppErrorState`                                      | 会话 `checking/not-required/signed-out/signed-in/expired/unavailable`，音乐源有效性 `unchecked/checking/available/invalid/unavailable` |
| 持久化结果 | 使用可恢复的明确终态，刷新后仍能解释历史                                                          | 下载批次、歌曲和尝试使用 `running/queued/downloading/succeeded/failed/cancelled/interrupted/completed` 的受限组合                      |

布尔值只用于正交属性，例如 `isLoading`、`isExpanded`；互斥流程不得由多个布尔值拼接。状态机失败分支必须携带结构化错误，正常分支不得保留上一轮错误。

## 5. 新增错误流程

账号状态与操作故障必须分开：登录 `signed-in/signed-out/unknown`、安全验证 `required/not-required/unknown`、连接 `available/unavailable/unknown` 各自保留最近的明确观察。需要验证、超时、格式变化和未知错误不证明退出登录；没有配置或启用账号使用 `account-unavailable`（`AM-2003`），不伪装成已确认的 `not-authenticated`。

列表保留原请求的 `AppErrorState` 和发生位置（搜索、导入、后续页、重新加载）。验证操作独立使用 `idle/opening/waiting/confirming/restoring/failed/cancelled/complete`；其错误只更新验证操作，不覆盖原请求的验证需求。恢复能力来自当前列表运行时：能够确定具体账号并执行动作时才显示验证按钮；失败、取消或超时允许对同一账号重试。更换列表、账号删除或停用必须取消旧操作并忽略晚到结果。仅初始公开账号 ID 和名称写入保留的列表结果；实时账号状态、操作状态和恢复闭包均不持久化。

1. 先确认现有语义码不能准确表达新情况，避免仅因文案不同新增 code。
2. 在 `APP_ERROR_DEFINITIONS` 的所属编号段追加定义，并写明默认文案、严重级别和是否可重试。
3. 在平台或 feature 边界把原始异常映射为该错误；动态上下文放 `message`，原始异常放 `cause`。
4. 响应式或持久化状态保存 `AppErrorState`，组件只派生展示文案。
5. 增加目录测试和触发该错误的领域测试；如新增状态机分支，同时更新本页状态表。

`verification-required` 与 `pagination-unavailable` 必须保持独立：前者表示用户完成来源站验证后可以重试，UI 可以提供由用户主动触发的来源页入口；后者表示服务端暂时不给后续页，只保留已加载内容并提示稍后重试，不能误导用户去验证。

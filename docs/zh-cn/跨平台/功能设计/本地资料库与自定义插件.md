# 本地资料库、自定义歌曲与声明式插件

英文对应页：[Local Library, Custom Tracks, and Declarative Plugins](../../../en/cross-platform/features/local-library-and-custom-plugins.md)。

适用范围：共享资料库、配方与声明式来源。工作台通过稳定值存储端口保存业务后缀；Userscript 添加 `any-music:userscript:*` GM 命名空间，桌面使用独立快照与 Rust `product.json` 镜像。凭证与代理秘密属于运行端专属存储，不进入本页产品快照。两端存储不隐式合并。

## 1. 产品数据归属

宿主记录、标签关联和创作草稿各有唯一归属。挂载前初始化当前代次存储，仓库命名端口访问 `core`、`host` 和 `namespaces`。资料库仅接受 schema 6，下载历史仅接受 schema 2，不转换早期布局。参见[数据归属](../架构/插件数据归属.md)。

## 2. 标签与我的歌单

用户标签由内置 plugin-tag-management 的 feature.tags 命名空间唯一持有，写前执行 NFKC、空白折叠、长度限制与大小写无关去重。启用时向资料库视图投影搜索、筛选、排序和编辑能力；停用保留记录并撤下投影，休眠条件需用户显式恢复。来源自带标签仍是核心元数据。

“音乐列表”保留单曲添加或移除标签的轻量入口；独立的“标签管理”集中展示已有标签的歌曲，支持平台多选、按平台收缩或混合排列、歌曲搜索、多标签 AND/OR 筛选以及按维护时间、歌曲名称或标签数量排序。标签管理卡牌不提供播放操作，但可继续增删单曲标签，并支持全局重命名、合并和删除标签；“我的喜欢”与“我的歌单”只读取同一标签命名空间的受控投影，不提供重复的标签写入口。

用户歌单使用 `playlist:<uuid>` 命名空间，只保存曲目 ID 和顺序。平台合集仍由音乐源插件返回 `TrackListing`，两者不会混用。

“我的歌单”外层按歌单展示并支持名称搜索。展开单个歌单后，可像“我的喜欢”一样多选平台，并在按平台收缩和保留歌单顺序的混合排列之间切换；每首歌曲显式标注是否已喜欢。音乐列表和“我的喜欢”都支持选择多首歌曲后一次加入目标歌单，从外部列表加入时会先保存规范曲目，再原子写入歌单成员关系。

### 2.1 自定义音乐列表与素材合集

内置 `plugin-music-creation` 通过一个 `feature.composer` 开关统一持有“自定义音乐”和“片段创作”。当前构建配置 `unavailableReason`，模块启动即关闭，不允许激活、启用或加载编辑实现，恢复和重试也不会绕过限制。点击启用时，由共用顶部提示显示配置的开发中文案。已发布作品、素材和草稿仍保留，其他板块中已引用作品的宿主播放、下载仍可使用。后续构建移除限制后，两个板块共用启停生命周期，沿用稳定导航 ID 及已保存的顺序、可见性偏好。其他内置模块也可配置自己的原因，与仅用于展示的 `developmentStatus` 独立。

“自定义音乐”是独立于“我的喜欢”的作品列表。外层搜索覆盖作品名称、本地创作者、来源博主和素材合集名称；单个作品作为抽屉，展开后按普通资料库歌曲卡牌展示配方中的直接素材及使用范围。自定义歌曲不再依赖是否被喜欢才能出现在这里。

素材合集使用 `material-collection:<uuid>` 稳定 ID，只保存成员曲目 ID。一次新配方的所有直接素材必须属于同一个合集；同一曲目可以加入多个合集。自定义歌曲本身可以作为直接素材加入另一个合集，保存时再由片段编译器递归展开为普通平台音轨，因此编辑体验保留复用层级，播放和导出仍只有可即时解析的叶子来源。

从音乐列表、我的喜欢、歌单或自定义音乐点击“截取”时，曲目先进入持久化待整理区，而不是立即猜测目标合集。待整理区在切换板块和刷新后保留；用户选择合集并加入后，该 ID 原子地从待整理区移除。合集视图默认只显示其成员，并为每首素材显示普通音频、视频音轨或可复用自定义成品等性质，以及当前时间线是否已截取、片段数和累计时长。

创建作品后，成品自动加入创建时的素材合集。已用于该合集作品配方的素材不能直接移出。删除合集默认只删除容器并保留曲目记录；若合集已有作品，用户必须显式选择级联清理。级联操作删除该合集创建的自定义歌曲，并只删除未被喜欢、歌单、其他合集、其他作品或待整理区继续使用的原始素材记录；若合集作品仍被其他自定义歌曲引用则拒绝删除，避免产生无法编译的悬空配方。

## 3. 播放历史

选择曲目时创建一条历史记录，播放进度覆盖该记录。共享存储写入按一秒节流，避免 `timeupdate` 高频触发存储；切换曲目、播放完成或组件卸载时保留最新状态。用户可在全局设置中把保留上限设为 1～500；调小后立即裁剪最旧记录，读取快照时也按同一硬上限校验。

待听列表使用独立的 `playback-queue:v1` 业务后缀（Userscript 添加正式 GM 前缀；桌面写独立快照），只保存资料库曲目 ID 的顺序和播放模式。加入待听前先立即保存规范曲目，刷新后再通过资料库解析 ID；“我的喜欢”可把当前筛选与排列结果作为临时播放上下文，并复用顺序、单曲循环、随机和随机不重复模式，但不会用整个喜欢列表覆盖待听。当前选中项、播放进度、临时媒体 URL、临时播放上下文和随机洗牌袋不跨刷新恢复。

### 3.1 批量下载与下载历史

音乐列表、待听、我的喜欢和单个用户歌单都提供曲目多选与“下载已选”。应用只运行一个全局下载调度器；设置中的最高并发值限制为 1～5，并在每个批次开始时形成快照。单首歌曲首次失败后最多重试 3 次，某一首耗尽重试不会取消同批其他歌曲。“下载”板块统一管理当前任务和已下载记录，提供状态选择、歌曲操作、暂停、继续与重试。批量下载统一即时解析媒体并生成 MP3；多曲批次只触发一次浏览器保存，ZIP 内包含所有成功文件及完整批次报告，单曲批次仍直接保存 MP3。自定义歌曲仍从已编译的叶子时间线生成，短时媒体 URL 不会作为下载身份或历史字段保存。

下载历史使用独立的 `download-history:v1` 业务后缀（Userscript 添加正式 GM 前缀；桌面写独立快照），与有数量上限的播放历史完全分开。每次用户点击形成独立批次，永久保存发起板块与名称快照、批次起止时间、实际并发、完整 `Track` 快照、每次尝试的起止时间与错误、取消/最终状态、成功文件与最终 ZIP 的名称、MIME 和字节数；不自动裁剪。已下载任务保留在下载页，确认移除记录时保留已保存文件。浏览器不能读取用户最终选择的磁盘路径。若页面在下载中关闭或刷新，下次启动会把仍在运行的批次和尝试标记为“中断”，保留中断前已经写入的全部信息。暂停任务继续时重新解析媒体，不保留字节；字节范围续传、调整单曲优先级和刷新后自动继续下载仍未实现。

## 4. 片段编译与播放

编辑配方使用来源曲目的时间轴：

```ts
interface SegmentRecipe {
  sourceTrackId: string
  startMs: number
  endMs: number
}
```

保存时执行：

1. 校验 `0 <= start < end <= duration`；
2. 递归展开被引用的自定义歌曲；
3. 用访问栈检测循环引用；
4. 将嵌套区间映射回普通平台曲目的叶子区间；
5. 合并同源连续片段并生成虚拟前缀时间轴。

自定义歌曲优先按编译后的叶子时间线切成有界播放块，为当前窗口和多个后续块并发准备解码结果，并在同一音频时钟连续排程。范围内 seek 复用现有窗口；范围外 seek 取消旧会话并从目标块重建，连续拖动只允许最后一次定位接管。无法范围读取的来源回到普通播放通道，并预解析后续短时媒体描述；会读取 `complete-binary` 的来源在调用解析器前排除出后台预取。只有叶子流式通道失败后才允许可取消的会话级 MP3 渲染兜底。短时 URL、原始媒体字节、解码缓冲、渲染结果和 Blob URL 都不持久化。

编译器对一次配方中重复引用的自定义歌曲缓存完整子时间线；截取嵌套区间时先按 `virtualEndMs` 二分定位首个重叠叶子，再只扫描实际输出范围。时间复杂度为 `O(U + K + log N)`（`U` 为唯一展开子图，`K` 为实际输出叶子数），避免对重复素材反复全量展开。

选段和成品均可试听、下载。导出链路使用 [Mediabunny](https://mediabunny.dev/) 逐块解码叶子音频，并在进入同一个编码轨前通过流式标准化层统一为 48 kHz 双声道，再按时间线编码。标准化层只保留插值所需的解码块尾帧，支持 44.1 kHz、48 kHz 等不同来源连续拼接，不会创建一份整首未压缩 PCM 副本。当前提供：

- MP3：192 kbps，使用官方 `@mediabunny/mp3-encoder` 的 LAME WASM 扩展；worker 与 WASM 随消费端构建产物打包，不依赖运行时 CDN。
- WAV：16-bit PCM；Mediabunny 内置 PCM 编解码，不依赖浏览器的有损编码器能力。

一次导出内每个唯一来源只解析、下载一次，远程字节通过注入的运行端 HTTP 读取（Userscript GM / Tauri IPC-Rust 与媒体 grant），内置源保持所属平台账号身份。 所有解析结果、媒体字节、Blob URL 与导出文件都只存在于当前会话，不写入资料库快照。

自定义拼接作品把两种身份分开保存：

- `creator`：本地设置中的稳定用户 UUID 与显示名，表示真正创建拼接作品的人；
- `sourceCredits`：从编译后的叶子片段收集并去重的 `pluginId + artistId + artistName`，表示 B 站、抖音等原始来源博主。

因此跨平台拼接不会把多个来源账号哈希成一个不可解释的“作者”，未来导入/导出时也能同时保留作品创建者和原始内容署名。修改本地显示名不会改变稳定用户 ID。

## 5. 原生插件包

Tauri 通过原生字节验证、显式同意和精确目标准入预览、安装 `.amplugin`。静态及代码目录提供分页元数据，目前不解析媒体；代码目录使用匿名有界原生 HTTPS，不借用账号 Cookie/代理。油猴端仅支持内置插件。参见[S15 能力矩阵](../架构/插件系统重构S15工具与桌面交付.md)及[运行策略](../架构/插件运行策略.md)。

## 6. 外置音乐源设置

Tauri 将“外置音乐源”（`feature.external-sources`）注册为可开关的内置插件，沿用现有模块偏好与安全启动恢复。插件启用且运行端提供原生包端口时，设置 → 音乐源新增“外置音乐源”，支持公共 HTTPS 插件包地址和本地 `.amplugin` 文件导入，以及原生预览、授权和已安装包管理。文件上限为 16 MiB；接口须返回标准插件包，音乐源包须声明 `music.sources` 贡献。可用操作仍由原生校验和目标准入决定；Android 端口仍仅提供预览。

停用插件会移除设置入口和音乐源管理中的“外置音乐源”分组，卸载已访问的导入表单，释放临时预览并取消在途命令和目录分页。已安装包、授权与产品记录保留；重新启用只注册当前原生目录快照，不重放查询。Userscript 的外部策略保持 `none`，不提供该模块或导入入口。

## 7. 验证

覆盖当前版本校验、损坏记录、标签/创作独立归属、可移植数据冲突及预算、逐写入中断恢复、来源生命周期竞争、配方编译与媒体取消。下载覆盖并发、重试、取消和刷新中断；原生插件包独立覆盖同意、预算及撤销。真实 GM/IPC/播放验证须明确请求。

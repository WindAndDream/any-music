# 跨端界面与交互规范

英文对应页：[Cross-Platform UI and Interaction](../../../en/cross-platform/features/cross-platform-ui-and-interaction.md)。

## 1. 文档状态

本文定义 Any Music 正式产品 UI 的长期视觉与交互契约。当前正式消费端为 `apps/userscript` 与 `apps/tauri`，共用 ui/music-workbench。Userscript 使用宿主页悬浮/Shadow 布局；桌面使用 embedded 布局和原生端口。移动原生适配尚未验收，手机网页布局不代表移动原生能力。

正式 Userscript 已具备原生启动器、首次展开后加载 Vue/Pinia 的产品壳、可换边/收起的导航、浅色/深色/跟随系统主题、导航顺序与可见性偏好、移动抽屉/可选底栏，以及共享的音乐源、播放、资料库、片段、下载、历史和插件功能模块。经典外壳／播放器、来源／搜索／目录及资料库／待听／历史／下载展示由 `packages/theme-default` 维护；中性契约、基础组件、无界面交互及受保护宿主 UI 归 `packages/ui`，Userscript 从 music-workbench 消费公共业务，只装配 GM/浏览器能力。它已经是后续产品开发基线，但仍需真实宿主页视觉回归、触摸设备验证和发布体积验收，不能仅凭源码存在认定为发布完成。

T11 应用现已通过构建已知元数据、加载器和明确经典回退，组合独立的经典／工作室完整根组件。唯一稳定工作台／控制器／音频持有业务及编辑状态。共享／SFC／主题 CSS 字符串进入内部展示 Shadow 曲面；受保护账号／原生控件及其详情弹层目标留在独立宿主样式曲面内。正式加载图审计和 Node 加载器／宿主测试属于自动化证据，真实视觉／焦点／已安装运行端验收仍归 T13。

## 2. 设计原则

- 内容和音乐操作优先。层级主要依靠留白、字号、字重、表面色和少量阴影，不添加没有信息或交互意义的装饰。
- 三端保持相同的领域词汇、导航标识、主题 token、状态语义和操作结果；布局与输入方式遵循平台习惯，不要求像素一致。
- 每个状态都应可理解：加载、空、不可用、过期、校验失败、部分成功和可重试不能只依赖颜色表达。
- 图标来自统一的 `AppIcon` 目录；按钮提供可访问名称。不得使用 Emoji、Unicode 符号或文本字符临时代替产品图标。
- 第三方图片由运行端统一远程图片组件显示，默认不发送 Referer，并提供稳定占位。

### 3.1 圆角层级

产品壳、全局设置、音乐列表与搜索/歌曲列表采用偏方但保留柔和转角的轮廓。按元素用途选择圆角，不因卡片更宽或移动布局而增大圆角；层级主要依靠留白、表面色和边界表达。

| 用途                                      | Token                 | 圆角 |
| ----------------------------------------- | --------------------- | ---- |
| 状态标签、计数、统计字幕和紧凑标签        | `--am-radius-detail`  | 4px  |
| 普通按钮、输入框、选择器和分段按钮        | `--am-radius-control` | 6px  |
| 封面、列表行和选项行                      | `--am-radius-sm`      | 8px  |
| 音乐列表/歌曲卡片、设置分组和分段控件外框 | `--am-radius-card`    | 10px |
| 内嵌面板和空状态                          | `--am-radius-panel`   | 12px |
| 产品壳、弹窗和底板外框                    | `--am-radius-overlay` | 14px |

嵌套元素的圆角应小于外框，贴边按钮随外框边界衔接。普通文字按钮和状态标签不使用胶囊形；开关轨道、滑块、圆形播放键、拖拽提示条及小圆点保留功能性圆形/胶囊。全屏表面、连续列表的内行与既有底线输入框保留直角。圆角调整不缩小点击区域，也不裁切键盘焦点环。

上述圆角角色用于已设计页面与共用壳层/浮层，也适用于插件中心的卡片、控件和数量标签；收藏、歌单、资料库、创作和下载等业务页面保留原有尺寸 token。跨页面复用的歌曲卡片和封面通过当前列表的局部样式调整，后续设计其他板块时再按用途接入。

### 3.2 滚动条

`.am-root` 内所有可见滚动条（包括后续新增的滚动区域）统一采用 `@any-music/ui/styles` 的默认样式。Chromium/WebKit 使用 6px 轨道、实际可见宽度为 4px 的圆角滑块、透明轨道并隐藏箭头按钮。滑块默认使用主文字色的 20% 不透明度，鼠标悬停或拖动时提高至 36%，通过 `--am-color-scrollbar-thumb` 和 `--am-color-scrollbar-thumb-hover` 跟随深浅主题；`--am-size-scrollbar` 统一控制轨道宽度。

不支持滚动条伪元素的浏览器使用标准细滚动条，在鼠标经过滚动区域时增强滑块对比度。两种实现分支保持独立，因为标准滚动条属性的非 auto 值会覆盖 Chromium 的伪元素样式。新组件自动继承共享默认值，无需单独设置滚动条尺寸或颜色。既有刻意隐藏的滚动条保留原有行为，强制颜色模式使用系统原生滚动条。样式仅作用于产品根节点，不影响 Userscript 所在宿主页。

## 4. 产品壳与导航

### 4.1 网页、Tampermonkey 与桌面

宽屏采用 Grid 产品壳：可换到左/右侧并可收起的导航、顶部上下文栏、滚动内容区和播放时出现的底部播放器。导航顺序与可见项由用户配置，设置入口固定在导航底部。Tampermonkey 额外保留显示/隐藏产品的入口；隐藏只改变可见性，不应静默丢失正在播放或下载的会话。

侧栏位置决定系统导航与移动端抽屉的左/右侧位、对应的展开/收起箭头，以及移动端抽屉入口的位置。移动端入口位于经典主题顶栏中与抽屉同侧的左边缘或右边缘，没有来源上下文的页面也遵循这一规则。桌面顶栏、吸顶返回栏、歌曲卡片、批量操作栏与设置控件均保持固定排列，不根据侧栏方向镜像；内容区仍随壳层轨道正常让出空间。经典主题顶栏文案区只显示左对齐的当前页面标题；移动端入口换边时，标题和来源上下文保持原有阅读顺序。

中等视口（768px < 宽度 ≤ 1024px，按浏览器 CSS 像素计算）默认只显示侧栏图标，但展开按钮必须在第一次点击时展开，再次点击收起；当前断点内的手动操作优先于自动收起，跨断点后恢复对应布局的默认规则。自动收起不改写桌面持久偏好，手动操作保存用户选择，按钮文案和辅助技术状态跟随实际展开状态。开合时保留图标列、品牌行高度和文字节点。桌面壳层的侧栏轨道使用 `--am-motion-normal` 和 `--am-ease-emphasized` 平滑伸缩，顶栏、内容区与播放器同步移动，文字配合淡入淡出，保持单行且导航无横向滚动。侧栏换边或进出移动布局时立即就位；减少动态效果模式停用侧栏和文字过渡。

“自定义界面”的界面主题、侧栏位置与明暗主题由显示当前值的按钮打开选择弹窗，当前选项先获得焦点，选择后立即应用并关闭；选择弹窗打开期间，底部设置面板暂停模态交互，关闭后焦点返回触发按钮。移动端底部导航使用有明确开启/关闭状态的按钮，开关按钮固定在说明文字左侧。导航排序在桌面保留加宽的上下移动按钮；移动布局只保留 44px 方形拖拽手柄，名称居中间，可见/固定显示状态靠右。手柄始终支持空格或回车开始排序、方向键移动及完成/取消的键盘等价操作。

控制栏的播放顺序与待听、喜欢、歌单等页面使用同一队列设置，提供顺序播放、单曲循环、随机播放和随机不重复；从歌单点播时按该歌单的曲目顺序建立播放上下文。播放顺序、音质、倍速与音量由按钮打开弹窗调整；当前歌曲尚不可跳转时，进度条显示禁止操作的指针。按钮文案和曲目信息在收窄时保持单行或省略，不能被挤压换行。

控制栏和完整播放器的下载入口复用共享下载管理器，每次点击在顶部提示中展示歌曲名与该歌曲当时的排队、下载中、已下载、失败、取消或中断状态，保持当前页面与焦点，不打开模态弹窗。提示复用操作器的 AppToast、状态色容器与 AppIcon：已下载为绿色勾选，排队/下载中为蓝青色时钟/下载，暂停为琥珀色暂停，中断为琥珀色警告，暂不可下载为琥珀色时钟，失败为红色警告，取消为灰色关闭图标；颜色随浅色/深色主题切换。普通状态与成功提示 3 秒后消失，失败提示 5 秒后消失；重复点击立即替换提示并重新计时，后续进度变化不自动弹出提示，也不在控制栏或播放状态中常驻下载消息。已有进行中的任务时避免重复提交；已保存记录仍允许重新下载，运行端校验保存文件后才能跳过。暂停、失败、取消和中断后的下一次点击也可重新开始下载，包括取消保存文件（AM-1005）。文件生成后仍须等待整批保存成功才能提示已下载，取消或保存失败不能误判为成功；旧任务晚到的结果不能覆盖新任务或其他歌曲。暂停任务可在下载页明确继续，重新获取媒体并保留原任务记录。

PC 控制栏沿用曲目信息、播放控制、设置操作三列布局，左右列等宽，让播放区对齐整条控制栏的水平中心；按播放器插槽宽度收敛为两行或三行后，播放区仍限宽居中。移动分页包装在桌面不建立布局盒，不能占据其中一列或继承旧共享样式的两列定义。只有手机进入分页视口与滑动布局，桌面保留原有按钮尺寸和胶囊反馈。

待听复用发现的歌曲卡片、展示密度、移动列数、背景区域色和克制圆角，顶部标题采用与 catalog-page__context 相同的字号和 44px 标题行，标题与歌曲网格共用横向留白，默认按真实播放顺序展示。待听内容和上方区域使用内嵌灰色表面，外框及歌曲项横向留白与发现中的歌曲页一致，不设额外宽度上限，表面默认占满页面可用高度，内容较多时自然增高，四周及底部沿用现有页面背景与留白。桌面歌曲总数使用主题色数量徽标和加粗数字；手机移除内容区介绍标题，在最顶部右侧显示完整待听歌曲总数。平台和账号上下文仅在发现展示，其他功能页不沿用该上下文。“全部歌曲 500ms 后进入拖拽状态并显示浮起描边，顶部同步显示带排序图标的青蓝色信息提示“已进入拖拽排序，移动调整顺序，松手完成。”；每次成功进入只提示一次，3 秒后自动消失，不抢焦点或拦截拖动；长按激活后的歌曲、平台卡片、子控件与内容间隙统一显示四向移动光标，松手或取消后恢复原有光标；等待期间移动超过 8px 才进入整组拖拽，成功进入后复用同一顶部信息提示和取消规则，松手后的合成点击既不改变选择也不打开平台详情；网格不额外叠加内边距，标题和两侧控件与歌曲项边缘对齐，容器约束横向排序位移溢出；平台排列下歌曲在组内排序，平台区块也可整体排序。手机端保留相同操作，不叠加第二层侧抽屉。

按平台排列时，待听中的本地拼接作品独立显示为“自定义音乐”分组，使用片段图标、主题色标题和“本地拼接”文字标记，与同名音乐源区分；分组身份依据稳定来源标识与媒体类型，不依据显示名称。分组右侧按实际播放器曲目与状态显示“正在播放”或“已暂停”，窄容器、平台概览及歌曲详情仍保留标记。仅选中歌曲、正在解析、播放失败或试听待听以外的曲目时，不借队列选中项显示播放标记。

待听在播放器上方提供与发现页相同的“筛选器 / 操作器”和数量摘要、返回顶部入口。返回顶部直接定位壳层内容滚动区，不通过惰性功能组件实例调用；切页、隐藏或打开模态面板中止旧滚动。非模态歌曲操作器默认提供加入歌单、下载已选、添加待听、添加喜欢四个动作；全选匹配歌曲独立放在上排。已选歌曲全部在待听或喜欢中时，隐藏对应添加按钮；无选择时保留四个禁用入口。待听操作器在第二位展示红色“移出待听”，位于加入歌单之后、下载已选之前，无选择时禁用；确认后批量移出已选歌曲，不删除资料库记录。全选和取消全选复用顶部提示，分别展示已选歌曲数量和“已取消选择”。单曲操作保留原有移出入口。筛选器复用独立草稿、概览、历史、日期日历和预览，提供文本、用户标签、歌曲时长、平台、添加时间五个维度；不同维度取交集，同维度的多个标签、平台或时间区间取并集，结束日期包含当天。进入平台详情后，外层导航已经限定平台，筛选器隐藏平台维度，标签选项和预览数量只统计当前平台的歌曲。添加时间记录真正入队的时刻，重复添加、排序、刷新不改写，移出后重新加入记录新时间。旧 v1 快照缺失添加时间时保留歌曲并显示“添加时间未知”，有日期条件时不匹配，不用资料库时间或来源发布时间代替。取消丢弃草稿，应用才改变列表，隐藏的已选歌曲退出选择集合。

筛选后仍允许排序：歌曲只在匹配项原有的槽位内重排，未匹配歌曲保持原位；平台拖动按匹配平台的槽位移动完整区块，未匹配平台保留相对位置，组内顺序不变。置顶与键盘移动也遵循当前匹配集合。拖动开始时测量固定槽位，外层维持布局，内层卡片浮起并随指针叠在其他项上方，邻项柔和让位；命中不读取动画中的卡片位置，避免反复交换。松手仅持久化一次，再从松手位置落位，避免重复叠加 FLIP 动画；原路拖回、Escape、指针取消、筛选或队列变化、窗口尺寸变化、切页和卸载都撤销未提交的预览。稳定列表容器持有指针捕获，命中检测和边缘自动滚动每帧最多处理一次，位移动画使用 transform，屏外卡片保留 content-visibility，浮起项保持可见，不为全部卡片常驻 will-change；减少动态效果时关闭位移动画。本次没有进行真实宿主页、桌面窗口或触摸设备的视觉与帧耗时复测。

我的喜欢与待听共用歌曲网格、平台卡片、平台详情导航、展示密度、手机列数、筛选器、操作器、返回顶部和拖动排序。桌面显示“我的喜欢”与歌曲数量，手机将总数放在顶部；介绍、空态、平台摘要、筛选与批量操作使用喜欢文案。日期显示和筛选使用真实喜欢时间，不使用入队或发布时间；筛选历史与数量设置独立归属我的喜欢。默认按最近喜欢排序，手动顺序与排列偏好仅保存稳定曲目 ID，独立于待听，不改写喜欢时间。取消喜欢后移除该顺序记录，重新喜欢作为新加入处理。歌曲点播使用当前筛选及平台范围作为临时播放上下文；单曲操作保留待听切换，排序行与待听一致，依次为后移、前移、置顶；批量操作复用统一的四个歌曲动作，选中喜欢歌曲后隐藏添加喜欢；操作器在第二位展示红色“移出喜欢”，位于加入歌单之后、下载已选之前，确认后批量取消已选歌曲的喜欢状态，保留歌曲资料和歌单关系；单曲操作保留原有入口。全选和取消全选与待听共用顶部提示。没有进行真实浏览器、桌面窗口或触摸设备的视觉复测。

当前正式导航的稳定目的地为：发现、待听、我的喜欢、我的歌单、自定义音乐、标签管理、片段创作、下载、播放历史和插件中心。下载页通过“已下载”查看保存记录，不再提供独立的下载历史板块。“自定义音乐”与“片段创作”属于同一个可选 `feature.composer` 插件，统一启用或停用。未来改文案时保留稳定 ID，持久化边界必须丢弃未知值、补入新增必选项并阻止隐藏核心入口。

播放历史与“我的喜欢”共用经典主题的集合外壳、标题与计数字号、平台卡片、展示方式、空状态、歌曲行和操作器，替换为历史文案并保留独立筛选范围。同一首歌的每次播放都是独立可选的记录，展示播放时间和进度。文本、用户标签、时长、平台和日期筛选作用于每条记录，日期使用实际播放时间。操作器可选择当前可见记录，提供歌单、下载、待听、喜欢操作，以及播放已选和清空历史。歌曲操作弹窗保留四个常用操作，在右侧追加“清空历史”，复用操作器横向操作栏，支持溢出箭头、触摸滑动和鼠标横拖。清空前需要确认，不删除喜欢、歌单或下载记录；发起确认的展示实例被替换后，旧确认不能继续清空历史。运行端布局和设备验收仍未完成。

### 4.2 移动端

Android 系统返回键先返回当前弹窗或设置页的上一级，再关闭浮层、收起完整播放器、退出集合详情，最后回到上一个访问的板块。账号编辑页返回账号详情，账号详情再返回所选平台的账号管理；显式关闭按钮仍关闭整个弹窗。板块访问记录仅在本次会话保留，最多 64 条，跳过已隐藏或撤回的入口；缓存中未激活的页面不能处理返回键。

没有可返回的页面或浮层时，第一次返回在顶部显示随主题变化的提示“再按一次返回键退出应用”，两秒内再次返回才通过 Tauri 结束 Android Activity。超时、导航变化、完成点击或前后台切换都会重置退出确认；取消的指针序列不重置，避免系统返回手势无法完成二次确认。原生退出权限仅授予 Android 主 WebView。上述行为由离线测试覆盖，实体返回键与手势仍需单独进行设备验收。

窄屏顶部的抽屉按钮跟随用户所选的侧栏位置，抽屉从同侧展开。可选底栏包含“发现”“喜欢”“歌单”“我的”，与侧栏共享激活状态；播放器、底栏和安全区高度必须共同参与内容区留白。

跨过 768px 移动断点时，桌面侧栏与关闭的抽屉立即切换，不能触发抽屉退场或延迟隐藏，以免侧栏在重新排版时闪现。只有同一移动布局内的抽屉开合使用滑动与淡入淡出；跨断点或换边时终止这类过渡，减少动态效果时立即切换。

完整播放器通过按住曲目信息或空白区域向上拖动，或明确的展开按钮进入底部面板，并始终保留键盘/辅助技术可触发的等价路径。面板跟随纵向位移逐步露出，慢速拖动不依赖速度或长按计时器；松手前可反向拖回取消，松手时按位移阈值展开或回弹。展开后顶部、标题和空白区域都支持下拖收起，短距离下拖回弹，保留收起按钮和 Escape；按钮、链接与进度条独占各自输入，短屏内容滚离顶部后先正常滚动。支持拖动的控制栏区域显示抓取指针，拖动时显示抓取中指针。详情去掉大封面，将歌曲标题和作者放到顶部，只在状态有独立信息时显示状态行，不重复作者。移动端不能静态打包桌面专属导航、完整操作器和重型时间线后再以 CSS 隐藏；未来 Tauri 移动应用需要独立入口和动态功能边界。

手机控制栏以等宽左右区域将上一首、播放/暂停、下一首整组水平居中，左侧封面与曲名、作者各自缩短，文本保持单行省略。控制页保留顶部进度条的独立热区，并增加底部手柄前的留白，让控制组稍微上移。控制栏上边缘为细进度条，已播放部分的前端带圆点，圆点在两端完整可见；提供独立的 44px 触摸热区、缓冲显示与键盘跳转。横向拖动预览时间，松手仅提交一次跳转，纵向或取消手势不跳转。进度热区与展开输入隔离，水平分页和纵向展开在初始位移后锁定方向，不能因中途拐弯同时触发。

搜索/导入列表与歌曲列表共用外层内容宽度和横向留白，按实际内容宽度自动分配列数，不设单行数量上限。卡片的搜索词或链接摘要统一占两行，长文本省略，同一行卡片高度与操作区对齐；时间行只有实际文字保留复制语义，剩余空白区域仅在操作器模式下可选择卡片并显示可点击指针。重选播放器当前歌曲时保持播放上下文，使用共享顶部提示反馈；提示展示 2.2 秒后退场，240ms 退场与 600ms 冷却期间忽略重复点击，不堆叠、排队或延长展示，不抢焦点。

移动迷你控制栏始终保留上一首、播放/暂停和下一首；窄屏下鼠标左键横拖与触摸滑动共用分页，滚轮或触控板向前滚动显示设置、反向滚动返回，惯性输入每次只翻一页，缩放手势不参与分页；右滑或点击边缘渐隐的磨砂箭头显示播放顺序、音质、倍速、音量和下载，左滑或点击返回箭头回到曲目控制。箭头保持透明点击表面，在周围铺设随主题变化的模糊渐隐层，不使用实色胶囊背景。两页通过水平位移连续切换，离场页立即停止接收焦点和点击；减少动态效果时关闭位移动画。设置与下载按钮统一使用圆角矩形反馈，移动触摸区域至少为 44px。水平手势不能误触落点按钮，取消或离开移动布局时释放指针捕获。上滑后的完整播放器也提供这些设置、下载和 10 秒跳转，且弹窗打开时背景播放器暂停接收焦点。

## 5. 页面与操作模式

集合展示设置分为“风格选择”和“排列方式”（卡片密度／手机列数）。点击分类横向滑入对应选项，返回后重新显示可扩展的分类列表。发现中的搜索／导入项统一使用默认卡片，不提供风格选择或独立风格偏好；音乐卡片初始风格为“留白”；“直显”（存储值为 `default`）将常用按钮直接显示在卡片中。每个板块通过运行端命名空间下的 `collection-display:*:v1` 独立保存卡牌风格，与各区域的排列偏好分开；歌单概览统一使用封面卡片，只提供排列方式，全局默认设置保持一致。切换密度、平台分组、下载状态或完整主题不覆盖卡牌风格。插件中心保持现状。

`packages/card-styles` 持有可复用的受控卡牌和轻量风格元数据；`packages/ui` 单独持有分类与选项弹窗。完整主题适配只读播放位置并转发操作意图，工作台持有保存、播放和下载业务。“留白”音乐风格覆盖发现、待听、我的喜欢、歌单歌曲、下载和历史：封面提供播放入口，悬停／键盘焦点显示带动画的黑色遮罩，操作收进三点菜单，批量模式显示选择框。主题主色边框展示当前歌曲真实播放位置，不创建逐卡计时器；跳转、循环和密度切换复用同一时钟，播完回到起点。触屏始终可见播放入口，减少动态效果时关闭过渡。歌曲已有标签使用共享标签块展示在时长／任务状态右侧，最多单行，溢出隐藏。音乐卡牌省略日期／上下文文本，下载保留任务状态，历史记录身份与详情保留在选择／操作中。支持排序的集合继续提供封面长按与方向键操作。

发现中的搜索／导入卡片直接显示常用操作。PC 保留搜索／导入时间，视口宽度不超过 600 CSS 像素时隐藏时间行，缩短移动端条目高度。状态预览保持有界，完整错误沿用宿主错误详情弹窗。批量选择、操作菜单、长按和方向键排序继续可用。

“留白”音乐风格在宽列表中使用横向封面与下方文字，封面高度最多 200 CSS 像素，宽松排列提高至 240 像素，让卡牌稍微高一些。列表宽度不超过 600 CSS 像素时改为横向条目，使用 72 像素方形封面；单卡宽度不超过 260 CSS 像素时保留小卡片，为手机双列中的文字留出足够宽度。悬停时仅在封面裁剪框内放大图片，减少动态效果时关闭缩放。实际正在播放的歌曲在悬停／键盘焦点时显示波形标识并提示“正在播放，点击暂停”，点击通过宿主播放器暂停；暂停后显示播放图标，再次点击从原位置继续，不重新解析媒体。批量选择框覆盖在封面上，显示或隐藏时不改变卡牌高度与文字排版，沿用直显风格的原生勾选框与透明的 44 像素点击区域。选择模式下点击封面仅切换勾选，正在播放或已失效的歌曲也遵循同一规则，鼠标悬停、键盘焦点和触屏均不显示播放遮罩；关闭操作器后恢复封面播放。支持排序的集合在两种模式下均保留长按和方向键排序。

歌单统一使用封面卡片，不提供风格选择；歌曲网格密度与受控卡片保持共用，宽列表中上方为横向封面，下方为较大的名称及一行截断标签。曲数在悬停或键盘聚焦时显示于封面右下角的阴影角标中，触屏持续显示。封面不显示序号，菜单保留独立悬停背景，继续支持预览、选择与排序。Node 测试覆盖设置隔离、宿主投影、进度归零和操作意图，不能证明浏览器、GM、WebView 的布局、焦点或真实输入验收。

- 来源在设置中停用时使用 `disconnected`，卸载使用 `missing`，已有歌曲、筛选和收藏保留，暂不加载新歌曲。空闲列表使用中性静态提示，不因旧错误自动弹窗；正在加载或验证的列表取消旧任务、忽略晚到结果，并保留“加载已中止”状态供用户主动点击查看。重新启用不会重复提示或自动请求，用户重试时从第一页重建。空闲列表停用时保留现有游标，启用后继续按需消费。无歌曲时查看按钮禁用；来源仍启用但有效性检查失败继续使用实际错误处理。受影响的播放恢复空闲，相关下载和导出中止，保存的列表、歌曲和待听保留。
- 歌曲列表中的平台和实际请求账号只读，发现页的账号偏好只影响新操作；桌面自动模式显示“随机”。账号删除或停用后，空闲列表下一次加载自动选择可用账号并重建第一页；正在加载时在列表中保留中止错误供主动查看，重试时重新选择，无可用账号则提示到设置中添加。列表标题全文按钮保留左右内边距，测量宽度扣除同样的留白。音乐列表操作详情的加载概况与置顶状态并排展示，窄屏允许概况文字换行。经典主题的列表重命名在同一操作弹窗内横向滑入，复用歌曲名称表单：上方为自定义名称，下方按类型显示“搜索原名”及完整搜索内容，或“导入来源”及完整导入链接。返回放弃草稿；保存修改后的非空名称（最多 80 字）后返回列表操作，不改变原始请求。置顶与取消置顶按稳定列表 ID 读取当前状态，操作弹窗关闭后也能正确切换。
- 顶部错误栏只显示可点击的错误提示，不额外放置“错误处理”“查看详情”或来源跳转按钮；点击整条提示打开“音乐列表错误处理”。账号验证和重试操作统一留在弹窗内。移动端的错误弹窗操作按钮按文案和舒适的最小宽度排列，空间不足时换行，不拉伸铺满每一行。
- 错误弹窗在等待账号验证和重新加载第一页时使用中性进度摘要，隐藏旧错误代码；重新加载期间不显示旧处理指引或“当前列表暂时无法继续加载”的兜底警告，只有重新加载失败才重新显示实际错误。已恢复的验证错误在运行端提供恢复能力时首次打开就显示“验证”，无需先点重试。桌面的“验证”按钮与篡改猴来源验证入口使用相同的表面色和描边样式，保留“重试”为实心主按钮。“重试”表示再次尝试加载；需要登录或安全验证时先完成对应操作，再重试。桌面验证指引中，关于验证完成前重试仍可能出现相同错误的提示加粗显示。验证通过后的自动加载使用“重新加载”提示。“恢复原名”和“恢复筛选历史”继续表示还原已有内容。
- 自定义音乐的详情优先使用底部面板。下载歌曲复用统一的歌曲操作弹窗，补充当前任务控制与确认移除记录。卡片/列表切换只改变展示，不改变数据身份。
- 片段创作保留可访问的排列模式；剪辑时间线是增强模式，需要同时支持缩放、重排、片段详情和键盘替代操作。引入时间线库前必须评估体积、触摸、可访问性、维护与许可证。
- 下载页提供全部、下载中、已暂停、已下载、下载失败状态选择。待听、我的喜欢与下载按板块及区域独立持久化展示偏好：全部歌曲、各平台详情、各下载状态互不影响；未设置的区域桌面默认第二项标准密度，手机默认第一项一行一个。当集合实际宽度不超过 760px、排列选项需要占满一行时，或宿主已进入手机布局时，仅保留一个展示图标按钮并移到筛选器左侧，与筛选器保持 36px 等高；宽列表保留顶部入口。侧栏引起的桌面内容区变窄也遵循相同规则。下载封面长按 500ms 后复用待听、喜欢的拖拽排序，短按仅在操作器模式下选择，方向键在两种模式下均可逐项移动。拖拽生效后使用十字移动光标，松手、取消或卸载时恢复。下载顺序仅独立保存稳定任务 ID，不改变批次归属和调度准入；筛选后排序保留隐藏项位置，进度更新不重置顺序。发现与下载顶部均复用操作器的无滚动条横向按钮栏：溢出时右侧出现箭头，点击前进，到末尾后可返回开头；尺寸或按钮数量变化时重新判断。状态和展示按钮在悬停、键盘聚焦时有背景反馈。灰色集合背景、白色空状态、歌曲行及筛选器/操作器入口与其他集合一致。蓝色数字区显示“2 并发”，数字在前，字号和字重与待听、我的喜欢保持一致。筛选包含文本、用户标签、时长、平台和任务日期，历史独立保存。下载按稳定歌曲 ID 保持跨批次唯一，再次提交复用任务 ID 和尝试记录，并替换原列表项。操作器支持继续暂停任务、重新下载已下载或失败歌曲、暂停活跃任务、取消所选排队/下载/暂停任务，以及确认移除记录而保留已保存文件。混合选择显示“下载”，处理可操作任务；只选已下载歌曲时显示“重新下载”。取消会清除待自动继续的任务并中止媒体和重试流程，保留可重试记录；已取消记录归入“已暂停”筛选并明确显示已取消。行内按钮随任务状态变化，末尾为“操作”；状态保留在歌曲信息和操作弹窗内，不再单独展示底部进度区。文件生成后仍须等待保存确认，部分批次重试不会改变已保存歌曲的成功状态。原生重新下载先在当前保存目录核对精确文件名、字节数与完整 SHA-256，同一 ZIP 文件每轮只流式校验一次；复用凭据前还需确认导出标题、配方与创作者一致。文件缺失、改名、内容变化或没有可信指纹时重新下载，仅内容相同但名称不同不能跳过。单曲仍保存 MP3，多曲仍保存 ZIP；ZIP 校验针对保存的压缩包，不检查另行解压的文件。Userscript 无法读取磁盘目录，允许重新保存而不声称已校验本地文件。
- 暂停会中止读取/编码，资源清理完毕后释放并发名额，并保留任务身份、尝试记录和明确提交的试听配方。继续时重新解析媒体，不保留媒体字节，也不表示 HTTP 字节断点续传。桌面和 Android 注入 Rust FIFO 信号量控制整首任务准入，篡改猴使用前端 FIFO；重试策略和受信浏览器编码器仍由共享层持有。刷新/挂起取消临时任务，不自动重放；中断任务由用户明确重启。优先级调整和字节断点续传尚未实现。
- 插件中心按运行端呈现：Userscript 管理内置功能/来源；Tauri 通过原生验证、显式审批及目标准入管理 .amplugin 包。安装预览、命令/目录和授权状态使用固定宿主界面；无媒体能力时明确不可用。

所有带操作入口的音乐项均在“自定义名称”下方提供“添加歌单”。其子视图与操作器中的加入歌单弹窗复用“我的歌单”的封面、信息、卡片尺寸和勾选框位置，歌单项只允许勾选。可滚动列表提供展示方式和筛选器；控件行左侧仅显示“已选 N 个”，右侧依次为展示方式、筛选器和全选。三个按钮在桌面与手机均采用外部操作器入口的 12px 字号和 36px 高度，全选勾选框为 16px；窄布局中展示方式使用 36px 图标按钮。容器宽度不超过 320px 时，第一行将已选数量和展示方式分列左右，下方筛选器和全选各占一半宽度。全选只切换当前匹配歌单；全部匹配项勾选时背景变蓝，否则恢复默认，单项变化立即更新按钮状态。筛选保留其他已勾选目标，计数和最终提交包含全部已勾选歌单；各目标只追加缺少的歌曲，已有歌曲保持原位。明确返回或关闭重置草稿，主题切换保留进行中的编辑。经典与 Studio 共用无界面选择逻辑，各自拥有展示布局。Node 测试覆盖选择和事件传递，真实布局与焦点验收单独执行。

标签管理以标签目录为主，左上角显示标题和标签总数，展示方式位于筛选器左侧。工具栏左侧提供“音乐标签 / 歌单标签”切换，复用“我的喜欢”的分段按钮样式；两类视图共用标签目录及全局重命名、合并、删除规则，关联数量、平台统计、单位和关联列表按当前类型分别计算。标签可直接创建，也可从歌曲或歌单操作中添加。“默认撑满”按名称长度决定标签宽度，最多占一整行；后一个标签最多使用当前行剩余宽度，超出文字省略，前面的标签与末尾短标签均不拉伸。剩余空间不足 44px 热区时才从下一行开始。“单独一行”让每个标签独占一行。名称保持单行，过长时省略并提供完整文本提示。经典主题标签统一使用浅色主题的白色表面背景，选中时保留相同背景并使用主题色描边。普通点击打开标签信息，顶部为基本信息，下方为“修改标签”“覆盖平台”“关联音乐”三个带图标和辅助说明的入口，沿用歌曲操作弹窗的间距与控件样式。点击入口横向滑入子视图，提供返回操作；离场内容立即禁用交互，并尊重减少动态效果设置。修改标签支持重命名和确认删除；覆盖平台以只读标签样式列出各平台歌曲数量及合计；关联音乐复用各主题的响应式歌曲列表、筛选器与展示方式，提供选择而不启用播放或内容编辑；关联歌单显示可勾选的歌单封面项。两类列表统一展示方式、筛选器和全选按钮的尺寸、排列及筛选数量提示，状态文案仅显示“已选 N 个”，全选在鼠标经过时保持默认或选中样式；音乐项复用原有选择控件与响应式勾选框位置，不启用播放或内容编辑操作。全选仅切换当前匹配项并保留筛选范围外的选择。弹窗随内容自然增高至可用视口上限，外层内容不滚动，仅内部列表溢出时显示滚动条；返回和红色“移除标签”按钮放在弹窗固定底栏，未选择时禁用移除。移除数量区域平滑展开和收起，位数变化也会过渡，并尊重减少动态效果设置。移除前确认选中数量，仅解除当前标签与选中音乐或歌单的关联，一次写入标签命名空间并保留其他标签、关联和实体；取消或写入失败保留选择。超过四项时桌面端宽度可扩展至 1440px。空歌单计入关联数量但没有来源平台；跨平台歌单在标签总数中只计一次，在每个覆盖平台中分别计一次。浏览条件、展示和关联项选择在返回概览和主题替换后保留，明确关闭标签信息或切换标签时重置。开启操作器后显示复选框，支持全选、单标签重命名、合并及批量删除，关闭操作器清空选择。Classic 复用集合背景、筛选面板和紧凑操作器，Studio 独立编排页面，共用插件持有的编辑状态。筛选器组合标签名称、关联平台（满足所选任一平台）、当前类型的全局关联数量（单项／多项）、单平台／跨平台覆盖，以及最近维护／名称／使用量排序。Classic 的标签名称输入复用发现页文本搜索控件；关联平台、关联歌曲、平台覆盖和排序使用对齐的选项行，首项“全部”与具体选项互斥，具体选项支持多选。同一筛选维度取并集，不同维度取交集；未选择具体项表示全部，平台新增后也自动包含在全部范围内。排序按选择先后逐级比较，默认按最近维护排序。概览内显示已标记音乐和覆盖平台统计。预览按标签计数，应用后更新列表，取消保留原列表。筛选不缩小标签的全局关联数量或修改范围，批量选择仅保留匹配标签；展示方式、选择、详情及未提交输入可跨主题切换保留。合并与删除先确认去重后的影响歌曲数量，再向标签命名空间一次性写入，不删除宿主歌曲；确认期间暂停底层弹窗，原展示销毁或关联快照变化后拒绝旧操作。空状态与无匹配状态保留筛选和重置入口。语义令牌、44px 热区和按容器宽度适配的窄屏布局与其他集合一致。Node 交互测试覆盖筛选、详情、选择、批量写入和主题连续性，浏览器与原生环境的布局、焦点仍需另行明确请求验收。

### 5.1 设置

每个设置区域的说明紧跟标题下方，间距统一使用 `--am-space-1`。外置音乐源与代理管理的内容区域去除装饰图标和操作图标。“添加代理”只在标题下方展示支持的协议与地址格式，不在字段下重复提示；输入框参照创作者资料，每个字段独占一整行。已保存代理区域包含“代理列表”标题，空列表也保留标题。资源缓存拆成硬盘用量与容量、内存用量与容量、缓存位置三个独立卡片，区域之间保留分隔线；长说明收进“缓存介绍”按钮，点击打开宿主弹窗并暂停外层设置面板。账号详情、平台、名称、连接与登录方式之间的切换复用音乐列表操作弹窗的前进、返回转场，离场内容立即停止交互，并支持减少动态效果偏好。

“展示方式”的设置入口使用布局图标，内容区域各板块复用对应导航入口的图标，按板块和区域配置默认值，同一时间只展开一个板块；板块卡片之间通过留白区分，展开区域列表内部的行间分隔线与上下留白均与筛选历史一致，覆盖发现中的音乐列表与歌曲、待听、喜欢、歌单封面与歌曲、下载、历史、自定义音乐、标签管理和插件中心。标签管理分别提供标签排列与“关联音乐”默认设置，后者配置歌曲风格、密度和手机每行数量；两个完整主题均继承该默认值，关联音乐中的局部选择优先保留，明确关闭标签信息后下次进入恢复继承。选择后通过所属运行端注入的存储立即保存；新增或未单独调整的区域继承默认值，已有区域的单独选择继续独立保留。仅支持风格的区域不显示排列方式。切换主题保留设置导航，实际关闭设置后旧回调失效；写入失败显示错误、保留会话值并允许重试同一选择。

手机设置详情标题与 `settings-navigation__back` 放在同一行，标题靠左、返回按钮靠最右，两端沿用详情页的左右内边距；描述独占下方一行。返回按钮保留 44px 触控高度、可见焦点，以及返回概览时的草稿和滚动位置恢复。

设置统一分为“外观与导航”“音乐源”“网络与下载”“记录与创作”四个大类，包含外观与布局、导航管理、音乐源管理、请求代理、歌曲下载、播放历史、筛选历史和创作者资料。侧边栏移除“自定义界面”快捷入口，主题、布局与导航仍从设置中的对应页面进入。分类摘要只显示当前已应用值，不能展示代理凭据。

普通设置、分类导航和选择弹窗的展示归 `theme-default`（T07）；中性校验／编辑及模态基础组件保留在 UI。账号／登录、代理凭证及原生安装／同意继续使用固定宿主插槽。展示替换保留未完成输入，真正关闭设置才失效编辑会话。

PC 使用居中面板：左侧分类与设置入口，右侧单项详情，两侧分别滚动。手机使用全视口分组列表，点击条目后横向滑入子页；返回按钮恢复列表滚动位置与入口焦点。访问过的表单保留本次设置会话的草稿，关闭设置后卸载。离场与隐藏页面立即停止接受焦点和点击，减少动态效果时关闭位移动画。控件触摸目标至少 44px，表单标签、辅助说明与保存操作保持清晰层级。每个完整子项使用浅背景卡片，说明、输入、校验反馈和对应的保存、导入操作都放在同一卡片中；分隔线只用于下载目录与并发等完整相邻子项，或独立音乐源、代理条目之间；同一子项内部的字段、说明、展开详情与操作区通过背景和留白建立层次，不再额外添加分隔线。外观、导航、音乐源、账号、代理、下载、历史、资料与外置音乐源共用这套背景层次，并适配浅色、深色主题；卡片采用 10px、内部选项行采用 8px、控件采用 6px 圆角，与工作台内容区一致。代理列表移除重复的页面标题与通用提示，保留各代理的账号分配和删除说明。音乐源分组使用内缩行分隔线，左侧显示身份与状态，右侧独立放置控件，窄容器将操作放到描述下方。导航管理使用紧凑行间距，导航项之间不加分隔线；设置输入校验提示统一采用与代理管理相同的较小字号、常规字重和行高。外观选项使用独立背景，仅在上方三个选择项与下方移动端底部导航设置之间保留一条分隔线；界面主题、侧栏位置和明暗主题均通过显示当前值的按钮打开共用选择弹窗；选择后立即应用并关闭，取消保留原值。外置音乐源分别展示插件包导入、原生身份与权限确认、已安装音乐源和命令结果；诊断与 DEV 操作可展开，预览替换时清空上一次的全部授权勾选。

筛选历史使用“板块 → 筛选区域 → 筛选项”分组。板块默认折叠，同一时间只展开一个板块；展开与收起平滑过渡高度和透明度，并尊重减少动态效果偏好，折叠及离场内容立即停止交互并对辅助技术隐藏。区域入口共用一个整体圆角背景，内部用分隔线划分，鼠标经过子项时中间边缘不单独出现圆角；区域入口只显示标题与“筛选项数 · 默认显示组数”一行摘要，默认显示组数取已保存值，未保存草稿用独立的“未保存”标记提示，具体保留数量进入区域查看。输入框按需打开，避免新增筛选器不断拉长设置页。“发现”包含“音乐列表筛选”（文本筛选、平台、命名、搜索时间）和“列表内歌曲筛选”（搜索、标签、命名、发布时间、歌曲时长）；“待听”包含独立的“待听歌曲筛选”（文本、用户标签、歌曲时长、平台、添加时间）；“我的喜欢”包含“喜欢歌曲筛选”（文本、用户标签、歌曲时长、平台、喜欢时间），历史与配置独立归属。点击区域后，PC 打开居中配置弹窗，手机从底部滑出按内容定高、最多占 80% 视口的面板，表单内部滚动，标题和保存按钮保持可达。配置浮层留在产品挂载根（Userscript 为 Shadow Root；桌面为 embedded 根），打开后暂停外层设置面板的模态语义和交互；关闭后恢复区域入口焦点。每次完整校验并保存当前区域，非法输入不裁剪任何历史，也不应用其他区域的草稿；返回后保留本次会话草稿，关闭整个设置后卸载。所有宽度下每项独占一行，标签与输入横向对齐，极窄容器把输入放到标签下方；区域标题、用途说明、组数单位和保存状态保持可见。所有设置数字输入框去除原生上下步进箭头，保留数值范围校验和移动端数字键盘。

操作器中的选择、恢复原名、喜欢、加入歌单、删除、下载启动/结果及历史清空，以及下载、播放历史、创作者名称、请求代理与筛选历史的保存按钮，都复用 `packages/ui/src/product/action-feedback.ts` 文案目录和统一顶部成功/失败提示服务，保留输入附近的校验说明。提示不抢焦点，新结果替换旧结果；成功展示 3 秒，失败展示 5 秒，设置确认不复用播放提示的冷却限制。共享顶部提示的文字支持原生选择与复制；鼠标悬停或提示获得焦点时暂停自动关闭，两者都离开后按剩余时长继续计时。新结果替换时保留交互暂停状态并重置展示时长，主题界面卸载时释放其暂停状态。只有校验和实际存储写入成功才提示已保存；写入失败保留会话数据并允许再次保存。

筛选历史配置弹窗分为“历史保留”和“默认展示”，使用独立标题、范围提示和分组卡片建立层次。数量输入复用其他设置表单的完整边框、背景、圆角和键盘焦点样式，组数单位放在输入框右侧。每项独占一行，标签与输入列对齐，字段之间用留白区分；分隔线只放在“历史保留”和“默认展示”两个完整子项之间，不放在单个字段或保存操作前；窄容器缩小输入列，极窄时标签与输入上下排列。保存说明放在表单末尾，底部右侧集中返回与保存操作。代理保存按钮左侧不再显示“配置已同步/有未保存的修改”文本。

音乐源管理标题下显示“至少保留一个音乐源。关闭音乐源不会删除已有歌曲和列表。”，音乐源列表底部不重复提示。

请求代理的“启用请求代理”开关立即应用已保存配置，保存配置保持当前启用状态。关闭时仍可编辑并保存主机、端口、类型、凭据与 SOCKS DNS 选项，刷新后保留配置且保持关闭。启用前必须存在有效的已保存主机；开关不能应用或覆盖未保存的配置草稿。上述单代理开关、凭据和 SOCKS DNS 表单仅属于 Userscript 的 GM 运行端；桌面使用独立账号与代理面板，支持范围见[桌面规范](../../桌面端/开发规范.md)。

组件／逻辑检查与运行态验收分别记录范围；[主题迁移计划](../架构/独立主题UI迁移计划.md)保存安装版 GM 和原生 Windows 设置的具体构建证据，以及仍开放的实体输入、原生对话框和移动验收。

桌面与 Android 在“歌曲下载”的并发表单上方注入“下载保存目录”。原生选择器确认后立即保存并应用，面板显示当前目录，提供“更改目录”和“每次询问”；取消选择保留原设置且不提示保存成功，处理中禁止重复提交，失败保留已显示设置并提供可重试的行内与顶部反馈。Android 说明系统目录限制，iOS 明确显示原生保存不可用。Userscript 不显示目录选择器。见[原生保存与存储](../../桌面端/运行端架构.md#共用产品功能与边界)。

## 6. 响应式与现代 CSS

- 简单对齐和一维分配使用 Flex；壳层和二维区域使用 Grid。
- 可复用卡片、工具栏、列表和面板优先声明容器并以 `@container` 调整后代。容器不能查询自身后再依赖该查询重排自身；顶层壳、视口安全区和输入能力使用 `@media`。
- 发现的顶栏、内容区、歌曲返回栏和播放器各自建立具名宽度容器，侧栏展开后按实际剩余宽度重排；窄桌面顶栏仍保留设置和隐藏入口，移动抽屉入口只由视口模式决定。列表使用 Grid 自动分配列宽，卡片只查询自己的网格单元，不新增逐卡片 `ResizeObserver` 或 Vue 尺寸状态。屏外音乐列表卡片和歌曲卡片采用 `content-visibility: auto`，配合可记忆实际高度的占位；侧栏开合只过渡壳层轨道，不额外添加逐卡片宽度过渡。自动化 CSS 契约检查不代替真实浏览器的布局、滚动与帧耗时测量。
- 使用 `clamp()`、`min()`、`max()`、逻辑属性和动态视口单位减少重复断点；关键布局保留可维护的兼容兜底。
- 断点由内容是否拥挤决定，不以具体设备型号命名。窄屏不能只缩小字体，应改变导航、操作器、表格和详情的呈现方式。
- Userscript 的 reset、token 和关键组件样式必须作为字符串注入同一 Shadow Root；默认写入宿主页 `<head>` 的样式不能作为关键布局依赖。

## 7. 动画与手势

所有卡片换位都具有渲染生命周期，包括键盘排序、密度／列数变化、被中断的 FLIP 和返回原位的拖拽邻卡。此前保护只覆盖落地，没有覆盖普通 FLIP 和邻卡回位；虚拟列表的默认卡片还会在手势边界切换绘制包含。这些缺口可能使后代内容被裁剪／跳过、内部像素坐标变化，或被后方兄弟项遮挡。延长动画时长、添加页面专属类都不能修复生命周期归属。

普通与虚拟 FLIP 都使用共享的 `grid-move-animations.ts`。稳定出现键的槽位从坐标重基到当前动画 finish／cancel 持有 `data-am-grid-moving`。先捕获当前可见位置，再取消旧 transform；取消、DOM 更新和剩余位移动画之间持续保留同一渲染租约。过期 finish／cancel／unregister 不能释放替换后的动画。零位移重基释放无用保留；禁用、减少动态效果、隐藏／停用根、动画失败和销毁均清理租约与监听。虚拟路径只处理两次布局均挂载的交集；换窗和元数据更新不触发布局动画或完整集合 DOM 扫描。

transform 包装层的可见性不会继承到独立裁剪的卡片。运动标记应保持受影响后代渲染；默认 `.track-card` 在静止、换位、拖动和落地期间保持同一 layout／style／paint 边界。不能将该边界切为 `contain: none`、增加 size 包含，或给外层定位／测量／运动包装层添加 paint 包含。虚拟自然测量继续禁用 intrinsic 占位。共享换位槽层级为1，键盘焦点项为2，落地项为3；指针拖动项保持高于让位邻卡。禁止常驻合成层或消费页面互相竞争的 z-index 规则。

拖拽让位的渲染租约通过几何适配器定位已挂载槽位，不在指针帧重新扫描完整 DOM。移出当前让位集合的邻卡仍在回位：按共享过渡 token 的完成预算保留渲染，再次让位时撤销旧释放任务，已卸载槽位及时释放。清空拖动／让位状态前，先在同一稳定节点设置 landing／settling 保护；两位归属方之间不能出现未受保护的测量或绘制。新增过渡延迟／时长必须同步完成预算和回归。

动效回归覆盖行内／跨行双向排序、新的受控快照、键盘换位、密度／列数快速反向、侧栏断点、邻卡回位、新手势、过期完成／注销、减少动态效果和销毁。断言可见坐标连续、渲染归属不中断、层级正确、挂载工作有界且清理完整。获准真实界面检查时，记录中间动画帧和节点身份，源码变更后确认实际注入样式库，区分被动帧录制与会强制布局的诊断。原生输入需验证按键／捕获语义和操作系统前台归属；只有最终截图不能关闭闪烁验收。

经典主题排序项的内层动画表面声明 `data-am-grid-motion`，并与稳定槽位共享布局原点。共享排序逻辑在松手时测量受影响邻项，让尚未完成的让位过渡在重排后从实际可见位置继续。取消监听必须通过 getter 比较实际值：混合多源监听若直接包含 shallowRef，即使取消条件未变，也可能在宿主快照替换时被强制触发。排序提交后的快照刷新必须保留落位状态。下载歌曲与歌单卡片从长按激活或开始位移到落位结束持续保留 transform 合成层，移动中的下载卡片也保持渲染。快速松手回归对照我的喜欢、下载与歌单，采用全新宿主快照，覆盖同一行、跨行的双向移动。

拖拽松手必须保持连续交接：提交受控顺序，在禁用过渡时将松手位移换算到新的稳定槽位，再仅对剩余距离播放落位动画。临时过渡／可见性样式与稳定槽位的 `data-am-grid-landing` 浮层层级由共享排序逻辑提供，不能只依赖页面专属的落位选择器。直到落位结束，卡片都必须保持渲染并高于邻项；向前移动时也不能被 DOM 顺序靠后的卡片遮住。取消、开始新拖拽或卸载时清理保护，并遵守减少动画设置。内置落位过渡使用共享 fast/normal/slow 动画令牌且不设延迟；引入其他时长前必须扩展结束契约。回归测试覆盖双向移动、父级提交新顺序、真实卡片的样式传递与清理。Node 测试只验证交接契约，浏览器／Userscript／WebView 的实际无闪动验收仍需单独现场检查。

待听拖动的位移在单张歌曲卡片内订阅，避免逐帧更新整个网格或触发 TransitionGroup 的全量布局测量。指针移动与滚动容器（包括 Shadow Root 内部）的滚动合并到同一动画帧；指针静止时滚轮滚动仍同步浮起位置与落点。边缘自动滚动先读取几何数据再写入滚动位置，到达边界即停止续帧。pointerup 只执行最终命中与平移，不能额外推进一次边缘滚动，否则松手会在最后预览之后改变视口，并按尚未显示过的滚动位置重基。相同位移复用样式对象，已有让位不重复渲染。

卡片高度和受控 DOM 更新时，浏览器原生滚动锚定也可能改变该视口。`native-scroll-anchor.ts` 在实际滚动根上按引用计数抑制 `overflow-anchor`，由拖拽和 `useVirtualScrollAnchor` 共用。起拖几何测量前获取租约，贯穿落地交接，最后一位归属方释放后才恢复原有内联值及优先级。起拖失败、取消、减少动态效果、根替换、过期完成和销毁只释放自己的保留，不能提前恢复其他归属方的租约。松手额外滚动或原生锚定竞争属于几何错误，不能通过延长动画修复。

DOM 拖拽在捕获根高度不变时复用稳定槽位几何。根的 ResizeObserver 报告高度变化后，合并为一批未变换槽位测量，再重基源项平移以保持抓取点。pointerup 也检查当前根范围，覆盖先松手、后送达观察通知的顺序；普通指针／滚动帧复用快照。根高度信号不能检测总高度不变的内部重分配，此类布局需要显式空间版本或测量适配器。宽度／列数、出现项顺序和根变化仍使手势失效。待落位的冻结坐标按内容坐标跟随后续滚动。清理时释放观察器、滚动监听及待执行帧，过期观察回调不能取消新手势；这些修改仍需当前构建的中间动画帧验收。

虚拟拖拽最多将源出现项和当前目的地计入共享交互保留上限；旧目的地先释放再获取替代项，源项则从受控提交到落地始终连续保留。获取失败时取消拖拽，不挤掉其他编辑／焦点会话。扁平网格单元负责定位、落点身份与拖动／落地层级，未变换的自然测量容器包住内部运动表面和唯一真实卡片。挂载窗口代次在指针／落点不变时也更新已挂载邻项的让位。网格的不透明 `layoutRevision` 仅随空间几何或出现项顺序改变，元数据刷新与几何等价的缓存测量不会推进；使用该代次和就绪状态判断起拖快照是否失效，并用原有显式视口进行自动滚动，包含初始短列表。指针捕获结束后，落地阶段独立持有尺寸／根元素／身份失效保护。宿主回调前分配代次，每个延迟阶段重查该代次及根／源节点连接。允许下一轮父级渲染发布预期的同组子集顺序，后续无关顺序／筛选变化取消落地。这些内存保护不延迟或回滚已提交的业务移动。这些共享基础不代表生产虚拟拖拽已准入，也不建立原生布局／指针验收。

动画用于解释进入/离开、展开/收起、排序和面板空间来源，保持克制。简单过渡优先使用 CSS `transform` 与 `opacity`，避免布局抖动和交错读写；所有动画尊重 `prefers-reduced-motion`。复杂拖拽、排序、手势或剪辑时间线只有在原生实现会明显增加风险时才引入第三方库，并按仓库依赖准入规则记录体积与替代方案。

手势不能成为唯一入口。水平滑动、上拖播放器和拖拽排序都要有点击/按钮或键盘等价操作；滚动区域内应设置合适的 `touch-action`，避免抢占输入框选择、纵向滚动或系统返回手势。

键盘排序保留同组子集的移动事件，只恢复发起操作的手柄。虚拟调用方将 `retainItem` 与可取消的 `focusItem(kind, id, signal)` 适配器接到 `useVirtualItemRetention.focusItem`：源项贯穿受控提交保留，滚动并挂载同一出现项，再根据测量后的几何做一次对齐后聚焦。新输入、手势、根替换、无关顺序变化或销毁撤销旧焦点任务；隐藏／不可交互的组合祖先（包括 Shadow 宿主）不能收到恢复焦点。弹窗／按钮操作不移动背景焦点。减少动态效果时，松手仍提交，但渲染后直接清理，不启动落地帧／定时器；运行中启用该偏好则取消现有运动。

虚拟键控 FLIP 只注册已挂载的稳定槽位，在自然测量与指针运动之间使用独立变换表面。仅集合／空间变化以及 CSS 属性提交前的显式展示布局变化触发；窗口进出和元数据刷新不读取运动盒子、不启动动画。首次／重新挂载的自然测量和缓存淘汰仍更新渲染、锚点与实时拖拽几何，只有已挂载项真正的 resize／load 高度变化才推进测量引发的运动代次。同一批次混合这两类变化、以及已挂载高度被有界缓存淘汰后，仍须保持该区分。只移动前后均挂载的稳定键，先批量读再写；打断时从当前可见位置继续，拖动／落地、展示隐藏、减少动态效果或销毁时取消。这些自动契约不建立原生布局／焦点或帧耗时验收。

可选实时测量拖拽在新挂载窗口改变自然高度时刷新完整的同身份行几何。重基源项变换使抓取点保持不动，再贯穿受控测量保留可见松手位置，之后开始落地；宽度、列数、列表起点、方向、身份和根变化使手势失效，纯元数据变化不重建空间索引。落地运动开始后的重排仍沿用既有取消规则。主题／概览恢复使用临时稳定出现项键、项内偏移与控件键，等待当前惰性渲染器就绪并先挂载后聚焦；新输入、导航、隐藏／替换根或销毁取消旧任务。这些契约仍受[虚拟列表准入门禁](../架构/虚拟列表与布局性能实施方案.md)约束。

### 7.1 拖拽松手与消费方生命周期

松手是由 `useGridReorder` 统一负责的一次交接。消费方的适配器注册回调必须在挂载表面的整个生命周期内保持稳定。替换受控 state／props／binding 对象，包括提交预期顺序，都不能注销该表面或调用 `clearDrag`。注册与注销跟随真实表面替换；实际布局、筛选与根变化由标量失效条件判断。回归必须经过真实消费方并提交不可变宿主快照，不能只用共享控制器和原地修改的数组验证。

| 阶段       | 必须满足的行为                                                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 拖动预览   | 稳定出现键的单元负责定位、捕获和层级；自然测量、FLIP 与指针平移分层。邻项在按住拖动时完成让位。                                                                                                                       |
| 松手读取   | 最终命中不能额外滚动。移除预览样式前，批量读取源项与邻项的实际可见坐标，包含尚未完成的过渡和滚动；不能用预览目标位置代替当前绘制位置。                                                                                |
| 提交与重基 | 释放拖动保护前先设置 landing／settling 保护，源项与目的地的保留贯穿预期受控提交。父级更新及当前自然测量完成后，在禁用过渡时设置 `translation = 松手绘制位置 - 提交后的自然槽位`，统一坐标系，每份滚动偏移只计算一次。 |
| 落位       | 先使重基起点生效，再启用剩余过渡。已经位于提交后槽位的邻项剩余位移为零，应保持不动；快速松手时邻项只完成未走完的距离。拖动项从实际松手点移动到目的地，不能重播整个受影响区间，也不能叠加普通 FLIP。                   |
| 完成或中断 | 清理全部标记、样式、观察器、监听、动画帧、定时器及交互／锚定保留。新手势、根、布局或顺序使旧延迟任务失效，旧清理不得影响替代任务。减少动态效果时正常提交，不保留过渡尾部。                                            |

不能通过调整缓动、延迟提交、关闭虚拟化、隐藏受影响卡片或等待用户滚动修复跳变。先查明归属丢失、提前清理、重复变换、坐标不一致或估算／测量往返。拖拽结束后，侧栏双向开合必须立即正常工作。仅宽度变化的测量批次应丢弃旧高度，在虚拟行更新前统一读取当前挂载项的自然高度，不能先渲染临时估算行，再强制布局重新测量。同列数连续宽度变化及其引起的自然高度变化随 CSS 布局推进，不逐帧重启 FLIP；列数／分组／间距和独立内容／加载重排仍推进运动，拖拽几何仍对宽度敏感。

排序还要负责视口归属：`suspendReorder` 将首个／最后一个排序保留连接到 `anchor.suspend`。除了原生锚定租约，语义补偿也必须在预览、受控提交和落位期间持续暂停，否则视口首项换位会在松手时滚动视口，即使平移计算完全正确。恢复时捕获当前已提交的几何，不能重放旧补偿。最后一次提交高度／窗口更新可能先于 ResizeObserver 通知：启动落位前检查当前范围，必要时在禁用过渡下再次重基，并将该范围作为观察基线。同一布局的延迟通知不能取消刚启动的动画；之后独立发生的重排仍应使落位失效。

测量网格的高度按每行带类型、与顺序无关的同行项集合确定有效性。排序提交只使同行项集合变化的行失效；行内换位及无关已测量行保留有效高度，不能用全局顺序／动画代次清空整个高度缓存。否则临时估算范围可能缩小到不足以容纳当前视口，浏览器会直接向上夹紧 `scrollTop`，语义／原生锚定抑制都无法阻止。回归需包含首次进入未测量区域、视口顶部对齐项顶部及小数像素边界，同时比较滚动范围与松手坐标。

必须执行以下回归矩阵：

| 维度         | 场景与断言                                                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 松手         | 前后双向、行内／跨行、等待让位完成／快速松手、滚动后松手／继续滚动。按稳定键比较松手、提交更新、首个落位帧和完成时的绘制坐标；已让位邻项不能跳动。 |
| 消费方更新   | 全新不可变提交快照、同身份元数据刷新、键盘排序／焦点、无关筛选／顺序替换。预期提交保留注册、落位与发起焦点，真实失效才取消。                       |
| 后续布局     | 连续拖拽后立即收起／展开侧栏、快速反向与跨列数断点；再与手动滚动后的结果对照。不能残留拖拽状态或依赖滚动恢复；被动帧间隔与读取几何的诊断分开记录。 |
| 资源生命周期 | 待落位／落位中开始新拖拽、过期完成／观察／注销、根断开／替换、取消、减少动态效果和销毁。挂载工作保持有界，资源回到基线。                           |

Node 回归验证行为与生命周期；当前构建的 WebView／Userscript 还需检查实际注入样式、输入／捕获及中间绘制。控制器测试通过或一张最终截图都不能建立消费方准入。

### 7.2 随视口变化的挂载预算

挂载数量由真实滚动视口、CSS 解析后的列数、当前展示／卡片风格和自然行高共同决定。顶部 30、中部 50、尾部 32、返回顶部 30 只是一组观测值，不能作为全局上限或目标数量。视口高宽、侧栏／播放器占用、密度、移动端列数和自然内容变化时都需重算。表格按逻辑项应用同一准则，另计声明的物理行及固定表头／表尾。

网格预算为可见行、两侧可用的 `overscan` 行（默认每侧 2 行）、一个保守边界行，以及范围外不同交互保留行之和，乘以当前列数，并裁剪到集合范围。交互默认最多保留 8 个不同出现项，可配置到 32；保留一项会保留其逻辑行，但不能填满到远处保留项之间的空白。挂载卡片单元与各风格内部 DOM 分开统计。较大／较高视口可以合理超过 50 张卡片；隐藏根不挂载，顶部／尾部因边界裁剪自然减少。测试覆盖大小视口、全部密度／移动端列数、顶部／中部／尾部／返回及实时调整，断言可见内容完整和几何预算，而不是固定截图下的数量。

## 8. 组件与打包边界

主题是通过 `theme.root` 选择的独立完整根组件包，局部歌曲行／列表／导航分派及跨主题覆盖已删除。经典歌曲行与页面样式归 theme-default，工作室拥有独立结构；UI 保留中性摘要／网格／媒体控件及固定宿主表单，创作插件拥有中性时间线样式。新增构建内置主题见[独立主题开发指南](../架构/独立主题开发指南.md)，元数据、惰性样式资源和模块注册使用同一目录。

- 经典产品展示由 `packages/theme-default` 维护；`packages/ui` 保留端无关的图标、导航／壳层基础组件、受控契约、无界面交互、远程图片策略、token 与受保护宿主面板，不读取 GM、Tauri 或音乐源私有状态。插件重构后，通用组件/宿主面板继续归 ui，标签与创作专属视图已归所属插件；三端消费同一份视图契约，不在应用复制模板，目标边界见第 10 节。
- 各 `apps/*` 把本端控制器映射为共享组件 props/emits。公共业务状态、播放器与跨视图异步编排在 `music-workbench`；Userscript 的 GM/DOM/页面桥在应用 platform，Tauri 的 IPC 在应用 platform、原生 HTTP/账号/凭证在 src-tauri。
- 平台差异必须是显式端口：壳层偏好通过 repository 注入；Userscript 显示/隐藏由受控属性启用；网络代理设置通过命名 slot 注入；播放器通过 player slot 绑定本端媒体管线。共享组件不得通过环境判断偷偷选择 GM 或 Tauri 实现。
- 共享组件以具名、可 tree-shake 的出口提供，重型编辑、下载与插件页面从组件子路径异步加载，动态导入失败允许重试。媒体编码与完整媒体读取仍留在运行端的用户动作边界之后。
- “响应式可见”与“是否进入产物”是两个问题。CSS 只负责布局；端级入口、具名导出和动态 import 才负责减包。新增移动应用时必须用构建产物分析验证，而不是凭源码目录推断。

## 9. 可访问性与验收

交互控件使用原生元素，所有无文字图标按钮有 `aria-label`；弹层管理焦点、Escape、关闭后焦点恢复与背景遮罩；选择和错误不能只靠颜色。远程图片有替代文本，触摸目标保持足够尺寸，文本在 200% 缩放下仍可操作。

虚拟列表沿用现有筛选器，在归属方提供的完整集合中匹配，包含当前窗口之外的项目；匹配结果继续通过同一个有界虚拟窗口渲染，应用或清除筛选均不切换为全量 DOM，也不遍历远程分页。浏览器 Ctrl+F／Cmd+F 保持原生行为，只搜索当前已挂载内容。不新增独立的查找／查看按钮、不拦截快捷键，也不挂载隐藏或离屏副本来扩大原生搜索或文本选择范围。

UI 变更至少验证：浅/深/系统主题、侧栏两侧与收起状态、窄容器、键盘顺序、触摸等价路径、reduced motion、加载/空/错误/部分成功、宿主页样式隔离、隐藏再显示、播放栏与移动底栏叠加。最后运行目标包测试和类型检查，再执行根级 `pnpm lint`、`pnpm format:check` 与 `pnpm build`；涉及移动端时额外比较各端产物依赖图和体积。

## 10. 插件贡献、授权界面与未开放目标

两个主题的插件中心均以响应式卡片或列表呈现内置音乐源、内置功能和原生安装快照。经典主题复用收藏列表的页面框架，在标题旁以同一块蓝色摘要显示内置与外置数量，与下载板块一致。移动端隐藏内容区的重复标题，同一计数以紧凑样式放入顶部栏右侧的上下文区域。全部、内置、外置页签使用滑动的白色选中底板和按方向切换的列表过渡，并适配减少动画设置；导入位于同一行右侧，沿用 44px 控件高度。底部工具栏提供展示方式、筛选器和操作器。经典筛选器复用列表筛选的概览、条件编辑、条件摘要及应用页脚；按关键词、类型及启用或错误状态预览结果，返回撤销当前维度的修改，应用后生效，取消保留原有结果。操作器支持选择当前匹配项，通过宿主动作串行启停内置插件，并刷新外置快照；外置安装权限仍由固定宿主管理。经典主题的无内容及无匹配结果复用列表的空状态表面与蓝底图标。正常浏览时启用开关保持在原来的右侧位置；打开操作器后，操作控件先平滑左移，再在右侧延时淡入、滑入选择框，沿用移动端歌曲选择的时序；关闭时控件平滑回到原位。插件图标与卡片布局保持稳定，两种动效均遵循减少动态效果偏好。操作器打开时点击卡片切换选择，其余时候打开插件介绍弹窗。卡片右上角的三点按钮也可打开介绍及明确的启停、重试或外置管理操作。窄容器中的紧凑卡片保留名称、分类、来源与状态；描述、发布者、代次及完整错误可在弹窗查看。外置管理和导入仍打开设置中已有的受保护宿主流程。不支持外置插件的运行端禁用导入，并在外置分类说明可用范围。内存中的浏览偏好在页面切换与主题替换后保留。工作台统一持有原生会话，同步设置与插件数量；关闭外置能力时释放临时工作。组件测试覆盖交互与连续性，真实布局、焦点和原生安装验收仍需单独请求检查。

内置模块元数据可声明 `developmentStatus`：`stable`（正常）、`updating`（更新中）、`fixing`（修复中）、`developing`（开发中）或 `disabled`（禁用中），省略时表示维护正常。这些构建时确定的开发者状态用于维护提示，与用户启停、加载或错误状态及运行权限独立。两个主题并列显示当前维护提示和运行状态；经典主题介绍弹窗分别列出开发者状态与运行状态，开发者状态筛选可与关键词、类型及启用或错误条件组合。片段创作当前在插件的轻量元数据中声明为 `developing`，两个运行端共用；用户开关与存储数据维持原有语义。

已接入贡献导航/页面出口、单曲/列表上下文和两套可信内置主题；专属视图归标签/创作插件，主题切换保留宿主业务实例。已接入受控目录/命令、安装审批/回退、独立 DEV 与文本/诊断保存。其余外置 UI/扩展点和手机授权流程仍是目标，不能从 DTO 渲染器或内置页面推断为已开放。当前矩阵见[S15](../架构/插件系统重构S15工具与桌面交付.md)。

采纳[插件扩展与安全契约](../架构/插件扩展与安全契约.md)的语义贡献机制；现有静态页面、CSS 类名与组件私有 props 不是外置插件 API。导航、workspace.views、单曲附加动作/详情、列表批量动作/筛选、插件设置与音乐来源使用带版本的扩展点，核心歌单和播放操作不依赖插件状态。

- 同一列表上下文覆盖发现、待听、喜欢、歌单与历史；区分单曲、多选、对象版本与可执行动作。when/筛选表达式只读白名单字段，不执行 JavaScript、不在渲染中逐曲调用沙盒。批量计算先形成有版本注解，远程列表不因插件筛选遍历所有分页。
- 宿主检查启用、授权、兼容性与上下文后显示贡献，使用插件/贡献组合键，禁止覆盖核心命令。禁用同时撤销视图、动作、订阅和请求，插件筛选与用户标签搜索/排序投影停止生效；保留可见的休眠条件，由用户恢复。
- 扩展点描述语义位置；桌面侧栏/操作器与手机底栏、抽屉、操作表由宿主映射。HostCapabilities 报告实际支持项，可选位置缺失不使整个插件失败。插件不控制像素布局、全局路由或模态层级。
- 外置 UI 只提交有界受控节点和本插件声明的命令 ID，禁止外部 Vue、HTML、任意 CSS/脚本及未经处理的 SVG。事件绑定 viewRevision/上下文，迟到事件拒绝；宿主列表节点不向插件交付隐藏或未授权字段。
- 插件区域固定显示宿主绘制的身份条；不提供密码输入节点，提示用户不要在插件表单填写凭证。登录、安装、授权、危险修改和文件保存确认由宿主掌握，插件不能提交或覆盖这些页面。标识与节点限制降低冒充风险，不能承诺识别所有欺骗性文案。
- 桌面与手机的文件导入、文件关联、分享接收、链接/深链均进入同一宿主安装流程；远程包先确认来源，再获取并展示身份、版本、执行类型、权限与兼容性。手机使用全屏预览和授权页；不支持的渠道、沙盒或必需能力在执行代码前明确提示并阻止安装，可选能力缺失只影响对应功能。重复入口事件不叠加预览或重复授权，不要求用户编辑 JSON，市场不是安装前提。
- 焦点进入/返回、Escape/系统返回、触摸与键盘替代、加载/错误/重试均由宿主保证；单插件错误局部隔离，不阻塞播放器。外链显示规范化目标并要求用户动作，图片/媒体使用继承插件身份和授权的资源通道，不能照搬现有远程 src 直连。

复杂内置创作视图可使用可信 /vue 入口，根入口仍无框架且按需加载；这一入口不向外部包开放。验收同时覆盖节点/消息超限、陈旧事件、核心动作稳定性、跨板块一致性和窄屏无障碍；现有组件测试不作为原生权限或视觉隔离已完成的证据。

已接入标签功能启停、批量输入、局部加载失败重试与休眠条件。插件 `/vue` 提供无渲染编辑器与中立控件，完整主题负责管理页排版。经典主题桌面端保留标签标题、简短描述、带单位的总数及“创建标签”入口，内容上方显示分隔线；手机端隐藏标题与描述，顶部保留类型切换和“创建标签”按钮，总数和单位放在顶栏右侧。下方栏复用集合控件，左侧显示“已选 N · 共 M”。操作器复用加粗“全选”和“已选 N 个”的共享选择行。合并弹窗在标题右侧显示“·N个标签”，名称输入框下方以横线分隔，确认按钮使用紧凑宽度、靠右排列和蓝色主色背景，移除原有名称输入提示。合并名称输入框沿用发现板块文本搜索的下划线样式，尺寸适配紧凑弹窗并自动聚焦；主题色底线在每次打开时从左向右展开，失焦后保持显示。“创建标签”的加号图标在悬停或键盘聚焦时旋转并轻微放大，两种动效均遵循减少动态效果偏好。创建入口打开紧凑弹窗，上方为名称输入框，下方为提交按钮；输入聚焦时的底线与发现板块的平台选择器一致，从左向右展开，并遵循减少动态效果偏好。名称沿用现有归一化与大小写无关去重规则；重名时保留弹窗和输入内容，通过共享顶部提示显示“已存在重复标签。”。独立标签定义保存在标签命名空间中，无需关联歌曲，零使用量时仍可查看。标签管理目录与歌曲标签选项使用同一份完整标签集合，包含仅用于歌单的标签，以及关联歌曲已不在宿主资料库中的标签；这些标签显示当前可用歌曲数为零，读取时不改写数据。全局重命名、合并与删除在一次命名空间提交中同时更新独立定义、歌曲关联与歌单关联。确认文案说明歌单变更，展示的歌曲数量仍按当前可用的宿主资料计算。已打开的编辑器和异步确认受功能代次约束，重新启用不重放旧写入；Node 自动化不代表真实视觉/焦点验收。见[数据归属](../架构/插件数据归属.md)。

经典与 Studio 主题的歌曲操作器只显示“添加标签”入口；已有用户标签放在确认弹窗内，不混入来源元数据标签。弹窗复用“加入歌单／移出喜欢”的确认排版，底部提供“取消”和主色“确认添加”按钮。支持输入新标签、搜索及多选已有标签；选择时仅保留草稿，确认后才写入，取消则丢弃草稿。“已添加”表示全部已选歌曲已有该标签，对应选项禁用；仅部分歌曲已有时仍可添加，草稿选项显示“待添加”。最近顺序随标签关联保存在插件命名空间中，仅在写入成功后更新。选择或上下文变化、功能停用会使旧编辑器失效。弹窗挂到主题专属浮层目标，脱离操作器滚动区域并保留在产品界面内。Node 组件与跨主题测试覆盖这些交互契约，真实布局及焦点验收仍需单独进行。

Tauri 插件中心从原生快照展示安装/授权并请求撤权，等待持久化确认后刷新；查询失败清除旧投影并允许重试。 通过可选具名端口加入安装/回退/命令/取消/导出，UI 不推导或持久化 grant。

安装预览由固定宿主组件渲染身份、指纹、内容哈希、执行类型、权限差异、历史等级和精确旧范围；文件选择及关闭只暂存/释放快照，不授权或执行。流程状态与过期结果处理归工作台 composable，Tauri 注入原生 preview/discard；Userscript 不注入该端口。生产准入未满足时显示原因且没有激活动作。见[包契约](../架构/插件包与恢复.md)。

文件选择/拖入/初次启动参数/公共 HTTPS/深链进入同一原生预览，确认安装或回退是另一个明确宿主动作。未准入目标显示原生原因，不能因按钮或 declarative 策略存在而执行。DEV 路径/秘密不持久化；替换预览、关闭与迟到监听都要释放资源。目录不加载客体 artwork/page URL，无媒体能力显示不可用。原生对话框/精确 Windows 隔离的既有证据不替代其他页面、主题或手机的视觉与焦点验收。

# 哔哩哔哩 Web 接口契约

英文对应页：[Bilibili Web API Contract](../../../../en/cross-platform/platforms/bilibili/web-api-contract.md)。

证据范围：本页维护来源网页端点与字段，不提供统一运行端实现。涉及 GM、宿主页、BDMS 页面签名/捕获及跨站播放的段落仅属于篡改猴；涉及 Rust CookieStore、原生登录与 HTTP 的段落仅属于桌面。网页测试 Profile 的成功不证明 GM 或干净 Rust 会话成功。`captureDate` 是最近真实复测日期，并不表示全页或两端均已验收；按各段日期和环境读取。端级规则见[篡改猴](../../../用户脚本/开发规范.md)与[桌面](../../../桌面端/开发规范.md)。

> 抓包日期：2026-09-03。以下为 B 站 Web 前端内部接口，不是稳定开放 API；实现必须允许字段缺失并通过实际浏览器定期复测。文档不保存 Cookie、令牌、设备指纹、WBI 结果或短时 CDN URL。

## 2. 字段映射

### 搜索视频

- 稳定 ID：`bvid`；不要使用可能超过安全整数范围的 `aid` 作为 JavaScript 主键。
- 标题：`title`，移除搜索高亮 HTML 标签后按纯文本展示。
- UP：`mid + author`；封面：`pic`；原始 `duration` 时钟字符串可能表示多 P 投稿的总时长，可播放曲目应使用所选分 P 的时长。
- 发布时间：`pubdate` 秒；标签：逗号分隔 `tag`。
- 统计：`play`、`video_review`、`favorites`、`review`、`like`。

### UP 投稿

`list.vlist[]` 提供 `bvid`、`title`、`author`、`mid`、`pic`、`created`、`length`、`play`、`video_review` 和 `comment`。UP 关键字搜索与视频投稿共用同一接口，只是 `keyword` 不为空、Web 页面页大小不同。

### 合集

`meta` 提供合集标题、UP `mid` 和总数；`archives[]` 提供 `bvid`、标题、封面、秒级时长、发布时间和播放/弹幕。抓取样例一页 30 条、总数 217；适配器不得一次拉完 8 页。

### 收藏夹

`info` 提供标题、所有者和总数；`medias[]` 提供 `bvid`、`ugc.first_cid`、UP、封面、秒级时长、发布时间、收藏时间和统计。失效内容可能缺少可播放字段，映射时应跳过并保留可诊断计数。

### 播放

搜索、UP 投稿、合集条目和收藏条目对应单个视频 URL，默认播放 P1。列表摘要的时长可能汇总所有分 P，即使收藏条目包含 `ugc.first_cid` 也不能直接作为单曲时长。读取当前列表页时，以最多三个并发请求获取视频详情，保留条目顺序并采用 P1 的 CID 和时长；不得提前读取后续列表页或播放地址。已失效视频保留条目但时长未知，不能回退到总时长；其他错误保留为可重试的列表页错误。合集 URL（`space.bilibili.com/<mid>/lists/<seasonId>`）仍对应惰性列表，带 `?p=` 的视频 URL 则指定其中一个分 P。

已保存但缺少 CID 的曲目也应先根据视频 URL 选择分 P，再解析媒体，不以 `view.duration` 兜底。播放确认的有限正时长会更新普通歌曲的本地资料库元数据，因此现有喜欢项播放后即可修正时长，保留喜欢时间、自定义名称、歌单成员关系和当前播放上下文。自定义歌曲时长仍由配方决定。这些是离线测试覆盖的适配器和工作台规则，不增加网站、GM 或 Rust 的实测验收证据。

先用 `view?bvid=` 获取所选分 P 的 `pages[].cid`。视频链接导入根据正整数查询参数 `p` 匹配 `pages[].page`，未指定时默认 P1。时长取该分 P 的 `duration`，多 P 视频的标题取 `part`；`view.duration` 是所有分 P 的总时长，不能作为单曲导出区间。P1 保留原曲目 ID，后续分 P 在 ID 后追加稳定 CID，并在来源页面 URL 中保留 `?p=`，使队列、缓存和下载区分不同分 P。所选分 P 不存在时明确报错，不能静默改为 P1。B 站宿主页用 `fnval=16` 请求 DASH，只选择 `dash.audio[]`，按 `bandwidth` 选最高可用项并保留 `backupUrl`。地址带有效期，每次播放重新解析，不能存入历史、标签或自定义歌曲。

2026-09-03 复测确认：同一 DASH 响应可同时给出多个音频 representation，稳定可消费字段为 `id`、`bandwidth`、`mimeType/mime_type`、`codecs`、`baseUrl/base_url` 与 `backupUrl/backup_url`。播放器默认按 `bandwidth` 选择最高项，音质 ID 使用 representation ID 与编码组合；切换时仍重新请求 `playurl` 并校验所选 ID 确实存在，不把短时 URL 当作选项身份。

2026-08-24 复测确认：DASH 音频 CDN 地址在 B 站页面可以由 `<audio>` 加载，但在其他宿主页会返回 403；`referrerpolicy="no-referrer"` 和 `crossorigin="anonymous"` 均不能绕过。非 B 站宿主页应改用 `platform=html5` 的 `durl[]`，该地址可由原生媒体元素按 Range 加载。兼容流是音视频合并 MP4，流量高于纯音频 DASH，因此只在跨站场景启用；不得改为 GM 整段下载后生成大 Blob。

2026-09-03 复测确认：HTML5 模式以最高 `qn` 请求时，响应的实际 `quality` 可能低于 `accept_quality[]` 中声明的最高项。适配器只展示不高于本次实际授权 `quality` 的档位，并使用同索引的 `accept_description[]` 作为文案；切换后若返回的实际 `quality` 与请求不一致，则判定该档当前不可用，不能静默播放另一档。

导出与原生播放不同：Mediabunny 需要由 GM HTTP 主动读取完整媒体字节。B 站 DASH、HTML5 和老音频 CDN 的二进制请求必须显式携带固定 `Referer: https://www.bilibili.com/`，否则主节点与备用节点可能全部返回 HTTP 403。该请求头只存在于即时 `ResolvedMediaSource`，不得持久化，也不得从当前宿主页动态复制；Cookie 仍由 GM HTTP 的 `credentials: 'include'` 独立控制。

2026-08-26 针对 UP 投稿复测确认：`view` 返回的首分 P `cid` 与 DASH 文件名中的资源段一致，`30280` representation 返回有效的 AAC/MP4 字节并支持 Range。浏览器原生 `<audio controls>` 暴露的下载动作不属于上述接口契约，它会绕过应用的 GM 请求头、备用节点和转码流程，失败时可能把 CDN 错误页保存为 `<cid>-1-<representation>.htm`。播放器必须通过 `controlslist=nodownload` 隐藏该入口，并把用户下载意图转交应用导出流程。

## 3. WBI

`nav.data.wbi_img` 返回 `img_url` 与 `sub_url`。取两个文件名去扩展名后拼接，按 B 站固定重排表生成 32 字符 mixin key；业务参数加入秒级 `wts`，按键排序、编码并过滤 `!'()*`，最后计算 MD5 得到 `w_rid`。

适配器只缓存派生 key 的短时间窗口，不缓存 `nav` 登录结果。遇到 `-352` 或 `-412` 进入风控/限流错误，不尝试绕过；遇到 `-101` 把会话转为过期。

## 4. URL 识别

当前导入器支持：

- `space.bilibili.com/<mid>/lists/<seasonId>`；
- `space.bilibili.com/<mid>/upload/video`；
- `space.bilibili.com/<mid>/upload/audio`；
- `space.bilibili.com/<mid>/search?keyword=...`；
- `space.bilibili.com/<mid>/favlist?fid=<mediaId>`；
- `www.bilibili.com/video/<bvid>`，可携带 `?p=<正整数>` 导入指定的单个分 P。

只接受精确的 B 站主机名和数字 ID/BV 号，拒绝相似域名与未知路径。

## 5. 跨站封面

`pic`/`cover` 返回的 `i*.hdslb.com` 图片在抖音等非 B 站宿主页中若携带页面 Referer，会被 CDN 以 403 拒绝。Track 仍保存稳定封面 URL，UI 统一通过 `RemoteImage` 使用 `referrerpolicy="no-referrer"` 显示；不要在 mapper 中拼代理地址或把封面字节持久化。

已在抖音宿主页用同一封面验证：默认 Referer 加载失败，`no-referrer` 可以正常加载。后续若 CDN 策略变化，应先复测该条件，再决定是否增加运行端 GM 图片回退。

## 6. 复测

接口变化时使用项目技能 `$bilibili-contract-capture`。复测至少覆盖：退出登录后的 `nav`；搜索第二页；大型合集第二页；空的音频投稿；私密收藏夹；多分 P 视频；DASH 音频备用节点；登录中途失效；非 B 站宿主页的封面加载；非 B 站宿主页的 HTML5 媒体加载。

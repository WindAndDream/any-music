# 文档变更流程

[English](../../en/guides/documentation-workflow.md)

## 定位应该读的文件

从[文档索引](../文档索引.md)进入，只读相关板块章节、最近的 `AGENTS.md`、实现和测试。查进度或接手时再打开对应的状态文档。实际依赖或契约受影响时才扩展阅读。系统架构指明归属，板块说明记录当前行为，交付矩阵和有明确范围的证据决定哪些目标、场景已通过。如果说明和当前代码冲突，指出差异，并在本次变更中修订归属文档。把用户最新意图写进任务记录。

## 开始与接手变更

增删改代码或配置之前，先在[内容修改中](../变更/修改中/文档索引.md)创建步骤文档并登记索引。用能定位任务的文件名，流转时沿用，保留另一语言的对应页。写清用户要的结果、影响的运行端／板块、步骤和验证方式。需要协调的纯文档任务也可以用同一格式。

**小问题用小流程。几行步骤和一次有针对性的验证就够了。不要过度防御性开发。** 步骤和检查按实际风险及用户意图调整，同一件事的相关修改写在一页。大任务按可独立交付的归属、实现或验收边界拆开。没有实际依赖阻塞时，写完步骤就接着实现。

步骤文档使用 `documentType`、`runtimeScope`（`repository`、`shared`、`userscript` 或 `tauri`）以及下表的状态。一个小修复可以这样写：

```md
---
documentType: change-steps
runtimeScope: userscript
status: in-progress
---

# 恢复入口快捷键

[English](relative-counterpart-path.md)

让宿主页刷新后仍能用配置的快捷键打开入口。

- [ ] 修正入口监听的生命周期。
- [ ] 运行快捷键定向回归。

下一步：查看启动时注册的监听器。
```

把当前状态留在首屏。暂停或交接时勾掉已完成步骤，写清剩余工作和一个可直接执行的下一步，只记录影响下一步的阻塞。搁置使用 `paused`。用户调整方向时，原地更新目标和步骤，有复用价值的旧选项移入[废弃计划](../计划/废弃/文档索引.md)。并行变更各维护自己的步骤和契约范围。

## 验收与收尾

| 状态与归属                                                         | 用法                                                                                                                                               |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `in-progress`／`paused` · [内容修改中](../变更/修改中/文档索引.md) | 还有实现或修复，保留已改范围和下一步。                                                                                                             |
| `awaiting-acceptance` · [修改内容验收](../变更/验收/文档索引.md)   | 实现可以验收时移动步骤文档，测试常见受影响场景，按运行端和范围记录实际结果。失败和未运行的必验场景继续开放。                                       |
| `passed` · [修改内容验收](../变更/验收/文档索引.md)                | 约定范围的检查通过后标记通过，并更新板块契约和相关矩阵。以后还要用到的决定或证据，留一份短记录。                                                   |
| `temporary-accepted` · [临时验收](../变更/临时验收/文档索引.md)    | 用户明确允许未完成或未通过的范围先使用／交付后才移入。记决定与日期、允许的范围、缺口、受影响的场景和复验动作。复验时移回验收，需修复时移回修改中。 |
| `proposed` · [未来计划](../计划/未来/文档索引.md)                  | 可选方向。选定后把当前要做的一批转成步骤文档，其余设想按需保留链接。                                                                               |
| `discarded` · [废弃计划](../计划/废弃/文档索引.md)                 | 只留值得回看的备选方案、搁置原因和重启条件。重启时新建或移动为步骤文档。                                                                           |

一项变更在每种语言中只保留一份当前记录，只登记在一个状态索引。移动时同时更新入链。可独立验收的范围可以拆成单独记录。用户缩小验收范围时，记录约定以及实际跑过的检查。临时放行仍保留已知缺口。原生能力和目标准入遵循各自契约。

证据要对应构建、运行端和场景。网页、安装后的 GM 和 Rust 的证据分开记录。只有用户在当前任务明确要求时才进行浏览器、应用或设备实测。按变更运行仓库检查，提交前执行对应门禁。日常结果直接汇报，只保留支撑开放场景、当前准入、安全、恢复或可复现对照的证据和原始标识。

## 同步双语和现行说明

实现行为和已知限制随变更更新到所属板块。代码已存在、运行端还要实测时，从板块链接待验收记录。保持总览和索引短小。保留准确的标识、界面文案、上游字段，以及平台契约的 `documentType`、`platform` 和真实 `captureDate`。语言与结果汇报见[开发工作流](开发工作流.md)。

收尾检查相关链接、锚点、双语对应和格式。将仍有用的决定与证据归位后，清理已完成的步骤和重复报告。删除记录或基线前先检查入链、代码及检查命令是否依赖。值得回看的废弃方案独立保留。

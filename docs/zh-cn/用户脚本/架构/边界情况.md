# Any Music Userscript 边界情况

英文对应页：[Any Music Userscript Edge Cases](../../../en/userscript/architecture/edge-cases.md)。

适用范围：Userscript 宿主页注入。桌面 embedded WebView 不继承本页的 GM 权限、Shadow Host 守护或悬浮挂载规则；共享组件仍遵守[跨端 UI 契约](../../跨平台/功能设计/跨端界面与交互规范.md)。

## 1. 文档目标

Any Music Userscript 需要把同一套悬浮面板注入不同网站。目标网站的 DOM 结构、样式规则、路由行为、快捷键和安全策略都不可控，因此不能把 Shadow DOM 当作完整的隔离层。

本文件记录跨站注入时需要长期关注的兼容性边界，并明确每类问题的处理原则和代码归属。当前重点包括：

- 宿主节点的挂载位置、重复注入与意外移除。
- Shadow DOM 内外的样式继承和变量污染。
- `rem` 等依赖目标页面根节点的尺寸单位。
- 鼠标、键盘、焦点与页面快捷键之间的冲突。
- Tampermonkey 沙箱、CSP、Trusted Types 与权限配置。

## 2. 隔离边界概览

| 边界     | 典型风险                                                  | 处理原则                                                  |
| -------- | --------------------------------------------------------- | --------------------------------------------------------- |
| DOM      | 页面重建 `body`、删除宿主节点或重复执行脚本               | 挂载到 `document.documentElement`，幂等创建并监控节点存活 |
| CSS      | 继承属性和 CSS 自定义属性进入 Shadow Tree                 | 在受控根节点显式建立样式基线，变量统一使用 `--am-*`       |
| 尺寸     | `rem` 跟随目标页面根字号变化                              | 优先使用 `px` 或受控的局部 `em`                           |
| 事件     | 组合事件穿过 Shadow 边界，快捷键同时触发页面行为          | 只在面板处于交互上下文时响应，并精确阻止相关事件          |
| 安全策略 | 执行上下文、CSP 和 Trusted Types 因浏览器或配置不同而变化 | 最小化权限与动态注入，按目标浏览器实测，不依赖隐式绕过    |

## 3. 宿主节点与挂载生命周期

### 3.1 挂载到 `document.documentElement`

悬浮面板的宿主节点应作为 `<html>` 的直接子节点，与 `<body>` 平级，而不是挂在目标网站的业务容器中。

这样可以降低两类风险：

- 目标网站的祖先元素可能设置 `transform`、`filter`、`perspective`、`contain` 等属性，改变后代 `position: fixed` 元素的包含块，使面板不再稳定地相对视口定位。
- 部分 SPA 会在路由切换时整体替换或清空 `<body>`。宿主节点位于 `<body>` 外时，不会随其业务 DOM 一起被删除。

该策略只能减少被目标页面布局影响的概率。目标网站仍然可以直接修改 `<html>`、操作 `<any-music-root>`，或使用极端的全局样式和脚本干预宿主节点。

### 3.2 使用低碰撞标签并保证幂等

宿主节点使用 `<any-music-root>`，避免裸 `<div>` 被目标网站面向通用标签的查询或批量操作误选中。

低碰撞标签本身不负责去重。脚本执行前仍需查询现有宿主节点；找到节点时直接结束挂载，避免热更新、重复安装或异常执行创建多个应用实例。

不应依赖重复调用 `customElements.define()` 抛错来判断是否已经挂载。自定义元素注册表和页面中的实际应用实例不是同一类状态，显式查询宿主节点更直接。

### 3.3 恢复被移除的宿主节点

目标网站可能在顶层 DOM 更新时误删宿主节点。挂载成功后使用 `MutationObserver` 监听 `document.documentElement` 的直接子节点；发现当前实例的宿主已经离开文档时，将同一节点重新追加：

```ts
const observer = new MutationObserver(() => {
  if (!document.documentElement.contains(host)) {
    document.documentElement.append(host)
  }
})

observer.observe(document.documentElement, { childList: true })
```

卸载时必须先断开观察器，再卸载 Vue 应用并删除宿主节点，否则主动删除会触发自动恢复。

如果某个网站持续高频删除宿主节点，不应无限增加观察范围或与页面脚本反复争夺 DOM。此时应记录为平台兼容问题，并考虑站点级降级或禁用策略。

## 4. Shadow DOM 的样式边界

### 4.1 Shadow DOM 能隔离的内容

Shadow DOM 可以阻止目标网站的大部分普通选择器直接匹配面板内部节点，也可以避免组件选择器意外作用于页面内容。共享 UI 样式必须注入 Shadow Root；注入到页面 `<head>` 的样式无法正常覆盖 Shadow Tree 内部组件。

Shadow DOM 不会隔离所有样式输入。以下值仍需主动控制：

- `color`、`font-family`、`font-size`、`line-height` 等可继承属性。
- 从 `<html>`、页面容器或 Shadow Host 继承的 CSS 自定义属性。
- `color-scheme` 对原生表单控件和滚动条外观产生的影响。
- `rem` 等仍以外部文档为基准的单位。

### 4.2 显式建立宿主基线

`apps/userscript/src/styles/host.scss` 负责隔离边界上的平台样式，应在 `:host` 中重置继承值并声明确定的显示环境：

```scss
:host {
  all: initial;
  color-scheme: light;
  font-size: 16px;
  line-height: normal;
}
```

`all: initial` 不会重置 CSS 自定义属性，因此不能只依赖这一条规则解决变量污染。

Shadow Root 内还应统一使用 `border-box`，避免目标网站的盒模型习惯影响组件尺寸判断。

### 4.3 设计变量必须显式声明

CSS 自定义属性可以沿继承链进入 Shadow Tree。目标网站可能在 `:root` 或其他祖先上声明 `--primary-color`、`--spacing` 等通用变量；组件引用同名变量但未提供本地值时，就会意外使用页面设计系统。

Any Music 的处理规则是：

- 自定义属性统一使用 `--am-*` 前缀。
- 所有共享设计变量都在 `.am-root` 上提供默认值。
- 组件只读取已纳入 Any Music 设计系统的变量，不直接依赖目标网站变量。
- 主题切换通过修改 `.am-root` 的受控变量完成，不修改目标网站的 `:root`。

## 5. 尺寸、定位与层叠

### 5.1 避免使用 `rem`

`rem` 始终相对外部文档 `<html>` 的根字号计算，Shadow DOM 不会改变它的基准。不同网站可能把根字号设置为 `10px`、`62.5%`、`16px` 或响应式值，因此同一份面板样式会出现不可预测的缩放。

共享组件应遵循以下规则：

- 固定尺寸、圆角、间距和边框优先使用 `px`。
- 需要随组件字号缩放时，使用基于受控父节点字号的 `em`。
- 不引入默认大量生成 `rem` 的样式方案；确需引入时，必须在构建产物中确认单位已经转换或隔离。
- 不通过修改页面 `<html>` 的字号修正面板尺寸，这会破坏目标网站布局。

### 5.2 明确定位和层叠上下文

面板需要悬浮时，由 Userscript 宿主样式负责 `position: fixed`、视口偏移和 `z-index`，共享 UI 组件不决定平台特有的定位。

`z-index` 应使用项目内统一常量，并选择足以覆盖常见页面浮层的值。即使数值很高，也不能保证覆盖浏览器原生界面、全屏元素、Top Layer 中的 `<dialog>` 或 `popover`；这些情况需要接受平台限制或设计专门的降级行为。

## 6. 事件、快捷键与焦点

部分具有 `composed` 特征的事件可以从 Shadow Tree 穿过边界，并继续在页面中传播。视频和音乐网站通常还会在 `document` 或 `window` 上注册空格、方向键等全局快捷键，因此面板不能只处理点击穿透。

键盘交互应遵循以下规则：

- 只有焦点位于面板内，或产品明确规定的其他激活条件成立时，才响应面板快捷键。
- 只对已消费且会与页面冲突的按键调用 `preventDefault()` 和 `stopPropagation()`。
- 输入框、文本域和可编辑元素应保留正常文本输入行为。
- `Escape`、`Tab` 等按键需要同时考虑关闭浮层、焦点循环和焦点归还。
- 不在 `window` 上无条件拦截所有键盘或指针事件，以免破坏目标网站的基本操作。

对于拖拽、调整尺寸和悬浮菜单，还需要测试指针离开 Shadow Host、窗口失焦以及组件卸载时的清理行为，避免残留全局监听器或错误的拖拽状态。

## 7. Tampermonkey 沙箱与安全策略

### 7.1 权限遵循最小化原则

`@grant` 用于声明实际使用的 `GM_*` 能力。`@grant none` 会禁用 Tampermonkey 沙箱；使用具体授权时，脚本可以访问对应 API，但不能把“存在非空 `@grant`”视为在所有浏览器、Tampermonkey 设置和执行上下文中自动绕过 CSP 或 Trusted Types 的保证。

权限配置应满足以下要求：

- `grant` 与 `apps/userscript/src/platform` 中实际调用的 API 保持一致。
- 删除不再使用的权限，不为切换沙箱而申请虚假权限。
- `connect` 在开发阶段可以放宽，发布前应收窄到实际音乐服务域名。
- 只有确实需要访问页面 JavaScript 对象时才使用 `unsafeWindow`，并隔离相关适配代码。
- 需要控制执行世界时，单独评估 `@sandbox`、目标浏览器和 Tampermonkey 版本的行为。

### 7.2 降低 CSP 与 Trusted Types 风险

页面安全策略可能限制脚本执行、资源加载、动态 HTML 或样式注入，具体表现与执行上下文有关。实现时应优先使用可预测的 DOM API：

- 使用 `textContent` 写入样式和纯文本，不用 `innerHTML` 拼接不可信内容。
- 不从目标网站字符串直接创建 HTML；确需渲染富文本时先建立独立的清洗策略。
- 外部字体、图片、脚本和音乐资源需要分别考虑页面策略、跨域规则与 Userscript 权限。
- 第三方 `<img>` 默认会携带当前宿主页 Referer；跨来源封面统一使用 `referrerpolicy="no-referrer"`，并验证来源 CDN 的防盗链行为。
- Userscript 运行依赖默认随产物打包，避免每次 SPA/页面打开都请求 CDN；如果确需 `@require`，必须锁定精确版本并验证离线、更新和缓存语义。
- 在 Chromium 和 Firefox 的严格 CSP 页面上分别验证，不用单一测试站点推断全部行为。

## 8. 代码职责归属

| 能力                                 | 代码位置                               | 说明                                |
| ------------------------------------ | -------------------------------------- | ----------------------------------- |
| 创建 Shadow Root、节点守护、完整卸载 | `apps/userscript/src/platform/dom`     | 只属于页面注入环境                  |
| Shadow Host 重置、固定定位、平台层级 | `apps/userscript/src/styles/host.scss` | 处理面板与目标页面的边界            |
| 设计变量、共享组件样式               | `packages/ui/src/styles` 和组件 SFC    | 可被 Userscript 与 Tauri 渲染端复用 |
| 焦点和组件内部交互                   | `packages/ui`                          | 通过 props 和事件暴露应用契约       |
| Tampermonkey 权限与匹配范围          | `apps/userscript/vite.config.ts`       | 与平台适配器的实际能力同步          |
| 音乐播放与快捷键语义                 | `packages/core`                        | 不包含 DOM 监听或 `GM_*` 实现       |

不要为了处理跨站兼容问题，让 `packages/ui` 直接操作外部页面 DOM，也不要让 `packages/core` 感知 Shadow DOM 或 Tampermonkey。

## 9. 兼容性验证清单

发布前至少验证以下场景：

1. 脚本重复执行时只存在一个 `<any-music-root>` 和一个 Vue 应用实例。
2. 清空或替换 `<body>` 后，面板仍然存在并可交互。
3. 手动删除宿主节点后，观察器能恢复同一实例；主动卸载后不会再次恢复。
4. 页面设置极端根字号、字体、行高和同名 CSS 变量时，面板视觉保持稳定。
5. 页面启用暗色 `color-scheme` 时，面板的表单控件与滚动条符合自身主题。
6. 页面祖先包含 `transform`、`filter` 或 `contain` 时，面板仍按预期相对视口定位。
7. 空格、方向键、`Escape` 和 `Tab` 在面板内外分别产生正确行为。
8. 拖拽中断、窗口失焦和组件卸载后没有残留全局事件监听器。
9. SPA 路由切换后无需重复初始化，页面功能和面板状态都保持正常。
10. Chromium 与 Firefox 的严格 CSP 页面上可以完成挂载、样式注入和必要的跨域请求。
11. 在 B 站、抖音及无关第三方页面中交叉显示各来源封面时，不出现 Referer 防盗链 403，失败图片能回退为占位。

新增跨站能力时，应先把失败模式补充到本清单，再决定由平台适配层、共享 UI 还是业务层处理。

# Cross-Platform UI and Interaction

Chinese counterpart: [跨端界面与交互规范](../../../zh-cn/跨平台/功能设计/跨端界面与交互规范.md).

## 1. Document Status

This page defines the long-term visual and interaction contract for the Any Music product UI. Production consumers are apps/userscript and apps/tauri, sharing ui/music-workbench. Userscript mounts floating/Shadow UI on host pages; desktop uses embedded layout and native ports. Native mobile adapters remain unaccepted; mobile web layouts do not imply native capabilities.

The product userscript now has a framework-free launcher, a Vue/Pinia shell loaded on first expansion, a side-switchable and collapsible navigation rail, light/dark/system themes, persisted navigation order and visibility, a mobile drawer and optional bottom navigation, and the source, playback, library, segment, download, history, and plugin modules shared by the runtime applications. Classic shell/player, source/search/catalog and library/queue/history/download presentation are maintained in `packages/theme-default`, with neutral contracts, reusable primitives/headless composables and protected host UI in `packages/ui`; the userscript consumes shared music-workbench business behavior and binds GM/browser capabilities. This is the product baseline, not proof of release readiness: real host-page visual regression, touch-device verification, and output-size acceptance still remain.

T11 applications now compose complete independent classic/Studio roots from build-owned metadata, loaders and an explicit classic fallback. One stable workbench/controller/audio owns business and editing state. Shared/SFC/theme CSS values enter the internal presentation Shadow surface; protected account/native controls and their detail-overlay target stay within separately styled host surfaces. Production graph audits and Node loader/host tests are automated evidence; visual/focus/installed-runtime acceptance remains T13.

## 2. Design Principles

- Put music and meaningful actions first. Use spacing, typography, surface color, and restrained shadow for hierarchy; do not add decoration without information or interaction value.
- Keep domain terms, navigation IDs, theme tokens, state semantics, and outcomes consistent across runtimes. Follow platform layout and input conventions instead of demanding pixel identity.
- Make loading, empty, unavailable, expired, validation, partial-success, and retry states understandable without relying on color alone.
- Use the controlled `AppIcon` catalog and accessible control names. Do not substitute Emoji, Unicode glyphs, or text characters for product icons.
- Render third-party artwork through the runtime's remote-image boundary with no Referer and a stable fallback.

### 3.1 Corner Radii

The product shell, global settings, Music Lists, and search/track lists use restrained corners that remain softly rounded. Choose radii by purpose; wider cards and mobile layouts do not need larger corners. Spacing, surfaces, and borders provide the main hierarchy.

| Purpose                                                               | Token                 | Radius |
| --------------------------------------------------------------------- | --------------------- | ------ |
| Status labels, counts, artwork captions, and compact tags             | `--am-radius-detail`  | 4px    |
| Ordinary buttons, inputs, selects, and segmented buttons              | `--am-radius-control` | 6px    |
| Artwork, list rows, and option rows                                   | `--am-radius-sm`      | 8px    |
| Music-list/track cards, settings groups, and segmented-control frames | `--am-radius-card`    | 10px   |
| Embedded panels and empty states                                      | `--am-radius-panel`   | 12px   |
| Product shell, dialogs, and sheet frames                              | `--am-radius-overlay` | 14px   |

Nested elements use smaller corners than their frame; edge-aligned buttons follow the frame boundary. Ordinary text buttons and status labels avoid pill shapes. Switch tracks, sliders, circular playback buttons, drag handles, and small dots retain their functional circles or capsules. Full-screen surfaces, inner rows of continuous lists, and existing underlined inputs keep square corners. Radius changes never shrink hit targets or clip keyboard focus rings.

These roles cover the designed pages and shared shell/overlay infrastructure, including plugin-center cards, controls and badges. Favorites, playlists, the library, creation and downloads retain their existing size tokens until their own design pass. Shared track cards and artwork receive local list styles so other business pages are not restyled; later designs can adopt these roles where appropriate.

### 3.2 Scrollbars

All visible scrollbars inside `.am-root`, including new scroll regions, use the shared `@any-music/ui/styles` defaults. Chromium/WebKit uses a 6px rail with a rounded 4px visible thumb, transparent track, and no arrow buttons. The thumb uses primary text at 20% opacity and increases to 36% on hover or drag, following the light/dark theme through `--am-color-scrollbar-thumb` and `--am-color-scrollbar-thumb-hover`. `--am-size-scrollbar` owns the rail thickness.

Browsers without scrollbar pseudo-elements use standard thin scrollbars and increase thumb contrast when the scroll region is hovered. Keep these branches separate: standard non-auto scrollbar properties override Chromium pseudo-element styling. New components inherit the shared defaults without local scrollbar sizing or colors. Existing intentionally hidden rails retain their behavior; forced-color mode uses native scrollbars. Styles stay within the product root and never restyle a Userscript host page.

## 4. Product Shell and Navigation

### 4.1 Web, Tampermonkey, and Desktop

Wide layouts use a Grid shell: a left/right and collapsible navigation rail, contextual top bar, scrolling content, and a bottom player while media is selected. Users control destination order and visibility; settings remains at the rail footer. Tampermonkey additionally keeps a show/hide affordance. Hiding changes visibility and must not silently destroy an active playback or download session.

Sidebar position controls the system navigation and mobile drawer side, the corresponding expand/collapse arrow, and the mobile drawer button. The mobile button sits at the matching left or right edge of the classic top bar, including pages without source context. The desktop top bar, sticky back bar, track cards, bulk action bar, and preference controls keep a fixed arrangement without mirroring. The content region still yields space to the shell grid normally. The classic top bar copy shows only the left-aligned page title; title and source context retain their reading order when the mobile button changes sides.

Medium viewports (768px < width ≤ 1024px in browser CSS pixels) default to an icon-only rail, but the first toggle must expand it and the next must collapse it. Manual actions take precedence within the current breakpoint; crossing breakpoints restores the applicable layout defaults. Automatic collapse does not overwrite persisted desktop preferences, while manual actions save the user's choice. Toggle labels and accessibility state reflect the visible state. Keep icon columns, brand-row height, and text nodes stable during toggles. Animate the desktop shell's sidebar track with `--am-motion-normal` and `--am-ease-emphasized`, moving the top bar, content, and player together while labels fade. Keep text unwrapped and navigation free of horizontal scrolling. Changing sides or entering/leaving the mobile layout settles immediately; reduced motion disables sidebar and text transitions.

Customize Interface opens interface-theme, sidebar-position, and color-theme choices from buttons showing the current value. The selected option receives initial focus; choosing an option applies it immediately and closes the dialog. The underlying settings sheet suspends modal input until the picker closes and focus returns to its trigger. Mobile bottom navigation uses a button with an explicit enabled/disabled state, fixed to the left of its description. Desktop navigation ordering retains wider up/down buttons. Mobile layouts keep only a square 44px drag handle, the destination name in the middle, and visibility/required status on the right. The handle always supports Space/Enter to start, arrow keys to move, and keyboard completion/cancellation.

The player bar shares one playback order setting with Listen Later, Favorites, and playlists: sequence, repeat one, shuffle, and shuffle without repeats. Starting a track from a playlist uses that playlist's track order as the playback context. Buttons open dialogs for playback order, quality, speed, and volume. The seek bar shows a prohibited pointer while seeking is unavailable. Labels and track metadata stay on one line or truncate as space narrows.

The player bar and expanded player reuse the shared download manager. Each Download click shows a top notification with the song name and its current queued, downloading, downloaded, failed, cancelled, or interrupted state, preserving the page and focus without opening a modal dialog. Notifications reuse the operator's AppToast, semantic color containers, and AppIcon: downloaded uses a green check, queued/downloading use a teal clock/download icon, paused uses an amber pause icon, interrupted uses an amber warning, temporarily unavailable uses an amber clock, failed uses a red warning, and cancelled uses a gray close icon. Colors follow the light/dark theme. Status and success notifications disappear after three seconds; failure notifications disappear after five seconds. Repeated clicks immediately replace the notification and restart its timer. Later progress changes do not automatically show notifications, and download messages do not remain in the bar or playback status. Active tasks prevent duplicate submissions. Saved records remain eligible for another download; the runtime verifies the saved file before skipping work. The next click also restarts paused, failed, cancelled, or interrupted downloads, including cancelled file saving (AM-1005). Generated files count as downloaded only after the batch saves successfully; cancellation or save failure must not report success. Late results from an old task cannot overwrite a new task or another song. Paused tasks resume explicitly from the Downloads collection; resume reacquires media and preserves the task record.

The PC player bar keeps three columns for track metadata, transport, and settings. Equal-width outer columns align transport with the horizontal center of the whole bar. When the player slot width requires two or three rows, transport remains centered with a bounded width. Mobile pagination wrappers do not establish layout boxes on desktop; they must neither occupy a column nor inherit the two-column shared layout. Only phone layouts enable the paging viewport and sliding pages. Desktop keeps its existing button sizes and pill feedback.

Listen Later reuses the catalog's track cards, display density, mobile column preference, background region, and restrained radii. The heading uses the same font size and 44px title row as catalog-page__context, shares horizontal padding with the grid, and shows actual queue order. An inset gray surface contains the heading and tracks, sharing the Discover track page's outer width and horizontal track padding without another width limit; the surface fills the available page height by default and grows with longer content, surrounded by the existing page background and bottom padding. Desktop totals use a theme-colored badge and bold number. Phones omit the content intro and show the full queue count at the top right. Platform and account context appears only in Discover. “All tracks / By platform” stays left as a direct collection grouping control. Display mode has one entry immediately before Filter in the lower toolbar at every width; narrow containers may use an icon with the same accessible name and target. Entries match Search/Import at 12px text and at least 44px height. Catalog state buttons and track-page header buttons share the 650 font weight of the Listen Later display entry. The toolbar sticks after scrolling past its original position, keeping arrangement on the left. Display settings reuse the catalog's density and phone column preferences. Density changes share grid movement animations; arrangement changes slide only the list content in both directions, keeping the intro, toolbar, and background surface in place, with movement disabled for reduced motion. Playback mode remains available in the player. Platform entries reuse CollectionCard and CollectionGrid with an ideal column width of 320 CSS pixels, independent of host-page root font sizes, and a 16px gap. Columns follow the actual content width; narrower regions use one column. Long names and count summaries truncate on one line with full text hints. Cards use 10px radii, theme icons, counts, type labels, and playback badges; selection controls remain separate from the view button. The platform overview omits breadcrumbs. Listen Later containers up to 600px wide use compact horizontal platform cards, placing the type before the count on a shared summary line. Actual text measurements remove the Source / Local composition prefix first when it does not fit; remaining count overflow is clipped on one line with a full text hint, wrapping playback badges as space allows, and keeping an independent 44px selection target on the right. The view button retains horizontal padding and room for its full arrow animation, reducing vertical footer spacing and card gaps. Opening a platform slides the whole page, including its intro, toolbar, and content, in both directions. Platform track details reuse the catalog sticky return header, title and summary font sizes, 44px context title row and horizontal text padding, collapsible context, with Display mode in the lower toolbar, showing platform name, queue counts, and playback status without repeating the overview intro or arrangement controls. Back to platforms restores the overview scroll position and entry focus. Leaving views become inert immediately, and reduced motion disables movement. The platform overview, All tracks, and platform track details retain the Operator entry, panel, and selected count. Each platform checkbox selects its currently matching tracks and displays a mixed state for partial selection; activating a fully selected checkbox clears that platform's matching selection. Selection is shared with track views, and bulk download and removal keep the existing track counts and confirmation rules. Selection, select all, download, removal, and counts in detail apply only to matching tracks from that platform. Empty filtered details retain navigation; removing the final platform track returns to the overview. Platform entries support two-dimensional drag and arrow-key reordering, while tracks stay within their platform. CollectionCard, CollectionGrid, CollectionBreadcrumbs, and useCollectionNavigation provide the same entry and navigation foundation for future playlists. Switching to platform arrangement preserves each platform's track order and persists contiguous platform blocks. Cards share Play, Favorite, Download, and Actions with search results. The shared actions dialog preserves custom names, tags, segment creation, and source links, groups Play, Listen later, Favorite, and Download into four compact columns matching catalog track actions. Listen later is selected for queued tracks; toggling it off retains the removal confirmation, with no separate Remove from Listen later button. The ordering row contains Move later, Move earlier, and Pin, with name, tag, segment, and source options in a final group. Spacing and dividers separate groups; catalog track actions use the same four-column layout and separation. Enabled actions and options change background on hover or keyboard focus and give icons a small translation or scale when motion is allowed. Moves remain disabled at the appropriate boundary. Track cards in both All tracks and platform details omit dedicated drag buttons. A short artwork press selects only while the operator is open; holding for 500ms activates dragging with a raised outline and a top teal info notice with a reorder icon: “Drag sorting is ready. Move to reorder; release to finish.” It appears once per successful activation, dismisses after 3 seconds, and does not take focus or intercept dragging. Once the hold activates dragging, tracks, platform cards, child controls, and content gaps share the four-way move cursor; release or cancellation restores their usual cursors. Movement over 8px or scrolling before activation cancels the hold; touch dragging takes over only after activation. The synthetic click after release does not change selection. Artwork supports arrow-key movement and Escape cancellation; Actions retains Move earlier, Move later, and Pin. The top-right selection control appears only in operator mode and stays independent of reordering. Platform overview cards omit dedicated reorder handles. In selection mode, a short checkbox press selects tracks; holding the platform card or its selection area for 500ms activates whole-group dragging with the same top info notification and cancellation rules. The synthetic click after release neither changes selection nor opens platform details. The grid adds no extra padding, keeping heading controls aligned with the tracks; the container bounds horizontal reorder overflow. Tracks reorder within their platform, and complete platform blocks can move. Mobile retains these controls without an additional side drawer.

In platform arrangement, queued local compositions have a separate “Custom music” group with a segments icon, theme-colored title, and “Local composition” text badge to distinguish them from a source with the same name. Stable source identity and media kind determine group identity, rather than display names. The right-hand badge follows the actual player's track and state, showing “Playing” or “Paused” in narrow containers, the platform overview, and track details. Selection alone, initial resolution, playback failure, or previews of tracks outside the queue do not infer a playback badge from queue selection.

The catalog's Filter / Operator launcher, selection and match counts, and scroll-to-top action appear above the player. Scroll-to-top targets the shell content scroll region directly rather than invoking the lazy feature wrapper; page changes, hiding, and modal panels cancel previous scrolling. The nonmodal track operator defaults to Add to Listen Later, Download Selected, Add to Favorites, and Add to Playlist, with Select All on the upper row. Hide the corresponding add action when every selected track is already queued or favorited; an empty selection keeps all four disabled actions. A red Remove from Listen Later action is appended at the far right and disabled without a selection. It confirms batch removal and keeps library records; individual track removal remains available. Select All and Deselect All show the shared top notification with the selected track count or confirmation that selection is cleared. Filters reuse isolated drafts, overview, history, calendar, and live preview for text, user tags, duration, platform, and addition date. Dimensions intersect; multiple tags, platforms or date ranges within a dimension form a union, with inclusive end dates. Platform details omit the platform dimension because navigation already limits their songs; tag choices and preview counts use that platform's songs. Addition dates record actual queue insertion, survive duplicate additions, sorting and refresh, and renew after removal and re-addition. entries without this metadata remain available and show an unknown date; they do not match date filters. Library or publication dates do not substitute for queue dates. Cancel discards the draft; Apply changes the list and removes hidden tracks from selection.

Filtered reordering changes only matching tracks' existing slots, preserving hidden tracks' positions. Platform moves reorder matching platform slots as complete blocks, preserving unmatched platforms' relative placement and internal track order. Pin and keyboard movement use the same matching set. Dragging snapshots fixed slots, preserves outer layout, and floats inner cards over neighbors that smoothly make room. Hit testing ignores animated card positions to prevent repeated swaps. Release saves once and settles the card from its release position without stacking another FLIP animation. Returning to the original slot, Escape, pointer cancellation, filter or queue changes, window resizing, deactivation, and disposal cancel uncommitted previews. The stable list container owns pointer capture. Hit testing and edge scrolling run at most once per animation frame. Movement uses transform, keeps offscreen content visibility and the floating card visible, avoids persistent will-change on every card, and respects reduced motion. Actual host, desktop-window, touch-device appearance, and frame timing have not been rechecked for this refactor.

The stable product destinations are Discover, Listen Later, Favorites, Playlists, Custom Tracks, Tags, Segment Creation, Downloads, Playback History, and Plugins. Downloads includes saved records through its Downloaded selector; there is no separate Download History destination. Custom Tracks and Segment Creation are two sections of the same optional `feature.composer` plugin and share its enable/disable lifecycle. Labels may evolve without changing stable IDs. Persistence must discard unknown IDs, add new required destinations, and prevent core destinations from being hidden.

Favorites uses the same track grid, platform cards and detail navigation, display density, mobile columns, filters, operator, scroll-to-top control, and drag ordering as Listen later. Desktop shows a Favorites heading and total count; mobile shows the total in the top bar. Introductions, empty states, platform summaries, filters, and removal actions use Favorites wording. Dates and date filters use the actual favorite timestamp. Favorites owns separate filter history and retention settings. The default order is newest favorite first; manual order and arrangement preferences persist only stable track IDs, independently of Listen later, without changing favorite dates. Unfavoriting removes the saved position; favoriting again treats the track as newly added. Playback uses the currently filtered platform scope as a temporary collection. Track actions retain the Listen later toggle. The ordering row matches Listen later: Move later, Move earlier, then Pin. Bulk actions reuse the four shared track actions, hiding Add to Favorites for selected favorites. A red Remove from Favorites action is appended at the far right and confirms batch unfavoriting while preserving library records and playlist relationships; individual track unfavoriting remains available. Select All and Deselect All reuse the Listen Later top notifications. Browser, desktop-window, and touch-device visual checks have not been performed.

Playback History shares Favorites' classic collection frame, heading/count typography, platform cards, display controls, empty state, song rows and operator, with history-specific wording and a separate filter scope. Each playback remains a distinct selectable record with its start time and progress, including repeated plays of the same song. Text, user tags, duration, platform and date filters apply to each record; the date is the playback time. Its operator selects visible records and offers playlist, download, queue and favorite actions alongside Play Selected and Clear History. The song Actions dialog retains its four common actions and appends Clear History on the right in the operator's horizontal rail, supporting the overflow arrow, touch swipes and mouse dragging. Clearing requires confirmation and leaves favorites, playlists and downloads intact; a pending confirmation cannot clear history after its initiating presentation is replaced. Runtime layout and device acceptance remain unverified.

### 4.2 Mobile

Android system Back first returns within the active dialog or settings page, then dismisses overlays, collapses the full player, returns from collection details, and finally revisits the previous destination. Account editors return to account details, then to the selected platform's account management. Closing a dialog explicitly still dismisses the whole dialog. Destination history is session-only and bounded to 64 entries; hidden or withdrawn destinations are skipped. Cached inactive views cannot consume Back.

When no page or overlay can go back, the first Back shows the theme-aware top notice `再按一次返回键退出应用`; a second Back within two seconds finishes the Android Activity through Tauri. The confirmation expires and resets on navigation, completed taps, or background/foreground changes. Cancelled pointer sequences do not reset it, so a system Back swipe can complete the pair. Only Android's main WebView receives the native exit permission. These behaviors are covered by offline tests; physical button/gesture acceptance requires a separate device check.

Narrow layouts place the drawer button at the configured navigation side of the top bar; the drawer opens from that same side. The optional bottom navigation contains Discover, Favorites, Playlists, and Profile and shares active state with the drawer. The player, bottom navigation, and safe-area inset jointly determine content padding.

Crossing the 768px mobile breakpoint switches immediately between the desktop rail and a closed drawer, without a drawer exit transition or delayed hiding that could flash during layout changes. Slide and fade transitions apply only to drawer toggles within the same mobile layout; crossing breakpoints or changing sides cancels them, and reduced motion switches immediately.

Holding and dragging the track metadata or blank region upward, or using an explicit expand button, opens the full player sheet; an equivalent keyboard and assistive-technology path is always required. The sheet follows vertical displacement continuously, including slow drags, without requiring speed or a long-press timer. Reversing before release cancels opening; release settles the sheet using a displacement threshold. The expanded header, title, and blank regions support dragging downward to collapse, with short drags snapping back, alongside the collapse button and Escape. Buttons, links, and seek controls retain their own input, and scrolled short-screen content scrolls normally until it returns to the top. Draggable control-bar regions show grab and grabbing cursors. The detail view removes the large artwork, places title and artist at the top, and only displays a separate status when it conveys independent information rather than repeating the artist. A future Tauri mobile entry must not statically bundle desktop-only navigation, full operators, or heavyweight editors and merely hide them with CSS.

Equal-width outer regions center the phone's previous, play/pause, and next group horizontally. Artwork, title, and artist shrink in the left region, with single-line ellipsis for text. The control page preserves the top progress target and adds space above the bottom handle to raise the controls slightly. The control bar's top edge is a thin progress rail with a dot at the leading edge of played progress, fully visible at both endpoints, its own 44px touch target, buffered progress, and keyboard seeking. Horizontal dragging previews time and commits one seek on release; vertical or cancelled gestures never seek. Progress input is isolated from expansion. Horizontal paging and vertical expansion lock their direction after the initial displacement so turning mid-gesture cannot trigger both.

Search/import lists share the track page's outer content width and horizontal padding, allocating columns automatically from the available width without a per-row limit. Request summaries reserve the same two rows for search terms and URLs, truncating long text, while cards in each grid row share height and aligned actions. Only actual timestamp text remains selectable; in operator mode the surrounding blank area selects the card and shows a pointer cursor. Reselecting the player's current track preserves its playback context and displays a shared top toast. It disappears after 2.2 seconds; repeated clicks during display, the 240ms exit, and a 600ms cooldown are ignored without stacking, queuing, extending display, or stealing focus.

The mobile mini player always offers previous, play/pause, and next. In the narrow layout, primary-button mouse dragging shares touch paging; forward mouse-wheel or trackpad input reveals settings and reverse input returns. Inertial input advances only one page per gesture, and zoom gestures do not page. Swiping right or activating its frosted edge arrow reveals playback order, quality, speed, volume, and download; swiping left or activating the back arrow returns to transport controls. The arrow keeps a transparent hit surface with a theme-aware blurred fade around it, without a solid pill background. Both pages slide horizontally, and the outgoing page immediately stops receiving focus and clicks; reduced motion disables the slide animation. Settings and download buttons use consistent rounded rectangular feedback and mobile targets of at least 44px. Horizontal gestures must not activate the button at their endpoint, and cancellation or leaving the mobile layout releases pointer capture. The expanded player also exposes those settings, download, and ten-second jumps, and its background stops receiving focus while a settings dialog is open.

## 5. Page and Operator Patterns

Collection display settings separate **风格选择** (item style) from **排列方式** (density/phone columns). Selecting a category slides to its options; Back returns to the extensible category list. Discover search/import request cards use one default presentation without a style selector or style preference. Whitespace (`留白`) is the initial music-card style; Inline actions (`直显`, stored as `default`) shows common buttons directly on each card. Each board owns its persisted item style in runtime-namespaced `collection-display:*:v1` preferences, separate from density regions. Playlist overview cards use one cover layout and offer arrangement only, including in global defaults. Changing density, groups, status tabs or complete themes never overwrites the item style. Plugin Center is unchanged.

`packages/card-styles` owns reusable controlled item renderers and lightweight style metadata; `packages/ui` owns the separate category/options dialogs. Complete themes adapt readonly player position and named intents; workbench owns persistence, playback and download operations. The 留白 (minimal) music style covers Discover, Listen Later, Favorites, playlist songs, Downloads and History: cover playback with an animated black hover/focus overlay, a three-dot menu, optional batch selection, and a primary-color border showing the active track's real normalized position. There are no card timers. Seeking, loops and density changes read the same clock; end returns the border to zero. Touch keeps playback visible, and reduced motion removes transitions. Existing song tags appear to the right of the duration/status in a single clipped line, using the shared tag blocks. Date/context text is omitted from these music cards; download status remains, and history record identity/details stay available to selection/actions. Cover hold/arrow-key ordering remains available where the collection supports it.

Discover search/import request cards show common actions directly. Search/import timestamps remain visible on desktop and are hidden at viewport widths up to 600 CSS pixels to keep mobile items compact. Status previews stay bounded, and errors open the existing host-owned details dialog. Batch selection, menus, long-press and arrow-key ordering remain available.

The minimal music style uses landscape artwork above its text in wide lists, capped at 200 CSS pixels high, or 240 pixels in comfortable arrangements for slightly taller cards. Lists up to 600 CSS pixels wide use horizontal rows with 72-pixel square artwork; cells up to 260 CSS pixels wide retain small tiles so phone two-column layouts leave enough text width. Hovering scales artwork within its clipped frame; reduced motion disables scaling. The actual playing track shows a waveform on hover/focus with “正在播放，点击暂停”; clicking pauses through the host player action. Paused covers show Play and resume the current track without changing its position or resolving media again. Batch-selection checkboxes overlay the artwork without changing card height or text layout, using the inline-action style’s native checkbox and transparent 44-pixel target. In selection mode the cover only toggles selection, including for playing or invalid tracks, and omits the playback overlay for mouse, keyboard and touch. Closing the operator restores cover playback; supported hold/arrow-key ordering remains available in both modes.

Playlists have one cover-card presentation without a style selector. It reuses the music-card grid and the controlled playlist renderer: landscape artwork above the text, a slightly larger playlist title and one clipped tag row underneath. Song count appears in a shadowed media-caption badge at the artwork's bottom right on card hover or keyboard focus, and stays visible for touch input. Artwork has no sequence number; the menu retains its independent hover background. The cards retain preview, selection and ordering. Node tests cover settings separation, host projections, clock resets and intents; they do not establish browser/GM/WebView layout, focus or physical-input acceptance.

- Main navigation preserves each destination's selections, applied filters, unfinished filter drafts, and Filter/Actions open states within the current workbench session. Leaving a destination hides its overlays and suspends keyboard and focus interaction; returning restores the previous state. Explicitly closing an Actions panel clears its selection and it stays closed on return. Queue, My Favorites, and Discover own these states, display density, and phone column preferences independently; actions and delayed summaries from another destination must not overwrite them.

The inset gray region expands through the shell's remaining content height while preserving outer and bottom padding; Listen Later, Favorites, playlist, and playback-history surfaces also fill that space when items do not fill the page, keeping items top-aligned and the same bottom padding. Collection arrangement and detail transitions adopt the incoming height immediately; outgoing content is clipped to that frame and does not hold the previous height until the animation ends. Center the icon, title, and description as one group horizontally and vertically within the surface, allowing natural wrapping on narrow screens. Listen Later guidance covers Discover, Favorites, playlists, and custom music rather than restricting additions to Discover.

## 6. Responsive and Modern CSS

- Use Flex for one-dimensional alignment and Grid for shells or two-dimensional regions.
- Give reusable cards, toolbars, lists, and panels containers and adapt descendants with `@container`. A component cannot depend on querying itself to restyle its own outer layout; use `@media` for the top-level shell, viewport safe areas, and input capabilities.
- Discover establishes named width containers for the top bar, content, sticky track header, and player, adapting to the remaining space after sidebar expansion. Narrow desktop headers retain settings and hide actions; only viewport mode enables the mobile drawer trigger. Grid assigns column widths, and cards query their own cells without adding per-card `ResizeObserver` instances or reactive Vue dimensions. Offscreen list and track cards use `content-visibility: auto` with placeholders that remember rendered heights; sidebar toggles animate the shell track without adding individual card-width transitions. Automated CSS contract checks do not replace browser layout, scrolling, or frame-time measurements.
- Use `clamp()`, `min()`, `max()`, logical properties, and dynamic viewport units to reduce repetitive breakpoints, with a maintainable fallback for critical layout.
- Let content pressure define breakpoints rather than device names. Narrow layouts change navigation, operators, tables, and detail presentation instead of only shrinking type.
- Inject userscript resets, tokens, and critical component styles as strings into the same Shadow Root. Styles emitted only into the host page's `<head>` are not a valid critical-layout dependency.

Operation results and existing settings, repeated-playback, and export notices share the wording catalog in `packages/ui/src/product/action-feedback.ts`. Selection, name restoration, favorites, playlist additions, list deletion, download submission/completion, and history clearing use the shared result notice slot. Persistence failures are reported from the actual write outcome; session state remains available for retry. A new result immediately replaces the previous notice without stealing focus or inheriting playback cooldowns.

## 7. Motion and Gestures

All card movement has a rendering lifetime, including keyboard ordering, density/column changes, interrupted FLIP and drag neighbors returning to their slots. Previously, protection covered landing but not ordinary FLIP or returning previews, and the virtual default card also switched its paint containment at gesture boundaries. These gaps can cull descendants, change internal raster coordinates or let later siblings cover a moving item. Extending animation duration or adding a page-specific class does not repair that ownership.

Both full and virtual FLIP use the shared `grid-move-animations.ts` owner. The stable keyed slot holds `data-am-grid-moving` from rebasing through the current animation's finish/cancel. Capture the current visible positions before cancelling old transforms, retain the same rendering lease across cancellation and the DOM patch, and then animate the remaining distance. An obsolete finish/cancel/unregister callback cannot release a replacement animation. Release unused holds after a zero-distance rebase, and clean all holds/listeners on disablement, reduced motion, hidden/deactivated roots, animation failure and disposal. Visibility on a transform wrapper is not inherited by a separately culled card. Motion markers keep the affected descendants rendered; the default `.track-card` retains the same layout/style/paint boundary in resting, moving, dragging and landing states. Do not toggle that card boundary to `contain: none`, add size containment or put paint containment on outer placement/measurement/motion wrappers. Virtual natural measurement keeps intrinsic placeholders disabled. Shared moving slots use elevation 1, the keyboard-focused mover 2, and landing 3; pointer sources remain above preview neighbors. Avoid permanent compositing layers or consumer-specific competing z-index rules.

Drag preview rendering holds resolve already mounted slots through the geometry adapter. They do not rescan the full DOM on pointer frames. A removed preview still animates back: preserve its hold for the shared transition-token completion budget, cancel an obsolete release if it becomes active again, and release detached slots promptly. Before clearing source/preview state, install landing/settling protection on those same stable nodes. There must be no unprotected measurement or paint between the two owners. New transition delays/durations require updating that completion budget and its regression cases.

Motion regressions cover both reorder directions within/across rows, fresh controlled snapshots, keyboard shifts, rapid density/column reversals, sidebar breakpoints, returning previews, new gestures, stale finish/unregister events, reduced motion and teardown. Assert visible-coordinate continuation, uninterrupted render ownership, correct layering, bounded mounted work and complete cleanup. When live inspection is authorized, record intermediate animation frames and node identity, verify the actual injected style bank after source changes, and distinguish passive frame capture from geometry-reading diagnostics. Native input tests must verify pressed-button/capture semantics and OS foreground ownership. Settled screenshots alone do not close flicker acceptance.

Classic's nested reorder surfaces declare `data-am-grid-motion` and share their stable slot's layout origin. The shared owner measures affected neighbors at release so an unfinished preview transition continues from its actual visible position after reordering. Cancellation watchers compare scalar getters: direct shallowRef sources in a mixed multi-source watcher can force a callback when a host snapshot is replaced without changing any cancellation condition. A committed order must retain its landing state across that replacement. The shared reorder owner supplies the temporary transition/visibility styles and the stable slot's `data-am-grid-landing` elevation; page-specific settling selectors are insufficient. Keep the item rendered and above neighboring cards until landing finishes, including backward moves where later DOM siblings would otherwise cover it. Remove protection on cancellation, a new drag or disposal, and honor reduced motion. Regression tests cover both directions, committed parent updates, real card style forwarding and cleanup. Node tests verify that handoff contract; browser/Userscript/WebView flicker acceptance remains a separate live check.

Queue drag translations are subscribed within each track card, avoiding per-frame grid updates and full-list TransitionGroup layout measurements. Pointer movement and scroll-container events, including scrolling inside a Shadow Root, share one animation frame; wheel scrolling keeps the floating card and drop target synchronized even with a stationary pointer. Edge scrolling reads geometry before writing the scroll position and stops scheduling frames at the boundary. Pointerup performs only the final hit test and translation: it must not take another edge-scroll step. Otherwise release can change the viewport after the last preview and rebase against a scroll position that was never displayed. Reuse style objects for unchanged translations so already shifted neighbors do not render again.

Native scroll anchoring can also change that viewport while card heights and the committed DOM update. `native-scroll-anchor.ts` owns reference-counted `overflow-anchor` suppression on the actual scroll root, shared by dragging and `useVirtualScrollAnchor`. Acquire before measuring the drag-start geometry, transfer the same hold through landing, and restore the original inline value/priority only after the final owner releases. Failed startup, cancellation, reduced motion, replaced roots, stale completion and disposal must release their own holds without restoring another owner's lease. A release-time extra scroll or competing native anchoring is a geometry error, not an animation-duration problem.

DOM-backed dragging reuses stable slot geometry while the capture root's height is unchanged. When its ResizeObserver reports a height change, coalesce one batch of untransformed slot measurements and rebase the source transform to preserve the grabbed point. Pointerup checks the current root extent too, covering release before observer delivery. Ordinary pointer/scroll frames reuse the snapshot. This root-height signal does not detect internal redistribution with an unchanged total height; such layouts need an explicit spatial revision or measured adapter. Width/column, ordered identity and root changes still invalidate the gesture. Frozen pending landing positions follow subsequent scrolling in content coordinates. Cleanup releases observers, scroll listeners and pending frames, and obsolete observer callbacks cannot cancel a newer gesture. Current-build intermediate-frame checks remain necessary after these changes.

Virtual reorder retains at most the source occurrence and current destination against the shared interaction cap; an obsolete destination releases before replacement, while the source remains held continuously through controlled commit and landing. A rejected hold cancels without displacing another editor/focus session. The flat grid cell owns placement, drop identity and source/landing elevation; an untransformed natural measurement container surrounds the inner motion surface and one real card. Mounted-window revisions refresh only mounted preview offsets even when the pointer/target stays still. The grid's opaque `layoutRevision` changes with spatial geometry or ordered occurrence identities, rather than metadata refresh or geometry-equivalent cache measurements. Compare that token and readiness to invalidate the drag-start snapshot; use the existing explicit viewport for autoscroll, including an initially short list. Landing owns resize/root/identity invalidation after drag capture ends. Its generation is allocated before the host callback, and every deferred phase rechecks that generation and connected roots/source. The expected eligible-subset order may arrive through the next parent render; later unrelated order/filter changes cancel landing. This in-memory guard does not delay or roll back the committed business move. These shared primitives do not complete production virtual drag admission or establish native layout/pointer acceptance.

Motion explains entry, exit, expansion, reordering, and spatial origin and remains restrained. Dialog/button actions do not move background focus. Reduced-motion release commits and cleans up after the render without a landing frame/timer; enabling that preference cancels active motion.

Virtual keyed FLIP registers mounted stable slots and a separate transform surface between natural measurement and pointer motion. Animate only stable keys mounted on both sides, batch reads before writes, continue interrupted movement from current visual positions, and cancel on drag/landing, hidden presentation, reduced motion or disposal. ### 7.1 Drag release and consumer lifetime

Treat release as one transaction owned by `useGridReorder`. The consumer must keep its adapter registration callback stable for the mounted surface's lifetime. Replacing a controlled state/props/binding object, including the expected committed order, must not unregister that surface or call `clearDrag`. Register/unregister follows actual surface replacement; scalar layout/filter/root guards own real invalidation. Exercise this through the real consumer and an immutable host snapshot, rather than testing only the shared controller with mutable arrays.

| Phase                      | Required behavior                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preview                    | The stable keyed cell owns placement, capture and elevation; natural measurement, FLIP and pointer translation use separate layers. Neighbors move once to make space while the pointer is held.                                                                                                                                                                                                          |
| Release read               | Perform final hit testing without an extra scroll step. Batch the actual visible source/neighbor coordinates before removing preview styles, including interrupted transitions and scrolling. Never substitute the intended preview endpoint for the currently painted position.                                                                                                                          |
| Commit and rebase          | Install landing/settling protection before releasing drag protection. Keep source/destination holds through the expected controlled commit. After the parent patch and current natural measurements, set `translation = released paint position - committed natural slot` with transitions disabled, in one coordinate system with each scroll offset applied once.                                       |
| Landing                    | Flush the rebased start before enabling the remaining transition. A neighbor that already occupies its committed slot has zero remaining displacement and stays still; a quick-release neighbor completes only its unfinished movement. The released item moves from its actual release point to its destination. Do not replay the whole affected interval or layer ordinary FLIP over this transaction. |
| Completion or interruption | Release every marker, style, observer, listener, frame, timer and interaction/anchor hold. A newer gesture/root/layout/order change invalidates deferred work by generation; obsolete cleanup cannot affect its replacement. Reduced motion commits without a transition tail.                                                                                                                            |

Do not repair a discontinuity by changing easing, delaying commit, disabling virtualization, hiding affected cards or waiting for the user to scroll. First identify the lost owner, premature cleanup, double-applied transform, coordinate mismatch or estimate/measurement round trip. After dragging, sidebar open/close must work immediately in both directions. Width-only measurement batches discard old heights and read current mounted natural units together before the virtual-row patch; do not render temporary estimate rows and then force another layout to remeasure them. Same-column continuous width changes, including their natural height changes, follow CSS layout without repeatedly restarting FLIP. Columns/grouping/gaps and independent content/load reflows still revise motion; drag geometry remains width-sensitive.

Reorder also owns the viewport: `suspendReorder` connects the first/last reorder retention holds to `anchor.suspend`. Keep semantic compensation suspended through preview, controlled commit and landing, in addition to the native-anchor lease. Otherwise a moved leading key can scroll the viewport at release even when transforms are correct. Resume by capturing the current committed geometry, without replaying an older compensation. A final committed height/window patch may precede its ResizeObserver notification: check the current extent before starting landing, rebase once more with transitions disabled when needed, and accept that extent as the observer baseline. A delayed notification for that same layout must not cancel the new animation; an independent later reflow still invalidates it.

Measured grid heights are scoped to the typed, unordered set of siblings in each row. An ordering commit invalidates stretched-height entries only for rows whose membership changes; same-row permutations and unrelated measured rows keep their valid heights. A global order/motion revision must not clear the whole height cache. Otherwise the temporary estimate extent can shrink below the current viewport and the browser clamps `scrollTop` upward, bypassing semantic/native anchor suppression. Regress first visits to unmeasured regions with the leading item aligned to the viewport top, including fractional pixel boundaries, and compare the scroll extent as well as the released coordinates.

Required regression matrix:

| Axis              | Cases and assertions                                                                                                                                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Release           | Forward/backward, same row/cross-row, held until preview settles/quick release, scroll before release/continued scroll. Compare paint coordinates by stable key at release, committed patch, first landing frame and completion; settled neighbors must not jump. |
| Consumer update   | Fresh immutable committed snapshots, equal-identity metadata refresh, keyboard reorder/focus, unrelated filter/order replacement. The expected commit keeps registration, landing and initiating focus; real invalidation cancels.                                |
| Follow-up layout  | Several drags followed immediately by collapse/expand, rapid reversal and column breakpoint crossing; repeat after manual scrolling. No drag residue or scroll-dependent recovery. Record passive frame intervals separately from geometry-reading diagnostics.   |
| Resource lifetime | New drag during pending/active landing, stale completion/observer/unregister, detached/replaced roots, cancellation, reduced motion and disposal. Mounted work stays bounded and resources return to baseline.                                                    |

Node regressions verify behavior and lifetime; current-build WebView/Userscript checks must also validate actual style injection, input/capture and intermediate paint. A passing controller fixture or one settled screenshot cannot admit a consumer.

### 7.2 Viewport-based mounting budget

Mounted counts are derived from the actual scroll viewport, resolved CSS columns, current display/card style and measured natural row heights. Values such as top 30, middle 50, tail 32 and return-to-top 30 describe one observation; they are never global caps or target counts. Recompute on viewport height/width, sidebar/player space, density, mobile columns and natural-content changes. Tables apply the same rule to logical units, with declared physical rows and fixed headers/footers accounted for separately.

For grids, budget visible rows plus `overscan` rows on each available side (default 2), one conservative boundary row and distinct retained rows outside that range, multiplied by the current column count and clipped to the collection. Interaction retention defaults to 8 distinct occurrences, configurable up to 32; retaining one occurrence retains its logical row, without filling the gap to a distant pin. Count mounted card cells separately from the DOM inside each card style. Larger/taller viewports may legitimately exceed 50 cards. Hidden roots mount none; top/tail clipping lowers the count naturally. Tests cover small and large viewports, all density/mobile layouts, top/middle/tail/return and live resizing, asserting complete visible coverage and this geometric bound rather than a fixed screenshot-specific count.

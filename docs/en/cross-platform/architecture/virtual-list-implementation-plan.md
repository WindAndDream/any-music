## 1. Goal, decisions and ownership

Virtualize every scrollable collection whose rendered content can grow substantially, while preserving the current appearance, ordering, controls, gestures, motion, focus, scroll behavior and business results. Use My Favorites as the first grid-family representative, then migrate production consumers in reuse batches while retaining each consumer's status and recovery boundary. Fixed navigation, short bounded protocol previews and short static option groups need an explicit inventory classification rather than automatic virtualization. A protocol maximum alone is not an exclusion: a bounded collection that still spans many screens or has substantial rendering cost is in scope.

Use `@tanstack/vue-virtual` as the proposed single engine. Version `3.13.51` was checked on 2026-11-03; P04 revalidates the exact version, license, adapter behavior and actual consumer bundle cost before installation. The [Vue adapter](https://tanstack.com/virtual/latest/docs/framework/vue/vue-virtual) and [Virtualizer API](https://tanstack.com/virtual/latest/docs/api/virtualizer) provide dynamic measurement, stable keys and an extensible rendering range. Their availability does not establish application performance. Do not introduce a second virtualizer or a new workspace package for this work.

## 4. Intended technical shape

- Keep data and selection in existing owners. A renderer receives readonly items, stable keys, the real scroll element and controlled display options. It exposes visible logical items, layout positions, total extent, scroll-to-key and temporary interaction pinning; it never reads a repository or resolves media.
- Put the adapter and cache lifetime in `packages/ui/src/composables/virtual-scroll/`, pure layout helpers beside it, and controlled components in `packages/ui/src/components/virtual-scroll/`. Names are proposed; add only modules with a tested responsibility, through public exports.
- Treat a card grid as **logical rows**, each as tall as its tallest cell, preserving row-major ordering and the existing equal-width CSS Grid result. `lanes` alone is not a replacement for that geometry. Preserve a flat keyed parent for mounted cards across column changes; do not reparent them into newly keyed row wrappers and lose resource identity.
- Separate virtual position, stable drop slot and inner drag/FLIP motion surfaces so their transforms never overwrite one another. Retain current cell query containers, semantic tokens and RTL/logical coordinates.
- Use one pooled observer for mounted measurement targets plus the container, bounded caches and batched geometry reads. No observers or effects for the entire dataset. Cache natural heights by stable identity and layout/content generation; invalidate on width/density/content changes and support shrinking as well as growing.
- `useVirtualItemMeasurements` registers a natural, unscaled border-box unit through `observeItem(key, element)` and its disposer. Supply a semantic content generation and a layout generation for density/typography; measured list width also invalidates heights. The presentation-local cache defaults to 512 entries (including mounted units), retains only the current generation and evicts by measurement recency. Evicted/offscreen units use estimates until remounted. Only mounted units have effects/listeners; no size/placeholder containment or assigned height may constrain the measurement target. `refresh()` re-reads mounted units; local capture-load events also cover delayed images without ResizeObserver.
- `useMeasuredVirtualList` uses that bounded cache as its sole height authority, resetting installed-engine geometry once per changed batch instead of accumulating a second visited-height map. Engine/index geometry still scales with the full collection; no bounded frame-time claim is made. Opt-in `useVirtualScrollAnchor` consumes immutable geometry snapshots; the default list never invents scroll compensation.
- `useMeasuredVirtualGrid` scopes stretched measurements by typed, unordered row membership: reorder invalidates changed cohorts only, preserving same-row permutations and unrelated cached rows so the native scroll extent does not collapse. It first derives bounded non-estimate row heights from the height cache. Equivalent ingress/eviction and measurements below an unchanged maximum reuse the prior immutable geometry without constructing all rows first. A row shrinks only when every cell is measured below the estimate; complete-row loops read captured scalars. Actual spatial changes still construct O(N) rows and reset the engine; high-velocity performance and total memory are not admitted.
- Same-column width changes discard previous height authority and batch-read mounted natural units before the virtual-row patch, avoiding a rendered estimate/measurement round trip. The motion snapshot spans that synchronous batch; CSS owns continuous width-driven positions/heights without restarting FLIP. Independent content/load reflows and columns/grouping/gaps still trigger motion; drag spatial revisions remain width-sensitive. Empty windows finish too. Old motion snapshots never repopulate caches, constrain natural height or become drag/anchor geometry. Full spatial comparisons can still be O(N).
- Measurement publications carry the height revision and reflow cause atomically. First/remounted units and bounded-cache eviction update rendering, anchors and live drag geometry without FLIP. A per-mounted last natural height recognizes genuine resize/load reflow even after cache eviction; mixed ingress/reflow batches preserve that signal. The private motion comparison baseline follows ingress without issuing a token. Row geometry and retained motion snapshots still scale with N.
- Share the actual scroll container with pagination and continuity. Include list-origin/header offsets and nested/Shadow surfaces; do not assume `window`, add an inner scrollbar or attach global measurement listeners to every row.
- Mount the visible rows plus tuned overscan and bounded interaction pins, dynamically derived from viewport height, resolved columns and current style/natural heights. Counts such as 30/50/32 are observations, not caps; follow the [mounting budget](../features/cross-platform-ui-and-interaction.md#72-viewport-based-mounting-budget). Pin the dragged/landing item, active editor and required focus/menu anchors only for their true lifetime. An offscreen playing track needs host-owned state, not a permanently mounted player per row. Consumer adapter registration follows mounted surface identity across immutable controlled reorder commits; see the [drag handoff checklist](../features/cross-platform-ui-and-interaction.md#71-drag-release-and-consumer-lifetime).
- Restore continuity by semantic key and offset after measurements settle, cancelling obsolete restore jobs when the user scrolls or the presentation changes. Keep caches and transient anchors out of product snapshots/backups. Any host contract extension stays neutral and receives cross-theme tests.
- `useMeasuredVirtualTable` reuses the measured-list cache and derives complete physical row positions. `VirtualTable` renders legal table sections and spacer intervals around distant retained groups; a track with details/actions uses one naturally measured keyed `tbody`. The default slot supplies cells for generated physical rows, while the `rows` slot preserves existing `tr` components. Callers declare exact header/footer/item row counts and raw-row ARIA positions, supply column widths and keep row spans within one logical unit. Inline zero-spacing/spacer geometry resists ordinary theme cell selectors. Native column/sticky-header/accessibility-tree parity remains open; no arbitrary `div` wraps `tbody` content.
- Migrated growing collections always use the virtual renderer, including empty, one-item, small and filtered results. Do not add a size threshold, native-Find/text-selection workaround or error fallback that switches to full-DOM rendering. Fixed short controls remain separately classified by the inventory. A temporary admission switch only isolates an unadmitted consumer from its existing production baseline; it is internal, is not a user preference or search mode, and is removed at G04.

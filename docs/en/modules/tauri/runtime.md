## Shared behavior and storage

`music-workbench` owns shared workbench, library, favorites, playlists, player, queue, downloads, history, host-owned published recipes and snapshot orchestration, with tests following their owners. Applications inject HTTP, stable storage, sources, login, media and file-saving capabilities. `plugin-tag-management` owns tag rules/associations and specialist UI; `plugin-music-creation` owns drafts/materials/editing state and specialist UI. Workbench consumes their named ports and projections. `ui` remains controlled presentation; `plugin-source-bilibili` and `plugin-source-douyin` own source protocols; `core` owns domain models and ports. See [package boundaries](../../architecture/package-boundaries.md).

The userscript retains its `any-music:userscript:*` keys, Shadow DOM, lightweight launcher, GM transport and single host account/proxy settings. Desktop uses embedded presentation and native file saving without touching those keys. Its renderer snapshot and native `product.json` mirror contain the current generation map and commit pointer. Startup selects the highest complete generation, then revision, and aligns both mirrors before exposing repositories or the workbench. Unsupported mirror versions and unrecoverable snapshot damage stop initialization while retaining recovery data; a readable peer can restore a damaged mirror. The renderer stages and verifies each generation in memory. At pointer publication it replaces the local mirror in one synchronous write and queues the complete native mirror. A native mirror failure is visible and blocks subsequent writes until restart. Snapshots exclude credentials, temporary media URLs/bytes, Blob URLs and disk paths. Account policies contain public IDs/operation metadata. Userscript data is not imported automatically. See [data ownership](../plugins/data-ownership.md).

Desktop and Android download admission uses the injected native `DownloadScheduler`. Rust owns a bounded FIFO semaphore (1–5 whole-song tasks), including waiting-task cancellation; renderer work cannot start before a native permit. The permit covers resolution, reading, encoding and retries, and is released after task cleanup. Shared orchestration retains retry policy and browser encoding. Closing/reloading the main WebView, application exit and mobile suspension clear transient admission. Userscript retains frontend scheduling; iOS media/saving remain unavailable. Automated tests do not establish device acceptance.

Download directory selection lives under Settings → Network and Downloads → Song Downloads. Desktop uses the native folder picker and persists only the selected directory in native `download-directory.json`, outside product snapshots and download history. Native save receipts expose only filename, length and full SHA-256, never a final disk path. Re-download verification opens only that exact name in the current directory and hashes the complete file with a 64 KiB buffer; name-only, size-only and content-only matches never suffice. Saving equal bytes under the exact requested name skips a duplicate write; other collisions exclusively create numbered files and preserve existing content. Android uses `ACTION_OPEN_DOCUMENT_TREE` and persisted read/write grants held in native preferences; only the folder's display name reaches the renderer. Downloads create documents in that tree through the existing bounded save-token adapter (32 MiB, foreground/lifecycle/deadline checks). Reset restores per-file system dialogs, and picker cancellation preserves the previous selection. Missing directories, revoked grants and write failures remain visible errors requiring retry or reselection. Android 11+ restricts storage roots and the Download directory itself; choose a permitted subfolder. See [Android SAF](https://developer.android.com/training/data-storage/shared/documents-files). iOS retains unavailable native-save capabilities. Automated Rust, renderer and Android compilation checks do not establish live picker/device acceptance.

## Operations, pagination and media

New searches, imports, session checks and media resolutions use the saved default account. Each operation attempts only that identity; failures do not switch accounts. Existing list and track bindings take precedence while their account remains enabled. The account switcher has no automatic-selection entry or configurable account competition policy. Standard attempt/total budgets are 25/60 seconds.

Douyin search retains its 105/115-second attempt/total budgets for official-page loading and cleanup; media resolution uses 50/70 seconds. Risk challenges await verification of the same account.

The first page binds the selected account; later lazy pages retain its identity/cursor. Consumer stop, disabling, deletion or environment changes release requests. Media descriptors become random loopback grants held by Rust. Native audio, Range and complete-read paths retain the grant's account cookies/proxy. Only a random grant ID enters the local URL. The listener binds 127.0.0.1 and streams Range without full-file caching; grants remain in memory with count/expiry budgets and are revoked on environment changes. Descriptor, native streaming, bounded Range/MSE and complete-read fallback order is preserved.

Douyin search uses official search pages to generate requests. Rust captures allowlisted general/search/stream and general/search/single bodies, preserving bytes for shared DTO parsing/mapping. Each listing owns a target, keyword and cursor. First consumption creates its page; later pages scroll on demand; stopping closes it. The official page may preload its next cursor, so matching responses are retained while consumers are idle or checking account state. Each listing keeps at most three pending responses, with a 24 MiB per-account cache budget, eight-listing cap and bounded response sizes/duration. Session checks also use official pages.

Work detail for playback, downloads and single-work imports uses the owning account's embedded pages too. Native validation accepts a numeric work ID and video/note kind. A work-detail request opens a hidden page on demand. A page that delivers a matching API response stays available for up to 90 idle seconds. When its controls are ready, a fixed script pushes the `/video/<id>` or `/note/<id>` route and the official client requests the detail itself (signed-in clients use the official `www-hj.douyin.com` API host, which is accepted alongside `www.douyin.com`). An unavailable or revisited route, or no matching API within 8 seconds of routing, closes the previous page before opening a replacement within the same budget. A newly navigated page captures only its matching aweme/detail response or main-frame work document, bounded to 12 MiB and 40 seconds (45 seconds for the native action and 50 seconds for the renderer playback attempt). The client detail request starts only after the official page loads its script set, so the matching API takes priority; documents are a fallback only when the read budget expires without an API response. On 2026-11-16 the main-frame document of a video work carried no media address fields, so on slow links the fallback cannot produce playable media and the longer API wait is the effective remedy. Network, verification and authentication failures retain their original error. Portable API/React Flight parsing checks work identity and playable media; listing URLs are neither reused nor persisted. The CDP detail reader intercepts media and image requests, and the embedded page bridge disables media playback. A page that delivers only the document fallback, or whose read fails or is cancelled, is closed. Actual media still streams through the same account's Rust HTTP and loopback grants. Official detail failures no longer fall back to local requests missing webpage security signatures. Watch history, personal likes, collected videos/mixes and mix works use the owning account’s embedded-page import port. Other lists and collected-music detail retain Rust HTTP/shared signing; contract records identify actual live coverage.

Native account checks resolved API detail for two real works through the portable parser. One also returned HTTP 206 and 1024 bytes of video/mp4 through its owning account's Rust HTTP; response bodies and media URLs stayed in memory. Automated regression covers document/load before the detail API, bounded no-API fallback, preservation of network failures, timeout, cancellation, response limits and target cleanup. This evidence excludes the product audio playing event and complete loopback-grant playback acceptance, and does not update the website contract captureDate.

# Custom track recipes, playback and export

[中文](../../../zh-cn/板块/资料库/片段配方与播放.md)

`plugin-music-creation` owns drafts and materials through its namespace. Published stable tracks belong to the host. See [library ownership](README.md).

## Recipe compilation

The implemented recipe uses milliseconds:

```ts
interface SegmentRecipe {
  sourceTrackId: string
  startMs: number
  endMs: number
}
```

Saving validates segment bounds and compiles recursive references to leaf intervals, rejects cycles and merges adjacent continuous segments from the same source. Keep the editable recipe and compiled timeline as separate fields. The compiler caches repeated subrecipes and locates the first overlapping leaf by binary search. A published work stores the local creator identity in `creator` and deduplicated original source attribution in `sourceCredits`.

## Playback

Playback starts from a bounded window of compiled leaves. The default path divides the compiled leaf timeline into range-decoded chunks of at most four seconds without crossing source boundaries. Before playback, it prepares at least three seconds and at most three contiguous chunks, while three workers continue decoding a rolling twenty-second look-ahead window into session-only PCM. A run of one-second fragments therefore occupies the prefetch slots concurrently instead of starting resolution at each join. AudioContext schedules every contiguous ready chunk on one clock, so boundaries no longer depend on a low-frequency `timeupdate` event switching URLs at the last moment.

Range prefetch reads only the media intervals needed by the target chunks. Ephemeral descriptors and decoded buffers live only for the playback session; rejected promises are removed immediately, and seek, track switch, or unmount aborts old reads and rebuilds the window around the new playhead. If a source rejects Range, the browser cannot decode it, or prefetch fails, the player preserves the virtual position and falls back to one native `<audio>` streaming one leaf at a time. That path still resolves lightweight descriptors over a ten-second look-ahead window, capped at twelve chunks and three workers. In-leaf seeks move the native clock directly, while cross-leaf seeks lock the requested position and playback intent until the target media clock takes control. Primary URL, backup-node, and runtime HTTP Range/MSE fallback ordering remains identical to ordinary-track playback.

Only after every streaming path for a leaf fails does the application render a session-only MP3 with Mediabunny and hand its temporary Object URL to native `<audio>` as a compatibility fallback. Switching tracks aborts an unfinished fallback render. Source bytes, rendered bytes, Blob URLs, and ephemeral media URLs never enter the library, and downloads continue to use the complete export pipeline.

## Export

Each unique source is resolved/read once per export through injected GM or Rust HTTP/media grants, retaining its built-in account identity. The stream normalizes to 48 kHz stereo and encodes 192 kbps MP3 or 16-bit PCM WAV. The packaged MP3 worker and WASM travel with the consumer build. External catalogs offer no media fallback. Media, generated bytes and URLs stay in the current session.

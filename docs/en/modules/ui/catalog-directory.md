# Discover and request directory

[中文](../../../zh-cn/板块/界面/发现与请求目录.md)

Classic receives controlled request and list metadata. The workbench owns request identity and retained pages. See [track results](catalog-track-view.md) for the opened list.

Discover search/import request cards show common actions directly. Search/import timestamps remain visible on desktop and are hidden at viewport widths up to 600 CSS pixels to keep mobile items compact. Status previews stay bounded, and errors open the existing host-owned details dialog. Batch selection, menus, long-press and arrow-key ordering remain available.

- Discover and its track pages use the same inset gray surface as Listen Later: gray covers only the content, its height follows the content, and the page background remains visible around it. Track cards keep 16px of vertical and 12px of horizontal space inside the surface without additional grid padding. Sticky back headers retain their existing layout.

- The middle of each Music List card header contains only Search/URL Import and waiting/loaded-track summary labels. Their full text width determines when they stack vertically, without squeezing or truncating label text. Pin status, loading, unavailable-source notices, and short error reasons share one row with loading metrics, with the notice group before the metric group. Both groups retain their DOM semantics inside a common horizontal viewport. Hide its scrollbar, keep labels uncompressed and unwrapped, and retain native touch, trackpad, and keyboard scrolling. Handle Error continues to show the full error.

- On desktop, when there are no music lists, move Search and Import up beside the title and description, vertically centered, without an empty state toolbar. When lists exist, a sticky toolbar keeps the four state filters on the left and Search and Import on the right in one row, including when no lists match the filters. On phones, hide the introductory description and pin the account/title, discovery entry, and state row together. On both layouts, the directory starts with the same outer top spacing as Favorites. The gap scrolls away and the opaque sticky controls reach the top of the viewport. Keyboard reorder and return-to-list focus bring the target card below the pinned controls. State buttons stay on one line; overflow reuses the operator's native horizontal viewport and right-side arrow, with touch and primary-button mouse dragging. Vertical gestures continue scrolling the list, and horizontal drag endpoints never select a state.

- The music-list Actions dialog places an icon-only copy control at the top right of the full-information card to copy its public projection as indented JSON, including the request, public account identity, current state, and loaded tracks. The original search-term field has an independently centered icon button on its right that copies the exact original text. Capture information only on click, without extra track/session requests or temporary media resolution. Repeated clicks reuse an active copy; failures allow retry, and closing or switching lists discards late feedback. All detail groups share equal-width columns; long requests, timestamps, and loading summaries span the row, and narrow dialogs switch every group to one column.

- Classic also virtualizes the outer search and import request cards and the song results for sources other than Douyin. Request filters, selection and reorder use the complete matching directory. Returning from a song result restores the directory scroll and focuses its request card. These song results keep the ordinary scroll threshold and page on demand.

- The runtime's workspace snapshot retains the last explicitly selected platform across visits and restarts. Disabled or removed platforms temporarily fall back to an available source without overwriting that preference. snapshots retain the default platform, and restoring selection does not load historical lists.

- List details use one subdued surface grouped into title/source, account, original request, and loading information. Wide containers use two columns, narrow containers one; complete text remains wrappable and selectable. Account name and custom name belong to the actual listing identity: desktop shows the winning or verification-required account, while Userscript reuses the known host username for that request's platform. Unknown usernames, unset custom names, and unloaded lists have explicit labels. Details do not issue additional session requests.

- When both Search and Import are available, non-control form areas show a grab cursor on hover and a grabbing cursor while held. Inputs and buttons retain their text and pointer cursors. Collections with an Operator start outside selection mode: item checkboxes and selected styling are hidden, and item clicks cannot select or open the operator. Headers, footers and compact platform rows reserve the same 44px selection target in both modes, so revealing a checkbox does not rewrap content or change item height. The toolbar's Operator entry enables selection and shows the checkboxes. Discover, Listen Later and Favorites cards toggle selection from any region except the three-dot menu, matching playlist cards. Phone checkboxes sit at the card's lower right, with separate menu and selection touch targets in both one- and two-column layouts. Selection changes, including deselecting the last item or deselecting all, leave the operator open. Explicitly closing the operator exits selection mode and clears its selection; switching list contexts also exits this mode. Navigation that only hides a page and presentation replacement retain its current mode. Opening the operator focuses its close control. Discover, library collections, playback history and downloads share this behavior. Hold and arrow-key reordering remain available independently of selection mode.

Each music-list card's Actions dialog offers Refresh using the original query or import URL. Preserve the list name, pin, creation time, and favorited tracks. When tracks are loaded, the confirmation action reads “刷新” (Refresh). Cancellation keeps the dialog and current results. The track-list header keeps Refresh visible for every source. Refresh stays disabled during loading or verification and when the source is disabled, removed, or unavailable. Revisiting a track list restores the retained results and the Any Music scroll position. Pagination stays locked even at the bottom. Confirming Refresh clears those results, returns the list to the top and requests page one. During the initial or refreshed visit, downward scrolling can request the next available page and shows a spinning indicator while loading. Empty-list messages distinguish no successfully loaded tracks, a page without usable tracks that still permits further loading, loaded tracks excluded by filters, and results without usable tracks.

- Music List cards retain a fine theme-aware separator between the body and loading summary, using spacing alone between the summary and bottom actions. The card loading summary shows only loaded track and page counts. Narrow cards use the same hierarchy. The source line and original input shrink to their text width: text remains selectable, while trailing blank space toggles selection and shows a pointer cursor. Returning from another section preserves the list state group, applied filters, selection, current track page, and scroll position. Only transient overlays close; hidden track pages pause automatic pagination and hidden lists cancel dragging. This state lasts for the current workbench session without persisting results or automatically repeating requests. Top badges use spacing alone. When the phone viewport or available list width is at most 600px, hide the source and original-request summary to reduce card height; narrow columns in a wide desktop list retain that summary. Actions opens the full list name, source, request kind, original search term/import URL, creation time, current status, loading summary, and pin state above the list actions. Full text wraps and remains selectable. Search terms and import URLs each provide a copy icon with a 44px touch target and corresponding success or failure feedback; copying preserves the exact input without closing the dialog or repeating source requests. Content scrolls when it exceeds the available dialog height. The bottom Filter/Actions launcher centers its controls vertically within the usable area. On phones, the launcher is 70px tall: its upper approximately 48px contains 36px buttons, while the lower 22px reserves space for the player's overlapping edge-seek target. Seeking retains the full 44px touch height, with approximately 6px between the buttons and the seek target to balance list space, dragging, and accidental activation.

- Blank areas of Music List cards toggle selection and show a pointer cursor on desktop. Text remains selectable, and button or checkbox clicks never toggle the card twice. Select All and Delete Selected Lists use filled button surfaces, with danger styling and confirmation for deletion. A single Actions dialog offers Favorite All, Rename, Pin, or Unpin. Pinned lists use a solid primary-color badge with bold text and an upward icon. Pin preferences survive refresh; pinned lists stay ahead of new or repeated ordinary searches, preserving the existing order within each group. Unpinning restores ordinary list order without replaying source requests. The right side of both desktop and phone top bars shares a compact platform-picker button with an explicit Switch label and no downward arrow. It opens a compact dialog with built-in and custom source groups and an explicit current selection. Selecting closes the dialog and reuses source activation and external-plugin checks; reselecting the current platform does not repeat probes. The phone top bar bounds the platform trigger width, truncating long names there while showing them fully in the dialog. Desktop and phones place Search and Import on the right of the list heading, aligned with the right edge of the card grid. The operator retains Restore Original Names, Select All, and Delete, and empty-state guidance points to the heading action. Desktop and phones omit the upper-left Your Discoveries label. The gray list container has 16px padding above and below by default. The introduction adds no padding, avoiding excess space at the top; phones retain extra scrolling space after the final item. On phones, a controlled session slot replaces the Music Lists heading with the username and an immediately adjacent refresh icon. The account row has no outer border or background block and retains the desktop session-status dot on the left. Narrow-container rules must keep the username visible. Account names appear directly without the Username prefix or middle dot, leaving more room for long names. The supporting description sits 12px below the heading/action row and uses a 1.6 line height when wrapping. The name uses bold 16px text, shrinks to the remaining width, and truncates with an ellipsis while retaining the complete accessible name and session status. Refresh preserves the known account name, spins the refresh icon while the request is pending, disables repeated clicks, and exposes the busy state. Reduced motion disables spinning. Signed-out or expired sessions retain Login, and the refresh icon keeps a 44px touch target. The platform dialog auto-focuses an underline search input and locally filters names or identifiers as users type, without probing sources. It explains empty matches and clears the query when reopened. Focus uses the filter editor's primary-color underline animation and respects reduced motion.

- The Discover destination opens on the list. At every width, Filter and Actions launchers sit above the player, with selected, matching, and total list counts on the left; phones also offer Scroll to Top and reserve space after the final card. The outer filter reuses the track filter overview, isolated draft, history, calendar, and live preview, with text, platform, naming, and search-date dimensions. Text matches the list name, original query/link, or source name. Date ranges match the original search/import creation date, union ranges, intersect with text, and include the entire end date. Cards show Search Time or Import Time from the existing recipe `createdAtMs`; refresh and retry preserve it. Older runtime projections without a timestamp show Time Unknown and do not match date conditions. Cancel discards the draft and Apply changes visible lists without requesting source data; State groups are All / Available / Unavailable / Error. The three specific groups are mutually exclusive and their counts sum to All. Disabled or removed sources belong to Unavailable, taking precedence over earlier request errors and invalid tracks; re-enabling updates the group automatically. The non-modal bottom Actions panel exposes Restore Original Names, Select All, and Delete Selected Lists at every width; narrow containers use two fixed-height rows, with Close occupying only the upper row and other actions scrolling horizontally below. Discovery remains on the right of the desktop Music Lists heading or phone account heading. Music List operators place Select All at the upper right, with Delete Selected Lists and Restore Original Names below. Select All affects current matches, deletion requires confirmation, and empty lists still allow search/import. The dialog switches modes through a segmented control or horizontal gesture. Submission returns to the list to show loading state without changing the main navigation destination. Viewing tracks slides the list out and the full-width track page into the content region; returning restores list filters, selection, scroll position, and keyboard focus to the source card.

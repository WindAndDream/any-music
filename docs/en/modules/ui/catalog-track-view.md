# Catalog track results and actions

[中文](../../../zh-cn/板块/界面/歌曲结果页.md)

Request and session logic live in [source listings](../sources/listings.md). Errors have a [separate interaction contract](catalog-errors.md).

- Opening tracks displays retained metadata, including after restart or a duplicate search/import. An in-flight request is shared across visits. On a fresh or refreshed Douyin list with no active filters, the track view shows a loading indicator while it measures the rows and fills the first viewport one page at a time. It reveals the available tracks from the top when the viewport is full, paging stops, or the budget of three extra pages or four seconds after the first page is reached. Later pages load on downward input. A downward wheel, an upward touch swipe, or a paging key on the focused list can admit a page even when the viewport has no scrollbar. Demand reaching the bottom during a pending request is checked again after completion. Duplicate admission stays blocked, upward scrolling withdraws pending demand, and filtering does not start continuous background paging. Sources without a resumable position retain their results and explain that manual refresh is required. Refresh and error retry retain their explicit entry points.

- Desktop Douyin track results use measured virtualization in the app view and in the Windows result WebView. Both surfaces use Classic track cards. The mounted window follows the theme viewport, while filtering, selection, playback order and pagination use the complete loaded collection. Moving between renderers restores the list's scroll position without creating new pagination demand. See [Desktop Runtime Architecture](../tauri/runtime.md).

- PC track-page context shows the list title, platform, and total/loaded track counts without an account name. In mobile track pages opened from Discover, the top-right area shows the listing's actual request account name with added end padding to balance its visible edge spacing with the icon inside the left navigation button. The context row shows only the platform on the left, with a button opening complete list details, and only total and loaded track counts on the right, without repeating the account or platform. The music-list page retains its platform picker.

- The desktop Discover account entry shows only the selected account's custom name. The desktop account switcher shows Platform Username (Custom Name). When a username is unavailable, it uses the platform's display name in that position. Platform usernames remain isolated by account. Douyin retains its last verified nickname across restarts. Opening the switcher can fill missing nicknames for signed-in alternate Douyin accounts in the background, while Discover checks the default account. Closing the switcher cancels its nickname reads. Renaming immediately follows the public account snapshot without replacing platform usernames or changing listing identity.

The track page has no Discover button; return to the list to search or import. Its fixed source indicator displays only the platform name, without the `固定` suffix. Entering and leaving tracks slides the content in the navigation direction, matching the full-width platform navigation in Favorites. The Classic music-list view uses the collection toolbar motion for All / Available / Unavailable / Error. Horizontal overflow is clipped without creating a nested scroll container; leaving content is inert. Reduced motion disables the transition. Permanently unavailable song markers persist across lists and restarts; transient network, login, verification and playback transport failures remain retryable rather than permanently disabling a song. See [retained results and continuation](../sources/listings.md#4-lazy-listings) for cache and source limits.

- The track page separates Filter and Actions above the player. Both list and track launchers show selected, matching, and total counts with a slightly heavier font weight. Track counts cover currently loaded tracks; draft previews do not change the launcher summary until filters are applied. Music List empty-state guidance uses the full content width and wraps only when needed. Track Actions places Close at the upper left and Select All at the upper right. The lower row orders Add to Playlist, Download Selected, Add to Listen Later, Add to Favorites, and Restore Original Names, which appears only when selected items include custom names. Buttons stay 44px high. All buttons align right as a group when they fit, with 12px gaps. Only actual overflow switches to a left-aligned scrolling row with a right-edge arrow, without shrinking or wrapping. Phone launchers remain compact and retain an icon-only scroll-to-top action. Returning to the top changes the product content scroll position frame by frame, starting slowly and accelerating, then settles with a 4px content pullback. The host page, navigation, and player stay fixed. Touch, wheel, scrolling keys, view changes, hiding, and disposal cancel the old animation; reduced motion jumps directly to the top. Filter slides up with no dimension initially selected; empty overview dimensions omit redundant unfiltered status labels. Wide layouts place Search, Tags, Naming, Publication Time, and Track Duration on the left and a vertical draft summary on the right. Each criterion is itself an edit button with a square-cornered rectangular hover background that opens its dimension and loads that specific value; updating a range replaces its original entry while preserving its siblings. Removing an overview criterion updates the draft immediately. An overview without conditions fills its content region with a borderless empty state and the collection icon above the title. Dimension buttons use a numeric badge for selected conditions. Editor headers pair the dimension name with a question-mark button that opens the dimension's help in a compact modal. The filter sheet suspends interaction and restores focus to the help button when the modal closes. Search placeholders scale with the input width, and keyboard focus rings stay inside the footer buttons. Keywords, tags, and valid pending date/duration additions or edits update the preview together with other dimensions. Incomplete or invalid input keeps the selected criteria; previewing never commits to the overview or history, and Back discards changes and restores the original count. The close-button header retains only the music-list name and omits duplicate matching counts. Search has one keyword matching track title, author name, and user ID together. Its theme-colored underline input appears immediately and receives focus; pointer and keyboard focus extend a theme-colored underline from left to right without a surrounding outline, while blur retracts it to the left. Rapid focus changes reverse smoothly from the current length, and reduced motion switches instantly, with vertically centered text in the search-history buttons below and no scope selector or multi-condition controls. Publication Time uses a compact custom calendar with smaller corner radii, date targets at least 44px high and a heading using the project font whose numeric year, month, and day labels are three native mode controls, keeping centered date order and fine underlines. The active dimension has a primary-theme background and pressed semantics. Paging arrows sit at the edges and are larger in the wide layout, with mode guidance and the current value below; a second row of duplicate view buttons is omitted. The heading and selected date cells use `--am-color-primary` / `--am-color-on-primary`, with a theme-colored selected-cell outline. Today retains its `aria-current="date"` semantics without underlining the date number; the day follows the active endpoint or the keyboard landing date in the displayed month. Navigation supports arrow, Home/End, and PageUp/Down keys. View changes and paging slide and fade according to direction; individual range color blocks scale and fade in. Leaving grids immediately stop accepting input and focus. Reduced motion disables these animations. The Start Time and End Time buttons sit side by side at equal widths with a gap, using the same inset styling as the Favorites All Songs / By Platform switch. The selection indicator slides between them and switches immediately under reduced motion. The group fills the row until Add/Update Range appears. It then animates to two thirds of the available width, with the action taking the remaining third after a gap. Reduced motion switches widths immediately. On PC the row stays at the top of the right column independently of history scrolling; on phones it appears above the calendar. Add/Update is initially hidden and appears after choosing End Time or when loading a range with an end date. It remains available when switching back to start. Adding a range hides it again and returns focus to Start Time. On PC, the controls reserve the same scrollbar gutter as the content below so the action aligns with the right-column content edge. The calendar changes only the active endpoint: the end stage highlights both endpoint cells and the intervening range; switching back to start highlights only the start cell while retaining the end value. A start cannot exceed an existing end, and an end cannot precede the start; same-day ranges are allowed. The current date summary uses two stacked endpoint rows, aligning each Start/End label with its date. Both rows are native buttons sharing the same stage switch as Start Time and End Time, with synchronized pressed state and activity hints. Pointer hover uses a theme background and pointer cursor; keyboard focus retains an inset ring. Dates use bold 20px text; narrow containers wrap labels and values naturally while keeping each date intact. A thin theme border, soft theme background, and Editing text identify the active endpoint without relying on color alone. The summary omits a nested outer card and arrow; historical dates retain their compact horizontal arrow summary. The PC editor uses the full available width and allocates calendar and right column at approximately 1.6:1 while reserving enough width for the controls. The left calendar and its six-week grid fill the available height. Year/month/day headings, date typography, and cells respond to the available space, with date, month, and year targets always at least 44px high. The calendar stays in place while pending ranges, selected ranges, and history share an independently scrolling right column; the left calendar first fills its available height. At short desktop heights, an explicit size container tightens spacing and supporting guidance. Once the minimum target size is reached, the left column may scroll to retain every date without further shrinking the controls. Narrow layouts stack the columns and scroll through the detail area together. Calendar surfaces, endpoint cells, and date-content blocks use smaller corner radii. A complete range remains submittable while adjusting its start. Duration provides underlined minimum/maximum minute inputs, supports an unlimited endpoint, and rejects negative/invalid values or an inverted range; its right column shows selected ranges and history. The content-sized Add/Update Duration button has an 8rem minimum width constrained by available space and retains a 44px target height on both layouts. Date and duration dimensions support multiple ranges; editor removal affects only the isolated draft. Confirm records the complete search, tag, date, or duration snapshot from that submission directly, rather than rereading stale v-model props before the parent update arrives. The first confirmation records the new snapshot, deduplicated and ordered by recency. Settings independently retain 0–100 groups per dimension, defaulting to twelve; zero disables retention and reducing a limit immediately removes the oldest records. Each history list initially shows three groups, with a configurable 1–100 display threshold and an Expand/Collapse control showing the remaining count. Expanded lists scroll within a bounded window. Every date or duration range within a history group occupies its own line, with fine dividers between ranges. Date and duration history share neutral background blocks and smaller corner radii. Date history omits repeated Start/End labels and connects dates with an arrow, without gradients, shadows, or a most-recent badge. The whole block still restores the complete group in one action. Expanded desktop date history shares the right-column scroll area; narrow layouts retain the bounded history window. The formal script persists history through its runtime storage across hosts and refreshes. History entries use the same 650 font weight as search time. Each group has an always-visible delete button beside the history entry. Deletion removes and persists the complete snapshot without changing the active filter draft. Focus moves to the adjacent group or returns to the current input after the final group is removed. Restoring history replaces that dimension's draft and populates its controls while preserving the other dimensions. Platform history shows individual name chips in one clipped row. Activating the row opens a compact dialog with all saved platform names and a Restore Filter action. Local tag search only narrows available options; empty-tag and no-match messages are horizontally centered. Tag labels and checkboxes use a pointer cursor, with a changed hover background and theme feedback for keyboard focus. History and selected-criterion deletion reuse the existing soft `--am-color-danger-container` background and red `--am-color-danger` foreground on hover, keyboard focus, or press. Each tag-history selection forms one outlined group using the theme surface (white in light mode), with individually separated tags using the `--am-color-surface-subtle` background. Content-sized groups fill each row and wrap naturally, with long labels wrapping within their group. Recency and keyboard reading order are preserved, and clicking the group restores all of its tags. The tag group uses the same background on hover, and its delete button uses the danger hover background. The editor footer aligns status left and Back/Confirm right. Back discards the dimension edit. All dimensions share a return transition that starts slowly, accelerates, and settles with a 3px overshoot and gentle pullback. Leaving views immediately stop accepting clicks and keyboard focus; entry completion restores the original trigger focus, and reduced motion disables the animation. Confirm includes valid pending input and keeps the editor open with an error for incomplete or invalid ranges. Phones stack the editor columns and move overview entries to a touch-scrollable bottom strip without visible scrollbars. Entry badges count independent criteria. Preview and the track list share one predicate; Close/Cancel discards the complete panel draft, and only Apply Filter updates tracks. Ranges and tags are unioned within a dimension, while dimensions are intersected.

- The track page keeps its back bar sticky at the top of the content region. It shows the list name, source, total count when supplied, loaded count, Favorite Loaded Tracks, and Refresh. The display-mode picker appears once, to the left of the bottom Filter launcher; Refresh uses the short label `刷新` at every width. When expanded, the header keeps two rows at every width, including ultrawide screens: list name on the upper left and source/counts on the upper right, then Back on the lower left and favorite/refresh actions on the lower right. Desktop places a single short line at the center of the back bar's bottom edge, positioned absolutely within existing spacing so it adds neither a grid column nor header height. Phones hide the graphic and accept held vertical drags across all noninteractive heading areas and the bottom edge, including ordinary title, source, and count text; taps, clicks, and clicks synthesized after a drag never change the collapsed state. Only buttons (including the truncated-title details entry), links, inputs, and editable controls keep their own input. At every width, noninteractive heading areas accept vertical drags and show a grab cursor on hover and a grabbing cursor while held; buttons retain their own cursor. Native text selection and copy menus remain available, and default input is intercepted only after vertical movement begins. Layout changes and unmounting release gesture listeners. Clicking the desktop handle or releasing an upward drag of at least 24px on either layout hides the name, source, and counts, retaining the three action buttons and handle; another desktop click or a downward drag on either layout expands the information. The bottom-edge control retains keyboard semantics: desktop supports Enter/Space to toggle, and both layouts retain Up/Down arrows to collapse/expand. Short drags, reversal to the start, horizontal gestures, and cancellation do not toggle it, and a native click following a drag never toggles it again. The state remains within the current workbench session; error and unavailable-source notices remain visible. Back retains its full text when the header itself is wider than 600px; narrow containers use the icon. The list name adapts to measured text widths. It shows the complete name (platform, search mode, and original query) when it fits; otherwise it shows the platform followed by the original query or import URL, omitting the search mode and truncating only when necessary. Only visibly truncated text becomes an accessible full-text button with hover feedback; fully visible text is plain and noninteractive. The dialog keeps the full name and original request, with wrapping and selectable text. Renaming preserves the original request. Width, text, and font changes trigger new measurements, and unmounting releases observers. A phone keeps the Favorite Loaded Tracks text visible and confirms the current loaded-track count before submission; unloaded pages are not included. Wide layouts offer comfortable, standard, and compact density, while phones offer one or two cards per row. Card contents adapt to each grid cell's width; switching preserves selection, filters, and playback. The grid retains empty columns, so even a single filtered track keeps the current display mode's column width. Only available space and display preferences change that width; phones retain the selected one- or two-column layout. Further pages load by scrolling; the manual Load More button is absent.

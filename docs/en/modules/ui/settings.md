# Settings and native entry points

[中文](../../../zh-cn/板块/界面/设置.md)

Themes render ordinary settings. Protected authentication, credentials and consent remain named host surfaces.

Each settings region places supporting text directly below its title with `--am-space-1` spacing. External-source and proxy content omit decorative and action icons. Add Proxy shows the supported protocols and address format below its title, without repeating the hint below the fields; each input occupies a full row, matching Creator Profile. The saved-proxy region has a Proxy List heading, including its empty state. Resource Cache separates disk usage/capacity, memory usage/capacity and directory selection into independent cards with sibling dividers. Long explanations move to Cache Introduction, which opens a host-owned dialog and suspends the settings modal. Account detail, platform, name, connection and login-method navigation reuse the music-list operation dialog's forward/back page transitions, including inert outgoing pages and reduced-motion support.

Display Mode settings use a layout icon for their navigation entry and the corresponding product-navigation icon for each feature group, with one feature expanded at a time. Feature cards use spacing without sibling dividers; expanded region lists use the same internal row dividers and top/bottom inset spacing as Filter History. They cover Discover's music lists and tracks, Listen Later, Favorites, playlist covers and tracks, downloads, history, custom music, tags and the plugin center. Tag Management separates tag layout from Associated Music defaults for song style, density and phone columns; both complete themes inherit the latter until a local browsing choice is made, and explicitly closing tag information restores inheritance on the next visit. Choices save immediately through the owning runtime's injected storage. New or uncustomized collection regions inherit these defaults; explicit per-region choices remain independent. Style-only regions omit arrangement controls. Settings navigation survives theme replacement, while actual settings close invalidates old callbacks. Failed writes show an error, retain session values and allow retrying the same choice.

On phones, the settings detail title and `settings-navigation__back` share one row, with the title at the start and Back at the far end. Both align to the detail page's horizontal padding; the description occupies the row below. Preserve the 44px touch height, visible focus, and draft/scroll restoration when returning to the overview.

Settings use four groups: Appearance and Navigation, Music Sources, Network and Downloads, and History and Creation. They contain appearance/layout, navigation management, music-source management, request proxy, downloads, playback history, filter history, and creator profile. The sidebar no longer includes the Customize Interface shortcut; appearance, layout, and navigation remain available through their settings pages. Summaries show applied values and never expose proxy credentials.

The active theme renders ordinary settings, navigation and pickers. Neutral validation, editing and modal primitives belong to UI. Account/login, proxy credentials and native installation/consent remain fixed host slots. Presentation replacement retains unfinished inputs; only actual settings close invalidates the editing session.

PC uses a centered panel with grouped navigation on the left and a single detail page on the right; both scroll independently. Phones use a full-viewport grouped list, with each entry sliding horizontally into its detail page. Back restores overview scroll and entry focus. Visited forms retain drafts within the settings session and unmount when settings close. Hidden and outgoing pages immediately stop receiving focus and clicks; reduced motion disables sliding. Controls keep targets of at least 44px and clear labels, supporting text, and save actions. Each complete setting uses a subtle background card containing its description, fields, validation feedback, and save/import actions. Dividers separate complete sibling settings such as download directory and concurrency, or independent source/proxy entries. Within one setting, fields, descriptions, expanded details, and action areas use background and spacing without additional divider lines. Appearance, navigation, music sources, accounts, proxies, downloads, history, profiles, and external-source settings share this surface hierarchy in light and dark themes. Cards use 10px corners, inner option rows 8px, and controls 6px, matching the workbench content areas. Proxy lists omit the repeated page heading and general hint, retaining per-proxy assignment and deletion explanations. Music-source groups use inset row dividers, with identity/status on the left and separate controls on the right; narrow containers stack the controls below the description. Navigation management uses compact rows without dividers between destinations. Settings validation text uses the same extra-small size, regular weight, and line height as proxy management. Appearance options use individual option surfaces; a single divider separates the three selection rows from the mobile navigation setting. Interface theme, sidebar position, and color theme all open the shared selection dialog from a button showing the current value; choosing applies immediately and closes the dialog, while cancelling preserves the current value. External-source settings separate package import, native identity/permission consent, installed sources and command results. Diagnostics and DEV controls are expandable; preview replacement clears all previous consent.

Filter History groups settings by feature, filter region, and dimension. Features start collapsed, with at most one expanded at a time. Expansion and collapse smoothly animate height and opacity, respecting reduced motion; collapsed and outgoing content immediately becomes inert and hidden from assistive technology. Region entries share one rounded surface with internal dividers and square hover boundaries between rows. Region entries show a title and one summary line with the dimension count and saved default visible count. A separate Unsaved badge identifies drafts, while individual retention limits appear inside the region configuration. Inputs open on demand so additional filters do not continually lengthen the settings page. Discover contains Music List Filters (text, platform, naming, and search time) and Tracks Within a List (search, tags, naming, publication time, and duration). Selecting a region opens a centered desktop dialog or a phone bottom sheet sized to its content and capped at 80% of the viewport, with internal form scrolling and reachable title and save controls. The overlay stays inside the product mount root (Shadow Root for Userscript; embedded root for desktop) and suspends the outer settings panel's modal semantics and interaction; closing it restores focus to the region entry. Each save validates the complete current region before applying it: invalid input never prunes history or applies another region's drafts. Returning preserves drafts for the current settings session; closing settings unmounts them. Each dimension occupies its own row at every width, with aligned labels and inputs; very narrow containers put inputs below their labels. Region titles, descriptions, group units, and save status remain visible. Every settings number input hides native spinner arrows while keeping numeric range validation and the phone numeric keyboard.

Save buttons for downloads, playback history, creator names, request proxy, and filter history show a success or failure notice at the top, while retaining validation messages beside the inputs. Notices do not take focus, and each new result replaces the previous one. Success remains visible for three seconds and failure for five; settings confirmation does not share playback notices' cooldown. Shared top-notice text supports native selection and copying. Hovering or focusing a notice pauses its automatic dismissal; leaving both hover and focus resumes the remaining duration. A replacement result retains the interaction pause with a fresh duration, and disposing a theme presentation releases its pause. Success requires both valid input and a successful storage write. Failed writes preserve session data and allow another save attempt.

Filter-history configuration separates History Retention from Default Display using section headings, range hints, and grouped cards. Count inputs reuse the full border, background, radius, and keyboard focus styles of other settings forms, with the group unit beside the input. Each dimension occupies a separate row with aligned label and input columns and spacing between fields. A divider separates the complete History Retention and Default Display settings, rather than individual fields or the save area. Narrow containers use a smaller input column, and very narrow containers stack labels and inputs. The save explanation sits below the form, with Back and Save grouped at the bottom right. The proxy save button no longer shows synchronized or unsaved-change text on its left.

Music-source management explains beneath its title that at least one source must remain enabled and disabling a source keeps existing tracks and lists. The source list does not repeat this notice at the bottom.

Enable Request Proxy immediately applies the saved configuration; saving configuration preserves the current enabled state. While disabled, host, port, type, credentials, and SOCKS DNS remain editable and saveable. Reloading preserves the configuration and disabled state. Enabling requires a valid saved host, and the switch must neither apply nor overwrite unsaved configuration drafts. The single-proxy switch, credential and SOCKS DNS form applies only to Userscript GM transport. Desktop has independent account/proxy panels with the limits in [desktop rules](../tauri/development.md).

Component/logic checks and runtime acceptance have separate scope. The [theme acceptance entries](../../changes/acceptance/README.md) records installed GM and native Windows settings evidence, exact builds and remaining physical-input/native-dialog/mobile exits.

Desktop and Android inject Download Save Directory above the concurrency form in Song Downloads. The native picker applies and persists the choice immediately; the panel shows the applied directory and offers Change Directory and Ask Every Time. Cancellation keeps the existing choice without a success notice, pending actions disable duplicate submissions, and failures retain the displayed setting with retryable inline/top feedback. Android explains system folder restrictions; iOS shows native saving as unavailable. The Userscript has no directory picker. See [native saving and storage](../tauri/runtime.md#shared-behavior-and-storage).

# Shared page actions and accessibility

[中文](../../../zh-cn/板块/界面/页面操作与设置.md)

The themes render controlled page intents and share keyboard, touch and reduced-motion rules. See [shell layout](layout-and-navigation.md).

## Shared actions and collection controls

Collection display settings separate **风格选择** (item style) from **排列方式** (density/phone columns). Selecting a category slides to its options; Back returns to the extensible category list. Discover search/import request cards use one default presentation without a style selector or style preference. Whitespace (`留白`) is the initial music-card style; Inline actions (`直显`, stored as `default`) shows common buttons directly on each card. Each board owns its persisted item style in runtime-namespaced `collection-display:*:v1` preferences, separate from density regions. Playlist overview cards use one cover layout and offer arrangement only, including in global defaults. Changing density, groups, status tabs or complete themes never overwrites the item style. Plugin Center is unchanged.

`packages/card-styles` owns reusable controlled item renderers and lightweight style metadata; `packages/ui` owns the separate category/options dialogs. Complete themes adapt readonly player position and named intents; workbench owns persistence, playback and download operations. The 留白 (minimal) music style covers Discover, Listen Later, Favorites, playlist songs, Downloads and History: cover playback with an animated black hover/focus overlay, a three-dot menu, optional batch selection, and a primary-color border showing the active track's real normalized position. There are no card timers. Seeking, loops and density changes read the same clock; end returns the border to zero. Touch keeps playback visible, and reduced motion removes transitions. Artist, duration and ordinary download status share one metadata line, with tags on a separate single clipped line. Date/context text is omitted from these music cards, and history record identity/details stay available to selection/actions. Cover hold/arrow-key ordering remains available where the collection supports it.

Classic shows terminal playback errors in the top notice and omits the inline status rows in the bottom player and minimal card. Song actions display the generic failed-task label for download access errors.

The minimal music style uses landscape artwork above its text in wide lists, capped at 200 CSS pixels high, or 240 pixels in comfortable arrangements for slightly taller cards. Lists up to 600 CSS pixels wide use horizontal rows with 72-pixel square artwork; cells up to 260 CSS pixels wide retain small tiles so phone two-column layouts leave enough text width. Hovering scales artwork within its clipped frame; reduced motion disables scaling. The actual playing track shows a waveform on hover/focus with “正在播放，点击暂停”; clicking pauses through the host player action. Paused covers show Play and resume the current track without changing its position or resolving media again. Batch-selection checkboxes overlay the artwork without changing card height or text layout, using the inline-action style’s native checkbox and transparent 44-pixel target. In selection mode the cover only toggles selection, including for playing or invalid tracks, and omits the playback overlay for mouse, keyboard and touch. Closing the operator restores cover playback; supported hold/arrow-key ordering remains available in both modes.

- Main navigation preserves each destination's selections, applied filters, unfinished filter drafts, and Filter/Actions open states within the current workbench session. Leaving a destination hides its overlays and suspends keyboard and focus interaction; returning restores the previous state. Explicitly closing an Actions panel clears its selection and it stays closed on return. Queue, My Favorites, and Discover own these states, display density, and phone column preferences independently; actions and delayed summaries from another destination must not overwrite them.

- Discover and Listen Later share an empty-state surface when the list is empty or filters match nothing. It is white in the light theme and follows the surface token in the dark theme. The inset gray region expands through the shell's remaining content height while preserving outer and bottom padding; Listen Later, Favorites, playlist, and playback-history surfaces also fill that space when items do not fill the page, keeping items top-aligned and the same bottom padding. Collection arrangement and detail transitions adopt the incoming height immediately. Detail navigation clips the outgoing content to that frame. Center the icon, title, and description as one group horizontally and vertically within the surface, allowing natural wrapping on narrow screens. Match the destination icon: a magnifier for Discover and a queue icon for Listen Later. Icon hover adds a subtle translation, rotation, and scale, disabled for reduced motion. Listen Later guidance covers Discover, Favorites, playlists, and custom music rather than restricting additions to Discover.

- The mobile mini player's second-page return arrow stays on the right. Expanding the full player only suspends mini-player interaction; collapsing retains the previous page and restores focus to that visible page. Leaving mobile layout resets paging.

- A Custom Name subview in the track Actions dialog accepts up to 80 characters. Its footer places Back before Save Name; Back returns without submitting the draft, and saving an empty input restores the source title. Classic track dialogs group tag previews and existing tags on a subdued surface with primary-tinted chips. Tag management places Back below the add form, with no top return control. The optional `customName` belongs to the local library record keyed by the cross-source stable and unique `Track.id`; parts and subresources use their own track IDs, never titles, list positions, or temporary media URLs. The source title stays in `Track.title`. Search refreshes, favorites, playlists, and tag edits preserve the custom name, and older snapshots without it remain readable. Shared cards and the player derive names immediately from one injected mapping; future editing entry points reuse the library's `renameTrack` action. Cards use the custom name as their heading and retain a separately labeled Original line, including compact and two-column phone cards. Cards truncate long text; Actions details and the editor wrap the complete names. Local track filtering matches both names and name sorting uses the display name. Naming never changes track identity, source resolution, or the active playback session.

- Classic collection filter overviews, including Discover, show the draft conditions with a small primary-tinted count badge beside each active dimension title. The groups have no top or bottom border. The overview footer shows the match count once, with the numbers and unit in bold. Wide sheets align the count left and Cancel and Apply right. Narrow sheets place the count above a full-width row of equal-width buttons. The add-tag input draws its focus ring inward so the horizontal subview container cannot clip it.

- Track cards stretch to the height of their current responsive Grid row and align bottom actions. Two-column phones also align the author and inline action at the bottom; original-name cards retain natural whitespace without per-card size observers. Track and Music List Naming filters use native All / Custom Name / Original Name radio choices independently of custom-composition source type. Platform filters union selected platforms, intersect with other dimensions, and show all when none are selected. The platform editor displays “当前无任何平台” when there are no choices. Both dimensions reuse isolated drafts, live previews, removable overview criteria, and scoped history settings. Restore Original Names changes only selected renamed items, publishes and saves one batch, and preserves favorites, tags, playlists, request input, and creation time. recipes use the existing default naming algorithm for recovery.

- The Actions panel stays non-modal and exposes Add to Playlist, Download Selected, Add to Listen Later, Add to Favorites, and Restore Original Names when selected items include custom names. Wide layouts and phones slide up a horizontal action bar over the bottom player. On phones it also covers bottom navigation, reaching the player's top edge while leaving the launcher above it available. The system sidebar and its scrim layer above the action bar. Either the launcher or the panel close control can dismiss it. Adding to Listen Later, downloading and adding favorites require confirmation; Add to Playlist opens the multi-playlist picker directly, including an empty-state guide to My Playlists when no playlists exist. Submitting the checked destinations performs the addition without a second confirmation. Search/import results are read-only and never expose Delete Selected. Add to Listen Later deduplicates and saves once in selection order, leaving existing tracks in place. Reselected tracks move to the end; Select All appends only newly selected tracks. Bulk addition switches platform arrangement to All Tracks to preserve actual playback order and rejects an over-capacity batch in full.

- Track cards place artist, duration, and publication date on one truncated line, with play and danmaku counts on a translucent artwork caption. Track cards expose Play, Favorite, Download, and Actions as primary controls; Queue moves into the Actions dialog. One-column phone cards use a compact horizontal summary with artwork fixed on the right, statistics at the artwork's lower-left corner, and selection at the card's lower-right corner. Statistics and selection retain these positions in the two-column layout, which retains top artwork and a compact Actions control. The actions dialog provides Play, Queue, Favorite, and Download alongside tag management and the source page. Favorite and Queue show their current membership and toggle off on the next click; invalid tracks can still leave saved favorites or Listen Later. Additions use green success feedback, removals use blue informational feedback, and actual persistence failures use red error feedback. Play, Queue, Favorite, and Download draw keyboard focus rings inside their buttons to avoid clipping by the sliding stage. Tag management slides into a subview with existing tags and add/remove controls. List and track selection controls have at least a 44px target, and the artwork is part of the track selection target. A checkbox state and theme-blue track border convey selection; the selected track border takes precedence over playback emphasis while music-list cards retain their existing selected border without filling the whole card background or repeating “Select” on each item; pointer selection does not leave the keyboard focus ring visible.

- Filters share draft transactions, previews, cancel/apply, date editing, and history mechanisms; each feature owns its state shape, matching rules, dimensions, and wording. Business containers must supply stable history ownership: the outer music-list filter has its own owner, and each track-list filter uses its recipe ID. Deduplication, retention limits, restore, and deletion affect only that owner. History limits and collapse preferences are configured by feature and filter region. Discover separates the outer music-list filter from the track-list filter; track lists share region preferences while retaining independent records. Listen Later has a separate track-filter region for text, user tags, duration, platform, and addition date, with its own history owner and preferences. The 100 most recently used filter owners are retained, and region preferences are independent. The current history repository stores only scoped entries.

- Desktop list and track operators keep 20px of space on each side and omit the divider beside the close control. Close and Select All share the upper row, while the lower row uses the full available width. All buttons align right as a group when they fit, with 12px gaps. Only insufficient width switches to left-aligned scrolling. Fit detection uses the full row width without subtracting the arrow, so fewer buttons or a wider panel can return to the right-aligned layout. Restore Original Names appears only when selected items include custom names; mixed selections restore only named items. On phones, lower-row buttons stay on one line with consistent heights and touch targets of at least 44px, without shrinking or wrapping. Overflow reveals a frosted fade arrow on the right that advances to the next group and returns to the start at the end; touch swipes and horizontal mouse dragging also scroll the row. Vertical input remains available, drag-generated endpoint clicks are suppressed, and changes in size or button count update the arrow. Reduced motion uses immediate scrolling. Operators coordinate bottom space with the same duration and easing as the panel slide when opening or closing. Missing space is calculated from the actual player height and already reserved mobile navigation, then added above the player so controls stay anchored to the bottom. The shell Grid shrinks the content viewport accordingly; trailing list padding and scroll alignment space let the last item scroll fully into view. Reduced motion disables this space transition. The three track collections share confirmation and deduplication for the four track actions, while each container owns business writes and the outer music-list operator keeps its own actions. Favorites, Listen Later, and Discover use the same zero-padding outer page rule; their inner gray content surface owns its surrounding spacing so Favorites does not double the inset.

- Enabled actions, Select All, Close, and overflow arrows in music-list, track-list, and Listen Later operators provide a subtle background change on hover and keyboard focus. Ordinary actions use the surface hover color, list deletion retains danger feedback, and blue primary actions brighten slightly through the light/dark `--am-color-primary-hover` token. The left icon of Search and Import entries scales and rotates slightly; form submission buttons also animate the left icon in the corresponding input row, with a slight upward movement for the import-link icon. Disabled actions do not react to hover. Reduced motion disables icon movement and color transitions while retaining static background feedback.

- Discover track lists, Listen Later, and Favorites default to four actions in order: Add to Playlist, Download Selected, Add to Listen Later, Add to Favorites. Contributed actions, including Add Tags, share the operator button size, border, background, hover, focus, disabled, and responsive styles. Hide queue/favorite additions only for a nonempty selection entirely in that collection; mixed selections add only missing tracks. Download and playlist actions remain visible. Downloads submit every selected song, including saved songs, for runtime verification or another save. Playlist additions skip existing membership in each checked destination. Downloaded means actual saved history; generated files, cancelled saves, and failed saves remain eligible. Favorites has no inline playlist selector: all collections reuse the multi-playlist picker and its empty-state guidance. Listen Later and Favorites place their respective red removal action second, immediately after Add to Playlist and before Download Selected, using the same danger colors, hover feedback, and disabled treatment as Delete Music Lists. Removal requires confirmation. Pending collection-action confirmations are ignored when their active page changes.

- Pages that need bulk selection, download, or collection changes use consistent action semantics, while filters remain visibly separate from data-changing actions; Delete appears only on editable collections. Playback transport remains in the player rather than in a bulk operator.

Every actionable music item offers “添加歌单” (Add to Playlist) immediately below Custom Name. Its subview and the operator picker reuse My Playlists artwork, metadata, card geometry and checkbox placement, with selection as the only item action. The scrollable collection provides display choices and filters. The control row shows only “已选 N 个” on the left, with Display, Filter and Select All on the right. All three use the operator launcher's 12px text and 36px height on desktop and phones; Select All uses a 16px checkbox. Narrow layouts use an icon-only 36px Display button. At container widths up to 320px, the count and Display occupy opposite sides of the first row, with Filter and Select All sharing equal widths below. Select All toggles the matching playlists, shows a primary-blue background only when every matching playlist is selected, and otherwise uses the default surface. Individual choices update that state immediately. Filtering retains other checked destinations; the selection count and final submission include all checked playlists. Each destination keeps existing songs in place and appends only missing tracks. Explicit return/close resets picker drafts; presentation replacement preserves active editing. Classic uses the shared headless selection logic. Node tests cover selection and event delivery; live layout/focus acceptance remains separate.

## Accessibility

Use native controls, label every icon-only button, manage focus/Escape/return focus for overlays, and never encode selection or failure through color alone. Artwork has alternative text, touch targets remain usable, and content works at 200% text zoom.

Virtual collections use the existing filters to match the complete collection supplied by its owner, including items outside the mounted window. Render the matching result through the same bounded virtual window; applying or clearing filters never switches to full-list DOM rendering or crawls remote pages. Browser Ctrl+F / Cmd+F stays native and searches only currently mounted content. Do not add a separate Find/View button, intercept the shortcut, or mount hidden/offscreen copies to expand native search or text selection.

At minimum, verify light/dark/system themes, both rail sides and collapsed state, narrow containers, keyboard order, touch alternatives, reduced motion, loading/empty/error/partial-success states, host-page isolation, hide/show restoration, and player/mobile-navigation stacking. Run the target tests and type check, followed by root `pnpm lint`, `pnpm format:check`, and `pnpm build`. Mobile work additionally compares each runtime's dependency graph and output size.

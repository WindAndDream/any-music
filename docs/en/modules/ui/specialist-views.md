# Specialist and plugin-center views

[中文](../../../zh-cn/板块/界面/专用功能界面.md)

Themes render bounded projections. See [library ownership](../library/README.md) for tag and creation data, and [plugin contracts](../plugins/README.md) for runtime authority.

- Download rows reuse the shared song actions dialog and add task controls and confirmed record removal. Card and list display preserve the same item identity.

- The creation workspace is paused. Active lists can still play and download published [segment recipes](../library/custom-tracks.md).

Tag Management presents a tag directory with its title and total at the top left and Display mode immediately before Filter. A Music Tags / Playlist Tags switch at the start of the toolbar uses the Favorites segmented-control styling. Both views share the namespace directory and global rename/merge/delete behavior; counts, platform coverage, units and associated items follow the selected entity kind. Tags can be created directly or added through song/playlist actions. Default fill keeps each tile at its text-based intrinsic width, capped at one full row. The next tile uses at most the remaining row width and truncates its name there; earlier tiles and the final short tile never stretch. A remainder smaller than a 44px control starts the next row. Single row gives each tag a full row. Names stay on one line with ellipsis and a full-text hint. Classic tiles share the white light-theme surface, including selected tiles; selection uses a primary-color outline. Normal activation opens tag information with a basic summary and three icon-led entries with supporting descriptions: Edit Tag, Covered Platforms and Associated Music. Entries slide into subviews with a return action, inert outgoing content and reduced-motion support. Edit Tag supports renaming and confirmed deletion with the same control styling as song actions. Covered Platforms shows readonly tag-like platform labels, each song count and the total. Associated Music reuses Classic's responsive music collection, filters and display choices, with selection but no playback or content-editing controls. Associated Playlists renders selectable playlist cover cards. Both collections share Display, Filter and Select All button sizing, arrangement and active-filter counts. The status shows only the selected-item count. Select All keeps its normal or selected appearance on hover. Music entries reuse their native selection controls and responsive checkbox positions, without enabling playback or content actions. Select All toggles only matching items and retains selections outside the filter. Dialogs grow with their content up to the available viewport height; only overflowing inner lists scroll, while outer content stays unscrolled; Back and a red Remove Tag action stay in the dialog footer, with removal disabled for an empty selection. The removal count expands and contracts smoothly, including digit-count changes, with reduced-motion support. Confirmed removal clears only the current label from selected music or playlists in one namespace commit, preserving other labels, associations and entities. Cancellation or failed writes retain selection. Desktop dialogs expand to 1440px when more than four items are associated. Empty playlists count as associations without source platforms; a multi-platform playlist counts once per tag and once per covered platform. Browsing conditions, view choices and association selections survive presentation replacement and returning to the overview; explicitly closing tag information or changing tags resets them. Opening the Operator reveals checkboxes, select-all, single-tag rename, merge and batch deletion; closing it clears selection. Classic reuses the collection surface, filter sheet and compact operator with plugin-owned editing state. Filters combine tag-name search, associated platforms (any selected platform), global counts of the selected entity kind (one/multiple), single/cross-platform coverage and recent/name/usage sorting. Classic tag-name input reuses Discover’s text-search controls. Platform, song-count, coverage and sorting choices use aligned option rows with an exclusive All entry and multiple specific selections. Selections within a filtering dimension form a union; dimensions intersect. Empty selections mean All, including new platforms. Sorting follows selection order as successive priorities and defaults to recent maintenance. The overview includes tagged-music or tagged-playlist and platform totals. Preview counts measure tags; Apply commits the draft and Cancel preserves the applied list. Filtering never narrows a tag's global association counts or mutation scope. Selection is restricted to matching tags; display, selection, detail and unapplied input survive theme replacement. Merge and deletion confirm the unique affected-song count and commit the batch once to the plugin namespace, without deleting host songs. Pending confirmations reject disposed presentations and changed association snapshots. Empty and unmatched results retain filtering and reset controls. Semantic tokens, 44px controls and container-based narrow layouts match other collections. Node interaction tests cover filtering, details, selection, atomic writes and theme continuity; browser and native layout/focus acceptance require separate requested inspection.

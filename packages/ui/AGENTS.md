# Shared product UI

Use `$any-music-ui-delivery` for implementation/review. Preserve the [UI contract](../../docs/en/cross-platform/features/cross-platform-ui-and-interaction.md). Shared UI does not choose transport; runtime adapters follow application guides.

- Own neutral responsive shell/navigation primitives, controlled contracts and reusable UI state. Classic chrome, source/search/catalog and library/queue/history/download pages belong to theme-default and are injected by applications. `/catalog` and `/library` export reusable headless filtering, selection and editing interactions; it never imports theme components. Depend on pure core/audio-composition entries, without apps, GM, Tauri or codec `/browser`.
- Ordinary settings/navigation/picker layouts and global feedback composition belong to theme-default. UI retains neutral settings contracts, validation/editing helpers, modal/feedback primitives and fixed host forms; no credential/runtime authority enters theme projections.
- Compose networking, storage, media and hide/show through props/events/slots or injected contracts. Do not expose GM keys or host selectors.
- Reusable item styles live in card-styles, consumed by complete themes. UI owns the separate extensible display-category/options dialogs; it never imports card-styles.
- Complete themes consume host-adapted values without plugin-center/SDK. Classic TrackRow belongs to theme-default; neutral TrackCardSummary, grid geometry and precise media controls stay in UI. No partial theme dispatcher or theme page/row skin belongs here. Host owns installation/account/consent/identity/recovery surfaces.
- SFCs own structure/presentation. Extract cancellation/retry, cross-view state and effects into composables; clean up scopes and reject stale results. Preserve props/emits/wording/outcomes during migration.
- Reuse `--am-*` tokens, `AppIcon` and the no-referrer remote-image component. Export shared styles separately. Both complete-theme hosts activate application-built inline resources in their stable presentation Shadow surface. Userscript also owns the outer host-page Shadow mount; Tauri normally imports native host styles. Host guards/floating launchers never enter desktop embedded layout.
- Product shells/global settings/music lists/search track lists use restrained radii: details 4px, controls 6px, artwork/rows 8px, cards 10px, panels 12px, overlays 14px through `--am-radius-*`. Pills/circles are for switches, rails, circular playback, drag indicators and dots. Limit shared card/artwork changes to designed pages; other areas need their own design. See [Corner Radii](../../docs/en/cross-platform/features/cross-platform-ui-and-interaction.md#31-corner-radii).
- Prefer container queries for descendants; preserve keyboard focus/reduced motion. Real mobile entries/async boundaries must exclude desktop modules; CSS hiding does not prune bundles.
- `useGridReorder` owns drop handoff: suppress transitions while rebasing the released transform after the controlled DOM reorder, then retain content visibility and the stable slot's `data-am-grid-landing` elevation until landing finishes. Keep this protection in shared motion logic/styles rather than relying on page-specific settling selectors. Cover both directions, committed order updates, reduced motion and cancellation/new-drag/disposal cleanup; Node tests do not establish visual acceptance. Theme reorder transitions use `--am-motion-fast/normal/slow` without delays; extend the shared completion contract before introducing other timing.
- Virtual reorder uses bounded `retainItem` holds for at most the source and current destination, transferred through landing without releasing the source. Wire them to `useVirtualItemRetention.retain(key, 'reorder')` and feed its retained indexes back into the grid; rejection cancels without evicting editing/focus sessions. Static sessions invalidate on spatial `layoutRevision`; opt-in live measured sessions refresh same-identity row heights only on spatial changes, preserving the grabbed point and frozen release positions through committed measurement. Width, columns, origin, direction, presentation and identity changes still cancel. Equal measurements/cache churn and metadata refresh are not reflow. `VirtualTrackCardGrid.reorder` keeps drop markers/elevation on its flat stable cell, natural measurement untransformed and movement on the inner surface. Release generations precede host callbacks; landing independently guards resize, roots and subsequent identity changes while allowing the expected eligible-subset commit through the next parent render. Every deferred phase rechecks its generation and connection. Focused virtual keyboard shifts pair retainItem with an abortable focusItem(kind, id, signal) adapter to retention.focusItem; dialog actions preserve background focus. Check composed hidden/inert ancestors and realign once after mounted measurements. Keyed FLIP registers only mounted stable slots, uses a separate surface between natural measurement and pointer motion, and triggers on spatial/collection or explicit display-layout changes, never scrolling or metadata alone. Cancel stale focus on newer operations or hidden/replaced roots, dispose both lifecycles, and disable motion for reduced motion while preserving keyboard focus. Production virtual drag admission still requires consumer semantic integration and runtime acceptance.
- Presentation continuity uses transient occurrence keys, intra-item offsets and control keys through the neutral `ui/theme` adapter contract and `ui/library` helper. Consumers register their current surface, use full virtual geometry or native item boxes, mount retained targets before focus, and cancel on user input, navigation, hidden/replaced roots or disposal. Lazy consumers expose readiness through a synchronous bridge; repeated render ticks do not establish loader completion. Never persist these snapshots or make restoration submit business actions. `VirtualTrackCardGrid` keeps track and collection layouts distinct; CSS remains the column/gap authority.
- UI tests belong in `test/`; application composition tests stay in apps. Node rendering proves neither real DOM/focus nor visual behavior.
- Full and virtual FLIP share `grid-move-animations.ts` rendering leases. Hold `data-am-grid-moving` continuously while cancelling/rebasing an interrupted animation; only its current finish/cancel/unregister may release it. Drag previews keep returning neighbors protected through their CSS tail, then transfer protection before clearing drag state. Keep card paint containment stable and outside motion wrappers. The [motion contract](../../docs/en/cross-platform/features/cross-platform-ui-and-interaction.md#7-motion-and-gestures) defines layering and the required regression matrix.
- Width invalidation discards old natural-height authority and batch-reads current mounted units before patching virtual rows; do not render temporary estimates then force layout to remeasure. Only motion may retain its preceding snapshot during that synchronous batch. Same-column width-driven positions/heights follow CSS without restarting FLIP; independent content/load reflows and column/grouping/gap changes still revise motion. Empty windows finish too. First/remounted measurements and cache eviction update rendering, anchors and live drag geometry without issuing a motion revision; retain a per-mounted natural height to recognize genuine resize/load reflow after cache eviction. Publish the height revision and reflow cause together, and advance the private comparison baseline on ingress/width. Keep drag revisions width-sensitive; never restore stale heights or use a motion snapshot as rendering/anchor geometry. CSS resize subscriptions belong to the element lifetime. Derive bounded row deviations before rebuilding complete geometry: estimate-equivalent ingress/eviction and changes below an unchanged maximum reuse immutable rows; a row shrinks below the estimate only when all its cells are measured below it. Capture scalar estimates outside complete-row loops. Actual spatial changes still rebuild O(N) rows/engine geometry. Follow the [drag lifecycle and dynamic mounting budget](../../docs/en/cross-platform/features/cross-platform-ui-and-interaction.md#71-drag-release-and-consumer-lifetime); fresh consumer snapshots and drag-then-sidebar regressions are required.
- Pointerup performs final hit testing/translation without an extra edge-autoscroll step. Drag and virtual anchoring share `native-scroll-anchor.ts` leases on the actual viewport: acquire before drag measurements, transfer through landing and restore only after the last owner releases, including cancellation/failure/disposal. A changed DOM capture-root height refreshes untransformed stable slots in one coalesced batch, including release before ResizeObserver delivery; preserve the grabbed point and reuse geometry on ordinary pointer/scroll frames. Unchanged-total-height redistribution needs an explicit spatial revision or measured adapter. Width/column, ordered identity and root changes still cancel; stale observers cannot cancel a newer gesture. Keep card paint containment stable while outer motion wrappers remain uncontained. Prior-build performance evidence does not accept the current motion build.
- Virtual grid/table retention pairs `suspendReorder` with semantic `anchor.suspend` from first through last reorder hold, including source/destination replacement and landing. Native-anchor suppression alone cannot prevent a semantic commit-time scroll jump. Before starting landing, recheck/rebase a final measured extent and adopt it as the RO baseline; its delayed notification cannot cancel that same landing. Independent later reflow still cancels. Regress both viewport offset and neighbor paint coordinates.
- Grid measurement validity follows each row's typed, unordered sibling membership, separately from global ordering/motion revisions. Keep valid heights for same-row permutations and unrelated rows; only changed cohorts remeasure. Clearing the whole cache on commit can collapse the extent and cause browser scroll clamping even with both anchor owners suspended. Regress first-visit/top-aligned release and fractional boundaries, checking total extent and scroll position.
- Typed editing sessions retain in-memory queries, filters, selections and unfinished inputs across presentation replacement. Scope by stable feature/recipe/task identity; never put repositories, services, media or runtime authority in editing cells or plugin snapshots. Only the owning controller/plugin disposes the session; explicit cancel/close/publish/clear owns its reset semantics.
- Complete themes share neutral settings cells and stable collection filter scopes. Range editors support an explicit editing owner when a layout composes the editor inside its own provider; do not rely on a component injecting its own provide. Theme-specific layouts stay in their theme packages.
- `/theme` also exports named specialist presentation contracts. Host-bound renderless editors expose readonly projections/actions and neutral controls; no editing-session disposal, namespace storage or concrete plugin import crosses into themes.
- `/theme` is the lightweight public complete-theme contract: readonly feature projections, named actions, protected slots, metadata and coverage validation. It must not load Vue, styles or business instances. Workbench adapts its stable controllers into it. See the [migration plan](../../docs/en/cross-platform/architecture/independent-theme-development.md).

Start with `pnpm --filter @any-music/ui test` and `pnpm --filter @any-music/ui typecheck`. Build actual consumers after style/public-export changes. Live inspection requires explicit user direction.
`VirtualTable` also offers opt-in `interaction`, `anchor` and `anchorResetKey`, exposing the same bounded retention/anchor ports as the grid. Register each natural tbody unit without introducing non-table wrappers; re-register surviving keyed groups on context handoff and release every listener/hold on disable/disposal. Consumer dialogs and semantic restoration remain caller-owned.

- tag rules/filter composables and neutral specialist controls/styles belong to plugin-tag-management; whole-page classic tag layout/styles belong to theme-default. UI retains controlled editing/filter primitives and public port types without reverse plugin imports. Disabled filters remain visible/inactive and need explicit restoration; async edits recheck contribution identity/generation.
- material editing/timeline/filter composables and neutral specialist controls/styles belong to plugin-music-creation; whole-page classic creation layout/styles belong to theme-default. UI retains controlled published-work lists/named port types. The creation plugin owns both Custom Music and Segment Creation sections; published assets/core playback/download actions remain independent of its lifecycle.
- Plugin UI projects built-in modules and current native package snapshots. UI never decides builtIn/signature trust or grants execution; host actions recheck native runtime policy.
- NativePluginAuthorityPanel consumes native snapshots and emits refresh/revoke only, without deriving/persisting grants or creating installs. Workbench/runtime own async/native commit order. No native crate/Tauri dependency.
- PluginPackagePreview displays native identity/fingerprint/hash, permission differences and blockers, forwarding selectFile/clear to workbench. File selection grants nothing; unadmitted targets have no activation action. Unverified publishers remain labeled as such; plugins cannot replace host preview/consent structure.
- Native file/URL/consent-install/rollback, controlled commands/result saves and DEV pairing use typed props/events only. Do not persist addresses, parse pairing secrets or start networking. Preview grants nothing; native code rechecks main actions. Show blockers for unknown targets; buttons/policy names are not grants. Userscript injects no native delivery entries.

# Classic theme

- Shared renderer presentation only. Read the [theme guide](../../docs/en/cross-platform/architecture/independent-theme-development.md) and use `any-music-ui-delivery`.
- Depend on public UI contracts/primitives, core types and controlled card-styles renderers. Never import workbench, applications, another theme, plugin implementations, runtime APIs or repositories.
- Root metadata exports only `descriptor`. `/vue` owns controlled Vue components; `/styles` owns scoped classic layout rules. Metadata must not load Vue, styles or business instances.
- Player input is a readonly projection with named events. Media elements, resolution, subscriptions, queues and disposal belong to the stable host controller.
- `/vue` exports the complete definition and named controlled widgets. Library pages cover favorites, playlists, Listen Later, history, published works and downloads; `/library` in UI supplies reusable headless interactions. Applications consume definition for complete-root production composition; no partial extraction maps remain.
- Own classic source selection/search/import, catalog lists/context/paging, filters, batch controls and ordinary song dialogs. `/catalog` in UI retains predicates, typed editing state and DOM interaction helpers. Catalog views consume stable source/request/account identities and emit intents; they never construct sources, iterators, media or persistence. Keep pagination admission and unfinished input in host-owned editing scopes across view replacement. Classic TrackRow and list skin belong here; neutral summary/grid geometry/image primitives remain public UI components.
- Themes emit named task and library intents. Runtime saving/verification, repository writes, scheduler admission, task identities, progress and cancellation remain in their stable host owners. Unmounting a page must not cancel downloads or replay a pending confirmation into another page.
- Ordinary settings/pickers and global confirmation/notice composition live under `components/settings` and `components/overlays`. Pass source descriptors, readonly values and named operations; reuse neutral UI editing/validation. Only actual host settings close clears drafts. Account/login, proxy credentials, native installation/consent and recovery remain fixed named host slots; theme styles must not target protected content.
- catalog-root editing cells belong to public `ui/catalog`, shared with independent themes. Queue/favorites/download filter scopes use stable feature identities; keep headless state neutral rather than requiring another theme to import classic internals.
- Own TagManagementPage/MusicCreationPage and ClassicTags/ClassicComposer, plus built-in plugin-management presentation. Consume the host-bound renderless editors and named public `ui/theme` projections/actions; reuse only explicitly adapted neutral plugin controls. Never copy associations, material selection or recipe state into theme storage. The definition covers all required and both optional regions, and applications inject it into both production runtimes.
- Tests mirror `src/` under `test/`. Run package tests/typecheck, boundary checks and both frontend builds. Product/browser inspection requires an explicit user request.
- Keep virtual adapter registration callbacks stable for each mounted surface across fresh controlled snapshots. Its own reorder commit must not unregister the adapter or cancel landing/focus. Cover real-consumer immutable commits and drag-then-sidebar behavior using the [drag handoff checklist](../../docs/en/cross-platform/features/cross-platform-ui-and-interaction.md#71-drag-release-and-consumer-lifetime); mounted counts follow viewport/style geometry, not fixed 30/50/32 caps.
- C00 Favorites, C01 Listen Later and C02 playlist details each have an independent private, default-closed gate, including flat tracks, platform details and the growing platform overview. One consumer's gate never admits another. Reuse the real rows/cards and collection-grid sizing. Semantic restoration uses `favorites:*`, `queue:*` and `playlist:<id>:*` regions, waits for the current lazy adapter and restores stable keys/offsets before focus; the existing collection remains the sole mutation owner. Preserve complete filtered order, queue positions/current item, playlist-scoped selection/removal and stale-confirmation rejection. Studio counterparts and runtime input/layout/drag acceptance remain separate; automated candidates do not admit production virtualization.

See [Independent Theme Development](../../docs/en/cross-platform/architecture/independent-theme-development.md) for new build-owned themes and current entry/style/allocation rules.

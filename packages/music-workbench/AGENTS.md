# Shared music workbench

Shared scope; consume capabilities through the [shared contracts](../../docs/en/cross-platform/README.md). Each application's guide owns Userscript/Tauri differences.

- Production Userscript, Tauri desktop and future mobile share business orchestration, player, downloads, repository validation and product entry points. No GM, Tauri, Electron, Node or app imports.
- Vue/browser media belong to explicit renderer consumers and must not load through document-start entries.
- Configure WorkbenchRuntime before mounting: applications inject HTTP, stable storage, sources, login and proxy configuration. Storage keys contain business suffixes only; runtimes add namespaces.
- Userscript injects GM HTTP/storage and host capabilities; Tauri injects IPC/Rust HTTP, separate product storage, media grants and native saving. Workbench knows no GM secrets, account cookies or WebView authentication. Shared algorithms never bypass ports.
- Controlled contracts and neutral UI stay in ui. applications inject complete theme definitions/loaders/resources; createWorkbenchThemeFeatures projects the existing controller into public ui/theme contracts. Production never imports a concrete theme. Only one complete theme.root contribution is admitted; extraction chrome/catalog/library factories are unsupported. Source protocols belong to plugin-source-bilibili / plugin-source-douyin. Runtime identity/proxy routing do not enter player logic.
- Complete-root settings/overlay features project ordinary settings, pickers and global feedback. Project source descriptors rather than executable plugins. Actual settings close invalidates its editing scope synchronously and advances presentation identity; theme replacement retains it. Account/proxy models, native consent and recovery remain host-owned.
- `src/plugin-adapters` owns trusted core/wire conversion; SDK never depends on core. examples grant no authority; product catalogs use named nativePluginAuthority ports with authority retained natively.
- `src/plugin-adapters` also owns built-in directories, named business ports and view contribution keys. Runtimes inject lightweight module/theme directories and reuse business instances. features/plugins owns independent recovery, contribution contexts and theme composition. tags/creation use app-injected loaders/named ports. Standard published-asset reads/playback/downloads remain independent of creation code.
- `createWorkbenchSpecialistFeatures` binds renderless tag/creation editors to the originating session and provides built-in plugin-management actions. Production complete roots consume these same stable adapters through named feature projections. Presentation replacement never replaces sessions, resets drafts or rebinds old async events to a new session.
- Tests mirror source under test. Preserve visible behavior, media budgets and cleanup; follow root checks/live-inspection limits.
- Cross-theme action/controller fixtures may consume theme-default and theme-studio as test-only dependencies. exercises both complete roots, including settings drafts, disabled plugins, no-source pages and real plugin/download/media continuity. Production source never imports either theme; production feature assembly is exercised by these real-root fixtures and the actual workbench host test.
- `MusicSourceWorkbench` owns one `useWorkbenchController` and native audio node above replaceable presentations. Business/media/plugin factories and protected form models live in that stable scope; Each theme owns its DOM, measurement and animation cleanup; the generic host restores semantic focus/scroll. Presentation disposal must never stop playback/downloads or replay business actions.
- `/theme` is renderer-only complete-root host composition: inject build-known themes/fallback, reuse the single trusted transaction and persist only successful current selections after render. It never constructs business state. The lightweight root stays free of Vue and theme implementations. Production uses this single complete-root transaction. Node host/continuity tests do not establish real focus/layout or native acceptance.
- tag namespace is the single source of truth; host library reads contain no user tags. features/plugins adapters own session generations, projections and error isolation without importing specific plugins. Bind management events to their originating session; disable/retry never replays confirmations into a new session.
- creation sessions exclusively consume their namespace. The creation module owns both Custom Music and Segment Creation navigation/views/commands and withdraws them together. Host library reads/writes never join or rewrite materials/drafts. Named host operations publish standard works and perform explicit material cleanup; bind page events to the originating session.
- independent source metadata/lazy /runtime assembly preserve provider IDs, separate from module/contribution IDs. Disablement/invalidation cancels lists/resolution/media. Restore never replays tasks; zero usable sources must not block core views.
- trusted `/plugin-data` projects allowlisted text/provenance and submits non-destructive annotations. Unknown provenance is at least L2; never downgrade Secret. Native authority owns annotations/versions/provenance/receipts; do not separately write renderer repositories after native commits. nativePluginAuthority supplies snapshot/revoke and package previews; display projections are neither persisted nor treated as grants. Userscript injects no native port.
- Optional nativePluginAuthority previewPackage/discardPreview and consent-install/rollback ports check pre-read budgets, async freshness and native results, forwarding user actions without locally creating installs/grants. Close/dispose releases previews. Controlled UI never consumes SDK/native authority directly. Userscript injects none of these capabilities.
- Native picker/URL/DEV/current-preview remain optional named ports. Clean up late previews, async listener registration and DEV selection after disposal. New native previews invalidate older async displays. Never persist pairing paths or treat them as authority.
- install/rollback/command/cancel/export ports keep grants/sessions/paths native. Register catalogs from enabled snapshots; replacement/revocation withdraws projections, requests one page on demand and propagates cancellation. Guest artwork/page URLs never load. Missing media is explicitly unavailable. Userscript injects no native delivery ports.

- The product is unreleased: implement the current architecture directly. Do not add compatibility packages, previous product-schema readers, source JSON importers, archive UI or duplicate IPC aliases. Current plugin upgrade/rollback and crash recovery remain supported.

See [Independent Theme Development](../../docs/en/cross-platform/architecture/independent-theme-development.md) for new build-owned themes and current entry/style/allocation rules.
